你好 👋

我是 Midnight。

一个长期在工程一线里折腾的人，也是一名正在把技术能力从“写功能”推进到“做系统、做平台、做产品”的开发者。

早期我主要关注前端工程化、Vue / React、Node.js、Webpack、Vite 等方向。后来随着工作场景变化，逐渐进入 平台研发、运维开发、自动化测试、研测一体化、AI Agent、企业知识库与工作流自动化 等领域。

现在这个博客不再只是前端笔记本，更像是我的一个公开工作台：
记录技术方案、架构拆解、AI 工程化实践、Agent 落地方法、产品化思考，以及一些独立产品和商业化实验。

我现在关注什么

我长期关注一个问题：

如何把 AI 从“能聊、能写、能生成”，真正变成可以进入业务流程、研发流程、测试流程和运维流程的生产力系统。

所以，这里会持续记录这些方向：

  • AI Agent 工程化：Agent 工作流、工具调用、RAG、MCP、Skills、多智能体编排
  • AI Coding 与研发协作：从 Vibe Coding 到 Spec Coding，从提示词到工程规范
  • 研测一体化平台：版本管理、构建部署、自动化测试、测试任务编排、质量回流
  • 自动化测试与游戏云测：录制回放、云手机、证据链、失败归因、用例资产沉淀
  • 运维智能化：CMDB、Jenkins、任务编排、告警收敛、工单流转、运维 Copilot
  • 企业知识库与 RAG：知识检索、文档治理、向量数据库、权限与上下文控制
  • 内容产品化与独立产品：工具站、浏览器插件、内容检测、AI 服务交付、会员体系

我做过或正在做的方向

研测一体化与自动化测试平台

围绕研发、测试、构建、部署、执行、回归等流程，建设平台化能力。

典型场景包括：

  • 版本管理
  • Jenkins 一键构建
  • CMDB 关联部署
  • 自动化测试任务编排
  • 云手机录制与回放
  • 测试证据链存储
  • 自动化执行结果回写
  • 失败归因与质量分析

目标不是单纯做一个工具，而是让研发、测试、运维之间形成一条能沉淀资产、能复用经验、能持续改进的闭环。

运维开发与平台工程

我关注的运维开发，不只是写脚本，而是把运维动作抽象成平台能力。

比如：

  • 资源申请
  • 环境部署
  • 游戏更新
  • 开服合服
  • 告警处理
  • 工单流转
  • 自动化巡检
  • 知识库问答
  • 运维 Agent 执行辅助

这些场景背后，本质上都是“流程标准化、动作自动化、知识结构化、结果可追踪”。

企业 AI Agent 与知识库落地

我比较关注 AI 在企业里的真实落地，而不是停留在 Demo。

常见方向包括：

  • 企业知识库搭建
  • RAG 检索增强
  • 客服 / 售前 / 运维 / 测试 Agent
  • Dify / Coze / n8n 工作流
  • 老系统 AI 接入
  • MCP 工具扩展
  • Agent 执行链路设计
  • 权限、审计、可观测性与失败兜底

我更关心的是：AI 怎么接进已有系统，怎么处理真实业务约束，怎么让结果可控，怎么让团队真的用起来。

我的独立产品与实验

除了工作中的平台建设，我也在做一些个人产品和内容产品化实验。

K101.net 是我正在规划的主站，用来承接我的工具、服务、内容和会员体系。

它不是单一工具站，而是一个“一人公司式”的产品与服务收口：

  • 在线小工具
  • AI Agent 定制
  • 开源工具部署与落地辅导
  • 内容、服务与用户资产沉淀

SuperTextSwap

一个浏览器文本替换插件，用来解决网页文本替换、内容改写、页面展示调整等轻量需求。

这个项目最初很小，但很适合作为独立工具产品的练习样本：
从功能设计、插件开发、图标设计、宣传文案、分发渠道，到后续能力扩展，都可以形成完整闭环。

映芽 / 内容检测方向

我也在探索 AI 内容检测、AI 感识别、文章质检、内容生成与分发辅助工具。

这个方向关注的不只是“检测是不是 AI 写的”，而是进一步分析：

  • 内容是否模板化
  • 表达是否空泛
  • 是否存在 AI Slop
  • 结构是否机械
  • 是否适合公众号、头条、小红书等渠道分发
  • 如何把检测结果转化为可修改建议

我对技术的理解

我越来越相信，真正有价值的技术不是孤立的框架、语言或工具，而是能解决真实问题的一套组合能力。

一个系统能不能落地，往往不只取决于代码：

  • 需求有没有拆清楚
  • 流程有没有跑通
  • 数据有没有闭环
  • 异常有没有兜底
  • 权限有没有边界
  • 结果能不能追踪
  • 用户愿不愿意用
  • 团队能不能维护

所以我现在更关注 工程化、平台化、产品化、业务闭环。

写代码是入口，系统设计是骨架，流程和数据是血液，最终能不能产生价值，才是这件事真正的答案。
