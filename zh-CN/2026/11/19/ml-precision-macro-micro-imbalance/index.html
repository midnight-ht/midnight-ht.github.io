micro precision 八成，为什么 macro 只有四成多？

用九比一的固定分类样本手算两种精确率，保留每类预测分母，解释总分怎样隐藏少数类错误。

正文

核心要点

  • 精确率的分母是该类预测数量
  • micro汇总计数后计算比例
  • macro对各类精确率取不加权平均

十条分类结果，总体 micro precision 是八成，macro precision 却只有四成多。没有换模型，也没有换测试集，变的只是聚合方式。九条真实类别 A、一条真实类别 B，两边各错一条时，少数类的问题很容易在总计数里变得不显眼。

先确定每个分母在数什么

scikit-learn 的 precision_score 文档把精确率写为 TP 除以 TP 加 FP。对某个类别来说，分母数的是预测成这一类的条目，分子数其中预测正确的条目。它回答这类预测有多少可靠，与真实属于该类的条目有多少被找回，是不同问题。

micro 先把各类的命中与误报计数汇总，再计算一个比例。macro 先算每类的精确率，再对这些类别值取不加权平均。这里固定标签只有 A 与 B，没有额外样本权重，也没有多标签输出。先把这些前提写清，才能解释同一组预测为什么会得到两个数字。

主例中，九条真实 A 有八条预测为 A，一条错成 B。唯一真实 B 错成 A。因此预测 A 一共九条，八条正确；预测 B 一共一条，没有正确。两类都有预测条目，两个精确率的分母都非零。

A 的精确率是九分之八，B 是零分之一。micro 把八次命中除以十次预测，得到百分之八十。macro 则将九分之八与零相加，再除以两个类别，等于九分之四，约百分之四十四点四四。这里的类别平均给 B 一个完整位置，不会因为它只有一条真实样本就缩小到十分之一的位置。

用固定标签与预测逐条算

下列脚本只使用 Node 的标准能力，不加载分类模型，也没有调用 scikit-learn。它按固定数组计算两类的命中与误报，再核对独立手算出的计数和两个比例。输入按位置对应，最后两项就是两次错误的位置。

import assert from 'node:assert/strict';
const actual = ['A', 'A', 'A', 'A', 'A', 'A', 'A', 'A', 'A', 'B'];
const predicted = ['A', 'A', 'A', 'A', 'A', 'A', 'A', 'A', 'B', 'A'];
const labels = ['A', 'B'];
const counts = labels.map(label => {
  let truePositive = 0;
  let falsePositive = 0;
  for (let i = 0; i < actual.length; i += 1) {
    if (predicted[i] !== label) continue;
    if (actual[i] === label) truePositive += 1;
    else falsePositive += 1;
  }
  return { label, truePositive, falsePositive };
});
assert.deepEqual(counts, [
  { label: 'A', truePositive: 8, falsePositive: 1 },
  { label: 'B', truePositive: 0, falsePositive: 1 }
]);
const perClass = counts.map(row =>
  row.truePositive / (row.truePositive + row.falsePositive)
);
const totalHits = counts.reduce((sum, row) => sum + row.truePositive, 0);
const totalPredictions = counts.reduce((sum, row) =>
  sum + row.truePositive + row.falsePositive, 0
);
const micro = totalHits / totalPredictions;
const macro = (perClass[0] + perClass[1]) / labels.length;
assert.equal(micro, 8 / 10);
assert(Math.abs(macro - 4 / 9) < 1e-12);
console.log(JSON.stringify({ counts, perClass, micro, macro }, null, 2));

原样脚本已在本地 Node 环境执行，计数断言和两个聚合结果检查都通过。输出应包含 A 的命中八、误报一，B 的命中零、误报一，以及 micro 的零点八与 macro 的约零点四四四。运行回执只证明这份算术脚本，没有证明任何分类器的真实质量。

可以把最后两条预测分别修正为 A 与 B，作为独立负控制。此时两类每次预测都正确，两种聚合都应得到一。当前脚本的固定预期就应该失败，需要另建对应新输入的预期。这有助于检查测试是否真的连接了预测数组，不能把旧断言删除后就把新输出当成验证。

报告要让读者追得回那一类错误

只给一个总分，读者看不出哪种预测被信任过头。保留每类命中、误报和预测总数，就能从分母追到本例 A 的九次预测与 B 的一次预测。再保留真实类别数量，才知道测试集本身九比一的分布。两种数量都值得记录，但计算精确率时不可互换。

这十条是说明聚合的人工样本，没有置信区间、代表性保证或线上覆盖证明。尤其 B 只有一条真实样本，换一条输入就可能显著改变报告。要据此制定产品验收，需要另有合适的样本设计和错误成本说明，不能把这里的九比一比例说成真实业务分布。

macro 也不自动决定产品应该通过还是拒绝。它让每类的精确率具有同等平均权重，但某个产品可能对特定类误报更敏感。应先声明类别职责与可接受代价，再决定阈值。把平均方式写明，可以审查选择，不会替业务作出价值判断。

在当前每条样本恰好一个真实标签、一个预测标签，且汇总全部类别的条件下，micro precision 也等于这十条的准确率。这个相等依赖当前条件，不适合直接推广给只选部分类别或多标签任务。报告中仍应使用明确的指标名称，避免同一个「八成」被带到另一种任务里。

如果报告还显示模型概率，应把概率可靠性另行分析。精确率聚合只看当前标签计数，不能回答说八成把握的预测是否真的大约八成正确。相关问题可看 置信度分箱与校准差距。这两份证据可以并列保留，各自回答自己的质量问题。

做版本对比时，固定标签集合、样本身份和平均参数。新增一类后，macro 的平均对象已经改变，不能只凭数值升降归因给模型更新。若确实改变了测试合同，应把改变列在结果旁，另外保存旧合同下的结果，让两次计算有可追溯的共同基准。

计算前还要核对样本一一对应，不能把两个数组分别排序再按位置比较。标签值来自同一批样本，并不保证排序后仍保留原配对。若生产报告改用样本标识连接，应检查标识唯一且没有遗漏，再进入这些计数。

某一类从未被预测到，精确率怎么记？

这里新增零预测条件。如果模型一条 B 都没预测出来，B 的 TP 与 FP 同时为零，公式出现零分母，不能直接套主例零分之一的结果。这是未定义的精确率情形，需要显式约定处理策略。

当前文档的 zero_division 参数可选 warn、零、一或 np.nan。默认 warn 按零返回并发出警告；选择 np.nan 时，这类值会从平均中排除。文档标明 np.nan 选项在 1.3 加入。本文没有运行该 Python 包，因此这里依据的是官方参数说明，不是本机库输出。

在报告中保存所用版本、参数值和没有预测的类别。若选排除，macro 的参与类别会受到影响，应把这一点一起呈现。不要悄悄把缺少该类预测记成完美，也不要把「按约定记零」与「实际预测过却全部错误」写成同一份原始计数。
