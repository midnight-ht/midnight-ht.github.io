数值已经接近零，isclose 为什么仍为 False？

用正负残差和界内界外控制，核对 math.isclose 的绝对容差、相对容差与特殊值边界。

正文

核心要点

  • 对零比较非零有限值时，默认容差不能接受它。
  • 按单位和业务误差界选择绝对容差。
  • NaN、无穷与有限输入分别验收。

计算残差只剩万亿分之一，math.isclose 与零比较仍然返回 False。默认绝对容差为零，仅靠相对容差，任何非零有限残差都过不了与零的比较。零附近的验收需要按具体量纲设置绝对误差界，再给界内和界外各留一份样本。

数字小，与误差允许多大不同

假设一个本地计算器把理论上应相互抵消的量相加，结果为很小的非零残差。测试作者觉得它已经足够小，于是把等号改成 isclose，希望测试通过。但是这个函数要根据明确的容差判断接近程度，它并不知道业务认为万亿分之一是否可以忽略。这个判断应该来自测量分辨率、算法要求或接口允许误差，而非数字打印时看起来是否很短。

isclose 比较两数之差的绝对值，是否不超过相对容差与两数较大绝对值之积，或者绝对容差，二者中更大的那个。默认相对容差为十亿分之一，默认绝对容差为零。若其中一个值就是零，相对比较那一项也随着另一个数一起缩小，始终只是它的一小部分。所以一个非零数再小，也无法不大于自己的十亿分之一。

这也解释了反复把残差缩小为何没用。从十亿分之一缩到万亿分之一，左边的差值变小，右边允许的相对误差也按同样比例变小。要表达“离零不超过某个绝对范围”，需要给 abs_tol 一个有业务含义的正值。函数保留这种区分，能避免用户把比例误差和固定误差混在同一条阈值里。

选一个假设误差界，先写两侧预期

这里假设一种量的允许残差为十亿分之一的十分之一，仅用于教学。这不是适合所有测量单位的默认值。为了使第二组检查只回答固定误差界，把相对容差显式设为零。正负残差和参数交换都有独立断言。

from math import inf, isclose, nan

assert not isclose(1e-12, 0.0)
assert not isclose(-1e-12, 0.0)
checks = [
    (1e-12, True),
    (-1e-12, True),
    (2e-10, False),
    (-2e-10, False),
]
for residual, expected in checks:
    assert isclose(residual, 0.0, rel_tol=0.0, abs_tol=1e-10) is expected
    assert isclose(0.0, residual, rel_tol=0.0, abs_tol=1e-10) is expected
assert isclose(inf, inf)
assert not isclose(nan, nan)
assert not isclose(inf, -inf)
print("zero needs an absolute bound; sign and argument order verified")

默认设置下，正负万亿分之一都不接近零。显式设置绝对容差后，这两条落在界内，两条大小为界限两倍的残差落在界外。交换参数不会改变这些结果。选择界内与明确界外的值，可以防止测试只看到成功那半边，再把一个过大的容差误当作正确修复。

这份夹具对输入直接构造残差，没有模拟真实测量设备或业务算法。它验证函数如何接受和拒绝这些有限值，后面的特殊值断言则单独服务读者追问。输出只归属于当前标准库运行，不证明任何生产误差已经合格。真正的算法验收还要先确认残差怎么算出来，避免在误差已经过大时只是放宽容差让测试通过。

给阈值保留单位和选择理由

绝对容差和输入采用相同量纲。如果记录用米表示，换成毫米以后，固定绝对界也要作对应换算。相对容差表达的是比例，不需要随单位乘同一倍数。接口可以把单位与误差界一起保存，让测试报告说明这次为什么接受。只在断言里散落一个常量，后来把输入字段换了单位却忘记调整，就会改变原来允许的物理误差。

同时使用两种容差时，要记住函数选的是较宽的那个范围。假设你给了非常小的绝对界，但在大数量附近仍允许某个相对比例，比较可能因相对一侧而通过。不能从设置了 abs_tol 就推断误差必然小于它。若测试要求固定差值上限，可以像夹具一样明确关闭相对项；若要求混合政策，就对大尺度与零附近分别给一份预期。

一个可核对的修复可以把容差选择与计算实现分开评审。先由合同写出何种单位、哪种误差在本阶段可接受，再比较算法输出。为拒绝路径挑一条明确超出范围的输入，检查日志是否包含当前使用的误差界和单位。这样有人日后把容差放宽时，测试至少会在原来的拒绝样本上暴露变化。本文没有实施这样的服务日志，只提供本地接受关系。

近似相等也不适合直接当分组身份。固定绝对界为一时，零与零点七五接近，零点七五与一点五接近，零与一点五却不接近。这是从比较公式独立推演的例子，没有纳入运行夹具。如果要把记录分组或去重，应另选稳定的分组规则，避免依次比较的先后影响最后归组。

显示格式也要另查。把一个非零残差输出成小数点后三位，可能显示零，却没有改变参与比较的原始浮点数。若测试先把文本格式化再转换回数字，会主动丢掉信息。本站的小数精度与舍入解释存储或转换以后怎样失去原始精度；这里保持原始有限值不变，只改变判断是否接近的规则。调试时保存足够精度的输入与容差，比仅贴一行零点零零零更容易定位。

NaN 与自身、无穷与自身也能这样比较吗？

特殊值有独立语义。NaN 与任何值都不被认为接近，包括它自己；正无穷只与正无穷接近，负无穷只与负无穷接近。夹具因此分别检查正无穷对自身、NaN 对自身，以及符号相反的两个无穷，不能把有限值的容差推导直接套进去。若接口要求只接受有限测量值，应在容差比较之前另做有限性检查，并明确拒绝原因。此处不把接近结果当作值域验证，也不为具体行业设定允许误差。
