PostgreSQL 的中位数为什么不在原始样本里？

用四项测量区分 PostgreSQL 连续百分位的插值和离散百分位的选值。

正文

核心要点

  • 连续百分位可以插值。
  • 离散百分位选择已有观测值。
  • 记录身份与统计值要分别核对。

PostgreSQL 的连续百分位可以返回输入里不存在的数值。对十、二十、三十和四十取中位数，连续版本在中间两项之间插值得到二十五。离散版本则从排序好的输入取值，这组数据中会选二十。

假设团队把导入时长整理成一张报表。产品希望读者知道典型完成时间，排查工具又希望能指回原有记录。查询结果写成二十五毫秒，拿原始数据搜索却没有任何记录使用这个时间。先确认字段要表达的是什么。如果它是一种统计估计，找不到同值的原始记录可以符合合同；如果产品要求给出一个观测值，连续百分位不承担这个要求。

先确认中位数来自哪套选择规则

PostgreSQL 十八版在同一份文档里分别描述两类有序集聚合。连续版本可以在相邻输入间插值。离散版本从排序后的值中选择达到指定百分比位置的第一项。给这两个函数相同的四个不同数值，都求二分之一，并不能预期输出相同。二十五来自排序位置两侧的二十和三十，二十本身是第二项，也是累计包含一半样本时所在的位置。PostgreSQL 18 聚合函数。

有序集聚合的排序写在 WITHIN GROUP 里。查询最后排列报表行，无法替代每个组里对观测值的排序。另一个容易忽略的输入是 SQL NULL。这里两个百分位都忽略输入中的空值。假如采集器把没有响应时间的任务也写进一张表，统计结果只覆盖有时长的记录。数据合同若要求展示覆盖程度，可同时返回总任务数和实际测量数，并决定未取得时长的任务如何解释。不能把二十五毫秒自动归给没有测量的任务。

用四项测量核对两份结果

下面是未执行的教学 SQL。它给出四个毫秒数，再加入一条 SQL NULL，不依赖已存在的业务表。用 PostgreSQL 十八版验收时，先保留 measured 的独立预期，再分别比较两个聚合结果。

WITH samples(ms) AS (VALUES (10), (20), (30), (40), (NULL))
SELECT count(ms) AS measured,
       percentile_cont(0.5) WITHIN GROUP (ORDER BY ms) AS interpolated,
       percentile_disc(0.5) WITHIN GROUP (ORDER BY ms) AS selected
FROM samples;

预期 measured 为四，interpolated 为二十五，selected 为二十。不要让测试通过从同一函数反算预期，否则两种入口即使误接成同一个，结果也可能被接受。可以保存这四项外加一条空记录为独立输入。若实际系统会对小数做显示取整，先核对数据库结果，再检查界面怎样显示。一份页面看起来没有小数的截图，不能证明离散选择真的发生了。

再准备一个反例，让排序值为十、二十、二十和四十。这时两种策略对二分之一都可以得到二十。如果验收只用这一组数据，换错函数仍可能通过。因此将没有相同中间项的主样本留作区分两种策略的用例，再用重复值验证测试确实允许它们出现。主程序未运行，重复值也是单独的纸面预期。

如果来源组完全没有有效测量，应明确报表怎样标示没有结果。例如按服务输出时，保留服务标识和可用样本数，再定义百分位缺失的显示。不要擅自把空值转成零，因为零毫秒与没有一次测量表达的是不同信息。现场检查还要验证整组服务是否出现在结果中；从仅包含测量的明细表起步，即使处理了聚合的空值，也可能根本没有需要展示的分组。

从消费者需要的证据选择模式

如果容量规划需要比较连续的时长估计，使用连续版本，并让字段名说明这是一种计算结果。若系统要从输入定义的等级里选一个阈值，离散版本更容易维持等级合同。若后续页面要直接定位原始任务，仅返回一个离散时长还不够，因为同一个值可以出现在多条记录上。应另定义用任务编号、时间或明确的排序方法选择代表记录。用两条耗时相同但编号不同的输入核对这一段，而不是拿百分位数本身充当唯一主键。

组边界也可能改变结果。按整批计算和逐租户分别计算时，同样四个数字能落在不同组。实际验收应保存每个结果行对应的源记录集合和非空计数，再检查百分位。若某个关联多复制了一次十，累计分布会随之改变。要区分函数选择错误和输入行数错误，先核对同一条观测究竟参加了几次。站内的 PromQL 直方图桶校验 处理累积桶输入，本例直接使用每条精确观测。

如果输出还会参与告警，预期里应注明选择依据。设时长阈值为二十二毫秒，离散中位数二十不会越过它，连续中位数二十五会。团队要先确定告警针对的是选出的已观测阈值，还是连续统计值，再按选择写回归。验证报告可把原始样本、数据库未格式化结果、页面展示和实际告警状态放在不同字段记录。如果产品改了统计策略，测试也应表明哪些消费者受到影响。这个告警对照没有运行，示例没有配置告警规则或模拟通知。

如果一次传多个百分位，其中还包含 NULL 呢？

数组重载的返回形状跟请求数组一致，空位置留空。给同样四个有效观测传入四分之一、NULL、四分之三，连续模式预期依次为十七点五、空、三十二点五。离散模式预期十、空、三十。调用方应核对位置，再给显示标签配对，不能先删除空位置以后再按原下标贴标签。这个数组变体未执行；主例同样只有预期，没有实际数据库或报表结果。
