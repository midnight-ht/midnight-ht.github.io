同一条 PR 曲线，AP 为什么不等于梯形面积？

三条固定排序样本分别算出AP六分之五与梯形面积二十四分之十九，保留阈值方向与独立并列分数条件。

正文

核心要点

  • AP按召回增量加权精确率
  • 相同曲线点不保证同一计算约定
  • 报告应保留版本方向与插值选择

同一组排序结果，average precision 与 PR 曲线的梯形面积可以不同。scikit-learn 的 AP 按召回率增量加权当前精确率，不在相邻点间做线性插值。把两者都写成一个含糊的 PR-AUC，会让报告读者无法复算分数。先固定计算约定，再比较模型版本。

同一批样本，差别发生在怎样连接点

average_precision_score 官方参考给出的公式是各阈值召回增量乘该阈值精确率后求和。核对页面标为 scikit-learn 一点九点一，并说明从零点十九开始不再采用原来的线性插值方式。这里讨论这个实现的定义，不把所有名叫 AP 的历史指标都归成同一算法。

梯形规则把相邻两个精确率平均，再乘这段召回宽度。AP 则使用当前点精确率覆盖本段召回增量。两种规则输入可以完全相同，差别在点与点之间假设怎样累计。不能只保留一张看起来相同的曲线图，就认定两份数值报告必然可直接比较。

本题固定二分类、正类为一、没有样本权重，分数只是人为写定的排序值。它们不必是经过校准的概率。阈值从高到低下降，满足分数大于等于阈值的样本进入预测正类集合。每一步都保存真正命中和误报计数，避免只按屏幕上的折线形状猜面积。

三条排序样本的两份独立预期

标签依次是一、零、一，分数依次为零点九、零点八、零点七。第一个阈值纳入一个正类，精确率一、召回一半；第二个多纳入一个负类，精确率一半、召回仍一半；第三个纳入另一个正类，精确率三分之二、召回一。曲线补一个召回零、精确率一的起点。

AP 是一半乘一，再加一半乘三分之二，得到六分之五。中间那次新增负类没有增加召回，因此它的 AP 权重是零。但它改变了后一段梯形使用的起端高度。梯形面积是一半，再加一半乘以一半与三分之二的平均，得到二十四分之十九。

下面是完整标准库算术模块，未加载 scikit-learn，也没有训练或调用分类模型。预期计数与两个分数独立写定，不从待测公式重新计算期望值。代码按不同阈值组织点，保留等召回的垂直变化，而不是为了让图更平滑删掉它。

import assert from 'node:assert/strict';
const labels = [1, 0, 1];
const scores = [9 / 10, 8 / 10, 7 / 10];
const thresholds = Array.from(new Set(scores)).sort((a, b) => b - a);
const positives = labels.filter(value => value === 1).length;
const points = [{recall: 0, precision: 1}];
const counts = [];
for (const threshold of thresholds) {
  let tp = 0;
  let fp = 0;
  scores.forEach((score, i) => {
    if (score >= threshold) labels[i] === 1 ? tp += 1 : fp += 1;
  });
  counts.push([tp, fp]);
  points.push({recall: tp / positives, precision: tp / (tp + fp)});
}
let ap = 0;
let trapezoid = 0;
for (const [i, current] of points.entries()) {
  if (i === 0) continue;
  const {recall, precision} = current;
  const {recall: previousRecall, precision: previousPrecision} = points[i - 1];
  const width = recall - previousRecall;
  ap += width * precision;
  trapezoid += width * (previousPrecision + precision) / 2;
}
assert.deepEqual(counts, [[1, 0], [1, 1], [2, 1]]);
for (const [actual, expected] of [[ap, 5 / 6], [trapezoid, 19 / 24]]) {
  assert(Math.abs(actual - expected) < 1e-12);
}
console.log(JSON.stringify({thresholds, counts, points, ap, trapezoid}));

原样脚本已在本机 Node 执行。计数依次为一比零、一比一、二比一；AP 约零点八三三三，梯形约零点七九一七。这是当前人工输入和本地算法的结果，不是 scikit-learn 包运行回执，更不是模型质量或真实业务分布的证明。

此例 AP 大于梯形，不能据此宣布两者永远保持这个大小关系。官方说明线性插值可能过于乐观，并不意味着它对每个具体点集都一定更大。比较时应展示实际点集和算法，避免把一句文档提醒改写成未被证明的全称结论。两个独立分数在这里的意义是揭示定义差异，而不是评选哪种方法总能拿更高分。

报告要保留阈值方向与积分约定

precision_recall_curve 参考说明返回阈值递增，对应的召回序列递减，末尾还有一个没有阈值的精确率一、召回零点。本脚本为了按召回增加累计，使用阈值递减方向。把库输出拿来时，应按实际方向与端点计算，不能直接照搬正负号。

如果忘记方向，可能得到负面积；如果漏掉端点或随意删除垂直段，又可能得到另一份数。报告中写上指标名称、实现版本、正类、权重、点的方向和插值选择，才足以解释数字。一个名字相同但算法不同的旧报告，不宜仅靠小数位变化来归因于模型改进。

已有 micro 与 macro precision讨论跨类别怎样聚合命中与误报。本题是在同一二分类排序上改变阈值，再按召回变化累计。类别平均与阈值累计是两条不同轴，不能从一个默认参数名字相似，就省去说明当前指标究竟在平均什么。

实际版本对照还需要固定样本身份和预测分数配对。两个数组分别排序后再按位置连接，会改变正负标签属于哪份分数，计算虽然仍能返回数，却已不是同一批预测。可以把样本标识与两种值一起保存，再进入阈值表。这里按固定数组索引对应，未检验真实数据流水线。

分数可复算也不表示样本有代表性。这三条只是识别算法差异的最小教学输入，没有置信区间或线上覆盖。用它作回归夹具可以发现实现约定被换掉，但不能据此给产品定一个通用通过阈值。模型是否满足用途还需要任务、错误成本与恰当评估数据。

正负样本分数相同，能任选顺序逐条计算 AP 吗？

不能把相同分数拆成不存在的阈值。这里新增一正一负都得零点八的条件。官方曲线文档按不同分数生成阈值，并以分数大于等于阈值选入；这个阈值出现时，两条样本一起进入，召回为一，精确率一半。按本题非插值定义，AP 就是一半。

import assert from 'node:assert/strict';
const labels = [1, 0];
const scores = [4 / 5, 4 / 5];
const thresholds = Array.from(new Set(scores));
const selected = scores.map(score => score >= thresholds[0]);
let tp = 0;
let fp = 0;
for (const [i, label] of labels.entries()) {
  if (selected[i]) label === 1 ? tp += 1 : fp += 1;
}
const recall = tp / 1;
const precision = tp / (tp + fp);
const ap = (recall - 0) * precision;
assert.deepEqual([thresholds, selected, tp, fp, recall, precision, ap], [
  [4 / 5], [true, true], 1, 1, 1, 1 / 2, 1 / 2
]);
console.log(JSON.stringify({thresholds, recall, precision, ap}));

这份独立脚本也已在本地执行，唯一阈值零点八，两条选中标志都为真，结果一半。若先把正例单独算成一段、再让负例进入，就相当于虚构一个能选中前者却排除后者的分数阈值。仅调整并列样本在数组里的位置，不应凭空创造这样的决策点。

因此回归用例除了不同分数的主例，还应保留并列分数条件，记录阈值集合和每次纳入的样本。当前脚本只验证这个固定算术事实，没有替 Python 包报告实际输出。移到真实工具时，保存版本和原始参数，再对照同样独立预期，别把本地示意算法的成功归给未执行的库。
