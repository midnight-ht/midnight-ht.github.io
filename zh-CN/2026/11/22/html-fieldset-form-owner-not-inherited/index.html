fieldset 写了 form，里面的输入为什么还没进表单？

分别检查外部fieldset与两个输入的form owner和FormData，解释分组关联不继承及显式无匹配ID的覆盖。

正文

核心要点

  • form owner属于各个表单相关元素
  • 外部字段组不能替内部控件建立关联
  • 收集条目不等于提交和保存

fieldset 的 form 属性只给这个 fieldset 建立表单归属，不会把归属自动传给内部输入。把字段组放到表单外时，应逐个检查实际输入的 form owner。外层已经指向 order，里面没有自己关联、也没有祖先 form 的输入，仍可能不属于 order，收集结果自然缺少它。

视觉分组与表单成员各有一份关系

fieldset 可以把相关输入组织在一起，并使用 legend 表达组名。form owner 回答的则是某一个表单相关元素关联到哪个 form。分组包含某个输入，不等于这个输入继承了分组的 owner。检查外层元素的属性，只能证明外层配置了什么，不能代替每个控件自己的关联结果。

HTML 的 Association of controls and forms为各个表单相关元素分别定义 owner。本文使用二〇二六年十一月二十日更新的当前原文，限于连接文档、唯一标识、普通文本输入，不涉及解析器形成异常嵌套表单的特殊历史情形。

重置某个控件的归属时，规范根据它自己的 form 属性查找目标；在没有该属性的相应分支，才查最近的祖先 form。这里没有「找最近一个 fieldset，再继承它的 owner」步骤。因而表单外的分组有 owner，内部没有独立关联的输入却是 null，并不矛盾。

已有 按钮类型与表单归属已经说明外部按钮可以通过自己的 form 属性关联。本题增加的是字段组不传递归属这个条件。修复时不是再给外层多写一次相同属性，而是把关联送到真正需要成为表单成员的控件，或重新安排它与 form 的结构。

一份页面同时记录三种 owner 与实际收集项

下面是完整教学页面，尚未在浏览器执行，不发送请求，也没有真实订单。order 表单本身为空，外部 fieldset 指向它。两个输入都有名字和值，其中只有 y 自己写了 form。检查按钮显式为普通按钮，只构造 FormData 并把结果显示出来。

<!doctype html>
<meta charset="utf-8">
<title>Fieldset and individual form owners</title>
<form id="order"></form>
<fieldset id="group" form="order">
  <legend>External fields</legend>
  <label>X <input id="x" name="x" value="X"></label>
  <label>Y <input id="y" name="y" value="Y" form="order"></label>
</fieldset>
<button id="inspect" type="button">Inspect without submitting</button>
<pre id="out"></pre>
<script>
const byId = document.getElementById.bind(document);
const encode = JSON.stringify;
const hasOwner = (id, expected) => expected === byId(id).form;
byId('inspect').onclick = () => {
  const form = byId('order');
  const observations = {
    groupOwner: hasOwner('group', form),
    xOwner: hasOwner('x', null),
    yOwner: hasOwner('y', form),
    entries: Array.from(new FormData(form))
  };
  const ownersCorrect = ['groupOwner', 'xOwner', 'yOwner'].every(key => observations[key]);
  console.assert(ownersCorrect && encode(observations.entries) === '[["y","Y"]]');
  byId('out').textContent = encode(observations, null, 2);
};
</script>

独立规范预期是三个 owner 判断都为真：group 属于 order，x 没有 owner，y 属于 order。FormData 条目只有 y 和 Y。x 值仍然存在于页面，不会因为没被收集就消失；只是它不是这次收集所依据的那个表单的成员。这个区分可以避免把少字段误诊为输入值被脚本清空。

样本把两个输入的名字和值都写定，排除缺少 name 或空值等其他因素。若主例同时漏掉名字，就不能仅从结果缺项推断关联不继承。对照检查应只改变目标变量：给 x 自己加上正确关联后，再重新收集，预期增加 x。具体浏览器中的结果仍须实际运行后才能记为观察，本页不把纸面预期写成实测。

外层 fieldset 本身是表单相关元素，也不表示它会作为普通文本值贡献一条相同的输入数据。本例检查它的 owner，是为了说明关系；检查数据时看的是两个具名文本输入。对象关系、控件资格和最终条目是分开的观察，不能从其中一个布尔值直接跳到所有数据都已保存的结论。

组件传参需要到达实际输入

一种常见结构是页面底部渲染外部编辑区，调用端把 form 名称传给组组件。若组件只把这个属性放在最外层 fieldset，实际输入仍没有自己的关联。调用代码里看得到参数，不代表最终 DOM 已完成所需合同。应查看渲染后的控件，而不是只审组件接口名字。

可以让组件显式接收表单标识，并把它配置给需要参与的输入。另一种选择是把整个字段组放回对应 form 的后代范围，让各控件采用祖先关联。两种结构都需要根据页面组合方式决定，不能为了少写属性创建嵌套 form。复杂组件里可能还有帮助按钮和只读说明，并非所有后代都该无差别套同一个表单职责。

关联成功也不等于已提交或已持久化。主例的 FormData 只是在本地收集条目，既没执行提交，也没发 HTTP。即使目标浏览器输出了正确数组，仍只能证明该页面此刻的收集结果。真实业务还要检查发送内容和接收结果；不要把点击检查按钮显示的数据叫做订单已保存。

排查缺项时，可以先记录控件值、名字、owner，以及所用表单的实际身份。当前主例固定了可参与收集的普通输入；若真实控件被禁用、换了类型或由自定义组件承担，则应另查相应收集规则。给每个观察写上对象，能避免把分组的正确 owner 当成所有控件都正确的替代证据。

输入在 form 里面，却显式指向不存在的 ID，会回退祖先吗？

不会。这里改变结构条件：输入现在确实位于 form 内部，但它自己有一个指向 missing 的 form 属性。文档中没有这个标识对应的 form，当前归属保持 null，而不是在查找失败后回退到外层表单。移除这个覆盖属性，才重新按祖先关系取得归属。

<!doctype html>
<meta charset="utf-8">
<title>Explicit unmatched owner</title>
<form id="application">
  <label>Note <input id="note" name="note" value="N" form="missing"></label>
</form>
<button id="inspect" type="button">Inspect and remove override</button>
<pre id="out"></pre>
<script>
const get = document.getElementById.bind(document);
const encode = JSON.stringify;
const input = get('note');
const form = get('application');
const collect = () => Array.from(new FormData(form));
get('inspect').onclick = () => {
  input.setAttribute('form', 'missing');
  const before = {nullOwner: null === input.form, entries: collect()};
  input.removeAttribute('form');
  const after = {ancestorOwner: form === input.form, entries: collect()};
  const valid = before.nullOwner && before.entries.length === 0
    && after.ancestorOwner && encode(after.entries) === '[["note","N"]]';
  console.assert(valid);
  get('out').textContent = encode({before, after}, null, 2);
};
</script>

这也是尚未运行的完整页面。预期 before 没有 owner，收集为空；移除属性后 after 指向 application，条目成为 note 和 N。检查按钮每次先恢复 missing 条件，保证重复操作不是拿上次已修复的状态充当新的失败样本。给目标标识起一个不存在的非空名字，清楚表达这个独立查找条件。

这个问题解释了为什么仅把控件搬回表单里面仍可能少字段。旧组件若遗留一个显式 form 属性，祖先结构就不是决定归属的唯一信息。修复应确认覆盖是否还需要：需要时改成正确标识，不需要时移除属性。随后重新记录 owner 与条目，把关联修复和真实保存验证留成各自可核对的结果。
