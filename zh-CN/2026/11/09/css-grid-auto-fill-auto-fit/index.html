Grid只有两张卡片，空列为什么还占着宽度？

用900px容器、20px间隙和两卡片计算空列差异，再以四卡片、跨列与不确定尺寸解释auto-fit的选择边界。

正文

核心要点

  • auto-fit在放置后折叠空的重复轨道与相邻间隙。
  • 末行空格不等于空列，其他行或跨列项目会占用轨道。
  • 次数计算先于空轨道处理，尺寸不确定时需核对计数回退。

容器能放三列而只有两张卡片时，auto-fill 仍保留第三条重复轨道；auto-fit 会在项目放置后折叠空的重复轨道。要判断卡片为什么没有拉满，应先算能生成几列，再检查整条列轨道是否为空，而不是只数最后一行剩了几个位置。

CSS Grid Layout Module Level 2 的自动重复章节是本稿依据，取得的版本为二〇二五年三月二十六日候选推荐草案。以下限定独立网格轴上的自动重复，不把草案存在当作目标环境已完成兼容验收，也不讨论 subgrid 的完整布局规则。

先生成轨道，再判断哪些轨道为空

auto-fill 根据容器相关尺寸、重复轨道的尺寸条件以及间隙计算重复次数。采用 auto-fit 时起初计算方式相同；差异出现在项目放置之后：空的重复轨道被折叠。这个先后顺序解释了为什么把关键字换掉，不一定马上看见列数或卡片宽度改变。

原文的“空”不是某一行没有卡片，而是整条轨道没有流内项目放入，也没有流内项目跨越它。三列四张卡片时，第一行已占三列，第二行虽然只剩一张，另外两列仍因第一行的项目而非空。auto-fit 不会把第二行那张卡片独自拉成整行。

折叠轨道按固定零像素处理，两侧间隙也会折叠。留下的非空轨道若采用 fr 分配剩余空间，就能变宽；变宽不是 auto-fit 自己给卡片设置了新宽度，而是折叠后剩余空间分配的结果。若轨道最大尺寸固定，不应期待所有空余空间都自动变成卡片宽度。

一个可以手算的两卡片页面

以下完整 HTML 尚未执行。两个容器均宽九百像素，间隙二十像素，每列最小二百五十像素、最大一份剩余空间。没有边框和内边距参与宽度，故意排除盒模型差异；示例卡片只是文字，不带商品数据或业务动作。

<!doctype html>
<meta charset="utf-8">
<title>Auto-repeat teaching fixture</title>
<style>
.grid { display: grid; width: 900px; gap: 20px; margin-bottom: 20px; }
.fill { grid-template-columns: repeat(auto-fill, minmax(250px, 1fr)); }
.fit { grid-template-columns: repeat(auto-fit, minmax(250px, 1fr)); }
.card { min-width: 0; background: #eee; padding-block: 20px; }
</style>
<h1>Two cards in identical containers</h1>
<div class="grid fill" id="fill"><div class="card">A</div><div class="card">B</div></div>
<div class="grid fit" id="fit"><div class="card">A</div><div class="card">B</div></div>
<button type="button" id="add">Add C and D once</button>
<pre id="out"></pre>
<script>
const byId = id => document.getElementById(id);
const ids = ['fill', 'fit'];
function report() {
  byId('out').textContent = JSON.stringify(
    ids.map(id => {
      const grid = byId(id);
      return { id, tracks: getComputedStyle(grid).gridTemplateColumns,
        widths: [...grid.children].map(n => n.getBoundingClientRect().width) };
    }), null, 2);
}
byId('add').addEventListener('click', event => {
  for (const id of ids) {
    for (const label of ['C', 'D']) {
      const card = document.createElement('div');
      card.className = 'card'; card.textContent = label;
      byId(id).append(card);
    }
  }
  event.currentTarget.disabled = true;
  report();
});
report();
</script>

独立预期先由最小尺寸计算。三列最少占七百五十像素加两段间隙，共七百九十；四列至少一千像素加六十，超过九百，因此初始生成三条重复轨道。auto-fill 保留它们，每列预期约为二百八十六点六七像素。这里是数学推导，不是已经获得的浏览器输出。

在后一种布局中，只有两条列轨道有项目，第三条为空并折叠。对应间隙折叠后，两条活动列之间剩一段二十像素间隙，各分得四百四十像素。观察时应同时查看计算后的轨道列表和卡片矩形，浏览器像素舍入可用合理误差比较，不要求显示字符串完全采用同一种小数格式。

点击按钮增加 C、D 后，两边都有四张卡片。现在前三张已经占满三条列轨道，第四张换到第二行；两种布局都没有空列可折叠，所以最后那张也不会占满九百像素。这个反例比只截图两卡片版本更有用：它能检验团队是否误把“空单元格”理解成“空轨道”。

跨列项目会改变“空”的判断

若一个流内项目跨越第二、第三列，即使你没有另外放一张卡片到第三列，第三列仍不空。要分析实际页面，应检查显式放置、跨越范围与自动放置结果，不能只数直接子元素个数。两个项目未必只占两条列轨道，四个项目也未必按默认顺序各占一格。

同样，某种样式看不见内容，不自动意味着那个项目不参与布局。本稿不提供按所有可见性状态分类的通用函数；检查标准应回到是否仍有流内网格项目占用或跨越该轨道。用浏览器的网格覆盖层和盒矩形解释结构，比从卡片颜色判断轨道是否存在更可靠。

自动重复还有语法约束，不能把任意弹性或内在尺寸表达式塞进重复体。常见的 minmax(250px,1fr) 保留可用于次数计算的固定最小值；把它随意改成不同的内在尺寸组合，可能已经不是有效的 auto-repeat 声明。先核对声明是否被接受，再讨论 auto-fit 为什么没有生效。

容器尺寸不确定时，为什么只生成一次重复？

该版规范在独立轴上先看相关确定的首选尺寸或最大尺寸，再看确定的最小尺寸；若这些条件都不提供计数依据，指定轨道列表只重复一次。因此，页面不再有明确的宽度约束时，不能把单列结果一律解释为空列被折叠。

这个问题发生在计数阶段，早于项目放置后的空轨道处理。应记录网格容器在该轴的尺寸约束、重复体尺寸与可用空间；width:auto 的字面值本身不等于整个布局结果一定不确定，需要结合包含块和布局上下文判断。不要只把示例的九百像素删掉，再把出现的任何结果归给同一条规则。

选 auto-fill 还是 auto-fit，应来自少量项目时的产品目标：希望保留可容纳的空位和相近列宽，可以采用前者；希望真正空列折叠，让已占列分配更多空间，可以采用后者。若要求每一行独立均分，包括末行少量卡片，需要另设计布局，而不是给 auto-fit 一个它没有承诺的任务。

待执行验证覆盖两卡片、四卡片、跨列项目、无项目以及容器尺寸变化，保存声明、放置范围、计算轨道与盒宽度。它和共享子网格轨道是不同问题：这里先确定哪些独立列存在。本文没有运行浏览器；交付前先用四卡片反例核对目标，能避免把一次两卡片演示批准成末行总会铺满。
