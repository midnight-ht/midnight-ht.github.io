CSS subgrid：卡片都写同样Grid，内部行为何仍对不齐？

以完整三卡片样本解释独立嵌套网格与subgrid的尺寸关系，核对共享轴、跨度和新增字段。

正文

核心要点

  • 相同模板不等于共享同一次轨道计算。
  • 子项参与采用subgrid轴上的父轨道尺寸。
  • 新增字段与阅读关系仍需单独设计。

每张卡片都写相同的行模板，长标题仍可能只把自己的价格和动作推下去。独立嵌套网格各自计算轨道；subgrid让选定轴上的子项参与父网格的轨道尺寸。先决定哪些内容需要共享哪几行，再检查卡片跨越的范围。

相同声明不等于同一次尺寸计算

CSS Grid二级规范的子网格章节说明，子网格在采用subgrid的维度使用父网格相应轨道，其子项参与那些父轨道的尺寸计算。本文读取页面的版本标题为二〇二三年十月三十日候选推荐草案；这是当前获取的原文，不写成刚发布的新功能，也没有目标浏览器兼容性测试。

普通卡片各自display:grid，再各自声明三条auto行，仍是三份独立布局。甲的长标题只影响甲自己的标题行，乙的短标题没有理由跟着增高。复制CSS可以统一算法，却没有让三次算法共享同一组输入和轨道，这正是“代码一样、结果没齐”的来源。

subgrid改变的是尺寸关系，而不是把标题强制裁成一行。若标题行需要容纳三张卡片中最高的内容，先让三张卡片都覆盖同一组父行，再让内部元素使用对应子网格。布局目标是对齐语义位置，不是给所有标题设一个猜测高度。

三张卡片共享三行的完整样本

以下是未运行的静态HTML，价格和卡片均为教学内容，按钮暂不承担业务动作。保存为文件后可比较长短标题的轨道关系；示例没有查询商品或测试点击结果。

<!doctype html>
<html lang="zh-CN">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>卡片共享轨道样本</title>
<style>
  .cards { display: grid; grid-template-columns: repeat(3, minmax(0, 1fr)); gap: 1rem; }
  .card { display: grid; grid-template-rows: subgrid; grid-row: span 3; border: 1px solid; padding: .5rem; }
  .card > * { margin: 0; }
  @media (max-width: 40rem) { .cards { grid-template-columns: 1fr; } }
</style>
</head>
<body>
<h1>教学方案对照</h1>
<div class="cards">
  <article class="card"><h2>短标题</h2><p>演示价10单位</p><button type="button" disabled>教学动作</button></article>
  <article class="card"><h2>一个需要在窄卡片中换行的较长教学标题</h2><p>演示价20单位</p><button type="button" disabled>教学动作</button></article>
  <article class="card"><h2>第三方案</h2><p>演示价30单位</p><button type="button" disabled>教学动作</button></article>
</div>
</body>
</html>

父网格提供三列，自动放置的卡片各跨三行；同一横排中的卡片覆盖相应三行。标题、价格、动作分别进入这组共享行，长标题可以影响共同的标题轨道。这里按布局规则描述预期，不提供实际像素高度或截图回执。

对照时只把card的grid-template-rows改成auto auto auto，保留其他条件。这样各卡片仍占父网格相应区域，但内部三行改为独立尺寸计算。比较的是共享轨道与独立内部轨道，而不是一边改字号、一边改宽度，再把所有差异都归给subgrid。

窄屏变成单列后，不同卡片可能落入不同的三行组。不能据此要求所有纵向堆叠的价格仍共享同一条全局横线；响应式目标应该重新解释为每张卡片内部完整可读、动作不被裁切。共享范围与当前放置关系一起决定效果。

先明确共享轴与跨度

只在行轴使用subgrid，不会自动共享列宽。需要共享列时应检查另一轴与父轨道；如果卡片在父网格只占一条轨道，却期待内部借用三条，就需要先改跨度关系。属性出现了，不表示它已经借到设计要求的范围。

子网格内部线号从它覆盖的范围起算，不等于父网格的全局编号。假设父网格第二到第四条线之间是子网格范围，内部的第一条线是这个局部起点。维护者如果照抄父网格数字，可能把项目放到另一个位置；应保留父范围与局部放置的对照。

间隙也参与关系。默认情况下，子网格可以沿用对应父间隙；若局部主动设置不同gap，内部项的边缘关系也会变化。这里不建议在第一个样本中同时改变padding、gap和行号。逐项修改并说明预期，比只看最后是否“差不多对齐”更容易定位问题。

多一项说明，会自动长出第四条共享行吗？

采用subgrid的维度没有独立的隐式网格轨道。固定跨三行的卡片突然增加第四个需要单独占行的内容，不能期待它在该轴随意新增一条与其他卡片共享的行。规范有放置和限制规则；应用仍需决定多出来的信息属于哪条内容关系。

若第四项是所有方案都有的必要条件，可以重新定义父轨道与卡片跨度，把它作为共同一行。若只是标题的补充说明，可以将标题和说明组织在同一个内部内容块，再让该块参与标题行。两种设计不同，不能通过固定高度和隐藏溢出把新增信息抹掉。

有些卡片根本不需要共享内部轨道，例如各自独立的文章摘要。此时普通嵌套grid或正常流可能更简单。选择subgrid应来自跨卡片的对齐合同，而不是因为它比复制一组数字更新。若对齐迫使用户来回比较不相关内容，就应先审视信息组织。

视觉排齐之后，阅读关系还要检查什么？

卡片内部的文档顺序仍应说明每个价格和动作属于哪个方案。subgrid没有替你建立业务身份，也不会把被打散的内容恢复成正确叙述。有意义的内容顺序讨论普通阅读关系，不能由三条视觉横线的对齐替代。

拟议验收先用长短标题对照，记录父轨道、每张卡片覆盖范围和内部实际位置；再增加一项说明、缩成单列并放大文字，确认信息和动作仍保留。对不支持目标能力的环境，应明确可接受的独立布局或其他回退，不假设规则被忽略后仍保持同样对齐。

本文没有运行浏览器或视觉回归。交付组件时可以写清“三项内容共享同一横排的三条父行，新增独立字段需同步调整结构”。这种约定让下一位维护者知道该改轨道还是改内容分组，而不是继续给某张卡片补一个碰巧合适的高度。
