IntersectionObserver比例为1，就能证明用户看见了吗？

用完整滚动根与透明切换样本解释面积比、零面积和异步阈值，避免把几何状态写成阅读回执。

正文

核心要点

  • 普通交叉比例描述几何关系，不证明用户阅读。
  • 相交状态与面积比有不同的边界条件。
  • 预加载与统计需要各自定义事件合同。

卡片几何上完全落在观察根区域内，不等于它已经被人看见或读完。在普通几何配置下，IntersectionObserver的intersectionRatio表达面积关系。把比例到过一直接记成一次有效阅读，会跳过遮挡、停留时间、后台状态和用户注意这些不同问题。

面积比实际回答了什么？

Intersection Observer的条目定义说明，目标边界框面积非零时，intersectionRatio为交叉区域面积除以目标边界框面积。交叉计算涉及根和相应裁剪关系，不能简单读作“整张屏幕里可见像素的百分比”。本文使用原文所描述的几何观察机制，不对可选可见性扩展或各浏览器支持作保证。

根也必须明确。页面视口与一个内部滚动容器不是同一个参照系；目标在滚动容器里占满可用范围，与用户当时是否正在看这个页面，仍是不同判断。根、目标、阈值应成为记录的一部分，不能只留一条“曝光成功”。

几何关系可以支持预加载、延迟加载和位置观察，却不能自动证明读者理解了内容。这里的限制不是说观察器没有用，而是要求结论与信号相称。若任务只是让下一张图片提前准备，根附近的交叉信号可能足够；若任务是统计有效阅读，就还需要产品定义。

一份可观察透明切换的完整样本

以下HTML未执行，没有发送埋点。它提供局部滚动根、教学目标和透明度切换，日志只显示最近收到的几何条目，不把旧条目冒充实时采样。保存后滚动容器，再改变透明度，可以准备待运行对照。

<!doctype html>
<html lang="zh-CN">
<head>
<meta charset="utf-8">
<title>几何交叉教学样本</title>
<style>
  #root { height: 180px; overflow: auto; border: 2px solid; }
  .space { height: 120px; }
  #target { height: 160px; background: #ddd; }
</style>
</head>
<body>
<h1>滚动后比较几何记录与透明状态</h1>
<button id="toggle" type="button">切换目标透明度</button>
<div id="root"><div class="space"></div><div id="target">教学卡片</div><div class="space"></div></div>
<p>以下是最近收到的条目，不是逐帧采样。</p>
<pre id="log">尚未收到条目</pre>
<script>
const [root, target, log, toggle] = ['root', 'target', 'log', 'toggle'].map(
  id => document.getElementById(id)
);
const observer = new IntersectionObserver(entries => {
  log.textContent = entries.map(entry => JSON.stringify({
    time: entry.time, ratio: entry.intersectionRatio,
    intersects: entry.isIntersecting
  })).join('\n');
}, { root, threshold: [0, 0.5, 1] });
observer.observe(target);
let transparent = false;
toggle.onclick = () => {
  transparent = !transparent;
  target.style.opacity = transparent ? '0' : '1';
};
window.addEventListener('pagehide', () => observer.disconnect(), { once: true });
</script>
</body>
</html>

样本让目标与周围空间都保留尺寸，透明切换不等于从布局树中删除目标。因此，按几何关系推导，目标边界并不会因为opacity变零自动缩成零。比例与可见外观可以不一致；透明度本身没有改变交叉关系时，也不应期待它必定产生新的阈值通知。

这不是某次浏览器的实测输出。实际检查要记录收到条目的时间、滚动位置与当时透明状态，而不是截图一条旧日志就说“当前比例证明当前可见”。覆盖层造成的遮挡同样不能仅由这个默认几何样本排除；更不能据此认证扩展可见性能力是否可用。

isIntersecting为真，面积为什么仍可能为零？

原文分别定义布尔相交状态与面积比。边缘相接可以形成零面积的相交；目标边界框本身面积为零时，比例还有按相交状态取一或零的专门规则。因此，布尔为真、比例为零和比例为一，都需要结合目标尺寸与条目条件理解。

假设业务只在至少一半目标面积进入时开始某项工作，单用isIntersecting就表达不完整；需要检查对应比例条件，也要排除业务不接受的零尺寸目标。反过来，只需要发现边缘接近以准备资源时，采用不同条件可能合理。阈值选择应来自工作目的，不是看到示例有一就默认照抄。

这里不建议给所有情况增加一套通用“有效曝光”函数。图片预加载、列表翻页和内容阅读拥有不同失败代价。预加载稍早可能只是多用资源，阅读计数过早则可能改变产品判断；把它们都压成一个布尔事件，会让后续指标无法解释。

回调会在每次滚动后立即执行吗？

规范通过异步通知交付条目，阈值区间或相交状态变化参与是否排队的判断。它不是每个滚动像素一次的同步回调，也不是连续录像。一个回调可能有多个条目，处理时应尊重各条目的目标与时间，不能假设列表只有当前这一张卡片。

样本用零、一半和一作为教学阈值，目的是让状态区间可说明，不是建议所有统计采用这三个值。若改变rootMargin提前触发预加载，也应在记录中说明参照区域已经扩展；不能仍把该触发直接描述为内容进入真实可见视口。

组件生命周期也需要安排。解除观察或离开页面后的清理，不代表某个已经发送的统计事件被撤销；重新挂载时再次收到条目，也不自动表示另一位用户的新阅读。对象身份、去重范围与事件重试属于应用合同，观察器不替业务建立它们。

比例到过一，能累计一次有效阅读吗？

如果产品要衡量阅读，就需要明确计量单位和最低证据。是否要求持续一段时间、离开前台是否暂停、同一对象重复进入是否去重，都应有自己的定义。即使这些规则满足，也宜准确称为某种可观察曝光或停留，而不是直接证明理解、记忆或任务完成。

已有的产品指标分母要求先定义完成与尝试单位；透明控件仍可交互则解释视觉状态与其他行为的差异。本篇增加的是几何观察的具体信号边界，不把三种问题合成“可见性通过”。

局部根整体在哪里，也应进入验证。一个容器内部的相对交叉条件，不能替代这个容器在上层页面中的显示条件；如果业务要求真实视口中的呈现，就要另核对这一层关系。即使记录两个不同根的比例，也不能不顾各自分母和裁剪范围，直接相乘就命名为“阅读百分比”。信号组合仍需明确的几何与业务定义。

拟议验证覆盖完整进入、部分进入、边缘相接、零尺寸、透明切换和重复挂载，分别保存根、目标边界、条目时间、比例及业务计数。本文没有执行这些检查，也没有真实曝光或阅读数据。先让事件名字准确描述你实际观察到的东西，再决定它是否足以支持下一项产品结论。
