product 还没取第一项，为什么输入已经读完了？

按构造与首次读取时点观察有限来源，核对完整组合及零轴和空轴的区别。

正文

核心要点

  • product 在生成组合前完整消费输入池。
  • 输出按需读取不能替代来源大小边界。
  • 零个轴有一个空组合，一条空轴则没有组合。

还没从 product 取出第一项，输入生成器却已经读完了。product 会先完整消费各输入并在内存里保存值池，再逐项生成组合。输出可以按需读取，输入准备仍要求有限来源，不能用“只取一个结果”保证无限来源能返回。

延迟发生在组合输出这一侧

假设一个本地配置工具要组合两种版本 A、B 和两个编号一、二。调用者先创建组合迭代器，稍后才显示第一项。他可能把这件事理解成“现在什么都还没读”。但要循环遍历同一条轴，product 需要能反复访问该轴已经提供的值，所以创建时先把来源装入池。

Python 文档明确说明，输入会被完全消费并保存到内存，因此只适用于有限输入。这不表示所有组合都提前生成。两条轴各有很多项时，输入池的数量是各轴规模之和，组合总数却按乘积增长。把两种数量混在一起，就容易把输出可逐步消费误写为整个过程无需存储。

生成器也可能带来可观察动作，例如记录读取编号、从数据库拉一页或执行一个转换。只要它确实提供了这些元素，池化阶段就会触发相应读取。例子只记录两个字符串，没有数据库或网络，因此不会把它外推为某个驱动具体会发送几条请求。要验证真实来源，应在它自己的边界记录实际读取行为。

在创建前、创建后和第一次 next 后分别检查

下面使用一个只会产生 A 和 B 的有限生成器。它每交出一个值就在 seen 里留下标记，输出端则按完整独立预期检查四个组合。程序没有尝试无限输入，避免用无法结束的演示代替不适用条件。

from itertools import product

seen = []
def source():
    for item in ["A", "B"]:
        seen.append(item)
        yield item

assert seen == []
pairs = product(source(), [1, 2])
assert seen == ["A", "B"]
assert next(pairs) == ("A", 1)
assert list(pairs) == [("A", 2), ("B", 1), ("B", 2)]
assert list(product()) == [()]
assert list(product([])) == []
print("source pooled before first output; four pairs restored; zero/empty axis controls passed")

创建组合前，seen 为空。只执行构造，seen 就已经包含 A 和 B；此时还没有对 pairs 调用 next。第一次读取得到 A、一，剩下三项依次为 A、二，B、一和 B、二。这样既检查输入准备发生的时点，也检查输出没有因为来源已读完而消失。单看最后四项都正确，无法发现输入是何时被消费的。

这组数据还把池规模和组合规模拆开。第一条轴有两个值，另一条轴也有两个值，最终有四个组合。实际来源可以更大，程序应分别约束每条轴的大小和允许展示的组合数。只限制页面取十个组合，不能据此证明创建之前仅拉取十条输入。池化已经在输出限制介入以前发生。

如果必须控制来源读取量，应把限制放在输入进入 product 之前，并确认这种截取符合业务。只保留前两个版本，与从完整版本集合的组合里取前两个结果，返回的候选含义可能不同。例如第一条轴有 A、B、C，第二条有一、二，取前两个输出只覆盖 A；先把第一轴限定 A、B，再完整组合则有四项。不能为了省读取，悄悄把产品需要的候选空间缩小。

选择有限快照还是一次性流处理

如果每条轴是已知且较小的参数清单，池化能够直接表达重复组合。可在接口接收时明确各轴最大规模，生成组合前先校验输入。若来源是持续增长的事件流，就要重新定义窗口、结束条件或另一种处理算法，不能把无限流原样交给这个有限池接口。

把来源变成列表之后再传入，不会神奇消除原来的成本，它只是把消费时点提前到应用可见的位置。这样有利于单独报告加载失败与组合失败，但仍需要承担存储。若业务允许磁盘快照或受控重读，可以根据条件选择实现；本文没有提供一个已验证的外部存储组合器，也没有测量内存阈值。

本站的tee 慢消费者缓冲讨论两条消费者进度不同而保留已见内容。这里的存储发生在生成第一项组合之前。二者都要看输入归属，但不能用 tee 的逐步读取观察证明 product 也会按同样方式推进。直接在实际使用的入口检查时点，能避免因都叫迭代器就复制错误假设。

应用验收还应覆盖创建阶段就抛错的来源。例如有限生成器在提供 A 后报告读取错误，创建组合可能直接失败，显示第一项的代码还没机会运行。错误回执应说明来源准备失败，而不是告诉用户“第一组组合无效”。这个失败变体没有纳入运行夹具；它根据先完整消费的合同说明应在哪个阶段设置应用处理。

如果配置在创建后发生变化，还需明确想生成哪份版本。输入池保留的是创建时读到的值序列，后面新增一个来源元素并不会自动让已经创建的组合器重读来源。对需要最新配置的请求，可以新建一次受控输入快照；对需要可重复任务的请求，则应记录当初使用的版本。当前生成器只有固定字符串，没有模拟活动配置更新。

没有任何输入轴，和有一条空轴，是同样结果吗？

不是。product() 得到一个空元组组成的结果，表示零个选择轴的唯一空组合；product([]) 则没有组合，因为那条轴没有可选项。夹具最后两条保存了不同预期。业务若动态拼接参数轴，应该决定缺少某个轴是采用默认选择，还是明确禁止产生候选。只用结果为空作统一判断，会把零轴与空轴的配置语义压成一类，随后可能多执行或少执行一个任务。
