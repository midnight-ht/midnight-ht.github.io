目标全是5，R²为什么默认只得到0或1？

用SSE与SST解释常量目标的非有限R²及默认替换，保留参数和有限零分反例。

正文

核心要点

  • 常量目标使R²分母为零
  • 默认策略区分完美与不完美预测
  • 分数之外需保留平方和和参数

三条真实目标全是五，完美预测得到R²一，不完美预测得到零。采用scikit-learn的默认force_finite时，这可能来自常量目标的特殊处理。原始公式的分母已经为零，非有限结果被按参数替换。报告需要标出这个条件，不能把两个数字直接解释成普通回归表现。

常量目标先让比较基准退化

对于这里无样本权重、单输出的情况，R²可以写为一减残差平方和除以目标围绕均值的平方和。前者记为SSE，后者记为SST。SST描述这批真实目标自身的变化量。真实值全是五，均值也是五，每个偏差为零，因此SST为零。

预测也全是五时，SSE为零，原始比值出现零除以零，结果不是有限数。若预测全是四，每项误差一，平方和为三，正数除以零使原始R²成为负无穷。两者都和常见的非恒定目标、有限分母情境不同。

当前r2_score文档明确说明这两个分支。默认force_finite为真，将完美预测的NaN替换为一，不完美预测的负无穷替换为零。将该参数设为假，可以保留这些非有限值。文档注明此选项在一点一版本加入，本文读取的是一点九点一参考说明。

这是一项为了更高层实验方便而提供的处理，不会为测试集创造原来没有的目标变化。两条模型记录都得零，也不能据此说它们残差相同。在常量目标下，只要不完美就可能进入同一替换结果；还需要保留原始误差与条件。

这里的均值取自这批真实目标本身，不是训练集均值或预测均值。换一批目标时应重新计算这个基准，否则分母已经不再描述当前测试材料的变化。保存原始目标，也能在后来复核时发现是否错误复用了另一批数据的均值。

四种参数结果，再加一个有限零分反例

完整脚本按公式做标准JavaScript算术，再演示文档中的替换政策。它只接收当前这些至少两条目标的固定输入，没有实现完整r2_score接口，也没有调用Python包或训练模型。代码对非有限值使用显式日志标记，避免JSON默认表示掩盖类型。

import { deepEqual } from 'node:assert/strict';
const sum = values => values.reduce((total, value) => total + value, 0);
function describe(target, predicted, forceFinite) {
  if (target.length < 2) throw new RangeError('Fixture needs at least two targets');
  const mean = sum(target) / target.length;
  const sse = sum(target.map((value, index) => (value - predicted[index]) ** 2));
  const sst = sum(target.map(value => (value - mean) ** 2));
  const raw = 1 - sse / sst;
  const score = forceFinite && sst === 0 ? (sse === 0 ? 1 : 0) : raw;
  return { sse, sst, score };
}
const constant = [5, 5, 5];
const perfect = [5, 5, 5];
const imperfect = [4, 4, 4];
const cases = [
  [constant, perfect, true], [constant, perfect, false],
  [constant, imperfect, true], [constant, imperfect, false],
  [[4, 5, 6], [5, 5, 5], true]
];
const actual = cases.map(([target, predicted, finite]) => describe(target, predicted, finite));
deepEqual(actual, [
  { sse: 0, sst: 0, score: 1 },
  { sse: 0, sst: 0, score: NaN },
  { sse: 3, sst: 0, score: 0 },
  { sse: 3, sst: 0, score: -Infinity },
  { sse: 2, sst: 2, score: 0 }
]);
const output = JSON.stringify(actual, (_key, value) =>
  typeof value === 'number' && !Number.isFinite(value) ? String(value) : value
);
console.log(output);

原样代码已在本地Node环境执行，五份字面预期全部通过。常量目标的完美预测在开启与关闭替换时分别是一和NaN；不完美预测分别是零和负无穷。SSE与SST也同时核对，因此不是只用四个分数猜测走了哪条分支。

第五项是必要的反例。真实目标改为四、五、六，均值五，预测都为五。SSE与SST都是二，R²为零，这次分母有限。它与常量目标下被替换成零的结果数值相同，计算条件却不同。只在报告里保存零，会丢掉这种区别。

日志将NaN与负无穷显示成字符串，实际断言比较的仍是数值结果。若把输出文件里的标记重新当成模型接口返回类型，又会制造另一层误读。执行证据只证明这份本地算术与固定数据，不证明某个分类或回归服务的真实质量。

给退化条件留下可重算记录

报告至少保存样本数、目标版本、SSE、SST、force_finite和最终分数。看到替换零时，可以沿着这些信息找到分母为零，而不必从模型名字或训练日志猜原因。若需要汇总多折结果，还应先说明怎样处理非有限折与替换后的值。

不要为了得到漂亮的有限分数，悄悄删掉所有常量目标折。删除可能改变被评估对象或数据条件。先查看为什么这一折目标没有变化，是任务本身如此、抽样限制，还是数据准备有误，再依据已声明的评测合同决定处理。本文没有修改实际训练集，也不推荐一条适用于所有项目的删除规则。

在产品验收中，R²也不替代具体误差要求。假设业务关心预测与真实值差多少单位，应同时保留与这个任务相关的误差读数。常量三样本只是解释参数的人工例子，没有代表性保证，也没有足够证据给一个真实模型排名。

如果两次报告的force_finite不同，即使预测完全相同，有限值与非有限值的呈现也会变化。版本比较要锁定该参数及输入，或把参数变化单列说明。不要将报告系统换了一种表示方式，写成模型本身突然获得或失去预测能力。

测试数据划分还决定哪些目标进入同一折。站内 按组切分的组数与行数讨论划分条件，本题是在目标已经固定以后检查评分分母。两份记录应能关联，但一份正确的组交集不能证明每折目标都有变化。

汇总界面应让读者辨认哪些结果用了替换政策。可以在数值旁记录常量目标标记，再提供原始平方和供复核。这样同样显示零的两行仍能追到不同条件。具体如何展示由报告用途决定，不能只换一个颜色便声称已经解释退化来源。

只剩一条测试样本，force_finite还会把NaN变成一吗？

不能把主例规律这样推广。这里新增样本数少于二的条件，主例每组都有三条。r2_score文档另行说明，少于两条样本时指标不适定，会返回NaN。这与至少两条常量目标的特殊替换分支需要区分。

上面的教学函数明确拒绝少于两条输入，没有用它冒充库的完整行为。这里依据官方文档说明，不提供本机Python包输出。若产品可能产生单样本折，应保存样本数与处理策略，并在实际评测入口验证，不要把所有NaN都统一补成成功的一。
