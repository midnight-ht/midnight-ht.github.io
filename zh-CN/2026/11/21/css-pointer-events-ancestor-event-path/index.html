pointer-events:none 的父容器，为什么还能收到子按钮点击？

把子按钮命中与祖先捕获冒泡分开读，用两处物理点击位置验证pointer-events的范围。

正文

核心要点

  • none排除自身命中而非整条事件路径
  • auto后代可命中并沿祖先传播
  • 日志需共同保留目标和当前处理节点

父容器已经设了 pointer-events:none，点击子按钮，父级日志却仍然出现。这可以符合规则。子按钮显式设成 auto 后仍能成为命中目标，父容器则仍是这次事件的祖先。排除自身命中与离开事件传播路径，是两件不同的事。

点击落在哪里，与事件经过谁分开读

CSS UI Level 4 对普通HTML元素说明，none让命中测试像元素自己的盒子不在那里。它并没有锁住整棵子树。虽然属性会继承，后代仍可显式使用 auto，恢复正常命中。这里依据二〇二六年十一月十三日工作草案，不混用SVG另有定义的其他取值。

同一章节还明确，事件以这样的auto后代为目标时，none祖先仍可在捕获或冒泡阶段处理事件。所以父级监听器运行，不足以证明父级成为了用户点中的目标。日志要同时保存target、currentTarget与阶段，才知道哪一项角色实际改变。

本例的目标按钮直接包含文字，没有额外图标子元素。真实组件若在按钮里套了元素，目标还可能是里面的节点，要按实际树记录。不能把某次目标字符串等于按钮编号的断言，直接当成所有复杂按钮共同的命中合同。

这个区别也能解释一种错误修复：看到父级还有日志，就继续给它增加排除样式。只要目标仍是允许命中的子按钮，祖先路径就没有因为同一个属性再次出现而消失。先确定是不是要阻止这个功能，再决定事件处理或区域状态，而不是把监听器运行都叫作样式没生效。

一份页面比较子按钮与空白区域

下面有底层按钮和覆盖在它上面的容器。覆盖容器排除自身命中，子按钮显式auto。父级分别记录捕获与冒泡，两个按钮各记自己的回调。读数直接在回调里取得，没有等到事件结束后再读取临时的currentTarget。

<!doctype html>
<meta charset="utf-8">
<title>Pointer target and ancestor path</title>
<style>
.stage { position: relative; width: 20rem; height: 8rem; }
#under { position: absolute; inset: 0; width: 100%; height: 100%; }
#overlay { position: absolute; inset: 0; border: 2px solid; pointer-events: none; }
#child { position: absolute; left: 1rem; top: 1rem; pointer-events: auto; }
</style>
<div class="stage">
  <button id="under" type="button">Underlying button</button>
  <div id="overlay">
    <button id="child" type="button">Child button</button>
  </div>
</div>
<pre id="log"></pre>
<script>
const byId = document.getElementById.bind(document);
const overlay = byId('overlay');
const output = byId('log');
function record(label, event) {
  output.append(JSON.stringify({ label, target: event.target.id,
    current: event.currentTarget.id, phase: event.eventPhase }) + '\n');
}
overlay.addEventListener('click', event => record('capture', event), true);
overlay.addEventListener('click', event => record('bubble', event));
byId('child').addEventListener('click', event => record('child', event));
byId('under').addEventListener('click', event => record('under', event));
</script>

按规范和这棵树推导，真实点中子按钮时，应看到父级捕获、子按钮处理、父级冒泡。三条记录的目标都是child，父级两条current是overlay，子按钮那条current是child。父级捕获与冒泡分别处在相应阶段，而不是自己变成了目标。

再点覆盖容器内、子按钮外的空白处。对于这个明确叠放的页面，排除容器自身后，底层按钮参与命中，日志应指向under。覆盖容器不是under的祖先，因此这条路径不应被写成同一份子按钮传播。两处位置形成对照，不能只点一次就解释整个区域。

这些是待执行预期，本文没有运行浏览器，也没有采集真实指针轨迹。调用child.click或手工派发事件不能证明命中测试正确，因为它们没有复现用户在画面某个位置点击的过程。真正复验需要保留点的位置、目标环境与实际事件读数。

祖先回调还需要自己的动作条件

如果父级监听器代表一个业务动作，它就要明确响应什么目标。比如容器监听点击用来选择卡片，而内部按钮执行另外的操作，父级是否也该选择需要产品规则。不能因为none写在父级，就默认这份业务处理已经不会执行。

在诊断中还要分开捕获与冒泡。某个修复只处理了冒泡路径，捕获监听器可能早已运行。这里的页面故意把两阶段都记录下来，是为了证明「有父级回调」需要更具体的定位。本文没有为所有委托事件设计统一的停止传播策略。

恢复样式时也先确认计算值。父级类名写着禁用，子组件内部却有通用auto，可能是有意的例外，也可能是封装泄漏的行为。保留父子各自的最终值与节点身份，再决定是否移除例外，不能只搜索父容器那一行声明。

若需求真的是整区暂时不可操作，还需核对键盘、编辑和其他用户路径。站内 inert的区域交互边界讨论那份合同。本题只说明命中与事件路径，不能从一次点击对照推出所有入口都已停用。

同样，外观是否显示属于另一份样式问题。透明或不可见的区域与指针排除没有自动一一对应。可以对照 visibility的后代覆盖，但应各自留下最终值和实际观察。把多个机制一并改动，会很难解释到底哪个条件修复了当前症状。

团队验收可把每次动作写成一行：用户点击哪个位置，预期目标是谁，哪些祖先应该接收哪个阶段，以及最终功能是否符合需求。日志数量相同也不说明对象正确，必须核对身份。若页面后来移动节点或换了布局，就重新确定点位与树关系，不能沿用旧截图里的坐标。

同一区域的文字，还能点击拖动选择吗？

不能把none直接理解成禁止文本选择。这里新增普通段落上的点击拖动，主例则是按钮命中。CSS原文特别限定，开始文本选择的点击与拖动仍按通常方式工作，它不是对所有与指针有关操作的一次总封锁。

可以另外准备一段没有按钮覆盖的普通文字，仅对它设置none，再用真实拖选观察范围和实际复制内容。本文没有执行这个变体，也不提供跨浏览器支持矩阵。如果产品另有选择限制，应按对应功能规则明确设计，不能只凭这项命中属性就宣布文字无法被选取。
