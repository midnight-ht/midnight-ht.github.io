ResizeObserver 能读边框盒，为什么 padding 改了没有通知？

通过同一元素的两份观察订阅，区分 ResizeObserver 的触发口径和回调条目中的尺寸。

正文

核心要点

  • observe 的 box 决定哪一类尺寸变化进入通知。
  • entry 可以同时包含多种盒尺寸。
  • 用固定内容尺寸和变化的 padding 隔离两者。

观察回调里已经读取 borderBoxSize，组件的 padding 变了，默认观察器却没有收到新的通知。ResizeObserver 用订阅时选择的盒来判断是否报告变化，交给回调的条目可以同时携带多种盒尺寸。想在边框外沿发生变化时重新布局，应该显式观察 border-box，并检查触发日志，而不只修改回调里读取的属性。

先确定什么变化需要唤醒调用者

Resize Observer 对 observe 的定义允许选择观察盒，默认是 content-box。观察器比较所选口径的尺寸与上次已报告值。另一个算法为实际通知构造 ResizeObserverEntry，其中包含内容盒和边框盒等不同测量。于是读取某个字段并不意味着这个字段的变化能够触发下一次通知。需要先按依赖关系选择通知，再选择条目中用于下一步计算的值。

假设有一张内容区始终两百像素宽的卡片，旁边工具条需要沿卡片外缘对齐。让卡片在宽屏时增加内边距，会改变外沿。观察内容盒的回调曾经拿到正确的外宽，可是后来只变化了 padding，它没有被重新调用，工具条继续使用旧值。检查时若仅盯着回调读取了什么，容易误认为读取字段拼错。实际原因可能在订阅选择，不在返回记录的内容。

反过来，画布或可滚动内容如果只关心分配给自身的内容区，订阅外沿也可能引入不需要的更新。用户在不同显示密度之间切换、边框样式改变或主题增加 padding，都应结合布局的实际变更口径验收。先写一句可观察的需求，例如“边框外沿一变就重新对齐工具条”，再确定是否应该订阅对应盒。若不同消费者需要两种触发条件，可分别观察，不必让一个回调承担所有响应动作。

用固定内容宽和两个观察器作对照

以下是完整的本地 HTML，尚未在浏览器执行。样本固定普通横向书写、无分片布局，内容宽二百像素，两侧各有十像素内边距和两像素边框，初始边框盒宽二百二十四。两个观察器订阅同一元素，各自记录内容盒与边框盒。等两份初始记录出现后，按钮才允许把内边距改成二十像素；另一个按钮再把内容宽改到二百二十。

<!doctype html>
<html lang="en">
<meta charset="utf-8">
<title>Resize Observer boxes</title>
<style>
#card { box-sizing: content-box; width: 200px; height: 80px; padding: 10px; border: 2px solid; }
</style>
<button id="pad" type="button" disabled>Increase padding</button>
<button id="width" type="button" disabled>Increase content width</button>
<div id="card">Example card</div>
<pre id="log"></pre>
<script>
const get = id => document.getElementById(id);
const [card, pad, width, log] = ['card', 'pad', 'width', 'log'].map(get);
const initial = new Set();
let phase = 'initial';

function receive(label) {
  return ([entry]) => {
    const { contentBoxSize: [content], borderBoxSize: [border] } = entry;
    log.append([phase, label, content.inlineSize, border.inlineSize].join(' ') + '\n');
    if (phase === 'initial') initial.add(label);
    pad.disabled = phase !== 'initial' || initial.size !== 2;
    width.disabled = phase !== 'padding' || label !== 'border';
  };
}

const contentObserver = new ResizeObserver(receive('content'));
const borderObserver = new ResizeObserver(receive('border'));
contentObserver.observe(card);
borderObserver.observe(card, { box: 'border-box' });
pad.onclick = () => {
  phase = 'padding';
  pad.disabled = true;
  card.style.padding = '20px';
};
width.onclick = () => {
  phase = 'width';
  width.disabled = true;
  card.style.width = '220px';
};
</script>
</html>

按独立盒模型计算，初始两条记录都应提供内容二百、外沿二百二十四。只增加内边距后，内容仍为二百，外沿变为二百四十四，预期只看到边框盒订阅的新通知。这一条仍能同时读取两种尺寸。最后增加内容宽，两类观察都应收到新尺寸，分别为二百二十和二百六十四。不要求同一次更新中两个观察器具有固定先后；判据是各自是否收到对应阶段和值。

负例在默认观察器里读边框盒尺寸，看到初次回调确实有数据，便断言边框变化已经被覆盖。只增加内边距的那一步能戳破这条断言。若测试把初次通知与变更后日志混在一起，还可能把旧记录当作新的通知。应先等初始状态，然后一次只改一个变量，并给每次变更留下独立的标签。回调是否出现、条目里每个值是多少，可以在同一份日志分开看。

应用改动有时会反馈给被观察的盒

把尺寸通知接到生产代码时，还需记录它最后修改了谁。如果对齐工具条的代码同时更新了卡片本身的宽度，就会改变后续观察输入，容易把一次预期的外部变化变成持续更新。更清楚的设计是将卡片作为尺寸来源，只更新真正依赖它的相邻元素；若必须更新卡片自身，就按应用的约定说明值何时稳定，并用变化后的尺寸记录验证。这里没有模拟反馈，也不能凭两个观察器的正常结果证明真实页面没有反馈问题。

真实页面常在同一个响应式断点同时改变外沿和内容宽。若把全部样式一起切换，两种观察器都可能收到通知，验收便无法判断哪个尺寸变化造成了哪条记录。把各属性改动分成不同操作，在每次操作前后记录计算样式和两个盒的尺寸。若产品关心的是最终对齐，断言最终工具条坐标也要写清使用哪一个盒，不能由收到通知自动推导位置正确。可以先用孤立卡片验证订阅，再把卡片放回真实父级，检查父级是否因为可用宽度变化反过来改了内容盒。两次验收使用不同证据，才能说明失效究竟在通知、测量还是应用更新。

测试还可以刻意保留默认观察器，在后续改宽时确认它仍工作。若它在 padding 步骤没有日志，下一步内容宽变化能帮助区分“按合同没有通知”和“观察器根本没连接”。浏览器版本、写入样式和真实日志应一起归档。本站组件宽度口径说明外沿如何计入边框和内边距；本篇在相同几何下检查由谁收到通知。

只把组件 scale(2)，视觉宽度变大也会触发吗？

若只改变 CSS transform，布局盒尺寸没有变化，Resize Observer 的说明指出变换不会触发观察通知。主例改变了实际盒模型，这里的新条件仅改变视觉变换。可以给同一卡片增加单独按钮，只切换缩放，并比较变换前后的 getBoundingClientRect 宽度与观察日志。前者可以变化，后者不会因为这次变换新增通知。该对照尚未执行，也不应把复合样式同时改变布局的情形归到纯变换。
