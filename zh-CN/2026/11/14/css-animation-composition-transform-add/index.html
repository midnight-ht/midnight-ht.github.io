组件加上位移动画后，原来的 translateX 为什么消失？

用固定关键帧对照 animation-composition 的 replace 和 add，分别核对静态偏移与合成结果。

正文

核心要点

  • replace 用效果值替换底值。
  • add 依照属性的加法合成底值与效果。
  • 固定取样可把合成问题与时间问题分开。

卡片原先用 transform 向右偏十像素，加上一段五像素的位移动画后，取样却只读到五像素。默认的 animation-composition 是 replace，动画效果值可以取代已有变换。需要在已有偏移上再叠一段时，可以用 add，但应按所用属性的合成规则验收。

先写清设计给的是新位置还是增量

CSS Animations Level 2 的定义规定合成操作，初始值为 replace。动画影响同一属性时，所选操作决定效果如何与底值合成。Web Animations 的效果合成进一步解释 replace 和 add。替换使用效果值，添加依赖该属性定义的加法。这里只用同轴平移，所以可以在明确的样本里用十加五计算预期。不应把这个算式推广到旋转、缩放或异轴变换。

设想库存卡片的普通位置由组件的布局设置，交互期间还需要一个短暂位移。设计稿写“五像素”时，要问这个数表示最终位置，还是从普通位置再多走五像素。若把关键帧写进已有 transform 属性的动画，并使用默认合成，结果按效果值解释。若效果是相对底值的增量，则应验证它仍保留那段已有偏移。相同的关键帧不保证表达了相同的运动合同。

不妨先对照没有动画时卡片的计算变换。如果底值来自另一条规则或较低合成顺序的效果，记录它是怎样得出的。生产问题有时出在开始前底值就不是十像素，而不是 add 选错。还要检查你比较的是变换自身，还是元素最终的屏幕坐标；在父容器也有变换时，两个观察会给出不同的信息。下面的样本没有父级变换，只读取自身矩阵的横向平移分量。

固定一个时点，读取三份计算值

以下是完整的本地 HTML，尚未在浏览器执行。第一个卡片只保留十像素底值。后两个共享同一段动画，起止关键帧都设置五像素平移。时间暂停在效果内，避免取样时不知处于哪一段动画。两个卡片分别显式采用 replace 和 add，输出按文档顺序列出三个横向偏移。

<!doctype html>
<html lang="en">
<meta charset="utf-8">
<title>Animation composition comparison</title>
<style>
.sample {
  width: 12rem;
  border: 1px solid;
  margin: 0.5rem 0;
  transform: translateX(10px);
}
.animated {
  animation-name: shift;
  animation-duration: 1s;
  animation-delay: -500ms;
  animation-play-state: paused;
}
#replace { animation-composition: replace; }
#add { animation-composition: add; }
@keyframes shift {
  from, to { transform: translateX(5px); }
}
</style>
<div class="sample">Underlying transform</div>
<div class="sample animated" id="replace">Replace</div>
<div class="sample animated" id="add">Add</div>
<pre id="results"></pre>
<script>
const readX = element => {
  const { transform } = getComputedStyle(element);
  return new DOMMatrixReadOnly(transform).m41;
};
const output = document.getElementById('results');
requestAnimationFrame(() => {
  if (!CSS.supports('animation-composition', 'add')) {
    output.textContent = 'animation-composition: add unsupported';
    return;
  }
  const offsets = [...document.querySelectorAll('.sample')].map(readX);
  output.textContent = JSON.stringify(offsets);
});
</script>
</html>

预期顺序是十、五、十五。第一项用于确认真正的底值。第二项只留下效果的五像素，第三项合成得到十五。若只观察动画有没有运行，就可能漏掉第二项中的底值变化；若只验证三份元素仍有宽度，也无法发现偏移不一致。这个对照用相同的时间和关键帧，把唯一差别放在合成操作上。使用 CSS.supports 判断语法支持之后，仍需实际读取矩阵来验证行为。

样本使用固定关键帧，目标是检查合成而不验证视觉过渡。真实交互可以在机制确定后加入真正随时间变化的关键帧，再检查开始、中间和结束的位置。截图如果会干预动画推进，应单独记录如何采样。本站截图时处理动画讨论测试工具怎样处理动画与结束事件，本篇关注同一采样时点的变换值来自哪里。

先决定属性归属，再引入第二个效果

若一个组件既用自身变换表达结构位置，又用同一个属性表达交互反馈，迁移时需要明确谁能覆盖谁。可把静态和临时偏移分别交给外层和内层元素，再验收整体位置；也可以用同一元素的合成操作明确两项关系。前者使责任更易分辨，后者可以少引入一个包装层。选哪种要看其他样式是否依赖这份变换，以及真实界面是否需要多种操作同时出现。

可以把三份计算结果放进一个实际界面的验收记录。先记录无交互状态下卡片左边缘和计算变换，再保持同一容器宽度触发交互，按已定义的时间读取新值。如果矩阵给出了正确的十五像素，卡片却仍遮住右边的按钮，问题可能出在整体空间分配或剪裁。此时应保留合成断言，再用独立的可操作区域检查按钮是否可见可达。若只继续调整矩阵数字，可能解决一个截图而破坏不同宽度下的组件。

还可以在一个同样的布局里关闭交互动效，检查底值是否仍由预期规则提供。产品可能在偏好减少动态效果时完全省略这一段动画，也可能用其他反馈表达变化。这个分支要验证真实的交互信息是否还存在，而不能从偏移没有发生就断言用户没有得到反馈。本文没有实现这样的偏好切换，也没有测量动画流畅度，数字只服务于两种合成策略的比较。

测试还应挑一条错误路径。如果设计希望位置直接停在五像素，却误用 add，最终十五像素也是错的。不要只拿 add 当修复按钮。先写清实际位置和需要保留的底值，再对照取样。应用若用效果结束表示某个业务动作完成，则另行验证业务结果；这里的矩阵不能告诉调用者网络或保存是否成功。

两条效果互换顺序，结果会变吗？

会，条件是合成顺序跟着这两条效果互换。主例只有一条动画与静态底值。现在假设同时采样两个效果，一条 replace 给五像素，一条 add 给两像素。先替换为五再添加二，结果是七；先添加二再替换为五，结果是五。这个纸面对照只用同轴平移。可为新验收建立两组相同的动画列表，将名字与各自合成操作成对交换，再比较矩阵。只更改名字而不随之更新合成操作，已经换了另一个变量，不能用来单独证明顺序效果。
