CMake 调用 file(GENERATE) 后，下一行为什么还读不到文件？

比较 CMake 配置中与生成后读取同一文件的结果，识别旧输出造成的假阳性。

正文

核心要点

  • 安排生成不会立即写文件。
  • 旧文件的存在不能证明本轮已经写入。
  • 跨配置输出要遵守内容与路径约束。

file(GENERATE) 返回时，新的输出还没写入。CMake 在处理完项目的配置文件后进入生成阶段，到那时才把结果落盘。

有人想给一个构建目录写一份状态文件，并在同一份 CMakeLists 里马上读取它。干净目录上读取失败，复用目录上却有时能通过。两次使用的是同一条命令，差异来自目录里是否已有旧结果。如果代码只判断路径存在，第二次的成功反而会隐藏错误。定位时要先写清读者希望得到这次的值，还是只要一份上次留存的状态。

在同一构建目录读取两次不同的值

下面是完整项目，不需要编译器。它在配置阶段安排生成 status.txt，再立即检查这个路径。如果路径存在，读取并显示内容，否则报告缺失。保存为独立源目录的 CMakeLists.txt。 CMake file 命令的 GENERATE

cmake_minimum_required(VERSION 3.18)
project(generation_boundary NONE)
set(VALUE A CACHE STRING "A short teaching value")
set(path "${CMAKE_CURRENT_BINARY_DIR}/status.txt")

file(GENERATE OUTPUT "${path}" CONTENT "value=${VALUE}\n")
if(EXISTS "${path}")
  file(READ "${path}" observed)
  string(STRIP "${observed}" observed)
  message(STATUS "during: ${observed}")
else()
  message(STATUS "during: missing")
endif()

先用一个全新的输出目录运行 cmake -S . -B out -DVALUE=A。等进程成功返回以后，再读 out 中的状态文件。第二轮使用同一个输出目录，把参数改成 -DVALUE=B，同样在结束后读取。这个教学项目实际在 CMake 4.2.3 上配置和生成两次，没有运行构建工具。第一次配置时报告缺失，命令返回后读到 value=A。第二次配置时读到的是旧 value=A，命令返回后才读到 value=B。

输入 配置文件内读取 命令成功返回后读取
A，干净目录 缺失 value=A
B，复用目录 value=A value=B

这两轮给出四个独立观察。第一轮证明没有文件可供下一行读取，第二轮证明有文件也未必新鲜。若测试只要求第二轮检查存在，就会把旧 A 当作新 B 的证据。若每次都在新目录测试，又可能漏掉真实工程里最常见的误判。最好把输出目录、输入标记、配置中的读值与进程后的读值放在同一份记录里。表里的第一列来自本轮设置，后两列来自两次实际读取，不能互相代填。

即使文件正好保持原样，存在也不说明发生了写入。手册还说明后续 CMake 运行只有内容变化时才修改生成文件并更新时间戳。因此单凭时间戳是否变化，也不能判定生成是否成功完成。若构建脚本要判断内容是否符合约定，应比较实际内容，必要时保存此次的输入和退出值。本文的两轮刻意改变内容，观察的是阶段，而不是测试文件时间戳的承诺。

如果把这两步交给外部脚本，最好将配置命令的结果和生成文件的校验分别记录。命令失败时，目录中可能还躺着上一次的文件。此时应先保留这次失败的日志，不能继续使用旧文件去证明新输入生效。命令成功时也不能只记退出值，应确认读出的路径位于本轮指定目录，并对照本轮传入的值。例如把文件从另一份构建目录拷来，既可能有正确名称，也可能有看起来合理的值，却无法证明它来自刚完成的配置。

把读取步骤移到生成后也要选择合适的调用入口。若终端里是人工执行，可在该命令成功返回后直接检查。若后续任务与配置由两个作业承担，应明确它读到的是哪个构建目录或哪份归档；同一个源代码修订有时会在多个输出目录用不同参数配置。验证记录能区分这些输出，就可以在出现一份状态文件时追问它究竟服务于哪次生成。这是对交付脚本的建议，样例没有运行两个独立作业。

根据消费者所在阶段选写入方式

如果一段配置逻辑在同一次配置中必须读取普通文本，可以让生成文本的动作在这个读取前完成。比如在支持的版本中，file(CONFIGURE) 可以按变量做文本替换；其输出和内容不接受生成器表达式。要在配置期决定目标列表或根据文件内容选择分支，先确认所需输入在那时已经可得。若源数据由本次生成阶段决定，把消费步骤推到生成之后，避免为了提前读取而偷偷采用旧目录的值。 CMake file 命令的 CONFIGURE

一个实际取舍是让配置逻辑直接使用内存中已有的值，同时保留生成文件给后续工具。假设配置和后置校验都需要知道本次的输出模式，配置可以使用自己刚选定的输入，后置校验才读取生成文件。两处共同核对的是同一个业务值，但读取时间不同。不要让后一份输出文件变成前一阶段的隐含输入，这样清理旧目录时不需要靠保留文件才能成功。

验收迁移时给读取方分别造一份干净目录和一份带旧状态的目录。若某一步从生成后移到了生成前，带旧文件的控制会最先暴露误读。也可给错误路径预放一个内容明显不同的标记，确认测试不会误把同名文件读成目标。这是拟议扩展，未包含在两轮执行里。实际项目还需要检查是哪条脚本读取文件以及它从哪个工作目录运行，避免两个路径刚好重名。关于配置目录结束时执行的延迟调用，可参看CMake 延迟调用的参数求值；那里的回调执行时点与本题的文件生成分别由不同机制决定。

多配置生成器能把各配置结果写进同一路径吗？

手册只允许多个配置在生成内容相同时共享输出路径。若 Debug 与 Release 的内容不同，例如输出当前配置名，应让路径按配置区分，可在文件名中使用相应的生成器表达式。主例没有这种差异。独立验收可以在支持多配置的环境中为两个配置设置不同内容，检查两个文件的路径与正文分别对应。不能只看到其中一个文件就宣称两个配置都得到预期结果。这项对照没有运行。
