HTML dialog重新打开后取消，为什么还读到上次确认值？

按当前dialog关闭算法区分上次值、本轮初态、显式结果与无参数关闭，避免把取消读成再次确认。

正文

核心要点

  • returnValue保留最后设置值，而非每次打开自动清空。
  • 省略关闭结果与显式空结果不同。
  • 本轮决定需要与本轮对象身份关联。

returnValue保存最后一次设置的字符串，重新打开不自动让它成为本次答案；每轮开始应明确初值，再区分确认、拒绝与无决定关闭。第一次点了确认，第二次取消却仍读到accepted，不能据此认定用户再次同意。

HTML的dialog定义规定，returnValue读取最后设置的值，元素创建时初始为空字符串。创建一个节点与再次显示同一个节点不是同一件事。关闭算法也不是每次都写入新值：只有结果不为null时，才把它赋给returnValue。

先画两轮操作，而不是只看一次close

假设一份本地教学确认框，按钮分别关闭为accepted与declined。用户第一轮确认，属性变成accepted。第二轮如果只是重新showModal，随后通过没有提供新结果的关闭路径退出，旧值就可能仍在。close事件只通知对话框已经关闭，不自带“这是本次明确确认”的含义。

这不是字符串值设计得太短。将accepted换成长枚举，仍不能弥补每轮初态没有定义的问题。应分别记录节点生命期、打开轮次、当前对象和本轮决定；不能因为节点没有销毁，就让上轮结果成为下一轮默认授权。本文只讨论本地返回值，不实现协议签署或真实业务同意。

模态焦点工作流已经说明进入、内部导航和退出位置。这里不把焦点规则再写一遍，而是补上关闭结果的时间归属。用户能返回原按钮，不证明应用读到的字符串属于这一次操作；两份检查需要各自留下依据。

一轮开始时显式建立“未决定”

下面是未执行的完整HTML，没有form，也不发送保存请求。每次打开前将结果设为空；确认和拒绝按钮显式给出结果；其他被浏览器接受的无结果关闭，保留本轮空值。外部打开按钮在这一轮及其close通知处理完成前禁用，避免示例在旧通知尚未处理时又重置下一轮值。

<!doctype html>
<html lang="zh-CN">
<meta charset="utf-8">
<title>教学对话框结果</title>
<button id="open" type="button">打开教学确认框</button>
<dialog id="decision" aria-labelledby="question">
  <h2 id="question">是否采用这项教学偏好？</h2>
  <p>这里只记录本地选择，不保存真实设置。</p>
  <button type="button" data-result="accepted">采用</button>
  <button type="button" data-result="declined">不采用</button>
</dialog>
<p id="status" role="status">尚未作出选择</p>
<script>
const [opener, dialog, status] = ['open', 'decision', 'status'].map(
  id => document.getElementById(id)
);
const say = text => { status.textContent = text; };
const on = (node, type, handler) => node.addEventListener(type, handler);
const setAvailable = available => { opener.disabled = !available; };
on(opener, 'click', () => {
  if (typeof dialog.showModal !== 'function') {
    say('此环境未提供本例需要的对话框方法');
    return;
  }
  dialog.returnValue = '';
  setAvailable(false);
  try {
    dialog.showModal();
  } catch (error) {
    setAvailable(true);
    say(`未打开：${error.name}`);
  }
});
on(dialog, 'click', event => {
  if (!(event.target instanceof Element)) return;
  const button = event.target.closest('button[data-result]');
  if (!button || !dialog.contains(button)) return;
  const result = button.dataset.result;
  if (result === 'accepted' || result === 'declined') dialog.close(result);
});
on(dialog, 'close', () => {
  const result = dialog.returnValue;
  say(result === '' ? '本轮没有明确决定' : `本轮本地结果：${result}`);
  setAvailable(true);
  if (opener.isConnected && !opener.disabled) opener.focus({ preventScroll: true });
});
</script>
</html>

禁用触发器也改变了焦点恢复的前提，不能只在关闭后把disabled改回去就声称焦点已恢复。标准关闭算法先尝试对先前焦点元素运行聚焦步骤，再排入发送close事件的元素任务。本例在打开前就禁用按钮，可能影响保存的焦点身份；关闭时按钮也还不可用。之后的通知把它启用，不会让已经过去的原生恢复步骤自动重做。

因此close回调在恢复可用状态后，明确检查触发器仍连接且未禁用，再调用focus。这是样本自己承担的交接，不是从returnValue推导出的浏览器保证。真实产品若关闭期间移除了原按钮，还需选定另一个有意义的位置；本例条件不成立时不尝试聚焦失效节点。检查时应分别记录关闭后的activeElement和结果文字：一个决定值正确，不能掩盖键盘位置丢失。这里没有运行焦点路径，不把新增调用当作已通过的无障碍结果。

完整对照先打开并采用，核对显示accepted；再重新打开，通过目标浏览器实际提供的关闭请求退出，核对空结果分支。拒绝后再重开同样检查。这里列的是预期路线，没有实际运行Escape或采集日志；若环境没有接受关闭请求，应记录仍打开的状态，不能预填“取消成功”。

打开前清空是样本选择的本轮合同，也与官方returnValue示例一致。它不意味着所有对话框都必须采用空字符串。产品可以定义其他未决定表示，但要保证与明确结果不混同，并且每次打开都建立相同约定。随意使用上轮字符串作为默认值，会让“未选择”和“保持上次选择”失去区别。

本例只允许两个明确结果，不从任意按钮文案推导动作。可见文字可以翻译，内部结果仍需对应已定义含义。若以后增加“稍后决定”，应先决定它是独立明确结果还是无决定关闭，再同步显示与处理。不能只添第三个按钮，让它无参数close后意外继承旧确认。

close()与close("")是同一结果吗？

不是。省略结果不会把既有返回值改为空，显式空字符串则会赋一个空结果。按标准算法，区分点是传入结果是否为null，而不是字符串是否为真值；空字符串仍然是一份提供的字符串结果。不要用if(result)概括这两种调用的参数行为。

可以准备一个独立纸面对照：先把returnValue设为accepted，再调用无参数close；另一份先设同样旧值，再用close("")。只有在对话框处于可关闭状态、相应算法确实执行的前提下，比较关闭后的值。若对话框根本未打开，不能把一次调用没变化解释成字符串规则失效。

这个差异也解释了为什么不要把视觉隐藏当成正常关闭。标准指出，直接移除open属性有额外后果，包括不发送close事件；若原来是模态，还可能留下文档阻塞等不期望状态。应用若绕过正常关闭路径，结果处理和清理便可能都没有执行。popover关闭策略是另一类浮层合同，不能从其显示状态推导dialog的结果语义。

本轮结果还要属于本轮对象

假设教学确认框将来复用于申请甲和申请乙。即使每次结果都清空，后台处理仍不能读取一个随时会变化的全局“当前申请”来决定写回对象。应在打开时明确本轮身份，并将结果与该身份一起交给后续流程；若对象已失效，要有拒绝或重新确认的路径。

这项归属是应用设计判断，不是returnValue自动提供的能力。关闭结果没有版本、权限或服务端接收证明。样本因此只更新本地文字，不用任何accepted值触发真实保存。若接入异步处理，何时允许下一轮打开、错误后保留什么决定，都应另外写进合同。

待执行验证保留两轮完整输入序列、打开前与close通知里的值、当前对象和实际关闭方式。加入有参数、无参数、空字符串、拒绝与关闭请求未生效的分支，分别核对。本文没有浏览器或真实同意记录。先为每轮定义未决定状态，再把这轮结果交给这轮对象，才能避免取消被旧确认借用。
