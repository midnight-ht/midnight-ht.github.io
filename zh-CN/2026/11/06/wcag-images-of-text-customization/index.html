图片有alt就满足WCAG文字图像要求了吗？

按文本、可定制与必要呈现条件核对图片文字，说明海报与可见同信息正文并存的路径。

正文

核心要点

  • alt不单独证明文字图像的视觉定制条件成立。
  • 同信息可见文本与图像可以按条件并存。
  • 截图定义和必要呈现例外须逐项判断。

图片有alt，不足以单独证明满足WCAG1.4.5；还要判断是否应使用文本、图像能否按用户要求定制，或特定呈现是否必要。替代文字解释了图片内容，不会自动让眼前的像素文字变成可以重新设置字体、配色和间距的正文。

WCAG2.2成功准则1.4.5的条件是：使用的技术能实现相应视觉呈现时，以文本而非文字图像传达信息，除非图像能够按用户要求视觉定制，或者特定呈现对信息本身必不可少。这是AA级条款，不是要求清除网页上的所有图片，也不能由一个alt字段批准整页无障碍。

先问需要调整什么，而不是图片有没有描述

假设活动页面只上传一张海报，日期、地点、参加资格和报名说明全部画在图里。alt完整复述了这些内容，依靠文字替代的人可能获得信息；另一位读者却需要深色背景、较大行距和不同字体。放大整张海报改变了像素的尺寸，没有独立改变其中每一行的字体或行距。两种需求不能用同一个“已填alt”勾选框结束。

理解文档说明，这项要求希望用户能调整字号、前景与背景、字体、行距或对齐等呈现。编辑需要区分两份工作：内容是否有合适替代，以及信息能否用可定制的视觉文本读取。本文讨论后一份选择，不重复功能性图片如何表达操作目的的命名规则。

“设计稿只给了图片”也不是必要呈现的自动证明。活动日期用哪一种装饰字体，通常需要与传达日期本身区分；展示某个字体的字形样本，则可能正是要让人观察那个字形。应说明移除特定呈现会怎样改变信息，而不是把制作方便等同于信息不可替代。

海报和可见正文可以各自承担明确责任

理解文档明确允许图像与传达同样信息的文本同时呈现，文本可以被调整。这为受到内容系统限制的页面提供一种路径：海报保留视觉设计，可见正文承担可读信息。条件是同样信息确实呈现给用户，不能只抄活动名和一句宣传语，漏掉资格、费用或取消规则。

下面是未执行的完整静态HTML。调用方需要提供自己的poster.png；文件没有包含在示例里。活动名、日期和地点都是虚构教学材料，不表示真实开放报名。代码没有form、报名接口或后台保存，重点是把信息放进真实文本结构。

<!doctype html>
<html lang="zh-CN">
<head>
<meta charset="utf-8">
<title>教学活动信息</title>
<style>
body { max-width: 48rem; margin: auto; padding: 1rem; }
img { max-width: 100%; height: auto; }
.info { line-height: 1.6; font-size: 1rem; }
</style>
</head>
<body>
<h1>夜间阅读交流会（教学示例）</h1>
<figure>
  <img src="poster.png" alt="阅读交流会海报；完整教学信息见下方正文">
</figure>
<section class="info" aria-labelledby="details">
  <h2 id="details">活动信息</h2>
  <dl>
    <dt>时间</dt><dd>2026年11月20日19时至20时</dd>
    <dt>地点</dt><dd>教学图书馆二楼讨论室</dd>
    <dt>参加条件</dt><dd>面向教学名单中的成年读者，免费参加</dd>
    <dt>报名说明</dt><dd>本页不接受报名；真实入口尚未提供</dd>
  </dl>
</section>
</body>
</html>

示例的alt只说明图像角色并指向正文，不是适用于所有海报的固定模板。真实海报若包含正文没有传达的其他重要视觉信息，应按实际语境处理替代；不能为了避免重复，直接把所有图像都改成空alt。这里完整正文与图片同处页面，用户不需要先找到另一个下载文件才能读规则。

接下来应拿海报与文字清单逐项核对。日期里的开始和结束时间、地点楼层、年龄条件、“免费”与“限额”等都可能改变决定。若海报更新了地点，而正文仍留旧地址，即使两者都容易读，页面也出现两份相冲突的信息。可见文本不是海报的附属摘要，它需要与实际活动信息一起维护。

一种可管理的做法是让活动信息有共同来源，再分别生成图像和正文；现有系统做不到时，也应指定谁在换图时复核文字。共同来源只是减少分歧的设计选择，不能保证渲染与内容都自动正确。仍应检查最终页面，而不是只确认数据库里有几个字段。

必须删掉海报图片吗？

不必。理解文档允许图像旁同时提供传达同样信息的可见文本。对使用技术能实现视觉文本的场景，还可以直接用HTML与CSS呈现主要信息，把图像留给有意义的插图或品牌。选择取决于信息职责，不是所有页面采用相同版式。

可定制图像也是条款列出的条件，但“有一个放大按钮”不能自动代表字体、颜色与背景都能按用户要求设置。若依赖这条路径，应明确具体能调整哪些特征、调整后信息是否仍完整，以及读者如何发现这些控制。本文没有实现这种图像生成器，也不声称示例已验证该例外。

截图中的字都必须改成HTML吗？

不一定。定义排除了包含重要其他视觉内容的图片中的文字，例如需要同时展示界面关系的某些截图、图表和示意图。单纯把一段公告截成图片，不能只因为文件名叫“截图”就获得这个分类。应判断图片传达的是否超出了文字本身，而不是凭扩展名决定。

必要品牌呈现也有自己的条件：标志中的文字被视为必要，字体样本可能需要保持特定字形。这不表示标志旁的活动日期、导航或正文一并免除。将局部必要呈现扩大到整张页面，会让最需要调整的说明继续只能作为图片读取。

待执行验证应准备仅图加alt、图加完整正文、图加故意缺少资格条件的正文三个版本。逐项核对实际可见信息，再改变文本字体、字号、前景背景与间距，完成查时间和确认资格的任务。记录遗漏、遮挡和文字重叠，而不是只截一张默认页面。

文字间距覆盖检查可以继续验证真实文本布局，但不能替代本篇对内容类型与例外的判断。这里没有运行浏览器、读屏或用户研究。交付先解释为什么采用文本、同信息并存或某个明确例外，再核对实际读者能调整和读到哪些信息。
