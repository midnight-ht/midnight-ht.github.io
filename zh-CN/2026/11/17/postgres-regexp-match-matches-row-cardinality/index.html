PostgreSQL 换了正则函数，为什么匹配不到的记录整行消失？

用同一份备注对照 PostgreSQL 正则标量、逐匹配明细和来源行保留。

正文

核心要点

  • 标量无匹配时返回 NULL。
  • 集合版本无匹配时不返回行。
  • 要按来源验收行数与归属。

PostgreSQL 的 regexp_match 在找不到匹配时返回 SQL NULL，regexp_matches 则可以返回零行。把标量函数换成返回集合的函数以后，无匹配的输入可能整行消失。先确定报表要保留输入行，还是要为每个匹配生成明细。

假设一个运维报表从文字备注里提取数字编号。原来每条备注都保留一行，没有编号时只显示空。后来需要在一条备注里找出所有编号，函数名多了一个字母，结果却漏掉了完全没有匹配的备注。只检查命中的编号，会让这种改动看起来符合需求。还需要验收哪些源行应该保留，以及同一行有两个编号时输出应该占几行。

一个空值和零行会进入不同的查询结果

PostgreSQL 十八版文档把 regexp_match 定义为返回第一次匹配的捕获数组，没有匹配时返回 NULL。regexp_matches 的返回值是捕获数组的集合。它没有匹配就不产生行；使用 g 标记时，可以分别返回多次匹配。这里的模式只含一组数字捕获，因此每次匹配的结果都是含一个字符串的数组。其他正则多捕获组，以及匹配到空字符串，都应按各自规则验证。不能用返回数组长度直接推断输入产生了多少匹配行。PostgreSQL 正则匹配函数。

在标量投影中，一个字段为 NULL，源行仍有可见的编号。用交叉关联组合匹配行时，每个来源只与它自己的匹配集结合，空集合没有可组合的明细。此时无匹配的源实际上仍在输入表，只是查询形状没有为它保留输出。报表日志应明确记录“没有提取结果”或“源行没有返回”，避免从结果空白倒推底层记录被删除。

对照一次、两次和零次匹配的输出

下面是未执行的 PostgreSQL 十八版教学 SQL。在隔离会话建立两条备注，第一条内容有数字十二和三十四，第二条没有数字。第一条查询只拿首次匹配，第二条将全部匹配扩为行。后者的最终排序只是让验收结果易读，不用它声明函数天然给所有消费方相同的输出顺序。

CREATE TEMP TABLE extract_demo (id int, note text);
INSERT INTO extract_demo VALUES (1, 'A12 B34'), (2, 'none');

SELECT id, regexp_match(note, '([0-9]+)') AS captures
FROM extract_demo ORDER BY id;

SELECT id, captures
FROM extract_demo
CROSS JOIN LATERAL regexp_matches(note, '([0-9]+)', 'g') AS m(captures)
ORDER BY id, captures;

标量查询应返回两行。编号一的 captures 是只含文本十二的数组，编号二是 SQL NULL。集合查询则都来自编号一，两份捕获分别是文本十二与三十四；编号二不出现在输出中。两条查询恰好都返回两行，因此只检查总数会完全漏掉丢失的源。同时核对每个编号出现的次数，以及数字仍属于正确来源。若应用只需要一次匹配，集合查询查全的两个编号也不能代替标量合同。

测试还可以准备一个来自错误来源的匹配控制。假设第二条备注仍是 none，但查询不小心使用共享文本 A12 去计算匹配，结果第二条也会带十二。输出行数可能仍对，结果归属已经错了。应通过输入编号比对原始备注与对应捕获。这里未运行这个错误变体，也没有评估索引、耗时或模式复杂度。重点是结果行怎样与原始数据对应。

按消费者需要确定每行代表谁

若每条记录对应一个表格单元，可以继续采用首个匹配，并给无匹配的值明确定义显示。若需要列出全部编号，则让每条匹配对应独立明细，并继续携带源行标识。两个来源行碰巧提取相同编号时，明细可能仍是两项；不能无意中把同值去重变成来源去重。给两条都含十二的备注各自检查归属，是另一份未执行的消费端测试。

汇总还要区分没有源行和返回了源行但为空。有的报表应该按来源计算完整分母，详情页才按匹配展开。如果使用明细输出直接统计源数量，两个匹配会重复算同一条备注，同时无匹配记录被漏掉。可以并列保存原始来源计数与每来源匹配次数，再决定在哪个阶段提供合计。站内的 每客最近订单与 LATERAL 也涉及逐来源关联，但本例的零行与多行由正则接口确定。

迁移前还有一项必要核对。旧调用者可能已经用字段为空表示“需要人工处理”。如果新查询直接丢掉整行，该流程就没有机会排入工作。应给无匹配的标识单独准备一条回归，检查它是否仍进入业务约定的出口。这里没有运行真实报表或人工流程。

若任务计划按是否能抽取编号来分发，还可保存一个独立输入清单。清单有编号一和二，不依赖任何提取函数。预期编号一进入正常报告，编号二进入人工处理。随后对比报道及待处理的可见结果，确保两个清单的并集仍覆盖原输入，且没有把同一备注排两次。若同一条备注产生两个捕获值，正常报告可以展开两行，分发统计仍只应算这一个来源。把分发数量和明细数量分开，方便处理方确认改变的是报告形状还是工作量。这个对照未运行，也未要求查询负责提交后续任务。

需要全部匹配，又要保留一条无匹配来源怎么办？

可以把第二条查询改成 LEFT JOIN LATERAL 并在连接条件写 ON true。用同一输入重新验证，编号一仍来自两条匹配，编号二保留一条右侧为空的行，合计三条。这样得到的输出仍混有真正的匹配明细和一行保留来源用的补空记录。若再按匹配字段做后置过滤，还要检查编号二是否被重新删掉。这项变体没有执行。
