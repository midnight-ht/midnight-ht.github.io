模型两次都选 A，为什么未必是同一个回答赢？

把交换顺序前后的 A/B 票映射回候选编号，区分一致胜出、显式平局和偏好不一致。

正文

核心要点

  • 展示标签不等于候选身份
  • 两轮映射到同一个候选才按示例宣布胜出
  • 保留显式平局和合法投票不一致的原始区别

两份客服回复送给模型做成对评审。第一轮模型选 A，交换展示位置后仍选 A。报表把这两票汇总成「同一份回复获胜」。可第一轮排在 A 的是草稿 X，第二轮排在 A 的是草稿 Y。先把位置标签还原成候选身份，才知道结果是否一致。

先分开候选编号和展示标签

候选 X 与 Y 在两轮里应该保持原样，包括具体回答和对应的问题。第一轮将 X 放在 A、Y 放在 B；第二轮由 Y 占 A、X 占 B。A 与 B 是当前次的标签，不是草稿的长期标识。同一个标签可以先后指向不同文本。

因此如果两轮都选 A，按草稿比较就得到 X 和 Y 两种判断。这次换序后没有形成一致偏好。若第一轮选 A、第二轮选 B，表面的字母不同，选择的却都还是 X。两种情况需要对照每轮自己的映射，不能只在汇总表里按字母计数。

Zheng 等人的《Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena》在位置偏差讨论中记录过改变展示顺序导致偏好翻转的例子。该论文的版本和实验用例有具体条件，不能拿一次现象说明所有现有模型都喜欢第一项。它提供了为什么值得测试这个操作的证据，并不替本文任何固定输入产生结果。

作者提出一种保守处理方式，把两个回答交换位置后再问一轮，只有两轮偏好相同回答才宣布胜出。论文可将不一致计为平局。这里采用更细的工程记录，把「模型两轮都给出平局」和「换序后偏好不一致」分开。两者都不会产生稳定胜者，但需要复查的原因不同。

把两轮原始投票翻回候选编号

下列 Node 夹具使用虚构的三组投票。每组固定同样的 X、Y 顺序和其反向。决策函数的输入限定为已经校验过的 A、B 或 Tie。脚本不会调用任何模型，也没有真实的人做标注。它只检查用这三组输入会不会把不同的候选误算成同一个。

import {deepEqual} from 'node:assert/strict';

const first = ['draft-X', 'draft-Y'];
const swapped = ['draft-Y', 'draft-X'];

function candidate(order, vote) {
  if (vote === 'Tie') return null;
  if (vote === 'A') return order[0];
  return order[1];
}

function decide(earlier, later) {
  const a = candidate(first, earlier);
  const b = candidate(swapped, later);
  if (a !== b) return ['unresolved', a, b];
  if (a === null) return ['tie'];
  return ['winner', a];
}

const cases = [
  [['A', 'A'], ['unresolved', 'draft-X', 'draft-Y']],
  [['A', 'B'], ['winner', 'draft-X']],
  [['Tie', 'Tie'], ['tie']],
];
for (const [[earlier, later], expected] of cases) {
  deepEqual(decide(earlier, later), expected);
}
console.log('Position labels mapped to the expected case outcomes.');

本机执行了三项断言。第一项两个 A 得到未决，同时保留两轮所选的 X 与 Y。第二项的 A、B 映射到同一个 X，可以按这份规则给 X 胜出。第三项两个明确的 Tie 进入平局分支。具体到真实评测，这只是一条决策规则，需要在跑数据以前把它及所有中间状态写清楚。

程序之外仍要保留两轮的原始上下文。一条记录至少需要问题编号、候选编号与对应位置、评审模型和提示版本、原始输出、解析出的标签、最后的候选身份。汇总时若只有 A 和 B，就无法查到给哪段文字评分，也没办法在评审提示升级以后重新核对两轮差异。

交换顺序检验结果是否稳定

真实试验应保持评审标准和候选内容不动，只交换位置。比如不能在第二轮把回复 Y 的错字顺便改了，再把改判归到顺序上。还需要记录同一模型在相同输入上可能存在的采样差异。一次异判能够标记这一对结果在当前测试里不一致，单凭一对不能隔离所有原因或测出整体偏向比例。

有些报表把每条没有稳定胜者的记录都合成一个平局百分比。要让团队判断是否值得调整流程，可以分别统计稳定胜者、双平局和合法投票不一致。先保留同一批问题作为分母，再按预定规则说明哪些案件不进入已完成的双向比较。后续如果切换模型或版本，应比较条件相同的测试，而不是把不同题型混成一个数字。

即使两轮都偏好 X，也只能说明在这次对照下交换位置没有改变结论。它不能回答 X 是否真的给出正确的客服要求，或优于特定用户更喜欢的写法。若评审结果关系到正式评估，可以另用已知答案或实质性人审校对。该夹具的结果不包含质量验收。

论文中的实验收集了多个对照样本，例如对同一道题生成相似的两份答案，再用固定提示比较两种展示顺序，同时记录判断一致、偏爱第一位置和偏爱第二位置等情况。若自己的测试只有少量类别，先按类别保存这个配对信息。不要把一类写作题的结果用于替另一类带标准答案的问题作结论，也不要把论文的样本数量当成本产品的验收样本数。

团队还可以在报表中设置两列计数。第一列按展示位置汇总，便于检查是否集中在开头；第二列按候选身份汇总，便于复核谁得到了稳定支持。如果只保存第二列，可能看不到评审持续偏好某个位置。如果只保存第一列，就会重现开头的标签错配。两列都从同一份回执生成，审查者可以逐项追到原来候选。

一轮返回了无法解析的标签，能依靠另一轮宣布胜出吗？

不能按这里的双向规则宣布胜出。例如第一轮明确选择 X，交换后的原始输出却只说「可能第二个，但要再看」且未按约定给有效标签。当前只有一轮能参与比较。把错误输出写成平局会掩盖数据缺失，把单轮成功当稳定胜出则会恢复这套流程本来要避免的判断。

保持这条记录未完成，并保留无效原始输出与解析原因。可以按事前约定重问同一方向，或者把它转入人工复看。做汇总时分别记录未完成和合法的双平局，不让数据质量问题直接进入候选计分。示例脚本在有效标签的前提下运行，没有实现重问或解析模型原文。

关于项目如何在证据不足时暂缓投入，可另看发现阶段的继续与停止条件。
