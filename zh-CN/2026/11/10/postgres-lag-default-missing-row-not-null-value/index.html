lag 已经写了默认值 0，为什么仍返回 NULL？

以四行读数比较缺前行、前行值NULL及两种COALESCE位置，保留prev_id判断空结果来源。

正文

核心要点

  • lag的default只在偏移行不存在时使用。
  • 内外COALESCE合并的空状态不同。
  • 保留前驱身份和原行数，才能解释空结果来源。

lag(value, 1, 0) 只在分区中不存在指定偏移行时返回零。如果前一行存在，其 value 恰好为 NULL，返回的仍是 NULL。第三个参数处理的是“没有这行”，并不是把取到的所有空值都改成默认值。需要选择的是空结果的业务合同，而不是给函数多塞一个零。

假设报表保留设备每次采集记录，并附上前一次读数。第一条记录没有前驱，某次采集却确实产生了一条值为空的记录。页面如果把两种情况都显示成零，读者可能以为都测到了零；如果后台只想给首次记录提供起始值，又会疑惑后续为什么仍有空栏。这两个要求应先分开，不能由“默认值”三个字替团队决定。

前驱身份先于数值填补

PostgreSQL 18 窗口函数表把 lag 定义为读取当前行在分区内之前 offset 行的值；只有不存在这样的行，才返回 default。offset 与 default 都按当前行求值。这里说的是偏移行，不是向前搜索一条符合额外业务条件的记录。

先固定 PARTITION BY 和窗口内部 ORDER BY。不同设备不能彼此借前驱；相同采集时间需要明确并列规则，否则“前一行是谁”本身就不稳定。下面用唯一 id 定序，表示教学合同认可这个顺序，不暗示数据库编号天然等于实际采集先后。真实数据可以用时间加稳定标识，但评审时要解释选择依据。

本站的last_value 与窗口帧已说明跳过空值与过滤丢行的风险。本题不再寻找最新有效记录，而是比较行已经确定以后，空值处理发生在哪一层。把这两个问题合在一起，会在只需要边界默认值时引入不必要的记录选择逻辑。

四行输入，三份不同合同

下面是未执行的完整 SQL。A 设备依次有值为十、空、三十的三条读数，B 设备只有一条空读数。每条输入都应保留为一条输出，不允许先删除空读数让结果看起来整齐。

WITH r(g, id, v) AS (
  VALUES ('A', 1, 10),
         ('A', 2, NULL::integer),
         ('A', 3, 30),
         ('B', 4, NULL::integer)
)
SELECT g, id, v,
       lag(id) OVER w AS prev_id,
       lag(v, 1, 0) OVER w AS boundary_default,
       lag(coalesce(v, 0)) OVER w AS input_fill,
       coalesce(lag(v) OVER w, 0) AS result_fill
FROM r
WINDOW w AS (PARTITION BY g ORDER BY id)
ORDER BY g, id;

按 A 的编号一、二、三，再到 B 的编号四排列，独立预期为：prev_id 是空、一、二、空；boundary_default 是零、十、空、零；input_fill 是空、十、零、空；result_fill 是零、十、零、零。四种向量应提前写进验收表，不从实际查询结果倒推“我们原本想要什么”。这里没有数据库执行输出。

boundary_default 的第三行最能暴露问题。它有前驱二，因此不触发第三个参数；前驱的值为空，于是结果为空。第一行和 B 的单行分区没有前驱，才获得零。第二行前驱值为十，不受任何空值处理影响，是需要保留的正常对照，不能只测所有列都变零的极端输入。

COALESCE 的官方说明规定它返回第一个非空参数。放在 lag 里面，是先把每个现有输入的空值解释为零，再去取前一行；不存在前行时，lag 自己的缺省结果仍为空。放在 lag 外面，则在取完结果后补零，因此同时吞掉没有前行与前行值为空这两种结果。

相同数字不等于相同语义

若再给内层写法补上边界默认，即 lag(coalesce(v, 0), 1, 0)，在这份固定零默认值的输入上，会与外层写法得到相同数字。不能据此说任何参数、任何表达式位置都没有区别；这里只证明两种明确选择在当前合同上合并了相同状态。将来默认值改为另一列，或需要保留缺行原因，就要重新核对。

选择时先问产品如何解释空值：首次记录需要起始零、已有失败读数仍留空，可用边界默认；所有取到的空结果都显示零，才考虑外层补齐；已有输入空值按零算、无前驱仍标未知，则是内层处理。这不是三个性能优化选项，而是三份不同的数据解释。

只返回前驱值会丢掉来源区别，因此例子同时带出 prev_id。由于教学输入的 id 唯一且非空，prev_id 为空可以表示没有前驱；prev_id 非空、前驱值为空则是已有记录的空读数。真实接口应保证身份列满足这个条件，若身份本身可空，就不能照搬这个判定。必要时返回独立的前驱存在标记，而不是猜测某个业务值。

验证还要检查原行数。删掉空读数以后再求 lag，会改变谁跟在谁后面；给现有结果补零则保留记录身份。即使某个页面只显示非空结果，也应把窗口输入集合和最后展示过滤分开审查。打乱 VALUES 的书写顺序，只要窗口排序明确，预期仍应按同一身份关系产生；外层排序只负责展示，不能替窗口补定序。

还可增加一组身份负例：只在独立变体中把 A 的第二条读数从空改成十，保留编号一和二都为十。此时 A 第三行的正确前驱仍是编号二，值为十；一个错误关联若拿到编号一，也恰好返回十。仅比较前驱数值的测试会通过，比较 prev_id 才能发现选错了记录。这个变体不是替换前面的空值样本，两组应同时保留。

对带状态或时间的接口，还应核对附加字段来自同一个前驱身份。不能让读数取编号二、采集时间却取编号一，再因为数值相同就宣告整行正确。教学查询尚未执行，验收目标应写为前驱编号与值的对应关系，而非只有一个数字列表。这项检查保留的是行身份，不是在向前寻找另一条有效记录。

default 引用另一列，取的是前行的值吗？

不是。文档明确 default 按当前行求值。增加这一条件后，可让每行携带不同的 seed，再使用 lag(v, 1, seed)；在一个分区的首行，回退的是该首行的 seed，而不是一个不存在前行的 seed。其余有前驱的行仍读取前驱 v，即使那个 v 为空。

验收时给 A 首行 seed 一百、B 首行 seed 四百，独立预期是两个分区起点分别回退一百和四百；A 第三行仍为空。这个探针同样未执行。把首行、已有空前行和正常前行三类身份一起保存，再检查数值与界面含义，才能说明默认值究竟填了哪一种缺口。
