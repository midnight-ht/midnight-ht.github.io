PostgreSQL ROLLUP 的 NULL，哪一行才是总计？

用 PostgreSQL GROUPING 位掩码区分原始空分类与 ROLLUP 小计、总计，保留行层级并避免混合层级再次加总。

正文

核心要点

  • 原始NULL与维度省略的占位NULL可相同，GROUPING对应位区分其层级。
  • 最右参数对应最低位，参与分组为零、省略为一。
  • 保留原始键与mask身份，先选汇总层级再使用金额。

ROLLUP 结果里的 NULL 不一定代表总计，也可能来自原始数据中未分类的键。PostgreSQL 的 GROUPING 可以标出当前行缺少哪些分组维度；应先识别分组层级，再给小计与未知分类命名。

假设销售报表同时返回地区与商品明细、地区小计和全体总计。某笔记录的地区还未归类，商品分类也允许缺失。若页面看到空地区就显示“全部地区”，原始未知数据便会被误标成总计；若只用两个分类键生成行标识，不同汇总层级还可能互相覆盖。问题不是先把 NULL 换成什么文字，而是识别这行由哪一份分组产生。

ROLLUP 将几个分组层级放在同一结果里

PostgreSQL 18 表表达式的分组集说明解释，ROLLUP 包含给定表达式列表及其各级前缀，直到空分组集。对 region、product 两项，等价的层级是按地区和商品分组、只按地区分组，以及全体汇总。

某个表达式不参与当前分组集时，它在对应结果行里用 NULL 表示。因此，地区小计行里的 product 为空，表示这一层没有按商品划分，不表示商品数据缺失；全体汇总行中的两个键都为空。同一个可见空值，也可能本来就存在于原始数据。仅检查键值无法分辨原因。

同版聚合函数的 Grouping Operations 表给出 GROUPING：每一位说明相应表达式是否被当前分组集省略，参与时为零，省略时为一。最右参数对应最低位。因此 GROUPING(region, product) 在明细层为零，只省略商品的地区小计为一，两项都省略的全体总计为三。

让三个同样的空键保留不同身份

下面是未执行的完整教学 SQL，金额是同一单位的假设数字，不代表真实销售或财务数据。四条输入中既有未知地区，也有未知商品；最后一条两个键都为空，专门检验它是否会被误当成总计。

WITH sales(region, product, amount) AS (
  VALUES ('north'::text, 'book'::text, 10),
         (NULL::text, 'book'::text, 20),
         ('north'::text, NULL::text, 5),
         (NULL::text, NULL::text, 7)
)
SELECT region, product,
       GROUPING(region, product) AS level_mask,
       SUM(amount) AS amount
FROM sales
GROUP BY ROLLUP(region, product)
ORDER BY level_mask, region NULLS FIRST, product NULLS FIRST;

纸面预期共七行：四行明细的 mask 都是零，金额分别为十、二十、五、七；两行地区小计的 mask 都是一，north 为十五，未知地区为二十七；一行全体总计的 mask 为三，金额四十二。这里列的是按文档规则推导的验收目标，没有运行查询或保存数据库输出。

尤其要检查键同为 NULL、NULL 的三行。它们分别是金额七的原始未知分类明细、金额二十七的未知地区小计，以及金额四十二的总计。只返回两个键和一个含糊的显示名称，会失去这些身份区别。把 level_mask 与原始键一起带给接口和导出，消费方才能保留行所属层级。

显示标签可以随后生成：先根据某一维的 GROUPING 位判断是否为汇总，再在仍参与分组的情况下，为真实 NULL 选择“未归类”等文字。不要先 COALESCE(region, '总计')，因为它会把两个来源不同的空值同时改名。真实数据也可能恰好包含“总计”这个分类名，文字标签因此不适合独自充当机器键。

原始键为 NULL，GROUPING 对应位就会是一吗？

不会。只要该表达式仍参与当前分组集，对应位就是零，与这个组的实际键值是否为空无关。上例金额七的明细两个键都为空，mask 仍为零；未知地区小计只省略商品，所以 mask 是一，而不是因为地区未知又多设置一位。

这也说明 GROUPING 不是对键再做一次空值检查。文档明确指出，其参数并不作为普通数据值求值，而必须精确匹配当前查询层级 GROUP BY 中的表达式。若分组键实际使用某个表达式，应让 GROUPING 对应同一表达式；不能随便包一层显示转换，再期待它继续代表原键的分组参与情况。

本题中的空键是结果结构与分类值的问题。站内二〇二六年十月十九日的SUM 空输入与未知金额讨论聚合输入有没有可计算的数值；那份默认值选择不能替这份多层结果识别明细和总计。

为什么不能把返回金额全部再求和？

因为同一输入已经在多个层级参与计算。上例明细合计四十二，地区小计合计四十二，全体总计也是四十二；把七行金额全部相加会得到一百二十六，而不是新的销售总额。金额列的名字相同，不代表所有行具有同一个可相加的粒度。

若需要只展示明细，可以按 mask 为零选择；需要全体总计，就选择 mask 为三的对应行。若在 SQL 中按 GROUPING 过滤层级，应明确这是聚合后的层级选择，不是把原始未分类记录从输入中删除。WHERE region IS NOT NULL 会改变参与金额，不能作为“去掉总计行”的替代写法。

有固定地区、商品层级时，ROLLUP 很直观；只需要某几种不构成前缀的组合时，可以明确列 GROUPING SETS。不要为了得到一个总计顺手加入所有组合，再让客户端猜哪几行有用。SELECT DISTINCT 也不能充当层级识别：省略 mask 后，不同层级在键与金额恰好相同时可能看起来完全相同，去重会删掉本来不同的汇总行。

GROUPING 参数换序后，旧的层级数字还能直接用吗？

不能直接沿用。最低位属于最右参数，换序会改变位与维度的对应关系。若仍按地区与商品做同样的 ROLLUP，却改为 GROUPING(product, region)，省略商品对应的位已经不同。接口应固定参数顺序和层级映射，或明确版本变化，不能把某个数字当成脱离查询定义的通用分类。

拟议验收应逐行比较原始键、mask 和金额，同时核对七行以及四、二、一的层级分布。再把输入顺序打乱，把未知地区换成真实分类，并让不同层级金额偶然相等，检查页面与导出是否仍保留身份。最后对同一层级单独核对四十二，确认没有混层再加总。本文未执行数据库或接口测试，也不承诺查询性能。先让每行可解释地属于一个层级，再决定它应显示在哪个位置。
