刚插入的提示条，为什么写了 transition 也可能不淡入？

用两条同时插入的通知对照起始样式，验收首次淡入、最终可见与减少动效行为。

正文

核心要点

  • 新插入节点可能没有变化前样式
  • 起始规则参与正常层叠
  • 过渡与最终反馈分开验收

点击按钮后，页面把一条新通知插进文档。样式写了透明度过渡，通知却直接停在完全可见的状态。新节点第一次参加渲染时，还没有一次可作为比较基准的旧样式。想让它从透明变到可见，需要给这次入场补一个起始值。

第一次渲染缺的是什么

CSS 过渡要比较变化前和变化后的样式。一个已在页面上显示的通知，先处于透明度零，再被更改为一，浏览器可以从上一轮样式读取起点。若节点在同一次样式变化里才插入，它之前并不参与渲染，就没有从上一轮留下的这个值。

CSS Transitions Level 2 草案为此提供 @starting-style。找不到变化前样式时，可以由普通的变化后样式加上适用的起始规则，得到比较起点。例子只补透明度零。节点普通样式的最终透明度仍是一。在不需要起点的后续样式更新中，浏览器可以用实际存在的旧样式做比较。

起始规则仍参加正常层叠。有了这层分组名称，并不保证里的任何声明都能压过普通规则。如果两个选择器具有相同的适用条件和权重，源顺序仍然会参与决定。如果项目中存在更高权重的透明度声明，要检查究竟能不能得到起点零，而不是只看样式表里有没有这个规则。

把持续时间加到更长，也不能为完全缺少起点的元素创造旧状态。真正的检查是有没有两个不同的计算值可以比较，以及过渡属性和持续时间是否允许这次变化。若起点和终点最后都等于一，即便写了时长，也没有可见的透明度插值。

两个通知一起创建，只改起始规则

下面是一个独立 HTML 页面。每次点击都会新建两个段落，放进同一容器。它们的普通透明度和过渡持续时间相同。只有第二个段落能匹配到透明度零的起始规则。监听器先绑定，再插入，因此不需要在动画已经开始后补注册。

<!doctype html>
<meta charset="utf-8">
<title>Notice entry comparison</title>
<style>
  .notice { opacity: 1; transition: opacity 600ms; }
  @starting-style {
    .entry { opacity: 0; }
  }
  @media (prefers-reduced-motion: reduce) {
    .notice { transition: none; }
  }
</style>
<button id="show" type="button">Insert notices</button>
<div id="notices"></div>
<pre id="output"></pre>
<script>
const byId = document.getElementById.bind(document);
const notices = byId('notices');
const output = byId('output');

function makeNotice(label, className) {
  const el = document.createElement('p');
  el.className = className;
  el.textContent = label;
  el.addEventListener('transitionend', event => {
    if (event.propertyName === 'opacity') output.append(label, ' ended\n');
  });
  return el;
}

byId('show').onclick = () => {
  output.replaceChildren();
  const plain = makeNotice('Ordinary notice', 'notice');
  const entry = makeNotice('Notice with starting style', 'notice entry');
  notices.replaceChildren(plain, entry);
};
</script>

在支持该规则且未启用减少动效的环境中，等待两个段落都显示。第一个预期直接出现在最终状态，第二个可以从透明淡入，在透明度过渡完成后写一条日志。两条通知的预期终态一样，都是可见文本。不要用固定截图时刻判断一定处于第几帧。

这是标准与代码推导，没有运行浏览器或报告实际轨迹。若样本没出现第二条日志，先确认目标浏览器支持规则、当前偏好没有关闭过渡、页面没有立即移除节点。再次点击时会换成新的段落，也会打断上一次可能还在发生的效果。验证一次完成应先避免重复操作。

如果只检查最后有没有通知，两个分支都能通过，因此不能证明入场效果正确。若只监听过渡事件，又会把用户主动减少动效判作失败。合适的验收把反馈能否被发现和动效有无分别记录。对不恰好有动画的环境，消息仍然需要被展示。

将起始入口放进实际的反馈流程

产品里的新提示可能来自表单操作或列表更新。先从实际按钮跑一遍，确认元素真的是本轮刚插入，而非一个早已存在的可见节点改了属性。可记录对象是否被创建、插入时匹配了哪些样式、终态是否直接进入。这样才能判断此处需要起始规则，还是普通过渡本来就足够。

若项目希望照顾减少动效的偏好，保留可直接到终态的分支。不要把真正的提示文本放到过渡回调才显示。用户即使关闭动效，仍需要知道刚才是否保存成功。例子用媒体查询禁用过渡，但两条通知都以普通样式承担可见反馈。

集成时还可以调试层叠。先在独立样本证明两个透明度不同，再把同一声明接到产品样式。若产品中出现变化，检查组件层、工具类和主题覆盖的顺序。这里的对照只问入场，未承诺其他属性也能从起始值做出你想要的变化。

验收可以再对照刷新前后的创建次数。一条保存回执如果因列表重新渲染被当作新节点创建两遍，可能重复播放入场，即使透明度规则完全正确。给回执保留稳定身份，并在日志里区分初次出现和内容更新。目标是新通知进入时有适当反馈，旧通知刷新文字时不会因为节点被无意替换而重复提示。对同一个按钮连续输入两次，也应明确第二次是在重新插入，还是只更新第一次创建的节点。

把通知移出文档时，会自动做一次反向过渡吗？

不会。这个新条件是应用直接删除已显示的节点。起始规则负责没有旧样式的入场比较，不会在删除时替节点保留渲染，也不会自动生成一个反向的终点。如果需要淡出，先保留节点，为仍在文档中的元素应用退出样式，再按实际组件的完成或取消策略移除它。

可以写一个与主例不同的退出用例。确认通知已存在，随后发出关闭动作，检查它在退出期间是否仍存在，然后才移除。也应检查跳过动画的分支，不能让元素只因没有收到一次过渡事件就一直无法清理。

减少动效时怎样保留提示反馈，可以另看减少动态效果时如何保留状态信息。
