Counter 相减之后，为什么欠货商品消失了？

用两条独立库存计算区分 Counter 的正余量与带符号差额，验证负数、显式零和原库存。

正文

核心要点

  • 保留欠货数时，在库存副本上计算带符号差额。
  • 只有售卖正余量时，使用二元减法结果。
  • 要验证显式零仍在，使用键成员断言。

仓库里有两件苹果，预留单上却有三件。你把两个 Counter 相减，准备把结果交给采购，里面找不到苹果。差额没有算错。二元减法会把为零和为负的结果从输出中滤掉，适合给出剩余可用量。采购需要的是保留符号的差额。

同一批货，要给两个团队看

先把库存和预留口径固定下来。苹果有两件，预留三件；梨有一件，刚好预留一件；柠檬有四件，没人预留。这三个商品恰好覆盖三种结果。苹果欠一件，梨正好用尽，柠檬还有四件。采购表需要区分苹果和梨，售卖入口只需要确认当前还能承诺四件柠檬。两个接收者对同一份输入提出了不同问题，不能直接拿其中一张表作另一张的证据。

二元减法按键计算差，输出只保留正数，所以苹果和梨都不出现。方法 subtract() 则修改调用它的计数器，并允许运算后的计数为零或为负。调用时可以交给它另一份计数器；在这个例子里，预留仍然全部是非负整数，负数来自库存不足。给采购保留差额时，先复制基线，再在副本上调用该方法。库存快照随后还能用来构造售卖视图。

这里特意不把“没有商品行”和“商品用尽”合并得太早。例如仓库同事希望盘点已知但刚好清空的货架，梨仍然有一行，只是值为零。如果调用方以零表示一个合法状态，就需要把显式零保留到那一层，再按报表用途过滤。与此同时，系统里某个尚未入册的商品也可能索引到零，单读一个数字无法区分这两种状态。

用两个独立计算重放同一张快照

下面所有数量都是件数。每次计算使用同一份原始库存和同一份预留，先让差额路径修改副本，再让另一条路径从原始库存得出可售余量。

from collections import Counter

stock = Counter(apple=2, pear=1, lemon=4)
reserved = Counter(apple=3, pear=1)
ledger = stock.copy()
ledger.subtract(reserved)
available = stock - reserved

assert dict(ledger) == {"apple": -1, "pear": 0, "lemon": 4}
assert dict(available) == {"lemon": 4}
assert dict(stock) == {"apple": 2, "pear": 1, "lemon": 4}
assert "pear" in ledger and "pear" not in available
print("ledger:", dict(ledger))
print("available:", dict(available))

先看断言对键的要求。采购结果里必须有苹果与梨，值各是负一和零。可售结果只剩柠檬。最后库存仍有二件苹果、一件梨和四件柠檬。如果把 subtract() 直接用在 stock 上，随后再做二元相减会从已扣过的库存再次扣预留；那样即使柠檬结果碰巧没变，输入断言也能报错。

检查梨是否显式存在时，可比较普通字典或测试成员关系。Python 3.10 起，两个 Counter 比较相等时，缺失的计数会按零处理。只写一个 Counter 相等断言，可能让少掉一条显式零的结果通过。类似地，读取可售结果中的苹果，默认得到零，也不能据此还原采购表的负一。这个区别在序列化前应当想清楚，尤其是下游按是否有键决定显示哪行的情况下。

再看一次交接事故。采购服务读到可售表后，若把所有缺键都补成零，就会把苹果和梨一起解释为没有缺口。保留符号的接口可以加一条核对规则：苹果差额在采购文件里必须存在且为负一，梨依然可以只在仓库盘点报告里显示。不妨让错误路径也跑一遍，使用可售表生成采购申请时，预期收不到苹果。这样测试不仅会阻止两个方法互换，还会阻止生成报表时选错上游输出。

先定业务状态，再写展示过滤

假设每天收盘要存一份可核对的差额表。可以让内部记录保留非正值，再生成仅显示欠货或仅显示可售商品的视图。保存时一并记录计算采用哪次盘点、哪一批预留；代码中即使每种算术都正确，拿昨晚库存扣今天的全部预留仍可能错判缺口。本文的夹具没有模拟盘点时间、并行预留、退单入库或数据库事务，它只检验同一次输入上的键与计数。

如果这个调用点只在商店页面算可用数量，二元减法可以直接给出正余量。若相同结果还要用于对账，给它起名叫可用库存，另存保留符号的差额。不要让两个报表共享一个还会被改动的 Counter 对象；即使后续要分享数据，也可以把已确定的数值和来源批次同时交出去。对测试人员而言，尤其值得把欠一件、刚好为零和还有余量保存在同一个夹具里，只有正余量的测试无法看出两种路径有什么差别。

还有一种业务输入是预留里出现全新商品，盘点表上没有它。应先决定这代表零库存、上游商品映射错误，还是尚未完成入库登记。数值可以算，但销售与采购需要先约定这条记录应该走哪条流程。本文用已在盘点表上的三件商品解释运算，未推定所有缺键都是有效的零库存。本站的忽略顺序时如何保留重复次数也把测试对象的身份说清楚，那里要保护的是每条记录出现的次数。

可以用 elements() 展开缺货单吗？

直接把差额交给 elements()，苹果不会出现。该方法按计数重复每个元素，计数小于一的键会跳过，柠檬则会出现四次。这个输出描述的是正数一侧，不能给采购生成单位明细。若下游确实需要逐件调用，可以先选出负计数并取相反数，得到苹果一件，再按需要展开。这里的新决定是单位计数和商品行之间如何转换。只要采购系统能接收商品和数量，保留一行带数量的记录会让批次及追溯关系更容易检查。
