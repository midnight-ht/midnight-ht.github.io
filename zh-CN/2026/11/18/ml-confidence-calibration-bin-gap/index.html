平均置信度等于正确率，为什么分类器仍可能没校准？

用八条分类预测检查每个置信区间的正确率与平均置信度，再按样本数加权计算 ECE。

正文

核心要点

  • 整体平均值相同仍可能掩盖分桶偏差
  • ECE 按样本量加权桶内绝对差
  • 保留各桶边界、样本数和误差方向

分类器验收表上，整体正确率是百分之七十五，平均置信度也是百分之七十五。团队准备把两列一样写成通过。展开各个区间才发现，置信度报六成的项目全对，报九成的项目只对一半。整体均值对上了，预测时给出的信心却没有反映这两批结果的实际把握。

比较的是相近置信度的预测

对于有明确正确标签的分类任务，置信度校准关心一件事：模型给出某个概率时，类似预测实际正确的比例大致是多少。如果报八成的一组只答对五成，那个分数不能按字面用于理解这批预测的把握。单条正确或错误不能完成这种比较，需要一组预测和对应标签。

Guo 等人的论文《On Calibration of Modern Neural Networks》展示了可靠性图的做法。将预测按置信度分入区间，对每桶计算平均置信度与经验正确率。两者的差是这个桶的校准差。关注哪个方向也有用：正确率低于平均置信度时，至少这批数据中的模型对那组结果更有信心。

论文给出的期望校准误差，也就是 ECE，是对每个非空桶的差取绝对值，按其样本数占全部样本的比例加权相加。先在桶里取绝对差，才能避免正负误差在加总时互相抵消。空桶没有经验正确率，图上应当显式区分没有数据与误差为零。

八条预测足以看清方向

用一份虚构的目录分类数据。四次给出百分之六十的置信度，四次全对。另四次给出百分之九十，只对两次。整体六次正确除以八次得到百分之七十五。平均置信度也同样为七十五，计算是四个六十与四个九十合计再除以八。

设四个等宽区间，第一桶包含零，其他区间以左开右闭归属。实际只占用五十到七十五与七十五到一百两桶。第一个有数据的区间正确率一百、平均置信度六十，差四十个百分点。另一个有数据区间正确率五十、平均置信度九十，差也为四十个百分点，但方向正好相反。

下面的本地脚本用整数百分数保存置信度，不会加载或运行模型。代码按上述边界记录非空桶，以便对照手算值。三个读数分别是整体量、各桶量和按桶样本量加权的结果。

import {deepEqual} from 'node:assert/strict';

const rows = [[60, 1], [60, 1], [60, 1], [60, 1],
              [90, 1], [90, 1], [90, 0], [90, 0]];
const sum = numbers => numbers.reduce((total, value) => total + value, 0);

function summarize(entries) {
  const n = entries.length;
  const accuracy = 100 * sum(entries.map(([, hit]) => hit)) / n;
  const confidence = sum(entries.map(([score]) => score)) / n;
  return {n, accuracy, confidence};
}

const bounds = [25, 50, 75, 100];
const bins = bounds.map((upper, i) => {
  const lower = bounds[i - 1] ?? 0;
  return rows.filter(([score]) => (i === 0 || score > lower) && score <= upper);
}).filter(bin => bin.length > 0).map(summarize);
const ece = sum(bins.map(bin =>
  bin.n * Math.abs(bin.accuracy - bin.confidence))) / rows.length;

const expected = {
  overall: {n: 8, accuracy: 75, confidence: 75},
  bins: [{n: 4, accuracy: 100, confidence: 60},
         {n: 4, accuracy: 50, confidence: 90}],
  ece: 40,
};
deepEqual({overall: summarize(rows), bins, ece}, expected);
console.log('Overall means, bin results, and ECE passed.');

本机断言通过。两个桶各占一半，乘上各自的四十个百分点，再相加得到四十个百分点。这个值在使用零到一的比例表达时是零点四。它描述这份小数据和这套边界，不能写成某个实际模型的测量结果。

保存能重算这份统计的证据

报告不能只剩一个整体误差。把区间边界、端点归属、每桶预测数、正确数、平均置信度和原始标签版本一起留存。这样后来才知道一个恰好落在七十五的分数进入了哪一组，或者两次结果不同是否因为样本分布已经改变。

如果还要评审某一分类子任务，先记录它会覆盖哪些条目。例如一次验收混合了解析文档和判断目录主题，两种错误的成本可能不同。可以对数据量足以说明问题的分组单独计算并列出样本数。不要因为整体表现更好就说每条工作流都能按同一个置信门槛放行。

置信度应来自已经明确含义的模型分数。一个对话系统写出「我有九成把握」的自然语言，并不自动成为可校准的分类概率。若团队确实想比较这类值，要先定义同一输出如何稳定取得、如何判对，再建立独立样本。本文只讨论有二元对错标签的分类结果。

改进这两处误差也不等于分类器答对更多。重新调整同一批预测对应的分数，可能让报告更接近观察正确率，而不改变每条预测的类别。因此比较改版时，要保留正确率与校准误差两套记录。若部署使用了特定阈值，还要另测阈值上方的真实通过条件。

同一份结果改用另一套分桶方式，也可能产生不同的统计值。粗粒度区间容易把本来不同的预测混在一起，细粒度区间又可能留下许多只有一两条的桶。比较发布前后的两个版本时，先锁住样本、边界和归属规则。若还想改变分桶，就把它作为敏感性检查另外报告。

在面向团队的图里，可以同时放每桶置信度与正确率的差，以及柱子对应的样本数。只保留两条差距相同的柱子，会让读者以为样本量也一样。一张用于复核的图应能回答这些点各代表多少条预测。

只有两条高置信预测，差很大也会支配 ECE 吗？

不一定。换一份二十条的样本。十八条置信度五十且九条正确，这一桶刚好相符。另有两条置信度九十却都错，那个小桶差九十个百分点。它只占总样本十分之一，所以整份 ECE 是九个百分点。这个数来自额外手算例，没有加入上面的运行脚本。

读数不只看总分。高分桶样本少，观察本身也有不确定性，但如果产品只自动采纳九成以上的预测，恰好就是那组最值得追加验证。保留各桶大小与误差方向，才能让团队做下一次取样和验收决定。

如果另一个问题是成对评审的同一答案是否会随顺序改判，可另看两次 A 票如何映射回候选身份。
