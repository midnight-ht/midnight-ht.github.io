Midnight 主题配置项完整指南

正文

Midnight 的配置文件不只是换 logo 和开评论。

它更像一份站点编辑部说明书：首页展示哪些频道，导航怎么高亮，多语言文章怎么互相找到，评论交给 Giscus 还是 Waline，广告合作页、隐私页、订阅页要写什么，都在主题 _config.yml 里有入口。

这篇按 hexo-theme-midnight 仓库当前配置来拆。写作时参考的是 GitHub 仓库 midnight-ht/hexo-theme-midnight 的 README、中文 README 和主题 _config.yml，仓库页面显示当前 latest release 为 v0.1.16，日期是 2026-05-30。

配置文件放在哪里

安装主题后，站点层一般保留两类配置：

# 站点 _config.yml
theme: midnight

主题自己的配置可以从主题包里的 _config.yml 复制出来，放到站点可维护的位置。常见做法是用 Hexo 的主题配置文件，例如：

_config.midnight.yml

这里有个安全边界要先记住：主题配置会进入构建产物或前端模板，不要把模型服务商 API Key、评论服务密钥、邮件服务密钥放进去。像 model_session.endpoint 这种字段只应该写你自己的服务端代理地址，真正的密钥留在服务端。

最小可用配置

如果只想先跑起来，可以先保留这些：

appearance:
  logo: /img/avatar.png
  logo_text: Midnight
  nick: Midnight
  default_scheme: dark

i18n:
  default_lang: zh-CN
  route_strategy: auto
  languages:
    - zh-CN
    - en

comments:
  enabled: false
  provider: giscus

seo:
  open_graph: true
  robots: index,follow

后面再慢慢补导航、首页频道、订阅、广告页和统计。Midnight 的配置项很多，但真正影响第一天上线的并不多。

基础信息

配置项 默认值 作用
name midnight 主题名称，通常不改。
description 技术写作主题描述 可作为站点描述的兜底文案。
favicon /img/favicon.png 浏览器标签图标。
apple_touch_icon /img/favicon.png iOS 添加到主屏幕时使用的图标。
tab_title_separator 竖线加空格 页面标题和站点标题之间的分隔符，默认显示效果类似 `页面标题
force_https false 为 true 时输出 HTTPS 相关处理；已经由 CDN 或托管平台处理 HTTPS 时通常不用开。

favicon 和 apple_touch_icon 建议放在 source/img/ 下面，然后写成 /img/favicon.ico 或 /img/favicon.png。不要写本地磁盘路径。

外观：appearance

配置项 默认值 作用
appearance.logo 空 站点 logo 图片路径。
appearance.logo_text Midnight 顶部品牌文字。
appearance.nick Midnight 作者昵称或站点昵称，部分模块会用作兜底作者名。
appearance.accent #4df2c8 主题强调色。
appearance.default_scheme dark 默认颜色模式，支持 dark 或 light。
appearance.background default 背景风格标识，主题 CSS 会读取这个值。

如果你是个人技术博客，优先改 logo、logo_text、nick、accent。default_scheme 可以按内容气质选：深色更像技术媒体，浅色更像资料库。

导航：nav

Midnight 的导航顺序是固定骨架：首页 -> 自定义按钮 -> 归档 -> 关于。你主要改 nav.items。

nav:
  home:
    name: home
    path: /
  items:
    - name:
        zh-CN: 工程化
        en: Engineering
      path: /tags/Engineering/
      style: underline
      active_match:
        - /tags/Engineering/
  archives:
    name: archives
    path: /archives/
  about:
    name: about
    path: /about/
配置项 作用
nav.home.name / nav.home.path 首页按钮文案和路径。
nav.items[] 自定义导航项数组。
nav.items[].name 可以是字符串，也可以是 { zh-CN, en }。
nav.items[].path 导航目标路径。内部链接会经过语言路由处理。
nav.items[].style 导航样式，支持 underline、text、pill、ghost、outline、solid。
nav.items[].active_exact 是否要求路径精确匹配才高亮。
nav.items[].active_match[] 命中这些路径片段时高亮。
nav.archives 归档入口。
nav.about 关于页入口。

我的建议是：长期栏目用 underline，临时活动或商业入口才用 pill、solid 这种更强的样式。

多语言：i18n

Midnight 对中文和英文站点比较友好，核心是两个东西：语言路由和文章翻译关系。

配置项 默认值 作用
i18n.default_lang zh-CN 默认语言。
i18n.route_strategy auto 语言路由策略。
i18n.languages[] zh-CN、en 支持的语言列表。
i18n.article_lang_field lang 文章 front matter 里表示语言的字段名。
i18n.translation_key_field translation_key 文章 front matter 里表示翻译关系的字段名。

同步文章建议这样写：

---
title: "Midnight 主题配置项完整指南"
translation_key: midnight-theme-config-complete-guide
lang: zh-CN
---

---
title: "Complete Guide to Midnight Theme Configuration"
translation_key: midnight-theme-config-complete-guide
lang: en
---

同一个 translation_key 会让主题在构建时找到不同语言版本。不同语言可以有不同 slug，不需要强行让中文标题和英文标题长得一样。

模型会话：model_session

这个模块只提供浏览器端 UI，不直接替你保管模型密钥。

配置项 默认值 作用
model_session.enabled true 是否启用文章里的 AI 会话面板。
model_session.endpoint 空 你的服务端代理接口地址。为空时不应真正调用模型。
model_session.title.zh-CN / model_session.title.en AI 会话 / AI Session 面板标题。
model_session.default_system_prompt 英文阅读助手提示词 默认系统提示词。
model_session.allow_user_system_prompt true 是否允许用户自己输入系统提示词。
model_session.max_messages 12 会话中保留的最大消息数。

生产环境里，endpoint 应该指向你自己的后端，比如 /api/model-session。后端再去调用 OpenAI、Claude 或其他模型服务。前端配置里不要出现 API Key。

评论：comments

评论总开关有两套字段：enabled 和 enable。这是为了兼容不同写法，实际配置时保持一致就行。

配置项 默认值 作用
comments.enabled / comments.enable false 评论总开关。
comments.provider / comments.type giscus 评论提供商。
comments.giscus.repo 空 Giscus 使用的 GitHub 仓库。
comments.giscus.repo_id 空 Giscus repo id。
comments.giscus.category 空 Giscus discussion category。
comments.giscus.category_id 空 Giscus category id。
comments.giscus.mapping pathname 页面和 discussion 的映射方式。
comments.giscus.reactions_enabled "1" 是否启用 reaction。
comments.giscus.emit_metadata "0" 是否输出 metadata。
comments.giscus.theme preferred_color_scheme Giscus 主题。
comments.waline.server_url / comments.waline.serverURL 空 Waline 服务端地址，两种字段都支持。
comments.waline.placeholder 空 输入框占位文案。
comments.waline.lang zh-CN Waline 语言。
comments.waline.page_size 10 每页评论数量。
comments.utterances.repo 空 Utterances 使用的 GitHub 仓库。
comments.utterances.issue_term pathname issue 匹配方式。
comments.utterances.theme github-dark 默认主题。
comments.utterances.theme_dark github-dark 深色主题。
comments.utterances.label 空 创建 issue 时附加的 label。
comments.utterances.crossorigin anonymous 跨域属性。

个人博客最省事的是 Giscus；如果你想完全自托管评论，选 Waline。

Sitemap 和 Feed

配置项 默认值 作用
sitemap.enabled true 是否输出 sitemap 入口。
sitemap.path sitemap.xml sitemap 路径。
feed.enabled true 是否输出 RSS/Atom 入口。
feed.path atom.xml feed 路径。
feed.title RSS feed 链接标题。

主题 README 推荐安装：

npm install hexo-generator-sitemap hexo-generator-feed

主题负责读取配置和展示入口，真正生成文件通常还要靠对应 Hexo 插件。

联系方式：contact

配置项 默认值 作用
contact.email ht@zyweb.vip 站点联系邮箱，广告合作、关于页等模块可使用。

建议改成你自己的公开邮箱。私人邮箱不想曝光的话，可以用专门的合作邮箱。

SEO：seo

配置项 默认值 作用
seo.twitter_card summary_large_image Twitter/X 卡片类型。
seo.open_graph true 是否输出 Open Graph 元信息。
seo.open_graph_image 空 默认分享图。文章可用 cover 或 og_image 覆盖。
seo.robots index,follow robots meta。
seo.keywords 空 默认关键词。
seo.baidu_site_verification 空 百度站长验证。
seo.google_site_verification 空 Google Search Console 验证。
seo.bing_site_verification 空 Bing Webmaster Tools 验证。

keywords 不要塞太满。真正影响站点质量的，还是标题、描述、内部链接和文章质量。验证字段只放验证码，不放整段 <meta>。

页脚统计：footer.statistics

配置项 默认值 作用
footer.statistics.enabled / footer.statistics.enable false 页脚访问统计开关。
footer.statistics.source busuanzi 统计来源。
footer.statistics.pv_format.zh-CN / .en 总访问量 {} 次 / {} page views PV 展示格式。
footer.statistics.uv_format.zh-CN / .en 总访客数 {} 人 / {} visitors UV 展示格式。

格式里的 {} 会被数字替换。中文站可以写得自然一点，比如 累计访问 {} 次。

配置项 作用

inner_pages.popular_reads[].meta.zh-CN/en 热门阅读说明，如阅读量或编辑推荐。
inner_pages.series_entries[].label.zh-CN/en 专题入口名称。
inner_pages.series_entries[].path 专题入口路径。
inner_pages.series_entries[].count 专题文章数或展示数量。
inner_pages.collections[].name 频道内部名称。
inner_pages.collections[].label.zh-CN/en 频道显示名称。
inner_pages.collections[].path 频道路径。
inner_pages.collections[].description.zh-CN/en 频道说明。
inner_pages.collections[].kicker.zh-CN/en 频道短标签。
inner_pages.collections[].accent 频道强调色。
inner_pages.collections[].map[].title.zh-CN/en 频道地图卡片标题。
inner_pages.collections[].map[].body.zh-CN/en 频道地图卡片内容。

collections 是把标签页做成“频道页”的关键配置。只靠时间线写博客，读者只能看最新；配置好频道后，旧文章才有机会继续被进入。

一份更贴近个人博客的配置顺序

真正落地时，不建议从头到尾填完。可以按这个顺序：

  1. 改 appearance，让站点先像你自己的。
  2. 改 i18n，确认中文、英文路径和 front matter 规则。
  3. 改 nav.items，只放长期栏目。
  4. 改 seo，补搜索引擎验证和默认分享图。
  5. 选一个评论系统，补 comments。
  6. 改 inner_pages.about，让关于页能承接合作和联系。
  7. 有 Newsletter 再配置 inner_pages.newsletter.form。
  8. 有广告合作再认真改 inner_pages.advertise。
  9. 最后再细调 labels 和 home。

Midnight 的配置量大，是因为它不是只服务“文章页皮肤”，而是试图把一个技术内容站的首页、频道、商业化和多语言一起放进主题里。别急着一次配完。先让写作和发布链路稳定，再让这些模块一点点长出来。
