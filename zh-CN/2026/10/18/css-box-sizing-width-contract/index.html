组件宽度验收：先约定内容边界还是边框外沿

用三百像素的两种计算口径，区分盒模型、内容溢出、异常状态与存量迁移。

正文

核心要点

  • 宽度参数必须明确内容或边框边界。
  • border-box 不包含外边距，也不解决所有内容溢出。
  • 迁移后重新验证真实文字和完整任务。

组件文档写“宽度三百像素”，必须先说明三百指内容区域还是边框外沿。box-sizing 决定内边距和边框是否计入声明宽度；如果设计稿验收的是外沿，组件却按内容宽度实现，就会出现 CSS 数字正确而实际占用超出的情况。先统一尺寸口径，再处理内容能否装下。

同一个三百像素，两种不同承诺

MDN 的 box-sizing 参考说明，content-box 的宽度针对内容，内边距与边框另加；border-box 将它们计入声明宽度，但仍不包含外边距。属性初始值是前者，实际元素却可能被浏览器样式、组件库或项目规则覆盖。因此排查应检查最终计算样式，不能只凭元素类型或某个全局样式文件猜测。

假设父容器可用宽度为三百像素，放入一个普通卡片，声明宽度百分之百，左右各十六像素内边距和一像素边框。先排除其他布局约束，做纸面计算：内容盒宽三百，左右合计再增加三十四，边框外沿就是三百三十四。若切换成边框盒，外沿保持三百，留给内容的是二百六十六。这里的计算没有在浏览器运行，也没有测量真实组件。

.panel {
  box-sizing: border-box;
  width: 100%;
  padding: 16px;
  border: 1px solid;
}

这段未经执行的示意样式表达了一个局部约定：宽度参数描述边框外沿。它适合设计给出外部占位尺寸的组件，但必须承认内部空间减少了三十四像素。若标题原本刚好一行，现在可能换成两行；固定高度的卡片也可能因此压到按钮。外沿回到容器里，只修复了一个测量条件，没有自动完成阅读与操作验收。

再比较一个要求固定内容绘制区域的图表包装器。若接口承诺内容区域三百像素，改成边框盒而不调整尺寸，就会改变图表实际可用空间。这里保留内容盒可能是合理选择，只是外部布局必须承担额外边距与边框占用。两种模型没有统一的胜负，应由组件接口回答尺寸参数保护的是哪条边界。

外沿正确，为什么页面仍然横向滚动

先确认溢出来自卡片自身还是卡片里的对象。假设卡片边框外沿确实为三百像素，但内部表格固定宽四百，或者一段订单编号不允许换行，那么减少卡片内容宽度不会让子对象自然变小。此时继续把父级百分比从一百改成九十五，只是在改变另一个条件，无法解释四百像素表格应如何展示。

外边距也仍在边框盒之外。假设卡片占满父容器，又给左右各加十二像素外边距，边框外沿三百并不表示布局总占用仍为三百。组件库若约定由使用方管理外部间距，应避免卡片内部偷偷附带两侧间距。若必须由组件携带间距，就需要调用方在布局中明确预留，不能拿盒模型开关掩盖接口冲突。

另一个反例是错误状态把边框从一像素变成三像素。在固定外沿下，内容空间会进一步缩小；同一段错误说明可能增加换行，提交区随之变化。若只比较默认状态的空卡片，会错过状态切换后的任务损失。把正常、错误、禁用和加载状态放在相同容器、相同真实文字下比较，才能知道变化来自样式还是测试内容。

改成 border-box 后，长编号仍溢出该查哪里？

先看编号所在节点的宽度、断行规则与父级布局约束，不要立即给整个页面加隐藏溢出。短编号正常而长编号失败，通常提示内容约束值得调查；但具体处理仍要看编号是否必须完整可见、能否断行、是否允许局部滚动以及复制行为。若业务要求用户核对完整编号，省略号可能隐藏关键差异，不能只凭无滚动条宣布成功。

对于 Flex 或 Grid 内的组件，还要继续检查相关的最小尺寸和轨道规则。边框盒只定义自身声明尺寸如何包含边框和内边距，不负责消除所有祖先与子代的尺寸约束。把超出区域的具体节点标出来，再逐项比较计算样式与需求，比全局缩窄所有卡片更容易得到可维护的修复。

展示策略应与交互一起选择。长文字允许换行时，需要重新检查高度与下方按钮；局部表格滚动时，需要用户能发现和操作滚动区；不可拆分图形若需要独立布局，应说明适用边界。本站十月十三日的放大与重排检查进一步讨论信息与功能保留，手机截图和边框测量都不能替代完整任务检查。

全局统一之前，先核对已有尺寸接口

新组件库可以采用统一边框盒约定，让设计外沿与代码参数更容易对应。已有系统则需要列出依赖内容尺寸的组件、嵌入部件和历史布局，再选择局部迁移或统一切换。局部修复范围较小，但要避免同名宽度参数在不同组件里含义相反；统一规则便于后续使用，却可能改变旧组件的内容空间。迁移记录应写明哪些接口改变，哪些调用方需要重新核对。

拟议验证可以对照两个除盒模型外完全相同的样本，记录父容器空间、边框外沿、内容宽度、外边距以及真正溢出的后代。再使用长标题、长编号、错误消息与放大状态完成同一条提交任务。尺寸数据应说明测的是哪条边，截图则保留任务结果；不要把视觉上没有横向滚动与用户能读完、点完混为一个结论。

本文保留原发布日期与地址，补充尺寸对照、内容反例和迁移边界，未执行浏览器测试。组件契约可以写成：“宽度描述边框外沿，外部间距由使用方负责；内容变长时按指定规则换行或局部滚动。”验收时先核对这句话，再核对边界内的真实任务。
