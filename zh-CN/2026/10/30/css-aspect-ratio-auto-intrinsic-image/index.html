CSS写了16:9，图片为什么又变回4:3？

解释auto与指定比例并存时自然比例的选择，限定纸面尺寸推演，比较固定框、自然高度和cover裁切、contain留白。

正文

核心要点

  • auto与比例并存时，有自然比例的替换元素采用自然比例。
  • 首选比例不凌驾于确定宽高和其他布局约束。
  • 固定展示框与内容适配需要分别决定和验收。

封面声明aspect-ratio:auto 16/9，图片自然比例却是4:3。尺寸信息可用后卡片变高，可能正是auto允许的选择，不是浏览器忽略了16:9。先决定要保留原图比例，还是要一个固定比例的展示框，再选择CSS声明；同一行里写了16/9，不代表所有状态都锁定为宽屏。

auto与比例同时出现，谁来决定？

CSS Box Sizing Level 4 的首选比例定义说明，auto和一个比例同时指定时，通常使用指定比例；如果对象是具有自然比例的替换元素，则使用其自然比例。它还说明，首选比例要影响首选尺寸，至少一个方向的尺寸需要是自动值。这里依据二〇二六年十月二十七日编辑草案分析，草案仍在发展，不是目标浏览器的实测回执。

因此，auto 16/9不是把两种比例平均，也不是先写的关键字永远获胜。它提供了一个条件分支：没有可用自然比例时采用所写比例，有自然比例的相应替换元素则走另一条路径。普通容器没有因为写aspect-ratio就变成图片，不能把图片分支不加限定地推广到所有盒子。

同时，它叫首选比例，而不是跨越全部布局约束的硬锁。宽和高都已经确定时，比例不能再替这两个首选尺寸作决定；最小值、最大值以及所在布局也需要一起核对。排查只盯住这一行CSS，却不看最终宽高与约束，可能把另一层的结果误认为比例失效。

用一张4:3图片推演两个阶段

假设封面原图的自然尺寸为四百乘三百，可用内容宽度为三百二十，图片高度为auto。为隔离机制，暂不设置额外内边距、边框、最小最大尺寸，也不引入Flex或Grid拉伸。以下是未执行的纸面示例，不是已加载某个资源的观察记录。

.cover {
  display: block;
  width: 100%;
  height: auto;
  aspect-ratio: auto 16 / 9;
}

在没有可用自然比例、且没有其他输入已经确定该比例的假设阶段，16:9为三百二十宽提供一百八十高的回退关系。当自然4:3比例可用且其他条件仍相同时，纸面关系变为三百二十乘二百四十。多出的六十不是本文测得的布局偏移，而是两个条件分支在这份简化输入下的尺寸差。

不要把边界机械写成“load事件触发后才切换”。资源的尺寸信息可能早于完整加载可用，页面也可能已经提供相关尺寸信息；应观察实际资源与布局状态，而不是用下载完成回调给所有图片规定同一时点。本文没有测量加载阶段，因此不报告这两个高度实际出现了多久。

再对照两种声明。只写16/9，使用的是指定的首选比例；只写auto，有自然比例的图片采用自然比例，没有时也不凭空产生16:9回退。若另有明确高度或更强尺寸约束，仍要回到完整布局判断，不能从这三个名字推导每个页面都恰好得到相同外框。

一个有用的失败样本是给原图换成竖图，而保持卡片其他内容不变。允许自然高度的方案会改变占位关系，固定展示框方案则需要处理图像如何装进去。验收应保留这两种不同的需求，而不是把“所有图最后一样高”预设成唯一正确结果。

卡片要等高，还是图片要完整？

如果页面是需要读完图表或文档缩略图的资料库，保留内容完整可能比封面统一更重要。可以允许自然高度，并围绕真实尺寸信息安排布局。若产品确实要求每张卡片封面都是16:9，则可以让独立容器承担固定比例，再明确内部图像的适配。两种选择对应不同的内容责任，不能只因固定框更整齐就替编辑作出裁切决定。

CSS Images Level 3 的object-fit定义区分图像内容如何适配元素的内容盒。contain保留自然比例并装入可用区域，可能留白；cover保留自然比例并覆盖区域，可能裁掉部分内容。这里引用二〇二六年十月八日编辑草案的定义，不宣称代码已经在某组浏览器验证。

假设四比三原图进入十六比九框，cover与contain都不是“把图直接拉扁”的同义词：它们保留比例，却对内容可见范围作出不同选择。人像边缘、图表刻度、图片中的文字，是否允许裁掉需要内容验收。调整object-position可以改变取景位置，但不能恢复被展示框排除在外的所有内容，也不替代原图编辑。

若选择让img本身形成指定外框，还要检查内容适配方式，避免把外框尺寸正确误记成图像没有失真。图片盒、被替换内容和卡片总高度是三个观察对象；标题换行或错误说明增加高度时，封面比例正确也不保证整张卡片等高。宽度口径还可结合内容边界与边框外沿分别核对。

怎样验证比例切换，而不是只截最后一帧？

拟议检查固定容器宽、原图尺寸、CSS宽高、auto是否存在及其他约束，分别记录自然信息可用前后的元素尺寸。再换横图、竖图和与声明一致的原图，检查结果是否能由条件解释。资源失败则另看替代内容和占位，不把无法取得自然信息的状态当作原图比例已经验证。

对于固定框方案，除了量外框，还要看内容边缘与关键信息。对于自然高度方案，则检查卡片后续按钮、阅读顺序与窄屏是否仍可完成任务。这里没有运行浏览器、加载实验或视觉回归，也没有CLS改善或搜索效果数据；这些检查应在目标页面取得真实证据后才记为通过。

去掉auto，就一定不会让图片变形吗？

不能这样推断。去掉auto改变的是首选比例分支，未单独规定图像内容如何装进元素盒。若盒子比例与原图不同，需要明确选择裁切、留白或产品允许的其他适配，并核对实际结果。也不能为了保持外框，把图表横纵坐标任意缩放后仍称其内容等价。

交付这张封面时，先写清楚三句话：哪一份信息决定元素比例，是否要求固定展示框，以及不一致的原图怎样保留内容。把auto视为一个有条件的选择，而不是一个无害的装饰词，才能解释图片为什么会在尺寸信息出现后变回自己的比例。
