CSS目录跳到标题，为什么标题藏在固定栏下面？

区分片段目标身份与可见位置，比较scroll-margin和scroll-padding的补偿归属，检查嵌套滚动、头部变化和焦点边界。

正文

核心要点

  • 片段匹配不代表目标完整可见。
  • 先找实际滚动容器，再选择补偿归属。
  • 滚动几何与键盘焦点分别验证。

点击目录里的“退款条件”后，地址栏已经出现正确片段，屏幕顶部却只看见第二行正文。标题到了滚动目标，仍被固定页头盖住。CSS 的scroll-margin可以参与目标滚动区域的计算，但要先找对目标、滚动容器和实际遮挡高度。

为什么网址正确，定位仍然不可读？

CSS Scroll Snap Module Level 1 的scroll-margin定义用外扩范围定义元素的滚动吸附区域。原文还说明，导航到片段目标或scrollIntoView目标时，用户代理应使用这个区域而不只是边框盒来确定带入视野的部分，即便元素没有开启吸附。这篇依据2026年9月8日编辑草案作机制分析，草案仍可能变化，不把它当浏览器实测结果。

因此，使用该属性不必先给文章加一套强制吸附效果。目录要解决的是定位时为页头让出空间，不是让每次滚动都停在标题。为了修复被遮挡的标题而顺手启用mandatory吸附，可能引入另一种滚动行为，超出了当前问题的范围。

普通margin和scroll-margin也不是同一份空间契约。前者参与布局间距，后者针对滚动目标区域。若只想让锚点定位时留出页头高度，给每个标题永久增加大块上边距会连自然阅读时的版式一起改掉。普通间距本身不是错误，关键是不要让布局补偿和定位补偿互相冒充。

一份政策目录怎样选补偿位置？

以下是未运行的示例：页面有一个假设高度为64像素的固定页头，正文包含“申请资格”“退款条件”“联系团队”三个带id的标题。目录链接指向相应片段。最小候选是在目标标题上设置滚动上边距，数值由页头实际高度加少量阅读留白组成：

:root { --header-height: 64px; }
.policy-heading {
  scroll-margin-top: calc(var(--header-height) + 1rem);
}

这里64像素只是示例配置，1rem是作者选择的留白，都不是规范推荐值。样式尚未在浏览器执行，不宣称复制后必然适合目标站点。落地时需要确认变量与真实页头一致，尤其是登录后多一行工具条、语言切换使标题换行、窄屏导航变高这些实际状态。

另一种做法是在滚动容器上使用scroll-padding-top，为该容器的最佳可视区域预留空间。前者从某类目标出发，适合只有正文标题需要特殊留白；后者从容器出发，适合容器内的多个滚动目标都受同一个固定区域影响。选择时要记录由谁拥有这份补偿，避免同一页头高度在多个样式层重复累加。

如果正文自己在一个可滚动面板里，根页面可能根本不是主要滚动对象。只在根元素设置补偿，不一定能修复面板内的标题；反过来，在面板上设置页头高度，也可能把不属于面板的全局遮挡算错。先观察实际哪个容器滚动、谁覆盖它的可视区，再决定属性放在哪一层，比不断调大数字更有效。

验收不止点击一次目录

拟议检查应包括直接打开带片段的网址、从页内目录点击、浏览器回退返回之前的位置，以及页面资源加载后布局改变的状态。每一步都记录目标标题边界、遮挡区域与当前滚动容器。地址栏片段匹配只能证明目标身份，不能证明标题完整可见。

窄屏与放大后还应重做。固定页头可能换行变高，如果变量仍保存桌面高度，补偿会不足。可以用项目已有的布局机制维护高度，或根据实际实现测量并更新；本文没有运行任何测量代码，不把某种自动观察方案当成已经验证。无论使用哪一种，验收都要覆盖高度变化后的结果，而不仅是变量曾被赋值。

靠近文档末尾的目标还会受到可滚动空间约束。页面已经接近底部时，不应期待任何留白都能把标题摆到指定像素位置。先判断标题是否可读以及是否仍被固定栏挡住，再决定是否确有必要调整末尾布局；不要为追求一张完全对齐的截图，无理由地给整篇文章追加巨大空白。

错误修复也要留反例。若目标id重复、链接指向错误元素，增加scroll-margin不会修复身份问题；若标题位于尚未展开的内容内，需要先确定内容如何显示，不能只调几何属性。定位故障应拆成找到了谁、滚动了哪里、最终看见什么三个问题，分别留证据。

标题露出来，键盘焦点就过去了吗？

不能用滚动后可见来证明焦点已经按任务需要移动。几何位置与当前焦点是两项不同状态，实际片段导航和组件脚本需要在目标环境分别检查。本文不对每一种浏览器组合声明统一焦点结果，也不建议为了移动焦点就把所有标题永久加入普通Tab顺序。

若目录还承担键盘快捷跳转任务，应记录激活前后的活动元素、后续Tab从哪里继续，以及读屏怎样识别目标。只有标题截图，没有这些状态，就只能报告可见性，不能报告完整键盘路径通过。这也避免把本篇的定位补偿误写成焦点遮挡准则的全面合规方案。

示例用top，是因为假设遮挡位于物理上方；不能未经判断就把它推广到所有书写模式。若设计按块轴安排导航，应再考虑scroll-margin-block-start及容器对应方向，但最终要匹配实际遮挡位置。逻辑属性的方向定义说明，书写方向与物理方向需要区分；垂直书写时块起点与物理顶部可能不是同一边。定位应同时记录书写模式、滚动轴和覆盖区域，避免只更换属性名却保留错误的空间假设。滚动祖先本身不清楚时，可先参照sticky与滚动祖先的排查。

交付时保留页头高度来源、目标选择器、滚动容器、补偿归属和各状态截图。让目录目标可读的修复应能解释空间为什么够用，而不是依赖一个在开发机上刚好合适的固定数字。
