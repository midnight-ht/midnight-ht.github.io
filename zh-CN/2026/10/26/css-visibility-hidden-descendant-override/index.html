父级 visibility:hidden，子按钮为什么仍然出现？

解释后代显式可见如何覆盖继承，比较透明合成与子树盒抑制，并拆分稳定占位和交互状态。

正文

核心要点

  • 后代可用自身 visible 覆盖继承的 hidden。
  • opacity 整组合成与 display 子树抑制属于不同机制。
  • 占位、绘制、交互和焦点需要分别定义。

审批卡片设成 visibility:hidden 后，边框和说明消失了，“继续审批”按钮却仍然出现，先检查按钮自己的可见性声明。visibility 是可继承属性，但后代可以显式采用 visible；父级隐藏并没有锁死整棵子树的绘制。要让整张组件退出，需要先说明是否保留占位、是否允许交互，再选择合适的状态实现。

父级隐藏，为什么子级还能恢复？

CSS Display Level 3 的 visibility 定义把它列为继承属性，并明确允许隐藏元素的后代在自己的 visibility 为 visible 时显示。hidden 让相关盒不可见，但仍参与布局；它与根本不生成盒子的状态不同。本文核对的页面是二〇二六年六月五日编辑草案，不把草案中的行为说明当成目标浏览器已完成的验收。

继承是缺少自身相应声明时取值的途径，不是祖先对后代绘制的不可撤销命令。父级最终值为 hidden，按钮最终值为 visible，两者可以同时成立。排查只截图父级计算样式，便会遗漏真正出现的那个节点；继续提高父级规则的选择器权重，也不等于对子级直接声明了隐藏。

这种机制可以用于刻意隐藏容器自身外观、保留部分后代的设计，但不能自动满足“整个审批区不可见”的需求。若按钮的可见性来自通用组件样式，页面开发者可能不知道它已覆盖继承值。组件库应交代本地 visible 声明的理由，否则调用方以为一个父级状态就能控制全部内容，实际却存在例外。

一张审批卡片怎样完整隐藏并恢复？

下面是未执行的假设示例。页面有一张审批摘要和“继续审批”按钮，切换记录时希望旧摘要暂时退出，更新完成后显示新记录。普通状态的卡片和按钮都可见；等待状态给父级增加隐藏类，但按钮样式仍明确要求可见。

<section class="review-card is-hidden">
  <h2>申请摘要</h2>
  <button class="review-action" type="button">继续审批</button>
</section>

.review-card.is-hidden { visibility: hidden; }
.review-action { visibility: visible; }

按上述规则推演，卡片中的未覆盖后代继承隐藏，按钮采用自己的 visible，因而可能留下一个脱离说明的动作。这是教学预期，没有在浏览器执行。修复前先问按钮是否应作为例外保留；如果答案是否，就去掉不必要的本地可见声明，或采用能表达整块退出的容器状态，而不是凭一个更大的层级值把它盖住。

继续走完这次假设任务：用户切换到另一份申请，旧动作退出；新摘要加载成功后，界面同时更新记录身份、摘要和动作目标，再恢复操作。若请求失败，应提供仍可到达的失败提示和重试入口，不能让唯一提示也留在隐藏卡片里。按钮重新出现，不证明它已经绑定新记录，恢复时还要核对对象归属。

一个反例是每次都给卡片全部后代追加更强的 hidden 规则。这可能压掉本来需要的局部提示，使以后新增子组件难以解释；再次显示时，又要逐个撤销。更可维护的起点是明确组件状态由哪一层负责，并减少无理由的后代可见性声明。若确实允许例外，把例外写进接口和验收，而不是让样式偶然决定。

换成 opacity 或 display，就等价了吗？

不等价。CSS Color Level 4 对 opacity 的说明把透明度描述为整组绘制后的合成操作：元素及后代先形成渲染结果，再按透明度与背景混合。父级为零时，给子级设一不能把它从这份透明合成结果中独立恢复。这与后代覆盖继承的 visibility 是两个机制；本文核对的是二〇二六年十月二十日编辑草案。

如果需求是连占位一起折叠，display:none 更贴近另一份合同：元素及后代不生成盒子，子级 visibility:visible 不能恢复被祖先抑制的盒生成。但切换会改变布局，还可能影响当前焦点和任务位置，需要重新检查。它不删除业务数据，也不阻止应用脚本继续运行；视觉退出不是后台工作的停止协议。

站内透明控件与交互状态解释了透明后仍可能可操作的问题。本篇的新增判断是，visibility 的父子计算值允许局部恢复，而 opacity 合成与 display 子树抑制各有不同范围。不能从“最后都看不见”推导它们可以在组件接口中随意替换。

想保留卡片高度，又不让子按钮恢复操作怎么办？

可以把稳定占位与实际内容拆成两层。外层负责布局空间，内层负责整块内容是否呈现；加载提示放在仍可访问的位置。若内层采用 display:none，外层需要根据真实响应布局安排占位，不宜把桌面高度写死后就当成所有文字与窄屏都合格。这个拆分是设计选项，不是标准强制结构。

如果内容只是暂不可交互，HTML 的 inert 子树规则提供另一种合同：在适用条件下使元素及其平坦树后代处于惰性状态，不负责给页面提供默认的视觉隐藏。它不能替代 display 或 visibility；还应有清楚的视觉状态，且重要恢复入口不能放进同一不可交互区域。本文只讨论普通卡片，不把存在模态对话框等例外的场景一并包进保证。

恢复时要撤销相应的不可交互状态，并把焦点安排在能理解当前记录的位置。若此前焦点就在即将隐藏的按钮上，应先设计去向，不能靠浏览器碰巧选择的落点作为产品合同。布局占位、可见性、交互和焦点分别有负责人，才能解释一次状态切换到底改变了什么。

还有语义关系的边界。CSS Display 草案提醒，隐藏具有特殊语义的父级、却显示有关联语义的后代，可能被浏览器或辅助技术错误处理；例如行隐藏而单元格显示，不能凭肉眼正常就认定关系可靠。不要用孤立可见的后代修补关键任务，再宣称读屏体验已经通过。

待执行验证从正常、等待、失败到恢复走完整条路线，记录父级与残留子级的最终计算值、占位变化、键盘后继目标和实际动作对象。再移除子级 visible 作对照，并检查窄屏、长文字与辅助技术关系。本文没有运行这些浏览器测试；先证明隐藏合同覆盖了哪个节点和哪种状态，再决定用哪一个样式开关。
