任务还没开始计数，为什么进度条不能先写零？

按 value 属性有无区分未知与零，将导入阶段、计数分母和最终结果分别表达。

正文

核心要点

  • 未知完成度应移除 value 属性。
  • 计数必须对应明确阶段与工作单位。
  • 阶段百分之百不替代业务终态。

任务完成度未知时，原生 progress 应省略 value 属性；写零表达的是已经知道进度、当前完成零，而不是尚不知道完成比例。资料导入还在扫描总量，就先显示零百分比，会把等待发现分母误写成停在起点。进度条应跟随真实可计量阶段，不能用一个默认数字替代任务状态。

未知与零，在原生元素里差在哪里？

HTML Living Standard 的 progress 定义说明，有无 value 属性决定不确定与确定进度。存在 value 时，数值表达已完成工作，max 表达总工作；max 缺失或无有效正值时，最大值按一处理。本文核对的是页面标注二〇二六年十月二十二日更新的标准，不据此承诺所有浏览器外观和辅助技术播报相同。

这意味着，把 value 赋零并不会切换到未知。若进度从已知阶段回到未知阶段，应该移除相应属性，而不是改成负数或无效文本，期待浏览器猜测业务含义。无效数值仍可能得到确定状态下的零；即使画面看起来像空条，语义也不是同一件事。

还有一个诊断陷阱：缺少 value 属性时，IDL 的 value 读值也可能是零，不能只按这个数字判断类型。标准提供的 position 在不确定状态返回负一；属性是否存在也值得直接记录。这里不是鼓励业务拿多个 DOM 值互相猜测，而是要求业务状态先决定语义，再用观察值检查输出是否符合它。

一次资料导入怎样让数字有依据？

下面是未执行的假设导入流程。用户选择一份文件，服务先检查格式并扫描行数，随后写入记录，最后核对导入结果。假定扫描完成后发现共五百条记录，这个数量仅供解释，不是性能或测试数据。扫描期间不知道总工作量，界面显示“正在读取资料结构”，进度元素省略 value。

拿到可用总量后，进入“写入记录”阶段，max 对应五百，value 对应已确认写入的条数。从零开始是合理的，因为这时分母已知。写入一百条后显示当前阶段完成一百条，而不是把已经发送到网络的条数当成已经持久保存。计数由哪里产生、失败回滚后怎样修正，必须按服务的确认语义定义。

写完五百条还可能需要检查重复或生成报告。这时可以转入单独的校验阶段，并说明正在做什么；若校验工作量未知，重新省略 value。不能把写入阶段一百百分比直接等同于整个任务成功。最终成功应来自业务终态，下载入口也应在结果实际准备好后出现。

一个失败反例是用定时器每秒加一点，涨到接近完成就停住等服务。它给人可测量进展的印象，数字却没有对应工作单位。如果产品确实要展示估计，应清楚标为估计并说明不确定性，不能把估计装成服务确认。本例更适合使用阶段文字与真实计数，不追求始终有百分比。

失败路径也要进入同一模型。写入被拒绝时，页面应离开运行中状态并说明可采取的下一步；不能让动画无限旋转，好像仍有工作在推进。取消只终止当前展示而服务仍运行时，更应说清取消了什么，避免用户以为所有后台工作已被撤回。

总行数在处理中增加，进度可以倒退吗？

如果总量的定义允许继续发现新工作，比例下降可能是数学上正确的结果，但读者需要知道分母变了。比如扫描和写入并行，前面只发现部分记录，后面又发现更多；早期百分比并不表示一个固定范围内的确定完成度。与其让数字忽上忽下却不解释，不如在范围未封闭前采用不确定进度，再对已确定批次显示完成条数。

这是工程选择，不是 HTML 禁止动态修改 max。真正需要约定的是工作范围：进度衡量本批、整个文件，还是包括后续校验。范围换了，阶段名称和说明也应换。不能把每个阶段都从零跑到一百，却给用户只有一个“总进度”的标题。

已经百分之百，为什么仍可能不能下载？

因为百分比只描述指定工作的完成比例，并不替结果文件作承诺。本例写入阶段完成以后，校验可能发现约束冲突，报告也可能生成失败。若把下载按钮在写入完成时就点亮，用户会得到一个不存在的结果，故障来自阶段合同，而非进度条样式。

应将运行阶段、已计量工作与最终结果引用分别保存和呈现。在相应阶段完成时说明“记录写入完成，正在校验”，最终失败则给出已确认范围及恢复办法；不要继续展示一个没有上下文的一百百分比。有关接收与终态的差异，可以对照HTTP 202 与任务完成。

待执行验证可准备扫描缓慢、可计数写入、校验失败和取消四条路径，逐步记录业务状态、value 属性是否存在、max、position 和可见阶段文本。还应故意让服务先发旧阶段消息，再发新阶段消息，确认界面不会被迟到计数拉回已结束阶段。这里的版本控制属于应用责任，不由原生元素提供。

无障碍验收还要让进度有可理解的名称，避免每个微小计数都制造打断，并在实际浏览器与辅助技术组合中观察。本文没有执行导入服务、页面或读屏测试。下一次检查先看扫描期的真实 DOM：只要业务还不知道完成比例，就不要让默认零替它回答。
