按钮点得中，还要检查目标尺寸与邻近间距

目标尺寸检查需要实际点击区域、邻近间距与例外依据；一次点中不能代替几何判断。

正文

点中一次不能代替 WCAG 目标尺寸检查。设计师拿鼠标点中了工具栏里的删除图标，只能说明这次操作成功；要判断目标尺寸，仍需知道真正接收指针动作的区域有多大、相邻目标靠得多近，以及是否符合具体例外。图标的视觉边界也未必就是可点击边界。

量的是目标，不只是图案

WCAG 2.2 的目标尺寸最低要求解释对应成功准则 2.5.8、AA 等级：指针目标通常至少为 24×24 CSS 像素，并列出间距、等效控件、行内、用户代理控制和必要性例外。它不是“每个图标都必须画成二十四像素”的视觉规范，也不是整个站点通过无障碍评估的证明。

假设一枚细小的关闭图案放在较大的按钮中，外围留白也能触发关闭。此时应检查按钮实际接受动作的区域。如果只是用外边距把图案推远，而空白部分不能点击，目标本身没有因此变大。这是设计推演，未执行浏览器测量；具体页面仍应核对实际命中区域与重叠关系。

圆角与异形目标也不能只看外接框的宽高。解释文档要求目标内部能够容纳一个与页面轴对齐的二十四像素正方形，才能直接走尺寸满足这条路径。评审记录若只写“宽高都够”，可能漏掉不能接受点击的角落。

间距例外不是固定加四像素

对于不足尺寸的目标，文档给出另一种几何判断：在目标边界框中心放置直径二十四个 CSS 像素的圆，它不能与其他目标或另一个不足尺寸目标的对应圆相交。判断对象包括上下邻居，不能只看一行图标之间的水平缝隙。

假设两个小图标之间留了可见空白，但其中一个靠在整张可点击卡片旁。围绕小目标的圆仍可能碰到卡片目标；只给两个图标之间加间距未必解决问题。反过来，某个较矮目标周围没有邻近目标，也可能符合间距例外。不能把局部例子中的缝隙数值抄成所有布局的统一规则。

这些条件说明为什么“我能点中”与“满足最低要求”需要分开记录。前者是一次观察，后者需要目标几何和适用条件。满足最低要求以后，重要操作是否仍容易误触，也值得通过目标用户的任务观察判断，最低门槛并不是使用舒适度承诺。

把例外写清楚，再讨论视觉密度

若援引行内链接例外，应说明目标确实位于句子中或受非目标文字行高约束，不能因工具栏有文字就一律当行内内容。若援引同页等效控件，应指出它在哪里、怎样完成相同功能。地图等必要性场景也需要解释为何这种布局对表达信息不可替代，而不是把紧凑当作理由。

交付时可以要求标明目标范围、相邻目标、采用的尺寸或例外路径，以及展开菜单等动态状态。扩大点击区时还要检查是否覆盖邻近动作，避免把留白变成争抢点击的重叠区域。本文没有实施完整合规检查；与放大后布局保留相关的另一个问题，可参看放大与重排。先把目标区域画出来，再决定扩大区域、增加距离还是采用有依据的例外。
