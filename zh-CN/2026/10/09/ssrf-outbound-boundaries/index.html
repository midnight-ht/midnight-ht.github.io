服务端抓取用户网址，为什么只校验域名还不够？

从 URL 解析、DNS 地址、实际连接、跳转与重试一路追踪 SSRF 的目的地边界，区分固定集成与任意外部抓取。

正文

核心要点

  • 固定集成与任意公网抓取是不同的产品安全模型，接口是否需要接受完整 URL 应先由需求决定。
  • 域名校验只有在解析结果与实际连接地址绑定、并覆盖 IPv4/IPv6、跳转和重试时，才约束到真正的网络目的地。
  • 受控验收要观察实际连接或出口拒绝证据；本文只提出测试计划，没有执行测试。

校验域名只判断了请求链路的一处；服务端真正需要授权的是每一次连接最后抵达的地址。安全的链接预览不能只问“输入是不是一个看起来合法的 URL”，还要问解析器读到了哪个主机、DNS 返回了什么地址、HTTP 客户端实际连到了哪里，以及跳转、重试和备用地址是否重新经过同一规则。本文给出防御设计和受控测试思路，没有访问真实目标、发送攻击请求或运行安全测试。

先确定产品到底要连接谁

服务端请求伪造（SSRF）的关键不是字符串里有网址，而是用户影响了一个比自己拥有更多网络权限的服务端请求。链接预览、远程头像下载、Webhook 回调、服务端渲染外部文档，都可能引入这条路径。服务器可能访问公司网络、管理端点或云平台提供的服务，而普通用户不能直接访问；一旦抓取器可以被任意控制，它就可能成为用户与这些网络之间的代理。OWASP 的 SSRF 防护指南把场景分成两类：目标是已知可信服务时可以用允许名单；目标是任意公网地址时，允许名单通常无法预先穷举，需要另一种边界设计。

假设产品只要生成合作方商品页的预览。此时不一定需要让用户粘贴完整 URL；可以让用户提交合作方 ID 或页面编号，由服务端从已配置的合作方地址中选定主机、协议和路径模板。这样用户提供的是业务对象，连接目标由服务端决定。相反，若产品本来就要支持用户提交任意外部页面，接受完整 URL 是需求的一部分，就不能假装一份短允许名单能覆盖目标范围。两种业务的风险模型不同，最好在接口设计时就分开，而不是先开放任意抓取，等规则不断打补丁。

URL 语法不是访问授权

URL 解析库能把输入拆成协议、authority、主机、端口、路径和查询参数，但“解析成功”只说明某个库能理解它，并不说明该目标符合业务授权。RFC 3986 的通用 URI 语法把 host 归纳为 IP literal、IPv4 地址或注册名称，同时强调 URI 语法本身并不意味着目标一定是可访问的互联网主机；具体操作由使用该 URI 的协议定义。RFC 3986定义的是通用组件语法，不是服务器出站访问控制策略。

当一个服务把 URL 字符串先交给校验库、再交给另一个 HTTP 客户端时，两个实现可能对边界、转义或 authority 的解释不同。OWASP 明确建议将解析器分歧视为拒绝条件，而不是试图用字符串替换把两个结果“协调”成一个。更可控的接口是只接受业务需要的主机或目标 ID，然后由服务端构造协议、端口和路径；如果必须接受 URL，则使用确定的解析实现，提取规范化后的组件，拒绝不符合支持语法的输入，并保证后续客户端不会换另一种解释。

即使主机名完全匹配允许名单，主机名也只是 DNS 查询的输入，不是连接目的地本身。若这个名称在校验时解析到公网地址，而连接时又进行一次新的 DNS 查询，第二次结果就可能不同。这就是 DNS 重绑定或检查与使用之间的竞态。OWASP 指出域名允许名单单独不足以防止 DNS 重绑定：应解析目的地址、检查结果是否符合应用允许的网络范围，并确保 HTTP 客户端实际连接到已检查的地址；不要在校验之后偷偷再做一次未验证的解析。OWASP 域名校验说明

一个连接决策至少要覆盖 IPv4 和 IPv6 的全部解析结果，并按部署网络定义可访问范围。固定合作方场景，应将解析出的地址与该服务允许的地址集合相交；任意公网抓取场景则需要阻止回环、私有、链路本地以及环境中不应触达的特殊内部资源，并在发起连接时继续使用经过判断的地址。只检查其中一个 A 记录、忽略 AAAA，或者只检查当前解析结果却让客户端自行再解析，都可能让策略和套接字分离。OWASP 还提醒，使用一个预先指定的连接 IP 时，要保留原始主机名用于 HTTP Host、TLS SNI 和证书校验；更改连接地址并不意味着可以把 TLS 身份验证关掉。具体客户端如何同时固定地址并保留主机身份，需要针对实际库确认。curl 的名称解析说明

跳转、重试和备用路径要重新过门

假设一个预览目标在第一次请求时通过了目的地检查，随后返回重定向。若 HTTP 客户端自动跟随跳转，第二次连接可能去到完全不同的主机或地址，初始检查就没有覆盖它。固定集成通常应关闭自动重定向；确实需要跳转时，每一跳都重新解析、验证协议和主机、检查解析地址，并为跳转次数、总时限和累计字节设上限。OWASP 建议在允许名单场景关闭客户端自动跟随重定向；OWASP 测试指南则把“每次跳转都重复检查目标地址”列为服务端抓取中的防护思路。OWASP DNS 重绑定测试指南

同一条规则也要覆盖重试、连接池、代理和故障转移。有些客户端在首个地址连接失败后会自动尝试同一 DNS 回答中的另一个地址；若应用只验证了一个地址，备用地址就可能绕开选择结果。重试时也不要把“之前允许过的 hostname”当作永远安全：根据设计，要么复用绑定到已经验证地址的连接，要么在重新解析时重新检查全部结果，且失败时采用拒绝而不是放行。若用了出站代理，应用到代理的连接和代理到目的地址两段都应明确责任边界；代理若自行解析或跟随跳转，应用侧的初始检查不能覆盖后半段。

网络出口是独立于 URL 校验的第二道边界。抓取工作者可以运行在与敏感服务隔离的网络中，防火墙或代理只开放业务需要的目的地或公共互联网路径。固定合作方可以把工作者仅连到批准的服务；任意公网抓取则可以让工作者无法访问内部网段，并对少数必须访问的内部服务保持默认拒绝。应用规则遗漏时，网络策略仍能限制影响范围。OWASP 将应用层校验与网络层防护作为纵深方案，并指出网络层目标是让工作者只能建立被允许的流量。OWASP 网络层说明

怎样测试连接边界，而不只测试 URL 解析？

受控测试应验证“允许目标能完成预览”和“目标不允许时连接没有发生”两类结果。对固定目标，可准备一个测试允许名称并在隔离环境中控制解析结果，确认客户端连接的是那一个已经审核过的地址，同时保留预期的 HTTP Host、SNI 和证书校验。再测试同一名称有多个 A/AAAA 结果时，只要其中一个地址不被允许，系统是否按设计拒绝整次请求，而不是悄悄换到未经批准的地址。

跳转测试要分别覆盖允许主机跳到另一个允许主机、跳转到禁止范围以及超过最大跳数；重试测试则验证连接错误后客户端不会使用未经重新检查的备用地址。解析竞态测试要让校验阶段与连接阶段观察到不同结果，并确认连接仍固定到已验证地址或请求被拒绝。还应测试不同组件对同一输入的解析不一致时系统会拒绝，而不是采用其中最宽松的解释。资源边界也要包括慢响应、过大响应、异常内容类型和并发积压；这类限制针对工作者资源与输出安全，不能替代目的地控制。

每个用例都要记录连接侧证据，例如测试代理看到的目标地址、出站防火墙拒绝记录或客户端实际连接回调，而不只保存 URL 解析后的对象。本文没有执行任何测试，所列内容是待在授权隔离环境中运行的验收计划，不是通过日志。产品层还应限制响应体大小与总时长，不把远端 HTML 当作可信应用代码执行，不向用户返回包含内部地址、连接信息或完整秘密查询参数的原始错误。

如果业务只依赖固定服务，最稳妥的变化可能不是增加更多黑名单，而是取消“用户指定网络目的地”这个接口能力。对于确实必须抓取任意外部目标的功能，需同时设计解析到连接的一致性、跳转和重试策略、网络隔离和资源预算。URL 目的地授权与请求用户能否读取某个业务对象是两类不同判断，后者可参看对象级访问控制；验证了其中一类，不代表另一类自动成立。
