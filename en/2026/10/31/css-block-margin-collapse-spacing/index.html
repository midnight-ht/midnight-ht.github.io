CSS margins: why do two twenty-four-pixel margins not add up to forty-eight?

Explain adjoining positive and negative margins, distinguish parent-child and sibling boundaries, and choose spacing ownership.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-31 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Eligible vertical margins can collapse rather than add.
  • Flow-root separates parent-child boundaries, not all internal siblings.
  • Spacing changes also need sizing and clipping checks.

Two adjoining twenty-four-pixel margins on ordinary blocks need not add up to forty-eight. Vertical margins can collapse under specific conditions. Establish the layout and adjoining relationships before choosing which object owns the spacing; increasing margin repeatedly does not explain the boundary being changed.

Adjoining is a layout relationship

CSS 2.2 margin collapsing defines the conditions and calculation. This discussion uses ordinary block flow in a common horizontal writing mode. Do not extend it directly to horizontal margins or Flex and Grid items.

For adjoining positive margins, the collapsed size is the larger value. Twenty-four and twenty-four yield twenty-four, as do twenty-four and sixteen. With negative margins, the calculation considers the largest positive value and largest absolute negative value; merely choosing the numerically larger declaration is insufficient.

Both declarations can remain active in developer tools while the visible distance reflects one collapsed result. A lack of crossed-out declarations does not rule out collapsing.

Separate sibling and parent-child observations

This complete static sample is unexecuted. Save it as HTML and modify one condition at a time; initially avoid a global reset that would obscure the participating rules.

<!doctype html>
<html lang="en">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>Margin collapsing sample</title>
<style>
  body { margin: 0; }
  .panel { margin-top: 40px; background: #eee; }
  h1 { margin: 24px 0; }
  p { margin: 24px 0; }
</style>
<div class="panel">
  <h1>Demonstration card</h1>
  <p id="first">First ordinary block paragraph.</p>
  <p id="second">Second ordinary block paragraph.</p>
</div>
</html>

Under these ordinary-flow conditions, the adjoining paragraph margins are expected to produce a twenty-four-pixel gap. Changing only the second paragraph's top margin to negative eight gives a predicted sixteen for that pair. These are paper calculations, not measurements of an existing page with additional constraints.

Parent-child collapsing is a separate observation. The panel has no top padding or border, and the heading is its first in-flow block. Their top margins can collapse. Inspect where the panel's edge and background actually begin instead of assuming the heading's margin always creates interior gray space.

If the card needs fixed internal space, use an explicit padding policy and review the heading margin. If the distance belongs outside the card, assign it to external spacing. Matching screenshots do not make those component contracts equivalent.

What does flow-root isolate?

CSS Display Level 3 flow-root establishes a new block formatting context. It can separate the sample's parent-child margin relationship without eliminating collapsing between ordinary siblings inside the new context.

A twenty-four-pixel paragraph gap after adding flow-root to the panel does not prove the property failed. Measure panel-to-heading and paragraph-to-paragraph relationships separately. One changed boundary need not change the other.

Switching the container to Flex or Grid is a layout change with effects on sizing, alignment and arrangement. Obtaining forty-eight pixels does not make that change cost-free. Decide whether a different layout and gap policy suit the content before adopting them as a spacing repair.

Why not add overflow hidden everywhere?

Some overflow settings establish a relevant formatting context, but they also have clipping and scrolling effects. A spacing change can cut off a dropdown, long content or focus outline. If the purpose is formatting-context separation, consider a more explicit choice and inspect the content effects.

Clipping can be valid when the product requires it. The problem is an undocumented universal repair. Sticky positioning and scroll ancestors describes another relationship affected by overflow, which may need checking after a change.

Padding and borders also alter parent-child adjoining conditions. Adding an invisible border simply to block collapsing still changes the size contract. Give the space a documented purpose rather than leaving the next maintainer to reverse-engineer a hidden barrier.

Why do empty blocks and negative margins complicate diagnosis?

An eligible empty block can allow margins to collapse through it, so the group may include more than the two edges you first noticed. Several negative margins are not simply added together before subtraction. List the participating group and apply the relationships before calculating.

A useful proposed diagnostic starts with two nonempty paragraphs and then restores headings, empty placeholders, error text and wrappers one at a time. Record the relationship that changes. This is a method suggestion, not a completed investigation or a measured browser result.

Proposed acceptance compares declarations with edge coordinates for siblings, parents and children, negative margins, empty blocks and flow-root. Real cards also need long titles and error states checked for clipping. Horizontal margins do not collapse under these rules; logical properties and different writing modes need their own axis review.

A handoff can assign internal padding to the container, paragraph spacing to the chosen flow policy and external margins to the caller. The next developer can then identify who owns the intended forty-eight pixels instead of repeatedly adding another twenty-four.
