WCAG Meaningful Sequence: why do clear columns become interleaved instructions?

Use two procedures to examine prose reading order, permissible block ordering and responsive and continuous-reading checks.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-31 · Estimated read 14 min
Translations
zh-CN en

Article

Key takeaways

  • Meaningful content order must be programmatically determinable.
  • Separate blocks may move while dependent steps remain intact.
  • A Tab route does not establish ordinary prose reading order.

The left column explains a first application and the right explains renewal, with three steps in each. If the source contains both first steps followed by both second steps, linear reading can merge two procedures into one. Preserve each procedure's relationships before choosing columns. A correct Tab route does not establish the order of ordinary prose.

Which relationships affect meaning?

WCAG 2.2 SC 1.3.2 is a Level A requirement: where presentation order affects meaning, a correct reading sequence must be programmatically determinable. Conditions and steps can have dependencies even when they contain no interactive controls.

The Understanding document allows more than one correct order. Independent articles may exchange positions without changing their meaning, but their contents should not be interleaved. This is not a universal mandate to reproduce every visual coordinate in one sequence. Explain which relationships matter.

“Obtain an eligibility number, then complete the application” belongs to one procedure. “Check your existing record, then supply updated evidence” belongs to another. Reading the four actions alternately can suggest one combined procedure. The failure is the loss of content boundaries, not the spacing between columns.

Keep each procedure as a complete block

This complete static example is unexecuted; its procedures are fictional. Save it as an HTML file to create a sample for validation.

<!doctype html>
<html lang="en">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>Application and renewal instructions</title>
<style>
  main { display: grid; grid-template-columns: repeat(2, minmax(0, 1fr)); gap: 2rem; }
  @media (max-width: 40rem) { main { grid-template-columns: 1fr; } }
</style>
<h1>Choose your task</h1>
<main>
  <section aria-labelledby="first">
    <h2 id="first">First application</h2>
    <p>For applicants without an eligibility number.</p>
    <ol><li>Obtain a number.</li>
      <li>Complete the application.</li>
      <li>Review and submit.</li></ol>
  </section>
  <section aria-labelledby="renew">
    <h2 id="renew">Renewal</h2>
    <p>For applicants with a valid existing record.</p>
    <ol><li>Check the existing record.</li>
      <li>Add updated evidence.</li>
      <li>Confirm renewal.</li></ol>
  </section>
</main>
</html>

The source contains the complete first application followed by renewal. Grid arranges the blocks. If a design puts renewal on the left, reconsider the structure and visual arrangement together. The two independent procedures may change places; their own conditions and steps still need to remain intact.

A counterexample places both headings first, then both conditions and alternating steps, using grid coordinates to reconstruct the columns visually. A desktop screenshot may look correct while continuous reading interleaves the procedures. Adding tabindex to every paragraph does not rewrite that reading order and creates unnecessary keyboard stops.

Tables can express genuine row and column relationships; ordered lists can express steps. Choosing a table merely because it places text side by side confuses layout with content semantics. Determine the relationship before selecting markup.

Reading and focus require different evidence

Continuous reading may include headings, conditions, explanatory paragraphs and links. Tab generally traverses focusable controls. If each procedure ends with a link, visiting those two links in a reasonable order says nothing about how the preceding six steps are read.

Focus order and task relationships considers operational relationships between controls. This article includes text that never receives Tab focus. Write separate checks for reading a procedure's conditions and steps and for reaching its action link. “Order is correct” is too vague to identify the evidence.

Responsive changes are useful inputs. A narrow single column can expose interleaving previously hidden by spatial layout. Disabling layout styles can reveal source-order concerns, but it does not establish compatibility with every assistive technology. Generated content, component semantics and actual reading behavior still require target-environment checks.

Dynamic additions also need ownership. A new warning applicable only to renewal should be attached to that procedure's content relationships. Positioning it visually near the right column while leaving its subject ambiguous in the source is insufficient. After editing, read the whole procedure again.

Is a sidebar before the main article always a failure?

No. Independent navigation, notes or articles may permit several sensible orders. The criterion concerns meaning and a determinable correct sequence. A template that outputs a sidebar first is not automatically defective, but an independent sidebar should not interrupt an unfinished sentence or split a dependent explanation.

A note explaining where to find a number may be understandable before or after the instructions if the reference is clear. “Stop here if you do not have a number” changes the next action and needs a more explicit relationship to the relevant step. This requires content judgment, not a rule based solely on element names.

Proposed acceptance starts by reading the source sequence and restating who each procedure applies to and what happens first and last. Then examine continuous reading at wide and narrow layouts and with target browser and screen-reader combinations. Record the actual sequence and any interleaving. None of these checks was executed here.

A CMS drag operation also needs review against exported content. It may change only visual positions, or it may move a complete section with its steps. Have an editor read the exported sequence without relying on columns, then separately run assistive-technology checks. Define the movable unit as a complete content block so that a later edit cannot move a heading while leaving its conditions behind.

Where more than one order preserves meaning, document the blocks that may move and dependencies that must stay together. Designers can then adjust columns without guessing which relationships an editor intended. The deliverable is an explainable content structure, not just a desktop image that conceals the problem.
