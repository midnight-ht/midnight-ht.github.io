WCAG Multiple Ways: does a site with navigation also need search?

Distinguish multiple ways of finding pages from mandatory search, then review guide coverage, maintenance and process exceptions.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-31 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Define the page set and target before counting methods.
  • Check that locating methods reach the same applicable content.
  • Search is an option; process steps and results have an explicit exception.

A navigation menu can list every category while leaving a new visitor unsure where a document belongs. WCAG Multiple Ways concerns how the same page can be found; it does not prescribe search for every site. Start with the content people need to reach and the available routes, then choose a directory, task index or search service.

Define the page people must find

WCAG 2.2 SC 2.4.5 is a Level AA requirement concerning pages within a set. It includes an exception for pages that result from, or form a step in, a process. This is different from bypassing repeated navigation on one page or adding a shortcut for every control. Identify the page set and its target pages before reviewing methods of finding them.

The Understanding document explains possible approaches, including link structures, directories and search, and discusses small sites. It is informative guidance, not a mandate to adopt one illustrated component. The engineering judgment here is to establish useful methods of locating the same content before deciding whether to maintain a search system.

Imagine a public document library organized into admission, accommodation and financial support. Someone looking for household income evidence may not know which category owns it. Having the category in a menu does not resolve that uncertainty. Include people who know their task but do not know the organization's taxonomy.

Describe two complete routes to one guide

This is an unexecuted design example. The fictional target is “Income documents for financial support,” at /guides/income-documents/. One method follows the topic directory: home, financial support, required documents, then the guide. Another follows a task index: home, apply for support, prepare income evidence, then the same guide.

The destination matters. If the task index opens an obsolete PDF while the directory reaches the current page, similar titles do not establish coverage of the same target. Record the target identity, labels along each route and content version. Where historical versions remain available, explain which one applies.

A small maintenance table can list each relevant guide, its directory location, its other locating method, destination and latest change. This table is a proposed maintenance technique, not an additional WCAG requirement. A missing second route for a new guide becomes visible before publication.

There is a cost: task labels need language readers recognize, rather than copied department names, and renaming a guide requires checking its index entries. A directory exposes a content hierarchy; a task index starts from an activity. Their different organizing cues give reviewers something more meaningful to assess than two copies of one menu.

Two menu locations alone do not prove two methods. Nor should the fact that both use links automatically disqualify them. Assess the locating mechanisms and their coverage of the actual page set. Component counts are observations, not the conclusion.

When is search a sensible choice?

Search can help when the library is large, visitors know concrete words and the classification is unfamiliar. It still needs a reachable entry point, useful results, clear titles and maintenance. A search component that reads an obsolete database does not establish that a newly published guide can be found.

For the fictional library, try phrases such as “income evidence” and “household documents.” Derive the eventual test vocabulary from research or label it as a design assumption. Check recovery from no results: can people revise the query, browse an index or reach relevant help? A permanent empty result merely changes the form of the original problem.

A small site may support appropriate methods through clear link structures and an index. Content scale, update ownership and users should determine whether an external search service is justified. This criterion provides no budget, speed or traffic guarantee, and no such outcomes were measured here.

If using a site map, provide an organization people can understand and operate. An XML file intended for crawlers does not alone establish a usable human locating route. Human and machine representations may share source data while requiring different acceptance evidence.

Must application confirmation pages appear in public search?

Process steps and results have an explicit exception. Do not expose private confirmation pages merely to make an “every page has two routes” checklist pass. The exception also does not define access control or the product's recovery experience.

Suppose a confirmation page contains personal document records. Its owner can reach it after submission, while anonymous visitors cannot discover it through public search. Record its process role, access scope and authorized return path separately. An authenticated task list may support returning users, but that decision needs the complete workflow requirements.

Search results can themselves be the result of a process. Requiring a separate public route to every possible result set misreads the scope. Conversely, an ordinary public guide does not become exempt merely because an application flow links to it; examine what the page actually is.

Proposed acceptance covers a new guide, a renamed guide and an access change. Follow the locating methods, record final addresses and applicable content, then observe people unfamiliar with the categories doing the same task. No browser or user study was run. Consistent identification of repeated functions addresses recognizable names; this article addresses whether the methods help readers find the target. Establish that before counting components.
