Two CSV records, three text lines: which count is wrong?

Round-trip a multiline CSV field while separating text newline translation, quoted-record syntax and physical line numbering.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-31 · Estimated read 15 min
Translations
zh-CN en

Article

Key takeaways

  • A quoted CSV field can span physical lines.
  • newline='' delegates newline handling rather than deleting field content.
  • Round-trip preservation, malformed-input rejection and downstream interpretation differ.

A quoted CSV field can contain a newline, so physical line counts and record counts differ. Do not split the text into supposedly independent records before asking a CSV parser to recover the boundaries. When using Python's csv module with files, open them with newline='' so that CSV handles newlines, and check field content separately from record counts.

Which layer handles which newline?

The Python csv reference specifies this file-opening convention and explains issues involving embedded newlines and additional carriage returns. The page checked on October 31, 2026 identified itself as Python 3.14.10. No program or Windows-versus-other-platform compatibility test was run.

The text-file layer decodes bytes and may translate line endings according to its newline setting. The CSV layer also tracks quoting, delimiters, escaping and record termination. Inside a quoted field, a newline can be content. In another syntactic position, it can end a record. Letting both layers transform it without a clear contract can alter content or line endings twice.

newline='' does not forbid newlines or replace every newline with an empty string. It configures text I/O so that the CSV parser handles line endings. Deleting newlines after reading would instead damage multiline notes. Cleaner-looking output is not evidence of unchanged input.

Consider a customer note containing “No one at the door” followed by a newline and “Please call.” Both lines belong to one record. A line-oriented import might treat the second as a new customer missing an identifier. Joining it back carelessly can also alter meaningful whitespace. The parser tracking CSV quote state should determine the record boundary.

Round-trip a multiline field

This complete, unexecuted standard-library program creates its own temporary input, writes two illustrative records and checks the restored structure. It has no dependency on an existing file, database or external service.

import csv
from pathlib import Path
from tempfile import TemporaryDirectory


def main():
    original = [
        ['101', 'Lin, Mei', 'first line\nsecond line'],
        ['102', 'He said "hello"', 'single line'],
    ]
    with TemporaryDirectory() as directory:
        path = Path(directory) / 'customers.csv'
        with path.open('w', encoding='utf-8', newline='') as output:
            writer = csv.writer(output)
            writer.writerow(['id', 'name', 'note'])
            writer.writerows(original)

        with path.open('r', encoding='utf-8', newline='') as source:
            reader = csv.reader(source, strict=True)
            header = next(reader)
            restored = []
            for record_number, row in enumerate(reader, start=1):
                if len(row) != len(header):
                    raise ValueError(f'wrong field count: record {record_number}')
                restored.append(row)
                print('record:', record_number, 'physical line:', reader.line_num)

        if restored != original:
            raise RuntimeError('CSV round trip changed fields')
        print('records:', len(restored))


if __name__ == '__main__':
    main()

The writer chooses quoting and the reader uses the matching default dialect. The first note should retain its embedded newline, its name should retain the comma without creating another column, and the second name should retain its quotation marks. Comparing complete nested lists tests more than the absence of an exception. The temporary directory is cleaned on exit, so any subsequent handoff must occur within its lifetime or use a separately retained artifact.

strict=True makes certain format errors explicit; it is not complete business validation. Having three fields does not establish a valid identifier, correct tenant ownership or an acceptable note length. The field-count check only enforces this teaching schema. Real imports must also decide how to handle blank fields, blank records, missing headers and duplicate column names.

Is reader.line_num a record number?

It counts physical lines read from the source iterator, not returned records. One multiline field can require several physical lines. The example therefore maintains a record number with enumerate and reports reader.line_num separately.

An error report can identify the record and its ending physical line, preserving a start/end range where helpful. Specify whether record numbering includes the header. Otherwise, a spreadsheet row number, an editor line number and a parser record number may point to different content despite displaying the same integer. Avoid copying sensitive notes into diagnostics; use controlled identifiers and only the required fragments.

This is also why splitting the original text and parsing each piece independently is unsuitable. Once line endings are removed, the parser cannot infer which ones were field content. A simple file may happen to work while another valid file with quoted newlines breaks the assumption. A deliberately restricted line protocol should state its restrictions rather than claiming general CSV support.

Should extra blank lines be fixed by filtering empty strings?

Locate the layer that introduced or translated line endings first. On some platforms, text I/O can process a line ending already produced by the writer and introduce an additional carriage return. Configuring the file boundary according to the reference addresses the cause more directly than postprocessing.

Filtering may also remove meaningful blank records or alter fields where whitespace matters. Successful import after deletion does not prove preservation. Check encoding, dialect and record grammar separately: newline configuration cannot repair an incorrect encoding, and a comma delimiter does not establish every supplier's quoting rules.

Build source-specific samples containing delimiters, quotes, embedded newlines, empty fields and incomplete quotes. Check acceptance and actual fields for each. An inferred format from the first few lines is not an unconditional promise about the whole file.

The existing discussion of text decoding across network chunks addresses an earlier boundary. Even after bytes become characters correctly, CSV syntax must determine whether a newline terminates a record. Repairing one layer does not validate the next.

Use two samples that differ only in a note: one contains an actual newline, the other a visible backslash followed by a letter. Logs may escape them in confusingly similar ways, while bytes and parsed fields differ. Compare retained content rather than treating its printed representation as the data itself.

Check record identity alongside counts. Incorrectly splitting a name at its comma can still leave the expected number of records. Find each result by stable identifier and compare its name and note rather than relying only on ordering. For rejected files, retain the reason and enough location information, and verify that failure was not hidden by silently rewriting the input.

Spreadsheet delivery additionally needs a policy for formula interpretation and other application behavior. A successful CSV round trip tests this program's structure and content, not another application's interpretation of cells. No round-trip, malformed-file or cross-platform tests were executed here. Preserve input bytes, parsed records and expected fields rather than using a matching text-line count as the acceptance criterion.
