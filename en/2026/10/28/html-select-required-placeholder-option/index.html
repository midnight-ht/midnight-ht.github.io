Does “Choose a region” already count as an answer?

Check option values, ancestry, display size, placeholder obligations, and the receiver's allowed region set.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-28 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Placeholder wording does not determine native semantics.
  • The placeholder definition differs from the obligation to provide one.
  • Evaluate multiple and size through the actual display size.

The first option says “Choose a region” but lacks an empty value. Submission may already treat it as a real answer. Placeholder wording does not determine HTML placeholder semantics. Inspect the option value, list position, ancestry, and display size before distinguishing an unanswered field from a business choice.

Which option is a native placeholder label?

The HTML select definition defines a placeholder label option through specific conditions: required is present, display size is one, the first option in the option list has an empty value, and no optgroup intervenes between that option and the select. Wording alone does not establish those conditions. The inspected page's October 26, 2026 date is a document update rather than a browser release.

A separate authoring requirement says that a required select without multiple and with display size one must have a placeholder label option. Distinguish its definition from the obligation to provide it. The definition itself does not exclude multiple; the separate obligation does. Omitting that difference creates mistakes with unusual multiple-select display sizes.

For required validation, the select is missing if nothing is selected or its only selected option is the placeholder label option. This is not a universal rule rejecting every selected empty value. Position, placeholder identity, and other selected options matter. A business prohibition on all empty values requires its own receiver contract.

How can a region field retain an unanswered state?

Consider an unexecuted delivery form that requires a region and permits “Other region” to enter manual confirmation. Keep an empty placeholder and give real choices explicit identifiers. Other is a real answer, distinct from no answer.

<label for="region">Delivery region</label>
<select id="region" name="region" required>
  <option value="">Choose a delivery region</option>
  <option value="north">North</option>
  <option value="other">Other region</option>
</select>

Leaving this placeholder selected exposes missing input; choosing other records an answer requiring the defined follow-up. These identifiers are hypothetical. The receiver must still validate the currently permitted region set rather than accept every nonempty string.

If the placeholder omits value, its text can become its value. A nonempty-only server check may then accept “Choose a delivery region.” Selecting North by default merely to remove the error instead answers for the user. A legitimate default needs a business basis, not a desire for green validation.

Which similar-looking changes affect the rule?

Moving the first empty option into an optgroup can preserve its appearance while violating the ancestry condition. Moving it later changes its first-option status. Inspect rendered option-list order and ancestry, not merely a component configuration property called placeholder.

Display size matters too. A dropdown and a multirow list need different assessment even though both are selects. Read size, multiple, and selectedness. Framework property names and operating-system menu styling do not replace the specification's conditions. Replacing asynchronously loaded options can also change which item is first.

A proposed matrix submits the unchanged placeholder, then North and Other, recording individual validity flags, payload, and resulting route. Move the empty option into an optgroup, change size, and remove all selection. The checks should distinguish structural conditions rather than classify every empty value identically. No browser tests were executed here.

Handle obsolete choices separately. A region available when a draft was saved may no longer be served when restored. Do not silently select another region. Showing the obsolete answer and requesting confirmation is one possible business policy. Required does not determine whether a delivery region remains available; retain the allowed set and displayed answer in the verification record.

Is selecting an empty value in a multiple select always missing?

No. Without an effective size, a multiple select defaults to display size four; a non-multiple select defaults to one. A typical multiple list therefore does not meet the placeholder definition's display-size condition. Explicit multiple size one requires reassessment against required, first empty option, and optgroup ancestry. “Multiple selects never have placeholders” is too broad.

Also distinguish the placeholder as the only selection from a selection that includes actual choices. The required rule's “only selected option” condition matters. If the business needs at least one valid region, validate real values against the permitted set instead of equating one native validity flag with complete acceptance.

The related disabled-control article addresses participation in submission, while this article addresses missing-value semantics. Restoration, disabling, and reenabling can affect both. Preserve a real unanswered state, then make native feedback and receiver decisions explain the same answer.

Also distinguish the selected content attribute, which supplies default selection, from current selectedness after user or script changes. Record initial load, user changes, reset, and draft restoration separately. A source-level selected attribute alone does not establish the current answer.

For example, choose Other and then reset: inspect the resulting default selection and missing state. Restore a saved draft separately and record that operation's selected options. Identical displayed words do not establish identical transitions; inspect the current answer before submission.
