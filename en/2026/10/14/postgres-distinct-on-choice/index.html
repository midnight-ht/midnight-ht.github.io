Define the representative row before using DISTINCT ON

Define representative-row precedence and validate ties and late arrivals before deduplication.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-14 · Estimated read 5 min
Translations
zh-CN en

Article

Choose what a representative row means before selecting one per group. PostgreSQL DISTINCT ON retains a first row, but without suitable ordering that row does not inherently mean newest, largest, or approved. Quantity reduction and business precedence are separate decisions.

Ordering defines the first row

The PostgreSQL 18 SELECT reference says selection is unpredictable without ORDER BY establishing the desired precedence. DISTINCT ON expressions must match the leftmost ordering expressions. The database does not infer a product’s meaning of current state.

Imagine several reports per device and a latest-report view. Deduplication alone does not decide whether device time, reception time, or approval time matters. Equal timestamps also need a rule. A stable identifier can make selection deterministic without making it the right business choice. If approval matters, encode that requirement first. No report query was executed here.

A representative is not a group aggregate

A requirement for totals, averages, or all anomalous reports may not suit one-row selection. A selected row’s amount or status cannot stand for the whole group simply because one row is convenient.

Keep associated fields from the same selected record. Independently combining a maximum timestamp with other values can create an apparent report that never existed. This is a review concern, not a tested query implementation.

Cover ties and late arrivals

Proposed examples include different times, tied times with different states, and late-arriving older reports. Define the expected selection before evaluating results. A group containing only one row cannot reveal a missing precedence rule, and incidental storage order is not evidence.

Retain the selected record identity so the displayed result can be traced to its source. A timestamp and summary alone make selection errors harder to investigate; a display position is not source identity.

Concurrent writes can change which row is latest; explain the observation conditions. If results are paginated, the separate ordering contract still matters. See pagination and ordering boundaries. Choosing within groups and paging between groups answer different questions.
