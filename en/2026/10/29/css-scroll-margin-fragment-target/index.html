CSS fragment links: why does the heading hide behind the header?

Compare target scroll margins and container scroll padding, then check nested scrolling, changing header height, target identity, and focus separately.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-29 · Estimated read 11 min
Translations
zh-CN en

Article

Key takeaways

  • A matching fragment does not establish target visibility.
  • Identify the container before choosing an offset owner.
  • Verify scrolling geometry separately from focus.

A contents link opens the correct “Refund conditions” fragment, but the screen begins with its second paragraph. The heading reached its scroll target and is still covered by the fixed header. CSS scroll-margin can contribute to the target area used for scrolling, once the target, scrolling container, and obstruction height are identified.

A correct URL does not establish a readable destination

The scroll-margin definition in CSS Scroll Snap Module Level 1 defines outsets for an element’s scroll snap area. It also says fragment and scrollIntoView targets should use this area rather than only the border box when determining what to bring into view, even when snapping is not enabled. This analysis uses the 8 September 2026 Editor’s Draft, a work in progress, and reports no browser testing.

There is no need to add mandatory snapping merely to compensate for a header. That would introduce a different scrolling behavior. Likewise, ordinary margin and scroll-margin have different jobs: layout spacing versus a target’s scrolling area. Large permanent margins can change ordinary reading layout when the requirement concerns only navigation positioning. Existing layout spacing may be appropriate; do not confuse its purpose with scrolling compensation.

Choose whether the target or container owns the space

Consider an unexecuted policy-page example: a fixed header with a hypothetical height of 64 pixels and three identified headings for eligibility, refunds, and contact. A candidate target-level rule is:

:root { --header-height: 64px; }
.policy-heading {
  scroll-margin-top: calc(var(--header-height) + 1rem);
}

The header height is an example configuration and the additional rem is an editorial spacing choice, not a standard recommendation. The rule has not been run in a browser. Establish that the variable reflects the real header, including signed-in toolbars, translated text, and narrow layouts that introduce another line.

An alternative is scroll-padding-top on the scrolling container, reserving space in its optimal viewing region. Target-level compensation suits selected destinations such as article headings. Container-level compensation suits many targets affected by the same fixed obstruction. Assign ownership so the same header height is not accidentally counted in several style layers.

A separately scrolling article panel changes the diagnosis. The root page might not be the relevant scrolling container. Setting a root offset may fail to address panel targets, while applying a global-header assumption inside the panel can misrepresent its own viewing region. Observe which container scrolls and what actually covers it before increasing the number.

Test more than a single contents click

Proposed verification includes opening a fragment URL directly, activating a contents link, using browser Back, and observing layout after resources load. Record the target bounds, covering region, and container for each path. A matching fragment establishes target identity, not full visibility.

Repeat on narrow screens and with enlargement. If the header wraps but the variable retains its desktop height, the offset may be insufficient. Use the project’s actual layout or measurement mechanism and verify the changed state; no measurement code was executed for this article.

Near the document end, available scrolling space also constrains positioning. Do not expect any offset to place every target at an exact pixel. First ask whether the heading is readable and unobscured before appending large blank regions to reproduce a particular screenshot.

Retain counterexamples. A duplicate id or a link to the wrong element is an identity problem that scroll-margin cannot repair. A target inside collapsed content introduces a disclosure question before geometry. Separate “which element was found,” “which container scrolled,” and “what became visible.”

Does a visible heading also receive keyboard focus?

Visibility after scrolling does not prove focus moved as the task requires. Geometry and active focus are different states. Inspect fragment navigation and any component scripts in the target environment rather than claiming a universal result across browsers. Do not put every heading permanently into the ordinary Tab order merely to address scrolling.

If the contents serves keyboard navigation, record the active element before and after activation, where the next Tab goes, and how the destination is identified by the screen reader. A heading screenshot alone supports a visibility observation, not a complete keyboard-path pass or broader accessibility conclusion.

The example uses physical top because its obstruction is above the content. Do not generalize that direction to every writing mode. A block-oriented design may need scroll-margin-block-start, but the actual covered edge remains the deciding geometry. The logical-properties draft distinguishes writing-relative and physical directions. Record writing mode, scroll axis, and obstruction together. If the container itself is unclear, see sticky and scrolling-ancestor diagnosis.

Retain the header-height source, target selector, container, compensation owner, and state evidence. A robust fix explains why enough space is available instead of relying on a fixed number that happens to work on the development machine.
