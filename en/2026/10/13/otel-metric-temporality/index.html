Preserve metric temporality before combining reported values

Preserve metric intervals and temporality across collection, conversion and restart boundaries.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-13 · Estimated read 6 min
Translations
zh-CN en

Article

Delta and Cumulative describe the time covered by a metric value. Do not discard that interval and combine values blindly. Delta describes change over a reporting interval; Cumulative describes accumulation from a starting point. Collection, conversion, and aggregation must preserve the distinction.

Interpret a value with its interval

The OpenTelemetry metrics data model describes both temporalities and their start and end times. Delta reports ordinarily cover non-overlapping intervals, while cumulative reports cover a common starting point through the current time. The checked page identifies specification version 1.61.0 and has overall Mixed status; not every section is a stable interface.

Imagine one pipeline reporting work added in the latest interval and another reporting work since process startup. Matching names and units do not make their values directly additive. Summing successive cumulative reports can count earlier activity repeatedly. This is a semantic illustration, not a production incident or executed collector experiment.

Temporality is not a freely interchangeable label for every metric. Check the data type and defined operations before subtracting, adding, or converting. A dashboard value stripped of intervals and series identity may no longer be interpretable from its title alone.

A new starting point affects continuity

A restart can change a cumulative series’ starting point. Use timing and continuity information rather than treating a smaller total as negative business activity. Likewise, missing intervals are not evidence of zero activity without further support.

Conversion needs explicit state ownership and loss handling. A processor with a previous value and a freshly restarted processor have different evidence. This is a review question, not a guarantee that every collector correctly handles all restarts, duplicates, and out-of-order reports. Inspect actual component capabilities and configuration.

Deliver the full ingestion contract

Document type, unit, temporality, interval boundaries, series identity, and restart behavior. A name and example value are insufficient. Where conversion occurs, specify before-and-after meaning, state location, and visible failure behavior rather than assuming another layer handles it.

A proposed review covers continuous reports, duplication, gaps, reset starting points, and processor restarts. These checks were not executed, so no duplicate-free claim is made. For downstream query semantics, see rate before counter aggregation. Transport temporality and query interpretation must connect without substituting for each other.
