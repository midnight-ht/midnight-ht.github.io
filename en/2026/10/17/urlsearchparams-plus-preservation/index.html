Where should raw values enter URLSearchParams to preserve plus signs?

Trace complete query round trips for plus, space, percent and repeated keys without confusing values with serialized text.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-06 · Estimated read 14 min
Translations
zh-CN en

Article

Key takeaways

  • A plus in query text is parsed as a form-encoded space.
  • Parameter methods receive raw values for serialization.
  • Equal values do not guarantee identical query text.

Parsing query text treats plus as form-encoded space. Supply raw values to append or set so serialization can encode a literal data plus. A serialized query and an unencoded parameter value are different inputs, even when both are strings.

The URL form-encoded parser replaces plus bytes in names and values with spaces before percent-decoding. URLSearchParams is following that query-text contract. Interpolating raw A+B into q=A+B has already failed to express the plus as data.

Meaning can be lost before reading—or through another encoding

The URLSearchParams reference contrasts interpolation with append using Base64 containing plus signs. The constructor parses syntax; append receives raw data for serialization. Fix the entry boundary rather than replacing every resulting space with plus, because a legitimate value may contain spaces too.

Consider A+B C%. Its plus and space are not interchangeable. Replacing all parsed spaces corrupts the original space. Compare raw value, serialized text and parsed result rather than judging whether an address looks valid.

The reverse mistake pre-encodes a value with encodeURIComponent, then passes it to the parameter API. Percent signs become data too, leaving A%2BB after one parse. Another decode may appear to fix that sample but corrupt a legitimate literal %2B value. Protocol boundaries, not appearance, determine decoding depth.

A complete round trip with independent expectations

This Node module has not been executed. It sends no requests and uses no real sharing data. Every input and expected serialization is a predefined literal. Save it as.mjs to run with Node; its scope is that environment's API behavior, not a backend or signature system.

import assert from 'node:assert/strict';

const samples = [
  { raw: 'A+B C%', query: 'q=A%2BB+C%25' },
  { raw: '%2B', query: 'q=%252B' },
  { raw: '中文+ space', query: 'q=%E4%B8%AD%E6%96%87%2B+space' }
];
const observations = [];
for (const sample of samples) {
  const params = new URLSearchParams();
  params.append('q', sample.raw);
  const serialized = params.toString();
  assert.equal(serialized, sample.query);
  const parsed = new URLSearchParams(serialized).get('q');
  assert.equal(parsed, sample.raw);
  observations.push({ raw: sample.raw, serialized, parsed });
}
const preencoded = new URLSearchParams();
preencoded.set('q', encodeURIComponent('A+B'));
const encodedText = String(preencoded);
const repeated = new URLSearchParams([['tag', 'a+b'], ['tag', 'c d']]);
const repeatedText = String(repeated);
const counterexamples = {
  interpolated: new URLSearchParams('q=A+B').get('q'),
  encodedText,
  encodedValue: new URLSearchParams(encodedText).get('q'),
  repeatedText,
  tags: new URLSearchParams(repeatedText).getAll('tag')
};
assert.deepEqual(counterexamples, {
  interpolated: 'A B',
  encodedText: 'q=A%252BB',
  encodedValue: 'A%2BB',
  repeatedText: 'tag=a%2Bb&tag=c+d',
  tags: ['a+b', 'c d']
});
console.log(JSON.stringify({ observations, counterexamples }, null, 2));

The correct path retains structured names and values until serialization. Comparing parsed output with the original literals can expose plus corruption, over-decoding of percent sequences and Unicode problems. The deliberately wrong path has explicit expectations too; it is not silently excluded from validation.

Repeated keys have their own contract. Get cannot replace getAll when checking an entire tag list. Whether ordering matters is a business choice. An API capable of multiple entries does not decide whether a server keeps the first, last or an array. Test the receiver independently with the same inputs.

The console statement specifies prospective output, not a captured log. An actual run needs version, stdout and exit code, with claims limited to this pure API path. It exercises no browser navigation, transmission, persistence or real sharing entry.

Should a literal %2B inside the value be decoded again?

Do not guess. It can be legitimate data, and the parameter contract must identify its layer. The second sample preserves the three-character literal %2B, encoding its percent sign during serialization and recovering the original string. A further decode changes its meaning.

Specify whether modules exchange raw values, query text or full URLs. A value-taking function should not require callers to construct q=. A complete URL needs structural parsing before searchParams. URL base resolution explains why paths and fragments retain separate meanings.

Keep historical links in migration checks. An old generator may have emitted a bare plus, and a receiver cannot reliably infer its original meaning from the resulting space. Compatibility, reissuing links or rejecting ambiguous data needs a protocol decision, not an undisclosed global replacement.

Do equal parameter values guarantee identical query text?

No. URL.search and URLSearchParams can use different valid representations, including different space encoding. The reference demonstrates parameter updates or sorting changing address text without changing values. Value-based business equality differs from raw-byte signature or cache identity.

If a layer signs the original text, check sorting, encoding and repeated-key representation against the actual signature input. This is conditional, not a claim that every serialization change breaks every signature. A receiver may already apply agreed normalization; both sides need the same protocol.

A clickable address does not establish a durable resource either. Blob URL lifetime covers another ownership boundary. This article preserves parameter meaning; access permission, expiration and resource existence remain separate.

Use nonsensitive teaching data for diagnostics. Publishing an entire signed link to investigate one character introduces another responsibility. Retain a sufficient redacted representation rather than real tokens in build artifacts. These literals represent no user records.

Proposed acceptance compares raw-value methods, interpolation, pre-encoding, repeated keys and raw-text changes. State whether each assertion compares values or bytes, then test the real receiver separately. This rewrite preserves the publication date, translation key and URL and performs no network or business test. Establish the input layer before assigning encoding to one explicit owner.
