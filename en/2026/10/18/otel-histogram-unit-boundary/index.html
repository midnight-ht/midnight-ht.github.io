Check histogram values against their declared unit

Check measurement values, histogram boundaries and downstream thresholds against one unit contract.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-18 · Estimated read 7 min
Translations
zh-CN en

Article

Check a histogram’s declared unit separately from the values supplied to it. Metadata saying seconds does not establish that a caller converted milliseconds. A visible chart and discoverable metric name are insufficient evidence of correct duration semantics. Follow the contract through measurement, recording, delivery and queries.

Metadata and measurements are separate inputs

The OpenTelemetry 1.61.0 Metrics API treats unit as instrument creation information and requires Histogram Record to accept a user-supplied numeric value. Those separate inputs do not prove correct application conversion. A particular SDK or collection chain may perform additional processing, so neither should one assume that every stage always leaves values unchanged.

The semantic conventions 1.44.0 unit guidance recommends seconds for durations and describes unit expression. That versioned guidance is not permission to relabel an existing millisecond metric without reviewing its meaning. A specific metric convention needs agreement on name, unit and recorded quantity.

Suppose an operation takes 300 milliseconds and the recording contract uses seconds. The corresponding input is 0.3. This is arithmetic in a hypothetical example, not an executed SDK measurement. Supplying 300 while changing a legend to seconds is not a repair. Applying conversion again downstream can introduce the opposite error. Identify the layer responsible instead of adding division at every boundary.

Buckets and thresholds share the contract

Review histogram boundaries, alert thresholds and presentation in relation to the stage whose values they use. Preserving a numeric bucket boundary from a millisecond design can give it another time meaning after migration. This is a review requirement, not a claim that any particular exporter automatically repairs configuration.

A setting that only changes display formatting cannot establish correct collection values; inspect the specific product to determine whether it also converts data. Plausible values can hide a problem in a limited sample. Conversely, an unusually large value can represent genuinely slow work and should not be scaled down without evidence. Preserve measurement provenance, recording location and transformations.

Explain current and historical meaning

When versions coexist, identify their contracts and determine whether consumers may combine them safely. A unit-induced jump in a chart is not evidence of improved performance. Do not conceal semantic changes merely to preserve visual continuity. Compatibility should follow actual consumers; no migration design was validated here.

Proposed checks use interpretable inputs and compare application values, instrument metadata, delivered data and final queries, including zero, large values and mixed versions. Record SDK, collection configuration and semantic-convention versions. These checks were not executed, and no performance or error measurements are reported.

A centralized recording helper can make conversion reviewable only if callers actually use it and refactoring does not duplicate conversion. Assign maintenance responsibility rather than treating the unit property as the end of the work.

Delta and Cumulative aggregation boundaries examines a separate metric meaning. Unit and temporal aggregation need their own contracts; histograms become useful evidence when values and interpretation agree.
