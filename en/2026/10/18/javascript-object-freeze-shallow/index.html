Why can nested settings change after Object.freeze?

Shallow freezing protects the outer object; nested references, accessors and recursive handling need explicit boundaries.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-18 · Estimated read 8 min
Translations
zh-CN en

Article

A nested switch can change after its parent configuration has been frozen with Object.freeze. Freezing handles the supplied object’s own properties; it does not automatically traverse every reference. Keeping a reference fixed and keeping its target unchanged are separate requirements. Establish which one the configuration needs before reviewing its protection.

A fixed reference can point to mutable content

MDN’s Object.freeze reference, updated in May 2026, describes shallow freezing. It restricts additions, deletions, and reassignment on the object itself. An object stored as a property value may remain mutable. This explanation concerns ordinary object properties, rather than treating all special objects as equivalent data containers.

The following configuration is illustrative code and was not executed here:

const policy = { upload: { enabled: true } };
Object.freeze(policy);
policy.upload.enabled = false;

The last statement changes enabled on the object reached through upload. It does not replace policy’s upload reference. Checking only that the outer object is frozen therefore cannot establish protection for the nested switch. A requirement for a stable configuration snapshot needs an additional treatment of nested objects, or an immutable update strategy appropriate to the project.

Shared references matter too. If two configurations point to the same upload options, a change through one path is visible through the other. Freezing the outer object neither copies that child nor removes the alias. This is another unexecuted example, suggesting that reviewers trace object origins instead of merely searching for a freeze call.

Limit the scope of recursive handling

Recursively processing a controlled tree of ordinary objects, arrays, and primitive values may meet a particular need. Applying a recursive snippet to arbitrary runtime objects does not establish deep immutability. MDN notes cyclic references and the need to track visited objects, as well as the risk of freezing objects that should remain mutable. Decide whether functions, accessors, and externally shared objects belong within the intended scope.

Accessors also qualify the claim that values can never change. MDN explains that freezing does not stop a getter’s computed result changing with external state, or prevent a setter being called. A configuration boundary may instead restrict the permitted data shape and produce controlled snapshot data. That is a design recommendation, not an additional capability supplied by freeze.

Copying and freezing answer different questions. Copying concerns shared references; freezing restricts modifications on a particular object. A shallow copy that retains the same child, followed by freezing its parent, still does not produce an independent, deeply fixed snapshot. Conversely, when the only requirement is to prevent replacement of top-level fields, shallow freezing may be enough. General traversal would need its own justification.

Describe allowed change first

A hypothetical permission-configuration review could ask whether in-flight requests should observe live updates, whether audit history must retain earlier values, and whether test cases may mutate their own fixtures. These uses have different sharing requirements. The word “configuration” does not imply a universal freezing policy, and freezing is not an external authorization check.

The site’s discussion of requirements and accountable decisions starts with acceptance boundaries. Here, proposed checks should distinguish top-level replacement, nested mutation, shared aliases, and the selected data-shape limits. None was executed for this article, and no production-validated deep-freezing utility is supplied.

When a review says “it is frozen, so it cannot change”, ask which objects were frozen, which references remain shared, and which changes are allowed. Those answers determine whether shallow freezing meets the actual requirement.
