Why can two pytest.approx tolerances allow a larger error?

Inspect alternative tolerance budgets, abs-only behavior, near-zero cases, and unit conversion using a fixed pytest version.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-28 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Two tolerance budgets are alternatives rather than an intersection.
  • Abs-only does not add the default relative tolerance.
  • Scale absolute budgets with units and retain relative proportions only under matching conversion.

An expected value of one million uses a relative tolerance of one part per million and an absolute tolerance of one trillionth. The smaller absolute number does not tighten the larger allowance. With both pytest.approx tolerances configured, satisfying either is sufficient. Review the accepted error range rather than reading two parameters as two mandatory gates.

Which allowance applies when both are supplied?

The pytest approx reference gives defaults of 1e-6 relative and 1e-12 absolute. The relative allowance uses the expected value supplied to approx. The official pytest 9.0.2 implementation and documentation calculate the candidate tolerances and take the larger. This fixed version supports reproducible inspection; it is not presented as the latest release.

For ordinary finite scalar values, the two-parameter contract accepts a difference within the absolute budget or within the absolute expected value multiplied by the relative proportion. Taking the larger budget differs from intersecting both restrictions. Relative tolerance has no unit; absolute tolerance needs the quantity's unit. Small-looking parameters can behave differently across magnitudes.

In an unexecuted paper example, an expected million units with rel 1e-6 permits one unit through the relative branch. Abs 1e-12 is much smaller. A half-unit difference remains inside the relative allowance. If the business requires the smaller budget alone, specify that contract instead of placing a small absolute number beside a wider relative one.

# Illustrative only; not executed.
assert actual == pytest.approx(expected, rel=1e-6, abs=1e-12)

This calculation does not endorse a one-unit business error. Approximation, measurement resolution, and required rounding can justify different budgets. Record the reference source, reason for the allowance, and requirement that approves it. A green assertion cannot retrospectively establish an approved precision rule.

Does abs-only retain the default relative tolerance?

No. Explicit abs with no rel uses the absolute tolerance without adding the default relative comparison. Supplying both accepts either allowance. Changing to abs-only therefore changes the range calculation, rather than merely tuning one number. Review the actual parameter combination.

Conversely, supplying only rel does not automatically remove the default absolute allowance, especially relevant near zero. Distinguish omitted parameters from explicit zero and a deliberate absolute budget. An intention to perform “pure relative comparison” is not evidence that the invocation implements it. If zero absolute tolerance is selected, assess its near-zero consequences.

Keep the reference clear too. The value inside approx determines the relative basis; the comparison does not separately compute two budgets and average them. Variable names and independently sourced expectations should expose that reference, particularly when conversion or normalization occurs first.

How can edge cases detect excessive relaxation?

Calculate the effective allowance for each expected magnitude, then choose clearly inside and outside examples. One familiar small-decimal test cannot justify copying the same configuration to a result six orders of magnitude larger. A fixed relative proportion necessarily permits greater absolute differences as the reference grows.

Floating-point representation complicates exact decimal boundaries. Start with examples clearly separated from the threshold, then design genuinely required edge cases with suitable numeric types and expectations. A paper boundary is not an executed pytest outcome.

Treat zero, negative, and non-finite values separately. The documentation says infinity compares equal only to itself, while NaN does not compare equal by default; nan_ok explicitly permits matching NaNs. That tool behavior does not approve missing data for the business. Preserve missing-value failures when the requirement demands them.

Tolerance also cannot replace a required rounding procedure. A wider range may conceal the wrong order of operations. The related parametrized-alias article explains why input mutation must not corrupt expectations. Similarly, construct tolerance expectations independently instead of letting the implementation approve itself.

How should seconds-to-milliseconds conversion change tolerances?

The relative proportion remains unchanged only when actual and expected values both scale by the same positive factor. Scale the absolute budget by that factor too. If the expected value is two seconds with an absolute allowance of 0.01 seconds, conversion gives 2,000 milliseconds and a ten-millisecond allowance. Retaining abs 0.01 while merely changing the label tightens that allowance a thousandfold.

Add rel 0.01. At two seconds, the relative allowance is 0.02 seconds, wider than the absolute 0.01. In milliseconds, the allowances are twenty and ten, preserving the relationship. At a different expected value of 0.2 seconds, the relative allowance is 0.002, below the absolute budget. These magnitudes exercise different dominating branches rather than treating one conversion as complete coverage.

A review record can list the expected value, unit, both candidate budgets, and the effective larger allowance, with one inside and one outside example. Reviewers should derive acceptance without running the implementation under test. No tests were executed here; parameter values alone are not approval evidence.

Add an independent zero-reference case: its relative allowance is zero, so any remaining absolute budget determines the range. If the requirement demands exact zero, configure and test that explicitly rather than letting a successful large-value example approve an undiscussed zero allowance.
