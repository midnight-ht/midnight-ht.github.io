WCAG 3.2.4: can users recognize the same search when its name changes across pages?

Apply WCAG 3.2.4 to recurring search controls, distinguishing recognizable functionality, contextual wording changes, and contact links that are not repeated instances.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-30 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Establish functionality and recurring-component relationships before comparing identification.
  • Contextual page numbers, positions, and scopes do not require literal string equality.
  • Contacting the same organization does not automatically make links repeated instances.

A repeated search feature called “Search” on one page and “Discover” on another may appear to do different things. WCAG’s Consistent Identification requirement addresses recognition of repeated functionality. It does not require every vaguely similar link across a site to have an identical name.

Imagine a library with article, report, and case-study pages. Each header searches the same library. One button says “Search,” another was renamed “Discover” for a livelier tone, and a third uses an unexplained magnifying glass. The team says they share a search endpoint. Readers still encounter changing clues for recognizing the function.

The WCAG 2.2 Understanding document for Consistent Identification explains success criterion 3.2.4, Level AA: repeated components with the same functionality within a set of pages should be identified consistently. Assess both the functionality and whether the elements are perceived as repeated instances of the same component. A site-wide text replacement cannot make that judgment.

Identify the repeated instances

For the library, list the three header searches and record scope, button wording, icon, and the name available to assistive technology. They search the same collection and recur as the same header component, giving a reasonable basis for reviewing them as a group. Without a distinct product meaning, keeping a clear “Search” label is more useful for recognition than rotating fresh synonyms.

Sharing an endpoint is not decisive. One page might search the whole library while another filters the current table through that same endpoint. Their user functions differ. Conversely, different implementations can offer the same function. Start with what readers can do, then use implementation details to explain it.

An unexecuted content-review example would use “Search the library” for the article, report, and case-study headers, and “Filter current results” in a filtering panel with a different scope. The first three form a repeated group; the panel differs. No page was run, accessible-name calculation inspected, or complete WCAG audit performed for this article.

If an icon contributes to recognition, review it alongside the words. Replacing a magnifying glass with an unrelated symbol on one page can make visual users relearn the control even if a hidden string remains unchanged. Consistent identification cannot be reduced to storing one identical value somewhere in the implementation.

Consistency allows meaningful variation

The Understanding document allows context-dependent differences. “Go to page 4” and “Go to page 5” can use a consistent pattern without being literally identical. A destination might also appropriately be “Page 4” in one context and “Previous page” in another. The aim is recognizable functionality, not eliminating every change in wording.

A library team can therefore maintain a stable pagination pattern while retaining the page number and positional information. Renaming every link “Next” for uniformity would erase useful destinations. Preserve differences that the task requires rather than treating string equality as the objective.

The current document also distinguishes elements with the same purpose that are not perceived as repeated instances of one component. A contact link in main content and a contact entry in the footer are not automatically forced into identical identification merely because both contact an organization. Context and the component relationship matter.

“All contact links must say Contact us” is therefore not a conclusion drawn here. “Contact the author” in an author card may have a different scope from an organization’s footer contact. Repeated instances of the same author-contact component, however, should be reviewed within their own group. Accurate grouping preserves real information while making corrections specific.

Make the change reviewable

Start with the three library pages without treating the sample as a complete inventory. Record the instances, their current differences, the agreed wording, and their actual scopes. After editing, inspect visible text, icons, and the name actually available to users, and confirm that each control still searches the intended collection.

Failures include an old template being missed, a mobile view rendering a separate icon, translations describing one component with different concepts, and a changed search scope retaining an outdated promise. Review repeated instances within each language and assess each language’s expression; different languages need not display the same original string.

A maintenance map can document what forms a repeated functionality group, which contextual changes are allowed, and when the group needs reconsideration. That is this article’s working recommendation, not a register format prescribed by the criterion. It helps a new page inherit an existing recognition pattern deliberately.

This question also differs from the relative order of help mechanisms. Stable order does not establish stable identification, and stable naming does not establish compliance with a separate ordering requirement. Keep findings specific if the two are assessed together instead of reporting one undifferentiated “consistency passed.”

What if a familiar button changes its search scope?

Reassess its function first. If a whole-library search now searches only the current project, readers need that change communicated. A familiar search expression can remain while its scope becomes explicit; formal consistency should not preserve an outdated promise. If it has become a different component, review its new functional relationship.

The useful addition is a rule for when to inherit identification and when to explain a change. That supports prior learning while leaving room for real differences, and lets a reviewer explain why three instances were aligned while another remained distinct.
