Separate visual transparency from interaction availability

Coordinate transparency, interaction availability and focus instead of relying on appearance.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-15 · Estimated read 5 min
Translations
zh-CN en

Article

Opacity zero makes content visually transparent; it does not automatically remove controls from pointer, keyboard, or accessibility interaction. Decide existence, availability, and focus behavior when hiding an operation. An invisible button can remain actionable.

Invisible is not inoperable

The MDN opacity reference explains that transparent elements remain in the document, can receive pointer events, and can receive focus when in the tab order. Transparency alone should not communicate information to screen readers. This explains CSS behavior, not browser accessibility certification.

Imagine fading out a submit button without updating interaction state. It can remain at the same clickable position or receive invisible keyboard focus. The example was not executed and alleges no real duplicate submission.

Disabling pointer events alone does not necessarily address keyboard interaction. Use semantics and state appropriate to the element, then check focus order. Do not mark something hidden while expecting it to remain a comprehensible keyboard target.

Choose the intended state first

A temporary fade, a collapsed area, and a removed operation have different requirements. Specify availability during animation and afterward instead of expecting one style property to decide. No universal attribute combination is offered.

When the focused area disappears, provide a sensible next location and understandable feedback. Loading, errors, and completion should not rely solely on transparency.

Also check restoration. Showing content again must coordinate availability, focus, and business permission rather than merely changing opacity. Visual return does not establish server authorization. No complete keyboard-fix result is claimed without testing.

Proposed checks cover pointer and keyboard input, mid-animation behavior, hiding and restoring, and removal of the current focus area. They were not performed. See reduced motion and state feedback. A visual change should explain interaction state, not be its only evidence.
