Image uploads need more than extension and MIME checks

Quarantine untrusted uploads and review parsing, storage and retrieval permissions as well as file type.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-10 · Estimated read 6 min
Translations
zh-CN en

Article

An image-only endpoint cannot establish safety from extensions and client MIME alone. Reception, parsing, storage and retrieval are different boundaries. Treat received bytes as untrusted first. This hypothetical avatar pipeline includes no malicious-file test or parser validation.

Submitters control type claims

OWASP’s upload guide warns that client Content-Type is spoofable and signature checks are insufficient alone. It recommends necessary allowlisted types, generated names, size limits, permissions and suitable storage. No detection result excludes every risk.

A picture extension and MIME value can catch mistakes but cannot replace server identification and safe parsing. Review double extensions, encoding and malformed structures against the actual implementation instead of immediately publishing accepted bytes.

Small compressed files may still require large decoded images, memory or processing time. Define necessary formats and dimensions, constrained processing, rejection and cleanup. Thresholds require evaluation of the real parser and environment; no universal safe size is claimed.

Quarantine before delivery

Successful reception need not mean successful review. Define pending, accepted, rejected and expired states. An obscure temporary URL is not authorization; control access and storage configuration explicitly.

Keep untrusted files away from script-executable locations. Generated filenames reduce path and overwrite risks, while original display names still need output handling. Do not construct storage paths from user input or overwrite unrelated objects.

Retrieval remains an independent permission check. Public avatars and private attachments need different policies, content types and presentation behavior. See object-level authorization.

Define responsibility when asynchronous checks fail. Pending or rejection may be appropriate; timeout must not silently mean accepted. Cancellation, repeated uploads and replacement need cleanup policies. Record reception separately from eligibility for delivery.

Verify the whole lifecycle

Proposed tests cover forged types, excessive parsing resources, repeated names, access before review, unauthorized retrieval and failure cleanup. Inspect storage state and public visibility, not just response codes.

These tests remain unexecuted, and no scanning service is claimed to be connected. Transporting file bytes does not establish trust. For each state, review who can read or transform the object and when it is removed.
