Can a bold table header explain an independently encountered number?

Trace quarterly expenses through header associations, missing values, template changes, mobile cards, and navigation.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-24 · Estimated read 13 min
Translations
zh-CN en

Article

Key takeaways

  • A value needs its region, quarter, and measure context.
  • Complex relationships may need unique header identifiers.
  • Recheck meaning after mobile rendering and data changes.

Bold headers do not automatically give an independently encountered number its region, quarter, and measure. An HTML data table needs determinable relationships between data cells and their headers. Simple axes may use headers and scope; complex relationships may need explicit identifiers. Establish the question each value answers before choosing markup.

One number can have several possible meanings

W3C WAI's multi-level-header tutorial describes document-unique header ids referenced by a data cell's headers attribute for complex relationships. The irregular-header tutorial addresses spanning headers and row or column groups. This structure supplies context when users are not relying on the visible grid.

Sighted readers may trace rows and columns. During cell navigation, an amount alone might not identify its region, quarter, or expense measure. Units and accounting definitions may also live outside the grid. Reconstruct a complete question such as “What was the northern region's paid amount in the second quarter?” and then inspect which parts of that context the value can recover.

A caption identifies the table but does not establish every cell's relationships. “Expense summary” can still contain an ambiguous sequence of budget, paid, and difference values. Conversely, a simple two-dimensional table does not necessarily need long explicit headers lists everywhere. Let the actual relationships determine complexity rather than treating elaborate markup as a quality signal.

Trace a quarterly expense through the table

Imagine rows for North and South and grouped columns for the first and second quarters, each containing Budget and Paid. All values are hypothetical; no business report or assistive-technology run is claimed. The target cell needs to retain North, second quarter, Paid, and the unit supplied by the table's explanation.

For a regular grouped structure, investigate suitable column-group headers and scope, with regions as row headers. If headings repeat partway through or relationships become irregular, consider explicit associations. Give the relevant region, quarter, and measure unique identifiers and reference the required headers from the data cell. Attributes existing does not prove the announcement works in the target combination.

Continue the task horizontally from first-quarter budget to second-quarter paid, then vertically to compare South for the same measure. Check that horizontal movement preserves quarter and measure distinctions and vertical movement identifies the changed region. One continuous reading from the upper left does not establish that these comparisons are understandable.

If second-quarter paid data is absent, a dash also needs a defined meaning: not yet incurred, missing, or zero. Header associations locate the cell but do not explain missing-data semantics. Distinguish an absent value from a valid zero. Readability does not establish correct business interpretation.

Merged cells can look right while relationships are wrong

A heading spanning several columns does not alone establish correct relationships for every subcolumn. Adding a column to a copied template can leave an old group span or headers reference unchanged. The grid may remain neat while Paid is associated with Budget. Generate structure and data changes together rather than fixing accessibility metadata to an old layout.

Explicit ids introduce their own failure paths. Copying tables onto one page can duplicate identifiers, and removing a header can leave stale references. Static checks for uniqueness and existing references can catch structural errors. They cannot decide whether a value should belong to the second quarter rather than the first.

A layout table is a different counterexample. Using table elements to arrange buttons or cards and adding headers does not create a sensible data table. Determine whether the information needs two-dimensional comparison. Splitting a complicated report into smaller quarterly tables may help, but assess whether cross-quarter comparison becomes harder as a result.

Does a mobile card inherit the desktop associations?

Do not assume so. If mobile renders cards, show the necessary region, quarter, measure, and unit rather than hiding desktop headings and assuming their relationships survive. If the native table remains with different CSS presentation, inspect its actual accessibility structure. Choose the implementation using target-browser and assistive-technology evidence.

A card showing only “Paid: twenty” can lose its quarter if that heading sits in another horizontally sliding panel. Retain enough local labeling for the value to make sense independently. This does not require repeating the entire report everywhere; preserve the context that identifies the value. Reflow must not change which object owns the number.

Validate against actual data questions

Dynamic tables should not confuse position with identity. After sorting moves North to the second row, code using fixed positional header identifiers may still create existing, unique references that identify another region. Compare the cell's data object with its header objects, rather than checking reference validity alone. Recheck total-row meaning after filtering so visible-subset values and whole-dataset totals are not mixed under one label.

A proposed check selects three easily confused cells and writes their complete business questions and expected headers. Inspect rendered th, scope, id, headers, spans, and caption against visible content. Then compare values using cell, row, and column navigation in the target screen reader. Repeat relevant checks after sorting, filtering, and pagination.

These checks have not been executed, and no component-library compatibility result is claimed. As the site's question protocol asks what a field is for, a report should explain what each value answers. Start with the most easily misread number and establish that desktop, mobile, and updated data preserve the same meaning.
