Why same-origin CSP still needs base-uri for relative links

Follow relative URL resolution through the base element, resource rules, and form destinations; verify what the browser actually targets.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-20 · Estimated read 13 min
Translations
zh-CN en

Article

Key takeaways

  • CSP base-uri controls the document base and has no default-src fallback.
  • A permitted same-origin base can still redirect relative paths within the origin.
  • Inspect raw and resolved URLs alongside policy enforcement in a browser test.

A document loads scripts and images only from its own origin, so a team assumes its relative links must also lead to that origin. Then a template emits <base href="https://other.example.test/">, and a link written as href="help" resolves against that new base. Resource permission and URL resolution are different checks. Reading default-src 'self' as a guarantee about where every relative address points misses the purpose of CSP’s base-uri directive.

Resolve the address before interpreting the request

MDN’s base-uri reference says the directive restricts URLs that a document’s <base> element may use. It has no default-src fallback. Leaving base-uri out therefore does not silently give the page a same-origin base restriction. The HTML base element reference explains that its href supplies the base URL for relative references in the document; even fragment links can be affected.

Imagine a page at https://app.example.test/account/ containing a link with href="settings", a form with action="save", and a script with src="/app.js". Without a <base>, the first two addresses resolve relative to the document location. If the first effective base becomes https://other.example.test/path/, both acquire another destination. The root-relative script path also resolves using the base origin and its root. These domains and elements are hypothetical; no browser experiment was run for this article. A real review should inspect the resolved absolute properties in the browser rather than infer them from the raw HTML attributes.

The script request might later be rejected by a restrictive source directive. That rejection does not undo the significance of a rewritten navigation link or form target. Different kinds of outgoing action follow different rules. In particular, default-src is not a replacement for form-action; the site’s form-action explanation covers the destination rule for submissions. Review both the base that determines a relative action and the directive that controls whether a submission to the resolved destination is permitted.

What does a same-origin base restriction buy?

If the application has no need for a cross-origin base, base-uri 'self' restricts an injected or mistaken <base> from selecting another origin. Where the application never needs <base>, an even stricter base-uri 'none' can be evaluated after checking historical templates and generated pages. Neither policy is a universal link checker. An allowed same-origin base may still change the path: changing a page’s base from /account/ to the same origin’s /legacy/ can redirect settings within that origin. The CSP check can pass while the route is wrong. Route correctness belongs in template and browser tests.

The HTML reference adds two details that matter during review. If multiple <base> elements appear, only the first href and first target take effect. Appending a safe-looking element near the end of the page cannot override an earlier effective value. A fragment such as href="#details" may also be resolved against the base, so a link that appears to be a local jump may cause navigation to a different document. Inspect the final DOM and the first effective value, especially when templates or rich-text renderers assemble markup in several places.

Classify address forms before testing. A path like settings depends on the base directory. A root-relative path like /app.js uses the base origin. A fragment depends on the base document URL. A complete https://... address already states its own destination. The mix of forms in a page determines its exposure. A single blocked script request does not prove that a template full of relative actions is safe. Conversely, a page composed of explicit absolute destinations has a different review surface, even if the same policy header is present.

The threat model matters as well. A hostile base requires an attacker to influence HTML that the browser will treat as a <base>; a trusted but faulty template can cause accidental breakage without an attacker. Restricting the base reduces one consequence of markup injection, but it does not repair the injection entry point. Check whether untrusted content can emit the element, where it lands in the document, and whether a client-side renderer can add it later. Also check the actual response header on every relevant rendered page, rather than only a source configuration file.

Verify both policy enforcement and page behavior

A controlled browser test can record document.baseURI and the resolved href, action and src properties. Compare a page without <base>, a legitimately allowed same-origin base, and an attempted cross-origin base that the policy should reject. Read the CSP console report and network destination together: a rejected base may cause the page to fall back to the document URL, after which relative links can still work or can break for a separate reason. Avoid submitting real sensitive data to a test destination.

Migration can make a restrictive policy appear to be the cause of broken links. If a site moves from / to /portal/ and has been relying on <base> to simplify relative references, changing every page to base-uri 'none' may reject a legitimate base and alter routing. Inventory where the element is used, decide whether to replace relative links with explicit paths, and then run a page-level regression. Conversely, allowing every base URL simply to restore navigation also restores the opportunity for an injected base to redirect relative targets. The policy should reflect the site’s actual URL model, not a copied header recipe.

This experiment is a proposed validation plan, not a report of execution. A useful result table has the raw relative value, expected absolute URL, browser-resolved URL, applicable CSP directive and observed action. It separates an address-resolution error from a blocked resource load or blocked form submission. That is the point at which base-uri becomes a testable constraint on the document’s URL model rather than a keyword added to a policy header.
