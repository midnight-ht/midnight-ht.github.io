Why emptyDir Survives a Container Crash but Not Pod Removal

emptyDir survives container crashes within a Pod. Pod removal deletes its data, so recovery requirements must name that boundary.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-19 · Estimated read 8 min
Translations
zh-CN en

Article

Files in emptyDir can survive a container crash, but they do not survive the Pod being removed from its node. A restart exercise that retains files has demonstrated only the boundary it actually crossed. It does not establish recovery after a release replaces the Pod.

Which object’s lifetime owns the files?

The Kubernetes volume documentation describes an initially empty volume created when a Pod is assigned to a node. Containers within that Pod can mount and share its files. When the Pod is removed from the node for any reason, the data is permanently deleted. A container crash does not itself remove the Pod, so the volume can survive that crash.

The ambiguous word is “restart.” One person may mean restarting a container process; another may mean deleting an old Pod and creating a replacement. Both operations can appear as brief service interruption in an interface while having different storage consequences. A record saying only “restart passed” cannot establish which recovery scenario was covered.

Consider a hypothetical computation writing progress into emptyDir so that it can continue after a process crash. Within the same Pod, this is a reasonable temporary-checkpoint use. If an upgrade removes the old Pod and a new Pod must continue the job, the old checkpoint cannot serve as a reliable handoff. This example was not executed, and no recovery time was measured.

A temporary checkpoint needs a defined failure scope

The decision is what the business can afford to lose. Downloadable cache content, recomputable sorting files, and the only copy of a user’s upload carry different consequences. Recovery across Pods needs a separately designed persistent store, external checkpoint, or replayable input. Its write completion and recovery consistency also need verification. Renaming a directory cannot supply that guarantee.

Sharing files between containers creates an additional application responsibility. A producing container and a consuming container can see the same directory without having an agreement that a visible file is complete. Define the handoff, recognition of partial output, and responsibility for rebuilding an empty directory. These are requirements of the proposed file protocol, rather than transactions automatically provided by emptyDir.

Setting emptyDir.medium to Memory changes the backing medium to a memory filesystem. Kubernetes documents that written files count against the memory limit of the writing container. It does not turn a Pod-scoped temporary volume into storage that survives Pod replacement. A capacity limit also does not establish that the node always has that amount of free storage.

Record two different recovery scenarios

A proposed exercise should separately describe container recreation within the same Pod and creation of a new Pod after removing the old one. Record Pod identity, container restart count, file origin, and recovery path. For a new Pod, verify whether an empty directory triggers recomputation, download, or an explicit failure rather than silently creating misleading state.

An initialization container may prepare baseline files for a new directory. Those files still differ from progress produced by the previous run. Successful initialization establishes readiness to begin; continuing old work requires a named external source of progress and a decision about what to do when it is unavailable.

No cluster operation was performed for this article. For a related lifetime distinction, see Docker volume initialization and later mounts. State a recovery requirement in terms of the object lifetime it must cross. Surviving a container crash and surviving release replacement are different storage requirements.
