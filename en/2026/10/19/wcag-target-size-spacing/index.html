WCAG 2.5.8: Check the Active Target Before Applying the Spacing Exception

Measure the active area, check every nearby target, and document the exact WCAG 2.5.8 exception that applies.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-20 · Estimated read 13 min
Translations
zh-CN en

Article

Key takeaways

  • The 24 by 24 CSS pixel route concerns the effective pointer target, not the icon artwork alone.
  • An undersized target’s 24-pixel spacing circle must clear other targets and other undersized circles.
  • Equivalent, inline, and essential-presentation exceptions each require evidence tied to the actual control.

A designer can click a delete icon with a mouse and still have an unresolved accessibility question. The click proves that one attempt worked. WCAG 2.2 Success Criterion 2.5.8 asks about the pointer target's effective area and its relationship to nearby targets. The artwork, the CSS box, and the region that actually activates the control may have three different boundaries. A review should start with the last one.

Measure the action, not the icon

The W3C explanation of Target Size (Minimum) sets a 24 by 24 CSS pixel minimum for pointer targets at Level AA, subject to specific exceptions. It does not require every visible icon to be drawn at that size. A 16-pixel symbol inside a button whose surrounding padding activates the same action may have a sufficiently large target. A 28-pixel decorative background surrounding a symbol with the event bound only to the symbol may not. Outer margin creates separation but does not, by itself, turn that space into an active target.

Imagine a toolbar with a 16 by 16 delete glyph inside a 28 by 28 button. If the whole button responds to deletion, assess the active button region. If the blank part is inert, assess only the region that responds. This is a design example, not a measurement of a published page. In an actual review, mark the hit boundary in the running interface and check what happens on the padding, near the edges, and where overlays or nested elements might intercept input. Reading width and height from a stylesheet alone can miss clipping, pseudo-elements, overlays, and different event targets.

Width and height also require care for unusual shapes. The W3C explanation says a target satisfies the size route if a solid, page-axis-aligned 24 by 24 CSS pixel square can fit entirely inside the active shape. A round or heavily clipped target can have a broad bounding box without room for that square. For a plain rectangular button, measuring the box is often enough. For a cut-out SVG region or a rounded hit shape, inspect the shape itself. A box hidden under another layer is not the user's available target, even if developer tools report generous dimensions.

When a smaller target can use spacing

An undersized target does not automatically fail. The spacing exception places an imaginary circle 24 CSS pixels in diameter at the centre of its bounding box. That circle must not intersect another target or the corresponding circle of another undersized target. The neighbours to inspect include controls above and below, as well as large clickable cards beside a small icon. This is a two-dimensional relationship, not a fixed horizontal-gap token.

A paper example makes the arithmetic visible. Two square targets are each 20 by 20 CSS pixels, with a 4-pixel gap between their edges. Their centres are 24 pixels apart. The 24-pixel circles touch at their boundaries without intersecting, which matches the W3C example for this arrangement. But setting every component gap to four pixels would overgeneralise it. Put the same buttons on wrapped rows or next to a clickable card and a different target may enter the circle. For an irregular target, the circle is centred on its bounding box, even when the visible mass of the shape seems off-centre.

The two repair options have different costs. Enlarging the active target is straightforward for consequential actions such as delete or submit, provided the larger region does not overlap the next control. Increasing space can preserve a dense visual system, but it must survive responsive wrapping and expanded states. Adding decorative blank space between icons works only if the spacing circle really stays clear of every other target. Making the artwork smaller without changing the active area or surrounding geometry does not solve a failed spacing check.

Treat an exception as a claim with evidence

Other exceptions have conditions too. An equivalent control must perform the same function on the same page and itself meet the criterion. A “clear all” action is not an equivalent replacement for deleting one particular record. The inline exception covers targets in a sentence or whose size is constrained by the line height of non-target text; a toolbar button does not qualify merely because it has a text label. The user-agent-control exception concerns a size determined by the browser and not modified by the author. Essential presentation requires the placement itself to convey information, as with map pins, or a legal requirement. “The layout is tight” is a design preference, not an essential-presentation argument.

Write down the actual basis whenever an exception is used: the equivalent control and its function, the sentence and line-height constraint, or the information that makes placement essential. That record lets someone reviewing a later redesign tell whether the condition still holds. It also prevents a team from applying one component-level exemption to every instance of a widget, including instances where the surrounding page has changed.

Dynamic content changes the target set. An unopened menu icon and the menu items after expansion are different review states. New targets in a dialog, suggestion list, or overlay need assessment. The W3C explanation discusses targets temporarily obscured as a result of interaction, but that does not exempt newly displayed controls. Review default, expanded, error, and narrow layouts when they change adjacency. Zoom is no shortcut to the CSS-pixel requirement; the related question of whether functionality survives enlargement is covered in the reflow article.

A usable handover marks each consequential action's effective target outline, its dimensions or spacing route, the nearest other targets, the viewport and interface state, and the evidence for any further exception. After the geometry check, observe real pointer and keyboard tasks to uncover confusion or misactivation. Those observations improve the design, while the geometry supplies the basis for this particular criterion. Neither check alone establishes full WCAG conformance. For the delete icon, drawing the hit area beside every nearby action is the step that makes the next decision possible: enlarge the button, change the layout, or document an exception that actually applies.
