Why does an in-range number still have stepMismatch?

Explain step grids and bases, distinguishing value attributes, current values, any, and server precision rules.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-25 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Range and the step grid are independent constraints.
  • The step base prioritizes valid min, then the value content attribute.
  • Any defines neither monetary precision nor server-side business validation.

A number between min and max can still trigger stepMismatch because it is off the permitted step grid. Range and step are separate constraints. Establish the step base, then ask whether the difference from that base is an integral multiple of the allowed step. Increasing the maximum usually does not repair a grid mismatch.

Does the grid start at zero or the minimum?

The HTML Number-state definition gives number inputs a default step of one. That does not unconditionally mean integers only. The step-base algorithm in the same document first considers a valid min content attribute, then a parseable value content attribute, then a type-specific default base, and finally zero. The base and interval jointly determine the permitted sequence.

Think of a ruler: step determines the distance between marks and the base places the ruler. Range trims values beyond its ends. With min 0.2, max 3, and no explicit step, candidate grid values include 0.2, 1.2, and 2.2. The in-range value 1.3 is off that grid, while noninteger 1.2 can satisfy the step condition.

This is a specification-based calculation, not an executed browser interaction. A real page can also impose required input, custom errors, parsing rules, and server validation. Satisfying step does not establish overall validity. Inspect individual validity flags instead of attributing every error message to stepMismatch or assuming that every failure means excessive decimal places.

How would you specify a weight field?

Suppose a materials request accepts weights from 0.2 to 3 kilograms in increments of 0.1 kilogram. This is a hypothetical business contract. Explicit min, max, and step values express that grid; 1.3 lies on the sequence beginning at 0.2 with intervals of 0.1. The server must apply the same unit and precision rules. A numeric-looking browser control is not trusted validation.

The complete path begins with entering 1.3, checking range and step, submitting a value in the agreed format, storing the approved business quantity, and displaying the same weight for review. Compare input, individual validity flags, request payload, stored value, and display. If a separate formatter sends 1 while the screen showed 1.3, the conversion pipeline is wrong even though the input's grid is correct.

Next enter 1.35. It is in range but outside this grid. The contract should reject it or supply an explicit correction choice rather than silently treating it as a neighboring amount. The standard permits rounding in specified step-mismatch circumstances, but that is not a promise that every input method and implementation will automatically select the same correction. If approximation requires confirmation, expose the original input, proposed value, and confirmation action.

A counterexample is changing step to any after decimals fail while continuing to claim that only one decimal place is accepted. That removes the step restriction without implementing the stated business rule. Another is a server that checks only range, creating different accepted values for browser submission and direct API use. Validate at the authoritative receiver; use client checks for timely feedback.

Does changing value move the grid?

Distinguish the value content attribute from the current value property. The base algorithm uses a parseable content attribute; it does not make every user edit the new base, which would make the constraint self-satisfying. A valid min takes priority over the initial value attribute.

With no min, step 2, and initial value attribute 1, the grid can include 1, 3, and 5. Editing the current value to 2 does not make 2 its own base. If script changes the content attribute, or a framework recreates the element with different initial attributes, inspect the final DOM and base source again. Record attributes and current values rather than inferring browser behavior solely from a framework state variable.

Choose a base from the business unit and accepted minimum, not by adding a convenient value attribute to make one failing sample pass. Measurements accepting arbitrary decimals may use any while other layers define range, finite values, and business precision. Discrete package quantities need a defined interval and origin. The accepted set matters more than whether the control displays increment arrows.

Can step=any replace monetary precision checks?

No. It defines neither settlement precision, display rounding, server numeric types, nor storage behavior. Establish units, precision, and conversions before selecting control constraints. The site's display-versus-business rounding article explains why two displayed decimals do not establish a settled two-decimal amount. Likewise, step validity does not establish a correct downstream calculation.

Identifiers should not automatically use number inputs just because they contain digits. If leading zeroes, fixed length, or string identity matter, design identifier validation rather than an arithmetic increment sequence. Ask whether increasing and decreasing the quantity has meaning, not merely whether letters will be typed.

A proposed verification set includes on-grid boundary values, in-range off-grid values, out-of-range values, empty input, and an initial value attribute without min. Record effective attributes, current value, stepMismatch and other flags, and changes after script updates. Send the same inputs to the receiving endpoint. No browser or API suite was executed here: the conclusions concern specification semantics and hypothetical calculations. Write down the ruler's interval and origin before deciding whether a failure comes from range, step, or a later conversion.
