Why Does Tab Return to Navigation After “Skip to Content”?

Verify the next keyboard action and cross-page return path, distinguishing a scroll destination from effective bypassing.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-26 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Scrolling alone does not establish effective bypassing.
  • Evaluate landmarks and direct shortcuts in supported environments.
  • Client-side routes need a destination for current main content.

The page scrolls after “Skip to content,” but the next Tab returns to the header menu. A “Skip to main content” link should let someone bypass repeated material and continue with the current page's task. Scrolling to the article does not establish that outcome. If the next Tab returns to the header navigation, a keyboard user still has to traverse the block they intended to skip. Check the action after activation, rather than stopping when a fragment appears in the address bar.

Does the criterion prescribe one particular link?

Understanding WCAG 2.2 SC 2.4.1 requires a mechanism to bypass blocks repeated across multiple pages, at Level A. Its techniques include skip links and structural grouping that assistive technology can navigate, including landmarks and headings. It does not prescribe an identical button for every site. The mechanism must actually let relevant users avoid the repeated blocks.

Those blocks can include navigation, search tools, or a substantial filter panel. A repeated word or individual link is not the same as a block. Repetition within one isolated page is also outside this particular cross-page requirement, although a shortcut may still help. Keep voluntary usability improvements distinct from the criterion's scope.

The existence of a main element does not settle the practical question. Landmarks help users whose technology provides landmark navigation. Whether a person using only ordinary browser keyboard navigation has a direct route depends on the environment and implementation. An early, reachable skip link is a readily explainable choice for a public site, rather than the sole technique accepted by WCAG.

Follow a reference-library task

Consider an unexecuted design for a library whose listing and article pages share a long navigation menu. A reader opens a guide from the listing. The first relevant keyboard stop is “Skip to main content.” Activating it should establish a position at the guide and let the next interaction reach an article action, such as a download, without visiting every header link.

Start with a clearly identified main region and a stable target. If using an in-page link, point it to an existing start of the current content. Decide whether additional focus handling is necessary for the target element and supported browsers. A programmatically focusable target outside the ordinary Tab sequence is one common design option, but its necessity and exact implementation need verification. A scrolling function cannot represent every browser's navigation behavior.

Record the activating link, the resulting position, and the next focusable element after Tab. With a screen reader, also confirm that enough heading or region context is available to identify the destination. Viewport coordinates alone do not prove the sequential-navigation starting point changed. Finding an identifier in source does not prove that the current page has exactly one intended target.

If the skip link is visually concealed until focused, it must become clearly visible on keyboard focus and remain clear of fixed headers. Removing it from interaction as well as presentation makes it unreachable. Placing it after the long menu defeats its purpose. Focus visibility adds an independent check against the rendered layout.

Why test returning to the listing?

Initial loading is only one part of the task. After visiting a guide, returning to the listing, and opening another guide, the shortcut must still refer to current content. An old article target or duplicate identifier can send the reader to an unintended place. Maintain a clear relationship between the main region and the current route.

A counterexample cancels the link's normal action and performs only smooth scrolling. The visual result looks correct while keyboard navigation continues from the old place. Another failure briefly reaches the article before a refreshed advertisement moves focus elsewhere. A check made only at the end of the first scroll misses the final position.

Complex applications can contain several repeated blocks. If offering multiple bypass links, name their destinations: skipping navigation to the article differs from skipping filters to results. Generic labels such as “Continue” conceal that distinction. Choose shortcuts according to actual repeated content and task paths.

Where should a single-page application skip after navigation?

It should reach the current view's main content, rather than an unchanged application shell. Suppose the library keeps its shell while loading a new guide. When the shortcut is activated, its destination must exist and express the current task. A stable main region can contain a loading state followed by the current guide, with an explicit route focus policy. An empty target followed by a return to navigation is not a useful success.

This adds a timing requirement to the proposed design, not a rule that every asynchronous update should move focus. For updates that merely report a result, see status messages and focus. A change of interaction context may require a different navigation decision. Verify each through its own task.

Proposed acceptance covers initial entry, another page, browser Back, an expanded narrow-screen menu, and delayed content. Record the repeated block, destination, next interactive element, and region information exposed by assistive technology. These browser and screen-reader checks have not been run; one environment's success would not establish all supported combinations anyway.

Choose the site's two related pages with the longest navigation and complete a task across both. Compare the actual interaction routes with and without bypassing. The useful outcome is reaching the second page's work directly, rather than merely making the first page scroll attractively.
