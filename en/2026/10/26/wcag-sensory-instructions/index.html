Which Button Does “The Red One on the Right” Identify?

Use actual control labels, retain useful visual cues, and check references after layout, reading-order, and translation changes.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-10-26 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Instructions must not depend solely on sensory characteristics.
  • Names must match the actual interface actions.
  • Direction words require evaluation of reading order and reference clarity.

The help says “Use the green button on the right,” but the phone stacks the buttons and another theme changes their colors. “Click the red button on the right” is not a stable instruction. A reader may not distinguish the color, may not hear a sound cue, or may be using a narrow layout that moves the button below the content. Give the target a name that matches the interface. Color, shape, and position can then assist identification instead of being its only basis.

Must every color and direction word disappear?

Understanding WCAG 2.2 SC 1.3.3 says that instructions needed to understand and operate content must not rely solely on sensory characteristics such as shape, color, size, visual location, orientation, or sound. This is a Level A requirement. Such cues can remain when additional information makes the instruction understandable. “Choose ‘Save draft’ on the right” differs materially from “Choose the one on the right.”

The object of review is identification, not removal of visual design. Color can support scanning; arrows can express relationships; location can shorten a search. Ask whether a person can still identify the target without that cue. Changing red to blue preserves the dependency. Adding an unnamed arrow may merely replace one sensory characteristic with another.

Names must also agree. An instruction saying “Submit” remains ambiguous if the interface only offers “Save.” Several “Save” actions may need visible object context. The related label-in-name check asks whether a speech user can invoke a control using its visible words. It does not replace review of the complete instruction.

Follow an application from drafting to review

Imagine an application with “Save draft” and “Submit for review.” Its old help says, “After checking, press the green button at the bottom right.” This is an unexecuted design example. On desktop, the actions sit on the right; on a phone they stack vertically, and another theme changes their colors. The instruction has no stable target.

A clearer version is: “Check the applicant and attachments, then choose ‘Submit for review.’ Choose ‘Save draft’ if attachments still need work.” It names actual labels and distinguishes consequences. Color and position may supplement it. Following the save instruction should retain an editable draft; submitting should enter the defined review or confirmation path. Those business outcomes are hypothetical product requirements, rather than outcomes prescribed by WCAG.

If a declaration is required before submission, identify it by its label instead of “the small box above.” Missing-material guidance should name the field or attachment instead of “the red area.” A reader using a different reading order, magnification, or spoken presentation can then connect the instruction to an object.

One failed repair adds hidden names to buttons but leaves the visible help dependent on green. That may assist a particular technology while still giving a reader who cannot distinguish color no visible basis for choosing. Improve visible labels and guidance first, then check programmatic names. Hidden text should not carry the entire burden of correcting visible ambiguity.

Another failure names both actions “Continue” and distinguishes them only by left and right. The instruction then needs more context because the actions have lost their meaning. Review the labels before adding a longer positional explanation. When a heading or button changes, treat related instructions as affected content too.

Is “the link below” always a failure?

No. The understanding document explains that, in some languages, “above” and “below” can describe reading order. When the referenced content is in the appropriate order and the reference is unambiguous, those statements can conform. Do not turn a direction-word search into an automatic verdict.

A paragraph followed by one link labelled “View required documents” can identify it using both the name and order. With many links, or when visual position disagrees with reading order, use more explicit names and context. This requires inspecting actual structure, rather than searching only for “left,” “right,” or “below.”

What about spatial tasks and diagram questions?

The issue is instructions for understanding and operating content, rather than deleting spatial information from every activity. A map question may deliberately assess direction. Separate the information being assessed, identification of answer controls, and any necessary alternative presentation. The presence of a spatial task does not excuse “Press the large button on the right to submit.”

The understanding document also distinguishes web controls from tactile hardware cues. Guidance suited to a physical kiosk must not be copied indiscriminately to screen controls. Specialized terminals and complex graphics need evaluation of their actual input methods. No such device acceptance was performed here.

Proposed checks identify the target without color, repeat the instruction in a narrow single-column layout, and complete the same task in screen-reader reading order. Record the instruction, visible label, rendered position, and resulting action. Success reached by guessing indicates missing identification information.

Include translation and state changes. If an English action is renamed, does its help change? If “Save draft” becomes “Update draft,” can the old instruction still identify it? A scanner can flag direction words but cannot determine whether the reference is clear. These checks have not been run, so there is no multilingual or assistive-technology acceptance claim. Start review by withholding the color cue and retaining the words: a reader should still be able to choose the intended action.
