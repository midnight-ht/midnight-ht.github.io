Which ARIA relation preserves a table in a chart’s long description?

Use a quarterly chart, visible table, and ordinary link to compare a structured extended description with a flat accessible description.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-13 · Estimated read 11 min
Translations
zh-CN en

Article

Key takeaways

  • Brief descriptions and navigable details serve different tasks.
  • Keep table headers and values in their original structure.
  • Verify the ordinary page route separately from assistive technology support.

A quarterly chart has a table beneath it. Someone looking up the third-quarter figure needs the relationship between the row, column, and value. Use aria-details to associate the chart with the visible structured explanation. A brief accessible description can offer orientation while the table remains available for looking up a number.

Decide whether the reader needs a sentence or a lookup

WAI-ARIA defines aria-details as a reference to an extended description. That target does not participate in the accessible name or description computation, so the relation does not flatten the table into a description string. The recommendation advises keeping the target visible to everyone. Assistive technology support for announcing or navigating the relation needs testing in the target combinations.

The same recommendation defines aria-describedby for the accessible description. A line such as “Attendance peaks in Q2” can orient a reader. A whole table used as a flat description cannot provide table navigation through that string. The original table can still be navigated through its ordinary page structure.

One reader may only want to know which quarter was highest. Someone recording the Q3 figure needs the value, its quarter, and its unit. Give the second reader a way to reach the details. Headings and labels that describe their purpose covers why the table link and target heading should identify what they contain.

Check the chart, route, and table independently

This complete local HTML has not been run in a browser or with assistive technology. It uses fixed values of 12, 18, and 15 people. The inline chart has a short accessible name and a structured details relation. An ordinary link points to the same visible region, where the heading, caption, and table headers explain the values.

<!doctype html>
<html lang="en">
<meta charset="utf-8">
<title>Quarterly training attendance</title>
<figure>
  <svg width="300" height="128" viewBox="0 0 300 128"
       role="img" aria-label="Quarterly training attendance, Q1 to Q3"
       aria-details="data-notes">
    <g fill="#264478">
      <rect x="36" y="52" width="44" height="48"/>
      <rect x="128" y="28" width="44" height="72"/>
      <rect x="220" y="40" width="44" height="60"/>
    </g>
    <text x="48" y="118">Q1</text>
    <text x="140" y="118">Q2</text>
    <text x="232" y="118">Q3</text>
  </svg>
  <figcaption>Attendance peaks in Q2.
    <a href="#data-notes">Read the attendance table</a>
  </figcaption>
</figure>
<section id="data-notes" aria-labelledby="data-heading">
  <h2 id="data-heading">Attendance by quarter</h2>
  <table>
    <caption>Training attendance in people</caption>
    <thead><tr><th scope="col">Quarter</th><th scope="col">People</th></tr></thead>
    <tbody>
      <tr><th scope="row">Q1</th><td>12</td></tr>
      <tr><th scope="row">Q2</th><td>18</td></tr>
      <tr><th scope="row">Q3</th><td>15</td></tr>
    </tbody>
  </table>
</section>
</html>

For a proposed check, follow the link beside the chart and find 15 in the People column for Q3. The expected value comes from the fixture. An existing ID does not show that a reader can follow the route, recognize the region, or reach a hidden target. In the supported assistive technology combinations, check whether the relation is exposed and whether the table remains navigable. No speech output is assumed.

For a negative control, replace aria-details on the chart with aria-describedby, leaving the visible table and link intact. Inspect the computed description and the page structure separately. Both versions can contain the same numbers. The task is whether a reader can look up a specific value with the structure intact.

Keep the relationship aligned when the chart changes

A dashboard can render several similar charts. The chart and its detail target need distinct IDs and a shared data version. If an update swaps the chart but leaves an older table attached, both components may look valid while the relationship points to the wrong quarter or unit. Include the target data identity in the check. A short note may need only a description. An explanation with tables, headings, or reference links needs a structure the reader can still use.

Can a chart have both a short aria-describedby and a long aria-details?

Yes, but verify how they are exposed. This differs from the main example by adding a separate short description target. WAI-ARIA 1.2 says that aria-details takes precedence in user agents whose accessibility API cannot support multiple descriptive reference relationships. That condition does not establish a universal precedence rule. Keep essential context and the ordinary data link visible, then check the two relationships in the intended environments.
