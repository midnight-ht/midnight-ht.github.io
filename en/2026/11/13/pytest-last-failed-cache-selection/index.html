Why did a green pytest --lf run skip my new test?

Reproduce pytest’s cached failure selection and compare a green rerun with the full test set.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-13 · Estimated read 8 min
Translations
zh-CN en

Article

Key takeaways

  • Cached failures affect which tests run.
  • Keep executed node IDs with the exit status.
  • Compare the selected set with the scope promised by the gate.

The previous failure now passes. The new test never entered this run’s selected set. Pytest’s --lf reruns known failures from its cache. Check what it selected before reading a green result as evidence for the change.

A maintainer fixes yesterday’s failing test and adds coverage for a new requirement. The last-failed rerun returns success. In a release record, that can look like evidence for the new test too. The output supports only the tests that were selected and executed.

Make the omitted test fail on purpose

In a disposable directory, save the first file as test_selection.py and add a pytest.ini containing only [pytest]. Disable external plugin autoload and any environment-supplied pytest arguments. Run python -m pytest -v and let the intentional failure seed the local cache.

def test_old():
    assert False

def test_stable():
    assert True

Keep the directory and filename. Replace the file with this version. It fixes the old failure and adds a new intentional failure.

def test_old():
    assert True

def test_stable():
    assert True

def test_new():
    assert False

Run python -m pytest -v --lf, then repeat the ordinary invocation without last-failed selection. Save all three outputs and process statuses. The local run used Python 3.11.15 and pytest 9.0.2. The archived driver wrote these same file contents and asserted the subprocess outcomes.

Run Key observation Exit
Seed the cache Old case fails, stable case passes 1
Last-failed rerun Old case passes, other cases do not run 0
Full run New case fails 1

The driver’s own successful exit confirms that it observed the expected results. Two pytest subprocesses failed on purpose.

The pytest cache guide describes last-failed selection as rerunning failures. The first run left the old test’s node ID in the cache, and that ID still resolved after the edit. The new test was in the same source file but outside the known failures. Verbose output records which tests actually ran. The separate full run proves the omitted test would have failed.

The negative case would be less revealing if the skipped test happened to pass. In a real gate it could cover a new input boundary unrelated to the previous failure. Keep the executed node IDs with the outcomes. This fixture puts all three tests in one file to isolate cache selection from an explicit file argument.

Keep the quick rerun and the release check separate

Use last-failed selection when the immediate job is reproducing a known failure. If you want to see known failures first and still run the rest of the selected tests, the guide describes --ff. This article did not run that variant. It changes ordering within the selected scope. It cannot restore tests excluded by a file argument or another selection expression.

A CI runner might restore the cache or inherit it from its working directory. When paths or names change, compare the current node IDs with the selection that actually ran. Record what was discovered, what was selected, and what executed. Discovering the file gives no result for an individual test that never ran. For a separate problem involving a test that did run, see how an unexpected pass can leave a gate green.

Keep the original cached-run output if you need to explain what happened. Run the complete gate separately against the same version and save its own result. The first log can explain the selection while the second supplies release evidence.

What happens with --lfnf none and no known failures?

The cache guide says this setting runs no tests and exits successfully. In a separate clean directory with the same pytest version, --lf --lfnf none collected one test, deselected it, selected zero, and returned exit status five. The outer verification driver exited zero after checking those observations. The versioned cache selection implementation clears the selected list, and the main entry point in that version returns NO_TESTS_COLLECTED for the empty run on this path. Verify the executable version, selected count and return code together.
