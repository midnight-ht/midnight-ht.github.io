Why can constant targets make the default R² score only zero or one?

Explain non-finite constant-target R² through SSE and SST, retain the replacement parameter, and compare a finite zero.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-21 · Estimated read 13 min
Translations
zh-CN en

Article

Key takeaways

  • Constant targets remove variation from the denominator
  • The default policy distinguishes perfect and imperfect predictions
  • Retain squared sums and parameters alongside scores

Three targets are all five. Perfect predictions receive R² one and imperfect predictions receive zero. With scikit-learn's default force_finite setting, those can be replacements for non-finite constant-target results. Retain that condition before interpreting the numbers as ordinary regression performance.

Constant targets remove variation from the baseline

For this unweighted single-output case, R² is one minus residual squared error, SSE, divided by the target's squared deviations from its mean, SST. Constant targets at five have mean five and SST zero.

Perfect predictions also give SSE zero, producing zero divided by zero in the raw formula. Predictions all equal to four give SSE three, so the raw R² becomes negative infinity. These differ from a nonconstant target with a finite denominator.

The current r2_score reference documents both branches. The default force_finite=True replaces a perfect prediction's NaN with one and an imperfect prediction's negative infinity with zero. False retains the non-finite results. The option was added in version 1.1; this article reads the 1.9.1 reference.

That convenience does not create target variation. Two zero scores on constant targets also do not establish equal residual errors. Different imperfect predictions can share the substituted result. Retain the error and its conditions.

The mean comes from the current true targets, rather than training targets or predictions. Recompute it for another target batch so the denominator describes that batch. Retaining the targets also lets a later review detect accidental reuse of a mean from another dataset.

Four policy cases and a finite zero counterexample

This complete script evaluates the formula in standard JavaScript and demonstrates the documented replacement policy. It accepts only the fixed inputs of at least two targets used here. It implements no complete r2_score API, calls no Python package, and trains no model. Non-finite log values receive explicit markers.

import { deepEqual } from 'node:assert/strict';
const sum = values => values.reduce((total, value) => total + value, 0);
function describe(target, predicted, forceFinite) {
  if (target.length < 2) throw new RangeError('Fixture needs at least two targets');
  const mean = sum(target) / target.length;
  const sse = sum(target.map((value, index) => (value - predicted[index]) ** 2));
  const sst = sum(target.map(value => (value - mean) ** 2));
  const raw = 1 - sse / sst;
  const score = forceFinite && sst === 0 ? (sse === 0 ? 1 : 0) : raw;
  return { sse, sst, score };
}
const constant = [5, 5, 5];
const perfect = [5, 5, 5];
const imperfect = [4, 4, 4];
const cases = [
  [constant, perfect, true], [constant, perfect, false],
  [constant, imperfect, true], [constant, imperfect, false],
  [[4, 5, 6], [5, 5, 5], true]
];
const actual = cases.map(([target, predicted, finite]) => describe(target, predicted, finite));
deepEqual(actual, [
  { sse: 0, sst: 0, score: 1 },
  { sse: 0, sst: 0, score: NaN },
  { sse: 3, sst: 0, score: 0 },
  { sse: 3, sst: 0, score: -Infinity },
  { sse: 2, sst: 2, score: 0 }
]);
const output = JSON.stringify(actual, (_key, value) =>
  typeof value === 'number' && !Number.isFinite(value) ? String(value) : value
);
console.log(output);

Exact local Node execution passed all five literal expectations. Perfect constant-target predictions produced one or NaN depending on the policy. Imperfect predictions produced zero or negative infinity. The assertions retain SSE and SST alongside each score.

The fifth case changes targets to four, five, six with predictions all five. SSE and SST are both two, giving a finite zero. That number matches the substituted constant-target zero while its calculation conditions differ. Saving only zero loses that distinction.

The log renders NaN and negative infinity as strings; assertions still compare numeric results. Do not treat those display markers as a model API's return types. The receipt establishes local arithmetic on fixed data and no service's actual predictive quality.

Preserve evidence of the degenerate condition

Retain sample count, target revision, SSE, SST, force_finite, and final score. That lets a reader trace a substituted zero to its zero denominator. A multi-fold aggregate also needs a declared policy for non-finite folds and substituted values.

Silently deleting every constant-target fold can change the evaluated population. Inspect whether constancy comes from the task, sampling, or preparation, then use the declared evaluation contract. No actual training data was changed and no universal deletion policy is proposed.

A product acceptance test may also care about error in concrete units. R² does not replace that requirement. These three artificial samples explain a parameter and establish neither representative quality nor a real model ranking.

Changing force_finite between reports can change presentation with identical predictions. Lock the parameter and input for version comparisons or report the parameter change explicitly. A reporting-policy change does not by itself establish a change in model ability.

Splitting determines which targets share a fold. See group counts and row counts in grouped splits. Here the targets are already fixed and the denominator is inspected afterward. Correct group isolation does not establish target variation in every fold.

A summary can mark constant-target rows and retain the raw sums for inspection. Identical displayed zeroes can then be traced to distinct conditions. Choose a representation appropriate to the report; color alone does not explain the source of a degenerate result.

Does one test sample become one under force_finite too?

Do not transfer the main pattern to this new condition. Every main case has three samples. The r2_score reference separately states that fewer than two samples is not well-defined and returns NaN. Distinguish that condition from the constant-target policy for at least two samples.

The teaching function rejects smaller inputs instead of pretending to implement every library branch. This statement comes from documentation, without a local Python-package result. A real evaluation producing single-sample folds should retain the count and validate its handling at the actual entry point instead of filling every NaN with one.
