Why does a reverse LPOS search still return a head-based index?

Compare occurrence rank, head-based positions, reverse result order, and a limited MAXLEN search.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-21 · Estimated read 9 min
Translations
zh-CN en

Article

Key takeaways

  • Negative RANK changes traversal, not the index origin.
  • COUNT results follow encounter order.
  • A bounded MAXLEN miss describes only the searched scope.

LPOS with RANK -1 searches backward for X but still returns its head-based index. In A, X, B, X, X, the final X is at four. A negative rank changes search direction and occurrence selection, leaving the returned coordinate system intact.

Occurrence rank and list position

The five positions run from zero to four. X appears at one, three, and four. The first forward match is one and the second is three. The first backward match is four and the second is three. Treating rank as an index or a tail-relative distance can select the wrong element.

The documentation defines zero-based list positions and negative rank as reverse traversal. Record both the requested occurrence and actual offset; rank minus one and index four are consistent.

The position belongs to the list at query time. A later head insertion or deletion can move it. A deferred modification needs a policy for version and target identity. The fixture first isolates coordinate behavior without concurrent writers.

Make the two numbering systems visible

This Redis fixture is unexecuted. Use an initially absent key in a disposable database with no concurrent writer or expiry. The last three commands support the bounded-search follow-up.

RPUSH review:lpos:nov21 A X B X X
LPOS review:lpos:nov21 X RANK 1
LPOS review:lpos:nov21 X RANK 2
LPOS review:lpos:nov21 X RANK -1
LPOS review:lpos:nov21 X RANK -2
LPOS review:lpos:nov21 X RANK -1 COUNT 2
LRANGE review:lpos:nov21 0 -1
LPOS review:lpos:nov21 X MAXLEN 1
LPOS review:lpos:nov21 X MAXLEN 2
LPOS review:lpos:nov21 X RANK -1 MAXLEN 1

After initialization, length is five. Ranks one, two, minus one, and minus two yield one, three, four, and three. The two second-match results coincide, so that single case cannot distinguish direction. The first-versus-last control can. One matching X alone would also fail to exercise occurrence selection.

Rank minus one with count two returns four, three in traversal order. It does not sort the offsets ascending or convert them into tail distances. Any sorting for presentation is a client transformation, with its own expected result.

The list must remain A, X, B, X, X afterward. LPOS reads without removing or moving matches. An integer result alone cannot establish either correct direction or unchanged source state.

Decide whether to retain a coordinate or an identity

A stable snapshot can highlight index four directly. A selection retained across requests may need an element identifier and a version check. Identical X payloads deliberately lack such identity here, making content and position distinct.

The site's worker claim and recovery article concerns processing ownership. A position lookup creates no claim. A task consumer needs a modifying or coordinating operation under its own contract.

Diagnostics can retain requested rank, returned index, and search scope. Three might be a second match from either end. A UI showing an occurrence number and one showing a position need separately specified numbering conventions.

For stronger regressions, use asymmetric locations and distinct head and tail markers. Assert complete index sequences, rather than merely that each result points at X. An implementation always returning the first X could pass a content-only test. This fixture's markers and three matching positions supply asymmetric offsets.

All results are expectations from documentation, with no server or client execution. Client libraries may represent absent results differently. A textual nil expectation is not an observed language object or network receipt.

Does a MAXLEN miss prove X is absent from the whole list?

MAXLEN limits comparisons. One forward comparison sees only A and misses. Two reach X at one. One reverse comparison with rank minus one sees the tail X and returns four. The last three commands distinguish those scopes.

A bounded miss cannot establish global absence. Use an appropriate full-search contract when that is required. Zero MAXLEN allows unlimited comparisons according to the documentation. Actual latency still needs service-specific verification; this fixture measures no performance.
