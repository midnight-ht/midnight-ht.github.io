Why does heapreplace evict the old minimum for an even smaller input?

Compare returned and retained values for two incoming scores, then verify the empty-heap startup condition.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-21 · Estimated read 10 min
Translations
zh-CN en

Article

Key takeaways

  • heapreplace removes an old root and inserts the incoming item.
  • heappushpop includes the incoming item in smallest-value eviction.
  • Empty-heap startup needs its own capacity policy.

A heap retaining the largest three values contains two, three, and five. An incoming zero makes heapreplace evict two and retain zero. It removes the old root before inserting the new item. If the incoming item must compete for eviction, heappushpop returns the smaller value and leaves the larger one in the heap.

Capacity does not decide retention

A min-heap can hold the current highest three scores. Its smallest retained score, two, is the admission threshold. An incoming four should replace two. Both operations do that, so testing only a qualifying value conceals their difference.

Zero is below the threshold. heapreplace nevertheless removes a value from the old heap and puts zero in. Capacity stays three. The resulting heap remains valid even though it violates the top-three policy. A length check cannot establish the desired retained set.

heappushpop includes the new item in the competition for the smallest value. Zero comes back out and two, three, five remain. Separate the heap invariant from the application selection rule.

Observe the returned and retained values

Each trial creates two fresh equal heaps. It checks the return and the complete retained collection. Sorting is solely a test observation; heap storage itself need not be globally sorted.

from heapq import heapreplace, heappushpop

for incoming, replaced, combined in [
    (0, (2, [0, 3, 5]), (0, [2, 3, 5])),
    (4, (2, [3, 4, 5]), (2, [3, 4, 5])),
]:
    first, second = [2, 3, 5], [2, 3, 5]
    out = heapreplace(first, incoming)
    assert (out, sorted(first)) == replaced
    out = heappushpop(second, incoming)
    assert (out, sorted(second)) == combined
empty = []
try:
    heapreplace(empty, 7)
except IndexError:
    assert empty == []
else:
    raise AssertionError("empty replacement must fail")
assert heappushpop(empty, 7) == 7
assert empty == []
print("incoming0: replacement retained0; pushpop retained2,3,5; empty controls passed")

For zero, replacement returns two and retains zero, three, five. Push/pop returns zero and retains two, three, five. For four, both return two and retain three, four, five. The latter confirms the shared qualifying-input case; the former separates their policies.

A return-only assertion can miss downstream code appending a rejected value back into the collection. A retained-set-only assertion can miss a consumer recording the wrong evicted identity. Keep both observations when a service reports selection decisions.

The local fixture covers short integer heaps and the empty case. It runs no ranking service, persistence, or concurrent access and measures no throughput. A combined primitive's documented operation count cannot substitute for a workload measurement.

A correct final set can conceal a wrong intermediate set. Starting again with two, three, five, feed negative two, four, and eight. Unconditional replacement first admits negative two, then later values happen to recover the correct final four, five, eight. A batch-end assertion misses the first lost candidate.

If each update publishes a shortlist, require two, three, five after negative two; three, four, five after four; and four, five, eight after eight. This additional sequence is a proposed acceptance test outside the executed fixture. Final membership and every visible intermediate list are distinct promises.

Put the admission rule at the intended boundary

heapreplace fits a caller that has already established eligibility. Test that the upstream gate rejects an under-threshold value. Without that guarantee, let the incoming value participate in eviction or compare explicitly before replacing. An unfiltered second entry point would invalidate an assumption made only by the first.

Keeping the smallest values changes the direction. Start from a small independent expected shortlist before choosing the heap policy. Negative and tied values need their own requirements, especially when equal scores must preserve arrival order.

The site's tied-priority heap article discusses payload comparison and tie order. This example isolates admission with distinct integers. Real candidate objects need assertions on comparison fields, tie policy, and evicted identity.

A service test can send one candidate set in different orders and compare the final shortlist with an independently sorted top three. Correlate rejection records with each actual input. Selection also differs from executing a candidate: evicting it cannot retract an external effect. This fixture selects without execution.

What happens on an empty heap?

heapreplace raises IndexError because no root exists to replace. heappushpop returns the incoming item and leaves the heap empty. The fixture checks both with seven. Startup logic must decide whether to push until capacity is reached or intentionally retain nothing. Applying a full-heap update routine to an empty shortlist can reject every candidate. Test that capacity state separately from the comparison on a full heap.
