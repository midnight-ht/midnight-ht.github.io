Why can IME text still change after beforeinput.preventDefault()?

Use the Input Events Level 2 Working Draft to distinguish ordinary edits from IME composition, with a textarea trace, post-edit validation and bounded correction.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-09 · Estimated read 17 min
Translations
zh-CN en

Article

Key takeaways

  • Composition input types and ordinary insertText have different cancelability.
  • Separate the editing process from accepted values without rewriting active composition.
  • Keep native IME traces distinct from synthetic tests and identify the editing host.

For insertCompositionText, the current Input Events Level 2 draft makes composition updates non-cancelable. Record inputType, cancelable and composition state before choosing interception or later reconciliation. Beforeinput occurring before an edit does not mean every edit can be stopped with preventDefault.

Input Events Level 2 is an October 15, 2026 Working Draft whose test suite and implementation reports remain in progress. This article explains its type table and composition sequence; it does not certify a particular browser or system IME, or say that every beforeinput event is non-cancelable.

Ordering and cancelability are separate

The draft distinguishes ordinary insertText from insertCompositionText during composition. The latter is non-cancelable. Repeated preventDefault calls do not change cancelable from false to true. A running handler is not evidence that the edit was blocked.

A composition session starts with compositionstart. Updates produce compositionupdate followed by beforeinput and input; the active passage changes between the latter two. Compositionend closes the session. Candidate selection, confirmation and cancellation are not equivalent to independent ordinary insertions for every keypress.

IsComposing is useful context, not a replacement for cancelable or a universal business-state classifier. Record event type, inputType, session state and actual value together. A cancelable edit can still be invalid; a non-cancelable edit need not be accepted for submission.

A fixture that does not rewrite active composition

This complete HTML is unexecuted. It models a teaching code restricted to ASCII letters, digits and hyphens—not a name, address or multilingual document. It intercepts only ordinary cancelable insertText, evaluates other edits after input, and provides explicit correction that refuses to run during composition.

<!doctype html>
<meta charset="utf-8">
<title>Composition input trace</title>
<label>Teaching ASCII code <textarea id="code"></textarea></label>
<p id="status" role="status">Empty code</p>
<button id="clean" type="button">Apply teaching ASCII correction</button>
<button id="check" type="button">Validate teaching code</button>
<pre id="out"></pre>
<script>
const ids = ['code', 'status', 'out', 'clean', 'check'];
const elements = Object.fromEntries(ids.map(id => [id, document.getElementById(id)]));
const { code, status, out, clean: cleanButton, check: checkButton } = elements;
let composing = false;
const rows = [];
const allowed = value => /^[A-Za-z0-9-]*$/.test(value);
const write = (node, text) => { node.textContent = text; };
const nullable = value => value === undefined ? null : value;
function assess() {
  if (composing) write(status, 'Composition active; not rewriting');
  else if (allowed(code.value)) write(status, 'Allowed teaching characters');
  else write(status, 'Correction required');
}
function record(event) {
  const { type, inputType, cancelable, isComposing, data } = event;
  const { value, selectionStart: start, selectionEnd: end } = code;
  rows.push({ type, inputType: nullable(inputType), cancelable,
    isComposing: nullable(isComposing), composing, data: nullable(data),
    value, start, end });
  write(out, JSON.stringify(rows.slice(-30), null, 2));
}
const handlers = {
  compositionstart(event) { composing = true; record(event); assess(); },
  compositionupdate: record,
  compositionend(event) { composing = false; record(event); assess(); },
  beforeinput(event) {
    record(event);
    if (!composing && !event.isComposing && event.cancelable &&
        event.inputType === 'insertText' && event.data !== null &&
        !allowed(event.data)) event.preventDefault();
  },
  input(event) { record(event); assess(); }
};
for (const [type, handler] of Object.entries(handlers)) {
  code.addEventListener(type, handler);
}
cleanButton.onclick = () => {
  if (composing) { assess(); return; }
  const at = code.selectionStart;
  const clean = value => value.replace(/[^A-Za-z0-9-]/g, '');
  const nextAt = clean(code.value.slice(0, at)).length;
  code.value = clean(code.value);
  code.setSelectionRange(nextAt, nextAt);
  assess(); code.focus();
};
checkButton.onclick = () => {
  if (!composing && code.value.length > 0 && allowed(code.value)) {
    write(status, 'Teaching validation passed; nothing submitted');
  } else write(status, 'Not accepted; finish editing or correct the code');
};
</script>

There are three independent expectations. Ordinary permitted characters remain. Cancelable ordinary invalid insertText can be intercepted. Invalid text arriving through composition or another unintercepted path is marked after the edit without rewriting every composition update. The final button also rejects empty or unfinished input and sends no request; its success message is not server acceptance.

Correction deliberately loses information: it removes disallowed characters and collapses the selection to the number of retained characters before the old selection start. It does not preserve a noncollapsed selection, an undo history or rich-text structure. A real product may be better served by an error and user correction than automatic deletion.

The input handler deliberately avoids rewriting value on every update. Mutating the active composition passage can disrupt candidate selection or caret state. A later strategy need not delete immediately: mark invalid final text, allow composition to finish, and offer explicit correction and revalidation. Failure to intercept is not permission to submit.

A native-input oracle can start with the ASCII prefix AB-, compose a Chinese character, confirm it, and press Validate. If that character reaches the final value, the result must be rejection rather than teaching success. Applying the explicit correction should retain AB-, after which typing 7 should yield AB-7 and allow validation. Canceling the composition is a separate case: preserve the trace and actual value rather than assuming confirmation and cancellation produce identical edits. These are proposed expectations, not captured IME results.

Synthetic events do not exercise a system IME

Constructing a non-cancelable InputEvent can test handler branching. It neither starts a system IME nor produces the same default editing behavior. An event trace matching a dispatch script proves that script's calls, not a real composition sequence.

Use the target OS, browser and IME for updating candidates, selection, confirmation and cancellation. Also cover paste, automatic replacement, selected-text replacement and undo. The pre-edit branch handles only insertText; post-input evaluation reads the resulting value from other paths. Programmatic value assignment is another entry point whose owner must invoke assessment rather than assuming a user input event appears automatically.

Preserve environment versions, traces, text and caret positions, then continue editing after correction. Keep synthetic-handler tests distinct from native-input evidence. Actual logs should use nonsensitive teaching text rather than export passwords or personal content.

Does an empty textarea getTargetRanges result mean no edit happened?

No. The draft overview gives textarea and text inputs empty range arrays, with different rules for contenteditable. An empty array cannot establish that value did not change. This fixture instead records selectionStart, selectionEnd and value for its textarea host.

Those offsets are not interchangeable with DOM StaticRange handling in rich text. Node structure, selection and an editor's data model need separate reconciliation. A string filter applied blindly to contenteditable can lose formatting or locate the wrong edit. Identify the host before selecting an observation and recovery strategy.

Passive listeners and cancellation flags covers the general cancellation conditions. The added scope here is IME composition and editing-host behavior. No browser or system-IME test was run for this article. Acceptance belongs to the final field contract, not the presence of a preventDefault call in a log.
