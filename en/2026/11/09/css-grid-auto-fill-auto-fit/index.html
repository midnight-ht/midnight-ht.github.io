Two cards, three Grid columns: why does an empty column keep its space?

Calculate empty-track behavior in a 900px grid with 20px gaps, then use four cards, spanning and indefinite sizing to define the choice.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-09 · Estimated read 14 min
Translations
zh-CN en

Article

Key takeaways

  • Auto-fit collapses empty repeated tracks and adjacent gutters after placement.
  • Empty last-row cells are not empty columns when other items occupy or span them.
  • Repeat counting comes before collapse; inspect its fallback for indefinite constraints.

With room for three columns but only two cards, auto-fill keeps the third repeated track. Auto-fit collapses an empty repeated track after placement. Explain a card's width by calculating the track count and then checking whether an entire track is empty—not by counting unused cells in the last row.

The reference is CSS Grid Layout Module Level 2, automatic repetition, the March 26, 2025 Candidate Recommendation Draft. This article concerns a standalone grid axis. It does not establish target-browser compatibility or explain every subgrid rule.

Track creation precedes empty-track collapse

Auto-fill calculates repetitions from relevant container constraints, track sizes and gaps. The initial count is the same for auto-fit, but empty repeated tracks collapse after placement. Changing the keyword therefore need not change widths in every layout.

An empty track has no in-flow item placed in it or spanning it. With three columns and four cards, the first row already occupies every column. Two vacant cells in the second row do not make their columns empty. Auto-fit does not expand the final card to a full row.

A collapsed track has a fixed zero-pixel sizing function, and its adjacent gutters collapse. Nonempty tracks using fr can then receive more remaining space. That collapse does not directly assign card widths. With fixed maximum track sizes, it need not convert every unused pixel into wider cards.

A two-card fixture with independent arithmetic

The complete HTML below is unexecuted. Both containers are 900px wide with 20px gaps and minmax(250px,1fr) columns. Borders and horizontal padding are absent to isolate track sizing. The cards have no product data or business behavior.

<!doctype html>
<meta charset="utf-8">
<title>Auto-repeat teaching fixture</title>
<style>
.grid { display: grid; width: 900px; gap: 20px; margin-bottom: 20px; }
.fill { grid-template-columns: repeat(auto-fill, minmax(250px, 1fr)); }
.fit { grid-template-columns: repeat(auto-fit, minmax(250px, 1fr)); }
.card { min-width: 0; background: #eee; padding-block: 20px; }
</style>
<h1>Two cards in identical containers</h1>
<div class="grid fill" id="fill"><div class="card">A</div><div class="card">B</div></div>
<div class="grid fit" id="fit"><div class="card">A</div><div class="card">B</div></div>
<button type="button" id="add">Add C and D once</button>
<pre id="out"></pre>
<script>
const byId = id => document.getElementById(id);
const ids = ['fill', 'fit'];
function report() {
  byId('out').textContent = JSON.stringify(
    ids.map(id => {
      const grid = byId(id);
      return { id, tracks: getComputedStyle(grid).gridTemplateColumns,
        widths: [...grid.children].map(n => n.getBoundingClientRect().width) };
    }), null, 2);
}
byId('add').addEventListener('click', event => {
  for (const id of ids) {
    for (const label of ['C', 'D']) {
      const card = document.createElement('div');
      card.className = 'card'; card.textContent = label;
      byId(id).append(card);
    }
  }
  event.currentTarget.disabled = true;
  report();
});
report();
</script>

Three minimum-width columns plus two gaps require 790px; four columns plus three gaps require 1060px. Thus three repetitions fit. Auto-fill retains all three, giving an expected width of approximately 286.67px per track. This is a derived expectation, not observed browser output.

With auto-fit, the third column is empty and collapses. Two active columns share the remaining width around one 20px gap, producing 440px each. Inspect both the computed track list and item rectangles. Compare with a rounding tolerance rather than demanding one exact decimal-string format.

Adding C and D creates four cards. The first three occupy all columns and the fourth wraps. Neither layout now has an empty column to collapse, so the last card does not fill 900px. This counterexample checks whether an acceptance criterion incorrectly equates empty cells with empty tracks.

Spanning changes whether a track is empty

An in-flow item spanning columns two and three keeps both nonempty, even without a separately placed card in column three. Inspect explicit placement, spans and automatic placement; direct-child count alone cannot explain track occupation.

Invisible content does not automatically stop participating in layout either. The relevant question remains whether an in-flow grid item occupies or spans the track. Use a grid overlay and box measurements rather than card color to infer structure.

Automatic repetition also restricts syntax. The familiar minmax(250px,1fr) includes a fixed minimum used for counting. An arbitrary replacement involving intrinsic or flexible sizing may no longer be valid auto-repeat syntax. Check whether the declaration is accepted before diagnosing why auto-fit appears ineffective.

Why can an indefinite container produce one repetition?

For a standalone axis, the specification first uses a relevant definite preferred or maximum size, then a definite minimum size. If neither supplies the counting condition, the specified track list repeats once. A single-column outcome is therefore not always evidence of empty-track collapse.

This occurs during counting, before post-placement collapse. Record container constraints, repeat sizes and available space. A literal width:auto does not independently prove that the size is indefinite; the containing block and layout context matter. Removing the fixture's fixed width does not justify attributing every subsequent result to the same rule.

Choose auto-fill when retaining available slots and their column allocation matches the product. Choose auto-fit when truly empty tracks should collapse so occupied flexible tracks receive more space. If each row, including a short last row, must distribute its own width independently, design that behavior separately.

Proposed verification covers two cards, four cards, spanning, no items and changing constraints, preserving declarations, placements, computed tracks and box widths. This differs from sharing subgrid tracks: first determine which independent columns exist. No browser run is claimed here. Test the four-card counterexample before approving a promise that every last row will fill.
