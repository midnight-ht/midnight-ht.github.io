Why can two pytest files with the same name collide during collection?

Compare pytest’s default import mode with importlib mode for same-named tests in non-package directories.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-14 · Estimated read 8 min
Translations
zh-CN en

Article

Key takeaways

  • Different paths can resolve to the same test module name.
  • Verify both executed node IDs as well as exit status.
  • Ordinary test utilities and fixtures use different discovery paths.

Two non-package directories each contain test_rules.py. Different paths can still occupy the same module name in pytest’s default import mode. Check the two paths in the error before changing the package layout or import mode.

Each directory can pass alone, yet a combined run can stop during collection. The collision concerns the name used to load a module. A unique path on disk does not ensure a unique name in Python’s module table.

Read both paths in the collection error

With its default prepend mode, pytest can put a test directory on the import path. Tests outside a package layout need unique module names because the imports are registered in Python’s module table. An error may point to the module already imported and the file pytest is trying to collect. This happens before the business assertion runs. Pytest import mechanisms

In importlib mode, pytest does not change sys.path and can generate a unique name for a test it loads directly. Ordinary imports still matter. If a test used a directory that pytest previously added to the search path, check whether its helpers remain importable after changing modes.

Keep both files and change only the import mode

Create a disposable directory and put a pytest.ini containing only [pytest] in its root. Save these complete test files under alpha and beta without adding __init__.py. Run from that root with external pytest plugin autoload and environment-supplied pytest arguments disabled.

# alpha/test_rules.py
def test_alpha():
    assert sum([1, 1]) == 2

# beta/test_rules.py
def test_beta():
    assert sum([2, 2]) == 4

Run python -m pytest -v --import-mode=prepend and python -m pytest -v --import-mode=importlib. The archived driver ran both with Python 3.11.15 and pytest 9.0.2. The prepend run reported an import file mismatch during collection and exited two. The importlib run exited zero and reported one passing node in each file.

Check the full node IDs and their results. If a directory had been excluded, the remaining test could still pass. A separate control could intentionally fail one test and check that the reported failure names the right directory. That control has not been run.

Keep the original mismatch output. It records the imported module path and the path of the file being collected. Both files in this exercise were new, so an old bytecode cache was not required for the mismatch. For a real incident, check the resolved module path and package layout before attributing the error to stale files.

Choose a layout that preserves the needed imports

If the two directories are naturally separate Python packages, make that layout explicit or give the files unique names. That can preserve the current import mode. If you need non-package directories and want pytest to leave the import path alone, importlib mode can fit. Inventory direct imports from test helpers before switching. Move shared helpers into an importable package and verify that the environment installs or locates it normally.

Record the application package’s origin separately. Both test modules can collect while importing an installed copy of the application. The node IDs establish which tests ran. The resolved module path or version helps establish what those tests exercised.

Run the two-file check and then inspect collection and execution across the actual project. File patterns, configuration and plugins can change the selected set. For a different omission caused by cached test selection, see why a last-failed rerun can omit a new test.

Do fixtures in conftest.py need an ordinary import?

No. Pytest documents fixture discovery through conftest.py separately from direct imports of test utility modules. An alpha fixture can provide a recognizable sample. Request it through a test parameter and check the returned marker. The main fixture does not exercise that variation. For a shared fixture, confirm that the conftest.py location covers the directories that use it.
