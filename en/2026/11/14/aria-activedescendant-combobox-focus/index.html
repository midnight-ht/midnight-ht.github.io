How can a highlighted suggestion leave the search input ready for typing?

Separate DOM input focus, active suggestions, and commit in an editable combobox, then check the reference when suggestions refresh.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-14 · Estimated read 14 min
Translations
zh-CN en

Article

Key takeaways

  • The active suggestion can change while DOM focus stays on the input.
  • The active reference must identify a valid item in the current popup.
  • Check keyboard movement, filtering, and commit separately.

Down Arrow highlights the second suggestion. The next character should still go into the search input. In an editable combobox with a list popup, keep DOM focus on the input and use aria-activedescendant to identify the active suggestion. Highlighting, typing, and committing a value have different conditions.

Track real focus and the active item separately

WAI-ARIA defines aria-activedescendant for supported controls that report an active object while DOM focus stays on the controlling element. A combobox can connect its popup with aria-controls and reference an eligible item within it. The property does not supply keyboard behavior or move DOM focus.

Imagine a course picker with three suggestions. The user moves to Biology, then starts searching for a course beginning with C. If the application moved focus into the option to highlight it, the next character might not enter the input. Retaining input focus keeps the native text operation available. Updating the active reference still tells the application which candidate the user is exploring.

An active suggestion can be selected inside the popup while the input still holds an uncommitted string. In this example, Enter or a click commits the name. If a product uses a different preview or autocomplete policy, check how cancellation and subsequent edits behave.

Follow one keyboard sequence

This complete local HTML has not been run in a browser or with assistive technology. It demonstrates a limited list-popup example rather than a production remote search control. Start on the input with no active suggestion. Press Down Arrow twice. The active option should change from Algebra to Biology while the real focus stays on the input and its value remains empty. Type c. The input should receive it, the list should show Ceramics, and the old active reference should disappear.

<!doctype html>
<html lang="en">
<meta charset="utf-8">
<title>Editable course suggestions</title>
<style>
[aria-selected="true"] { background: #173959; color: white; }
</style>
<label for="course">Course</label>
<input id="course" role="combobox" aria-controls="choices"
       aria-autocomplete="list" aria-expanded="false" autocomplete="off">
<ul id="choices" role="listbox" aria-label="Courses" hidden></ul>
<script>
const get = id => document.getElementById(id);
const [input, list] = ['course', 'choices'].map(get);
const all = ['Algebra', 'Biology', 'Ceramics'];
let matches = [], active = -1;
const write = (node, name, value) => node.setAttribute(name, String(value));
const activeAttr = 'aria-activedescendant';
const cancel = event => event.preventDefault();

function show(items, index = -1) {
  matches = items;
  active = index;
  input.removeAttribute(activeAttr);
  const rows = items.map(text => {
    const option = document.createElement('li');
    option.id = 'choice-' + text.toLowerCase();
    write(option, 'role', 'option');
    write(option, 'aria-selected', 'false');
    option.textContent = text;
    return option;
  });
  list.replaceChildren(...rows);
  list.hidden = rows.length === 0;
  write(input, 'aria-expanded', !list.hidden);
  if (active >= 0) {
    const option = rows[active];
    write(option, 'aria-selected', 'true');
    write(input, activeAttr, option.id);
    option.scrollIntoView({ block: 'nearest' });
  }
}
function filtered() {
  const prefix = input.value.toLowerCase();
  return all.filter(name => name.toLowerCase().startsWith(prefix));
}
function commit(value) {
  input.value = value;
  show([]);
}
input.oninput = () => show(filtered());
input.onblur = () => show([]);
input.onkeydown = event => {
  const { key, isComposing } = event;
  if (isComposing) return;
  if (key === 'ArrowDown' || key === 'ArrowUp') {
    const items = matches.length ? matches : filtered();
    if (!items.length) return;
    const last = items.length - 1;
    const next = key === 'ArrowDown' ? Math.min(active + 1, last)
      : active < 0 ? last : Math.max(active - 1, 0);
    cancel(event);
    show(items, next);
  } else if (key === 'Enter' && active >= 0) {
    cancel(event);
    commit(matches[active]);
  } else if (key === 'Escape' && matches.length) {
    cancel(event);
    show([]);
  }
};
list.onmousedown = cancel;
list.onclick = event => {
  const option = event.target.closest('[role="option"]');
  if (option && list.contains(option)) commit(option.textContent);
};
</script>
</html>

Press Down Arrow and then Enter. The input takes Ceramics, the popup closes, and the active reference is removed. Escape closes an open popup without committing. Other text keys remain native; the handler skips its custom actions during a composing event. Check actual target editing and composition behavior separately.

For a negative, make the options focusable and move DOM focus to the active option. The highlighted row can look identical while document.activeElement and the destination of the next typed character change. A different failure is updating the style without the active reference. Record focus, reference target, visible options, input value, and commit at their own steps.

Keep the reference tied to the current popup

When replacing suggestions, remove the old reference and update it only for an eligible new option. If the application reuses elements, verify that the target belongs to the current list and represents the current result. A matching ID somewhere in the document is insufficient.

Use the APG combobox keyboard guidance to select and test the intended pattern. DOM focus inspection can establish where keyboard input goes. It does not establish an assistive technology announcement. Navigation current state and tab selection uses actual focus movement among tabs. The editable input here keeps focus in place.

What if a server refresh removes the active suggestion?

Do not keep a reference to the missing option. The main fixture clears its active item on input; here a background response replaces the results. If Biology is active and the server returns only Ceramics, clear the reference or select a valid replacement under an explicit policy. Keep focus on the input and check that Enter cannot commit the removed suggestion. Check response ownership before applying any results from an earlier query.
