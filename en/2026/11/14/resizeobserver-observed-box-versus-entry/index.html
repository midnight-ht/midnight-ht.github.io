Why can ResizeObserver report a border box but stay silent when padding changes?

Use two subscriptions on one element to separate the ResizeObserver trigger from the sizes in its entry.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-14 · Estimated read 10 min
Translations
zh-CN en

Article

Key takeaways

  • The box option determines which size change triggers notification.
  • An entry can contain several box measurements.
  • Hold the content size fixed and change padding to separate the two.

The callback reads borderBoxSize, but a padding change produces no new entry in the default observer. ResizeObserver chooses what to watch when you subscribe. Its entries can carry several box measurements. If a layout depends on the border edge, observe the border box and check the notifications as well as the value read by the callback.

Choose the change that should trigger work

Resize Observer defines the observe option, with content-box as the default. The observer compares the selected measurement with what it last reported. A ResizeObserverEntry can contain both content and border box measurements. Reading one of them does not subscribe to changes in that measurement.

Suppose a toolbar aligns with the outside edge of a card that has a fixed 200-pixel content area. Increasing the card’s padding moves its edge. The default observer may have delivered the correct outer measurement earlier, then stay silent on the padding-only change. Check which box was selected before investigating how the callback reads it. A consumer concerned with the card’s content area may still want the default.

Compare two subscriptions on the same element

This complete HTML fixture has not been run in a browser. It uses a single unfragmented card with a width of 200 pixels, padding of 10 pixels and a border of 2 pixels on each side. The initial border box is 224 pixels wide. Both observers report measurements. The first button becomes available after their initial entries, and increases padding. The next button changes the content width.

<!doctype html>
<html lang="en">
<meta charset="utf-8">
<title>Resize Observer boxes</title>
<style>
#card { box-sizing: content-box; width: 200px; height: 80px; padding: 10px; border: 2px solid; }
</style>
<button id="pad" type="button" disabled>Increase padding</button>
<button id="width" type="button" disabled>Increase content width</button>
<div id="card">Example card</div>
<pre id="log"></pre>
<script>
const get = id => document.getElementById(id);
const [card, pad, width, log] = ['card', 'pad', 'width', 'log'].map(get);
const initial = new Set();
let phase = 'initial';

function receive(label) {
  return ([entry]) => {
    const { contentBoxSize: [content], borderBoxSize: [border] } = entry;
    log.append([phase, label, content.inlineSize, border.inlineSize].join(' ') + '\n');
    if (phase === 'initial') initial.add(label);
    pad.disabled = phase !== 'initial' || initial.size !== 2;
    width.disabled = phase !== 'padding' || label !== 'border';
  };
}

const contentObserver = new ResizeObserver(receive('content'));
const borderObserver = new ResizeObserver(receive('border'));
contentObserver.observe(card);
borderObserver.observe(card, { box: 'border-box' });
pad.onclick = () => {
  phase = 'padding';
  pad.disabled = true;
  card.style.padding = '20px';
};
width.onclick = () => {
  phase = 'width';
  width.disabled = true;
  card.style.width = '220px';
};
</script>
</html>

Initially expect both entries to carry 200 and 224. After the padding change, only the border subscription should deliver the new 200 and 244 measurements. Changing the content width to 220 should trigger both subscriptions, with an outer width of 264. Compare each stage and source without requiring the two observers to run in a particular order.

A test that only sees borderBoxSize in the first default entry can falsely pass. The padding-only stage distinguishes it from a border subscription. The subsequent content-width change also checks that the default observer is still working. Keep initial delivery separate from both changes.

Apply updates without changing the measurement by accident

If the callback also changes the measured card, it can create another change to observe. A toolbar alignment routine can often update the toolbar without touching the card. If the card itself needs to be updated, define when the result should stabilize and measure the real layout. The fixture does not exercise that feedback. The component width contract explains the geometry. Here the decision is which consumer needs a new notification.

Does a pure scale(2) change trigger the observer?

A CSS transform alone does not trigger a resize observation. The main example changes layout dimensions. Here only the visual transform changes. Check getBoundingClientRect before and after a pure scale and inspect the observer log separately. The visual bounds can change without a layout notification. This additional check remains proposed and does not cover styles that also change layout.
