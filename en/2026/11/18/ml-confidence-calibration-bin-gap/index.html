Why can mean confidence match accuracy without calibration?

Use eight classification predictions to compare confidence with accuracy within each bin, then calculate ECE using sample weights.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-18 · Estimated read 13 min
Translations
zh-CN en

Article

Key takeaways

  • Equal overall means can hide bin-level gaps
  • ECE weights absolute bin gaps by sample count
  • Preserve bin boundaries, counts, and gap direction

A classifier report shows 75% accuracy and 75% mean confidence. The team is about to treat the matching averages as a pass. Open the bins and the picture changes. Every example rated 60% was correct, while only half of the examples rated 90% were correct. The overall averages agree even though the scores misdescribe both groups.

Compare predictions with similar confidence

For a classification task with known labels, confidence calibration asks how often predictions at a given confidence are actually correct. If a set scored at 80% turns out to be right only half the time, its scores don't describe that group's observed likelihood of correctness. A single prediction cannot establish the relationship.

Guo and colleagues describe reliability diagrams in On Calibration of Modern Neural Networks. Group predictions into confidence intervals and calculate mean confidence and empirical accuracy for each bin. Their difference is the bin's calibration gap. Keeping the direction helps explain whether a group displays more confidence than its measured accuracy supports.

Expected calibration error, or ECE, takes the absolute gap in each nonempty bin and averages the gaps weighted by their sample counts. Taking the absolute value within a bin prevents opposing gaps from cancelling. An empty bin has no empirical accuracy. Do not label it as if its observed gap were zero.

Eight examples expose the difference

Use invented catalog classifications. Four predictions have 60% confidence and all are correct. Four have 90% confidence and only two are correct. Six correct out of eight gives 75% accuracy. The mean confidence is also 75% because four scores of 60 and four of 90 average to that value.

Use four equal-width bins, with zero included in the first and remaining intervals open on the left and closed on the right. Only the 50–75 and 75–100 bins have observations. The lower occupied bin has 100% accuracy and 60% confidence, a 40-point gap. The upper occupied bin has 50% accuracy and 90% confidence. Its gap is 40 points in the opposite direction.

The local script records confidence as an integer percentage. It doesn't load or run a model. Check the overall values, each nonempty bin, and the weighted result against the values calculated above.

import {deepEqual} from 'node:assert/strict';

const rows = [[60, 1], [60, 1], [60, 1], [60, 1],
              [90, 1], [90, 1], [90, 0], [90, 0]];
const sum = numbers => numbers.reduce((total, value) => total + value, 0);

function summarize(entries) {
  const n = entries.length;
  const accuracy = 100 * sum(entries.map(([, hit]) => hit)) / n;
  const confidence = sum(entries.map(([score]) => score)) / n;
  return {n, accuracy, confidence};
}

const bounds = [25, 50, 75, 100];
const bins = bounds.map((upper, i) => {
  const lower = bounds[i - 1] ?? 0;
  return rows.filter(([score]) => (i === 0 || score > lower) && score <= upper);
}).filter(bin => bin.length > 0).map(summarize);
const ece = sum(bins.map(bin =>
  bin.n * Math.abs(bin.accuracy - bin.confidence))) / rows.length;

const expected = {
  overall: {n: 8, accuracy: 75, confidence: 75},
  bins: [{n: 4, accuracy: 100, confidence: 60},
         {n: 4, accuracy: 50, confidence: 90}],
  ece: 40,
};
deepEqual({overall: summarize(rows), bins, ece}, expected);
console.log('Overall means, bin results, and ECE passed.');

The local assertion passed. Each bin contains half the examples, so the ECE is 40 percentage points, or 0.40 on a zero-to-one scale. This describes the invented data under those bin boundaries. It does not measure a deployed classifier.

Keep evidence that allows the report to be recomputed

Retain the interval boundaries, endpoint convention, prediction count, correct count, average confidence, and label version. When a score lands on 75, the record should tell the next reviewer which bin included it. That also helps locate differences between reports after the sample distribution changes.

If different classification subtasks have different consequences, inspect groups with sufficient data separately. A report might combine document parsing and topic classification, though the operating cost of a wrong answer differs. An improved global value cannot establish that each workflow can use the same confidence threshold.

Use a score whose meaning you have defined. A conversational reply saying “I'm 90% sure” does not automatically provide a calibrated classification probability. To evaluate that kind of output, specify how scores and correctness labels will be obtained, then collect a separate sample. This example assumes labeled Boolean correctness for every prediction.

Improving calibration also doesn't guarantee that more predicted classes are correct. Changing scores on an unchanged set of predictions can reduce the gaps without changing any classification. Compare both calibration and accuracy across changes. If the product applies an acceptance threshold, test actual decisions above that threshold separately.

Changing the bins can change the summary even if every prediction stays the same. Broad intervals can group dissimilar predictions. Fine intervals can leave very small groups. Lock the sample, boundaries, and endpoint convention for a release comparison. Report alternate boundaries as a separate sensitivity check.

Show counts next to a chart of bin gaps. Two bars of the same size do not establish that they represent the same number of predictions. The report should let someone trace each gap to its sample count.

Does a large gap in a two-prediction bin dominate ECE?

It need not. Use a new set of twenty predictions. Eighteen have confidence 50% and nine are correct, so that bin matches. The remaining two have confidence 90% and both are wrong. Their 90-point gap has a weight of one tenth, making the overall ECE 9 points. This is a separate hand-calculated example, outside the executed script.

The small bin is inherently uncertain, but it can still be the group a product needs to examine most. A workflow that automatically accepts scores at 90% and above operates in that region. Report bin counts along with gap direction so sampling and acceptance decisions address that group.
