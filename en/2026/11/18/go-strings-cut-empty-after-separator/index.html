Did strings.Cut see an equals sign if the value was empty?

Use four configuration lines to distinguish an empty right side from a missing separator and preserve inheritance, clearing, and assignment.

Updated 2026-11-18 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Use the third result to distinguish an empty assignment from a missing separator.
  • Keep the complete text after the first separator.
  • Validate the key against the configuration grammar even when Cut found a separator.

Both timeout and timeout= can leave a Go parser with an empty string. The format gives them different meanings: the first inherits a previous setting, and the second explicitly clears it. When strings.Cut splits the input, the empty right side cannot settle the question. The third result records whether there was an equals sign.

Two inputs produce the same empty right side

This example's format has three actions. A bare key inherits. An equals sign followed by nothing clears. An equals sign followed by text sends that text to the field's decoder. Suppose the previous layer set timeout to thirty seconds. The bare key keeps that value, and the trailing equals sign can explicitly invalidate it according to the application's clear policy. Those are choices in the format; Go supplies the split.

Cut was introduced in Go 1.18. It splits around the first complete occurrence of the delimiter and returns the text before it, the text after it, and a boolean saying whether it was present. Without a delimiter, the first string is the entire input, the right string is empty, and the boolean is false. With an equals sign at the end, the key and empty value can look the same, but the boolean is true. Code handing off only the two strings cannot recover whether the equals sign was written.

Keeping the boolean removes the need to infer presence elsewhere. Checking whether the right side has any text makes a clear look like an omitted assignment. Looking only for a nonempty key mistakes the bare name for an assignment. That boolean describes the actual delimiter. A change in the meaning of inheritance would leave that lexical fact intact.

Four inputs protect four branches

The fixture compares all three returned values. It has not been run in Go. Two similar inputs distinguish presence, the repeated equals sign checks the first-delimiter behavior, and the last line shows that an empty key can still have a delimiter.

package main

import "strings"

func main() {
    cases := []struct {
        line, before, after string
        found bool
    }{
        {"timeout", "timeout", "", false},
        {"timeout=", "timeout", "", true},
        {"timeout=30=raw", "timeout", "30=raw", true},
        {"=30", "", "30", true},
    }
    for _, c := range cases {
        key, value, present := strings.Cut(c.line, "=")
        if key != c.before || value != c.after || present != c.found {
            panic(c.line)
        }
    }
}

The first two rows give identical strings and different booleans. For the repeated separator, the right side keeps 30=raw intact. Even if timeout is numeric and the application will reject the value, the split should preserve the supplied text so the error can identify the field and input. Splitting every equals sign and taking only the first two pieces silently changes the value to 30. Number validation might then pass.

The final row reports a delimiter with an empty key. A format that requires key names must reject that key separately. A delimiter is a lexical fact, and validity is a grammar decision. Checking only the boolean could accept the nameless assignment. Even a format that permits arbitrary names has to define whether an empty string is a valid name. The fixture checks splitting, not a whole parser for names, values, or comments.

Preserve the action the next layer must take

If the next layer merges previous settings and validates their types, it can map the returned fields to an application action such as inherit, clear, or assign the raw text. Validate the key, then use the boolean and the supplied value to select a branch. If the format has no defined meaning for an explicit empty value, that branch can raise a syntax error. Keeping the branch distinct lets a caller explain why the setting failed validation.

You can run two merge tests from the same thirty-second default. For timeout, expect the inherited result to stay thirty seconds. For timeout=, expect the application's explicit clear state. Add timeout=30=raw to check that validation preserves the original invalid value in the error. That is an application acceptance test, separate from the fixture's three-result assertions. It can catch a merger that ignores the boolean and judges presence from value length even when the splitter itself works.

If one process writes the parsed record and a second process reads it, add a round-trip test. Start both lines from the same default and write out the bare-key and explicit-clear states. Read them back and verify they still merge differently. Saving only a key and value, or omitting empty strings from that intermediate record, can leave the reader with identical shapes. Calling Cut there cannot recover evidence about a source line that was already discarded.

Choose where to handle whitespace. Preserve it if the format treats it as part of keys and values. If keys may be indented but whitespace in values is significant, trim only the key. An empty string, a run of spaces, and no equals sign can map to distinct actions. Trimming an entire line early discards information before the grammar gets to use it. The site's pytest config key validation article deals with catching bad names. This parser needs to preserve assignment state for the same valid name.

Will a single colon split the text if the delimiter is two colons?

The separator is matched as a complete string. Split scope:part::x::y on two consecutive colons and the left side is scope:part, the right is x::y, and found is true. The single colon remains in the key and the second pair remains in the value. If a format needs to permit the exact delimiter as literal content in both positions, it must define an escape or quoting rule of its own. Cut finds the first literal match in the original string.
