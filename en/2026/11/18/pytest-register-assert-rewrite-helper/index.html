Why did moving the same assertion into a helper leave pytest with a bare AssertionError?

Keep the failure fixed and compare pytest assertion diagnostics before and after registering an imported helper.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-18 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • An ordinary helper may not be rewritten.
  • Register the module before its first import.
  • Check the failure and its diagnostic separately.

Move an assertion into an ordinary helper and pytest may show AssertionError at the failure line without the expanded comparison. Default assertion rewriting does not cover every imported module. To restore the compared values for that helper, register its module name with pytest before the test imports it.

This often surfaces during test refactoring. A shared assertion function can remove duplicated business logic. Before and after the move, the same mismatch still fails. The difference appears when someone reads the report. A comparison that used to show expected and actual values now requires a trip through the test and helper. Keep that failure constant and vary only whether pytest rewrites the helper, so the diagnostic itself becomes observable.

Fail twice with the same pair of values

Create helper.py in an empty directory. This ordinary equality assertion has no custom message. That lets the comparison reveal pytest's expression introspection rather than a change in supplied message text.

def check_total(actual, expected):
    assert actual == expected

Save this as test_total.py. Its values intentionally differ. Both runs should fail. If either passes, another change occurred and the diagnostics no longer form a controlled comparison.

from helper import check_total


def test_total():
    check_total(7, 9)

Use one local isolated environment and run from this directory. Disable third-party plugin autoload and the cache plugin. For the first run, there is no conftest. Save the output and exit status of this invocation.

export PYTEST_DISABLE_PLUGIN_AUTOLOAD=1
python -m pytest -q -p no:cacheprovider test_total.py

For the second run, add conftest.py in the same directory with the following contents. Do not import helper before the registration. Start a new pytest process using the same command so the first run's imported module cannot carry over.

import pytest

pytest.register_assert_rewrite("helper")

On Python 3.11.15 with pytest 9.0.2, both runs exited one. The first reported AssertionError at helper.py:2 without the generated assert 7 == 9 line. The second included that line. Frames and call sites elsewhere in the report may still show values in the first run. The comparison checks for a rewritten expression at the assertion failure. The exit status independently verifies that the mismatch still fails the test.

Find the first import to change the report

Pytest's import hook rewrites the assertion syntax tree when it loads an eligible source module, before compilation. Test modules are normally eligible. An ordinary helper may need to be registered. Registration takes the module name, such as helper, rather than the function name. For a submodule, use its importable qualified name and check that pytest imports the file you intended.

A common failure is importing the helper first and registering its module afterward. The imported function is already defined and late registration cannot rewrite that import. Someone can see the registration line in the tree yet get no expanded comparison. Move registration to an earlier entry point and repeat the same failure in a new process. The fixture exercises the correct order, without a separate late-registration run. Trace plugin and conftest imports if the earlier importer is unclear. Investigate an actual same-name module conflict separately.

Decide who calls the helper. If its diagnostic is only for pytest, registration can be convenient. If a debugging tool or another runner imports the function directly, give it an appropriate explicit message or use the comparison facilities of that entry point. Verify that callers can see the required diagnostic there. A packaging checker importing the function directly through Python is a separate path, and the two pytest runs do not cover it.

For CI, retain a short negative case where two different totals produce an identifiable diagnostic. Save the unregistered result first, then preserve the rewritten comparison and test node from the second run. The node and value checks together keep a different failure with the same numbers from satisfying this check. Run the intentionally failing test in a dedicated self-check that expects a failure, then check the report. That CI arrangement is a proposal. The local fixture ran the example processes only. Identifying the assertion, the two values, and the entry point gives the next reviewer enough to find the original decision.

Even after registration, inspect whether the failure comes from an assert statement or a manually raised exception. If the helper uses an if branch and raises AssertionError with fixed text, rewriting does not infer a comparison from that branch and exception. To preserve expected and actual values, include them in the explicit message or keep the comparison in an assert statement. Check the source at the failing line and retry with the same mismatched inputs. This branch was not run. It identifies what to inspect if registration is correct but the comparison still does not appear.

What if the assertion lives in a directly loaded pytest plugin?

A module loaded directly as a pytest plugin is eligible for rewriting. An ordinary helper it imports is a separate module. In a separate local run, the comparison lived inside a fixture in plugin_entry.py itself. Loading it with -p plugin_entry and no conftest registration produced assert 7 == 9. That changes the role of the module holding the assertion. The earlier runs kept the same ordinary helper. Distinguishing the plugin entry point from its helpers tells you where explicit registration matters.
