How can a quality slider describe position 2 as Standard?

Use a native three-position slider to check that the numeric position, visible preset, and aria-valuetext stay in sync.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-17 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Use readable value text when numbers are only positions
  • Derive both labels from one mapping
  • Check actual assistive presentation separately

Preview quality offers three presets: Draft, Standard, and High. The slider starts in the middle, at the numeric value 2. The application can use that number to locate the saved setting. A user needs to recognize Standard. A number alone makes them remember which preset each position represents.

Keep the position and describe the preset

A native range input can represent an ordered choice. This example moves one step at a time. The integers connect the control with application state, while the preset labels describe the effect of each setting.

WAI-ARIA 1.2 uses aria-valuetext as a human-readable alternative to a numeric value. Use the text when the number alone doesn't express the value's meaning. Here 2 is the middle position and has no quality unit. A slider for a familiar quantity such as font size has a different reason to use or omit extra text.

The example keeps the native control, range, step, and keyboard behavior. The label remains Preview quality. Its current value changes among the presets. Renaming the whole control to Standard would make it harder to tell whether it represents the same setting after an adjustment.

Use one lookup for the visible preset and the readable value. An application can otherwise update the string on the screen while leaving the attribute that described the initial position. Keeping the mapping in one place lets both outputs update at the same time.

Check both outputs for each position

The HTML below has one slider. Its initial value is 2 with the text Standard. On input, the handler chooses the preset for the current position and writes it to the paragraph and the attribute. The page does not save a setting or generate a preview.

<!doctype html>
<meta charset="utf-8">
<title>Preview quality</title>
<label for="quality">Preview quality</label>
<input id="quality" type="range" min="1" max="3" step="1"
       value="2" aria-valuetext="Standard">
<p id="preset">Selected preset: Standard</p>
<script>
const byId = document.getElementById.bind(document);
const quality = byId('quality');
const preset = byId('preset');
const labels = ['Draft', 'Standard', 'High'];

function showPreset() {
  const label = labels[quality.valueAsNumber - 1];
  preset.textContent = 'Selected preset: ' + label;
  quality.setAttribute('aria-valuetext', label);
}
quality.addEventListener('input', showPreset);
</script>

Expect 2 and Standard initially. With the slider focused, press Right Arrow to reach the final position and look for 3 and High. Then press Left Arrow twice and look for 1 and Draft. If navigation differs in the environment under test, confirm the value actually reached the target before comparing its label.

Read the native value, the visible text, and the accessible value attribute separately. Seeing the slider move won't detect stale text. Seeing the paragraph change won't detect an attribute stuck on Standard. Put the number and both text readings on one line so a failure can point to the stale output.

These are predictions from the control, script, and specification. This article does not report a browser or assistive technology run. An actual presentation can include the control name, role, or other information. Check whether someone can tell which setting is active, where it is now, and what changed after a keypress in the combinations your product supports.

Keep the same labels wherever a preset appears

If a tooltip also displays the preset, use the same mapping there. “Normal” in a tooltip and “Standard” beside the slider can look like different settings. Test the individual correspondences rather than accepting any non-empty label.

The same principle applies to translation. Store a stable setting value and use the current locale to display its label. Don't reverse-parse the translated text to recover the number. Compare stable values to verify the actual choice and use the displayed words to verify its presentation.

If the team adds or reorders presets, check the meaning of older saved settings. A new label cannot repair a situation where 2 used to mean Standard and now selects something else. The fixture's presets remain fixed. A product with changing options needs a stable application identity for each one before deciding how to order them on the control.

Test the initial render with a saved High setting as well. Both the third position and the High label need to be right before the first keypress. Initial defaults and later updates can share the same mapping rather than maintaining separate preset lists.

If choices have no useful order, consider a named choice instead of a slider. Black-and-white, warm, and original previews are themes, so the next option does not necessarily mean a higher degree. A text attribute cannot supply an order missing from the product model.

Does setting position 3 while restoring a draft update the text?

Not on its own. The main example relies on a user action firing input. After assigning the restored value, call the same showPreset function explicitly. Check that the numeric value is 3, the visible text says High, and aria-valuetext reports High before another action.

Test draft restoration without typing or pressing an arrow. If you move the slider before reading those outputs, the resulting input event can repair stale text. The test then misses the defect in the restore path.
