Why did narrowing pytest’s conftest boundary hide a fixture?

Change pytest's conftest boundary while keeping the test file fixed, then use collection and fixture setup to locate a missing definition.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-17 · Estimated read 13 min
Translations
zh-CN en

Article

Key takeaways

  • The boundary can still provide a local conftest.
  • Move the boundary without changing the test path.
  • Record collection and fixture setup separately.

The test is still collected, but setup can no longer find its fixture. If you just narrowed pytest's --confcutdir to the tests directory, check where the fixture was defined. A fixture in that directory and one from an ancestor's conftest.py can behave differently in the same run.

Both invocations use the same test path and file. That separates a conftest lookup failure from a change in collection. This fixture puts two similar definitions in different locations and gives each a distinct name and value. A passing test can then reveal whether it saw the local value or the project-root value.

Two definitions, one set of tests

Start in an empty directory and create these files. Use the same root configuration. Run from the experiment's root directory and explicitly pass the same test file to both commands.

pytest.ini
conftest.py
tests/
  conftest.py
  test_tokens.py

The root pytest.ini consists of [pytest]. The root-level conftest.py provides the parent marker.

import pytest


@pytest.fixture
def parent_token():
    return "parent"

The local marker goes in tests/conftest.py. Each fixture returns a single value and needs no files, environment variables, or external plugins. Start by checking whether pytest can find the fixture.

import pytest


@pytest.fixture
def local_token():
    return "local"

Save the tests as tests/test_tokens.py. One test verifies the definition inside the boundary directory. The other asks for the parent marker. Keeping them separate lets the local control run even when the other fixture fails to resolve.

def test_local(local_token):
    assert local_token == "local"


def test_parent(parent_token):
    assert parent_token == "parent"

Run both commands in the same isolated environment with pytest already installed. Disable third-party plugin autoload and the cache plugin. Save the exit status and output of each run. The second command is supposed to return nonzero.

export PYTEST_DISABLE_PLUGIN_AUTOLOAD=1
python -m pytest -v -p no:cacheprovider --confcutdir=. tests/test_tokens.py
python -m pytest -v -p no:cacheprovider --confcutdir=tests tests/test_tokens.py

With Python 3.11.15 and pytest 9.0.2, the first run collected and passed two tests and exited zero. The second collected two as well. The local test passed, but the parent test reported fixture 'parent_token' not found during setup. The run exited one. The parent test never received its argument or entered the function body. Both the project root and the test file stayed the same. The missing definition accounts for the difference in output.

Locate the definition before moving the boundary

The boundary directory itself can still supply a conftest. In the second run, pytest excluded the experiment's root conftest above tests while retaining the one inside tests. A local pass and a parent setup error can coexist. The overall exit status alone would miss unchanged collection. Watching only the local test could also leave the false impression that shared fixtures from the root still load.

A team might move the boundary so that one suite can run independently of the root test configuration. Suppose the root defines a common login fixture that every child project names in its test signatures. Moving the boundary also removes that shared input. Decide who should provide it. An independent child project can put its required fixture somewhere its own entry point loads and rerun the narrow command to confirm. If loading fixtures from the root is part of the repository contract, choose a boundary that includes the definition and preserve the invocation. Changing the working directory at the same time adds other variables, including relative paths and test selection.

Start from the smallest test signature that requires the missing fixture. Locate its definition and check for competing definitions of the same name before repeating the two runs. Hold the working directory, test path, and dependency set constant. Distinct return values can identify which definition supplied a test. If the narrow run still receives a fixture with the same name but a different value, investigate the provider. This fixture demonstrates a missing definition and does not exercise shadowing. Verify that the test receives the data intended for that entry point.

Save three observations from a CI failure: project and config locations, collected test IDs, and the failure phase. Save the old run as a reference and change the boundary. If the test count changes, first check whether both runs examined the same tests. A CI edit that also removes the test requiring the parent fixture can make the setup error disappear by never exercising it. Keeping a separate parent test makes that mistake visible here. An exit status also distinguishes a passing control from a passing invocation.

Record the environment in a handoff as well. If one run uses the project interpreter and the other uses a different pytest installation on the same machine, matching test IDs still cannot distinguish a boundary change from a fixture supplied by a plugin. Run through the same interpreter, save the pytest version and plugin autoload setting, and include the collected IDs and exact error. For a real project that depends on plugins, disabling them can help isolate the problem. Restore the intended plugin setup and verify the fixture provider in the final invocation.

Does this block conftests in sibling directories?

In the pinned pytest 9.0.2 implementation, the option filters ancestors above the designated boundary. It does not act as a global directory allowlist. In a separate run, a sibling directory beside tests contained a conftest defining sibling_token and a single test asserting that it returned sibling. The command kept --confcutdir=tests and explicitly passed sibling. One test passed. That changes the selected test entry point and tests a path outside the ancestor chain used in the main example. Check what paths CI actually passes if the goal is to run only a designated suite.
