How do you link only the names in a localized list?

Use two locales to compare list parts, placing links around names while preserving the punctuation and conjunctions supplied by the formatter.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-17 · Estimated read 11 min
Translations
zh-CN en

Article

Key takeaways

  • Link only element parts
  • Preserve literal text as emitted
  • Joined parts should match the formatted string in the same runtime

A project roster already reads correctly in the current language. Click the word between the final two names, though, and it opens someone's profile. The links cover the wrong spans. The input supplied three people, and the formatter supplied the separators. Ask it for the parts before deciding which nodes should be links.

Get the boundaries before adding links

The component knows the names Ada, Lin, and Mia and the profile target for each. It doesn't need to decide which word belongs between the last two names. Intl.ListFormat can return the complete string with format or return typed parts with formatToParts.

An element part represents an input name. A literal part comes from the formatter, which supplies punctuation, spaces, or conjunctions. Use both types of value for display. Wrap only element parts in links and leave the literal parts as text.

Splitting the full string on English commas or a known conjunction guesses at a boundary the formatter already provides. Another locale may use different punctuation or spacing, and a name can contain the separator a developer picked. Trimming each part before joining it can also remove spaces that belong in the rendered list.

Hold the names constant across locales

The following Node script uses three strings and two locale settings. For each setting, it checks that the element parts preserve the input order and that concatenating every value reproduces format on the same instance. The first test checks the elements the app will link. The second checks the text a person reads.

import {deepEqual, equal} from 'node:assert/strict';

const names = ['Ada', 'Lin', 'Mia'];
for (const locale of ['en', 'zh-CN']) {
  const list = new Intl.ListFormat(locale, {type: 'conjunction'});
  const {format, formatToParts} = list;
  const parts = formatToParts.call(list, names);
  const values = parts.map(({value}) => value);
  const linked = parts.filter(({type}) => type === 'element');
  deepEqual(linked.map(({value}) => value), names);
  equal(values.join(''), format.call(list, names));
  console.log(locale, JSON.stringify(parts));
}

The assertions passed locally, with the emitted parts captured for both runs. The element sequence was Ada, Lin, Mia in both cases. The fixture does not prescribe punctuation for every runtime or locale data version. Keep each environment's actual output if you need to compare support.

These checks don't build a DOM or click links. For a component regression, check the number and text of the anchors, the destination of each, and the literal text outside them. The faulty roster in the opening can pass a whole-string check because the displayed text hasn't changed.

Render the sentence and route the actions separately

Start from ordered records containing an ID and display name. Format the names and walk the resulting parts. Consume the next record on an element part and use its destination for the link. Render literal parts as text and leave the record cursor where it is. The conjunction never needs a profile ID.

Prepare the list once after applying filters or sorting. Formatting the visible records while attaching links from another array can send a user to the wrong profile. The first record in the two arrays could have the same name even when the IDs differ. Keep the format and render passes tied to the same ordered data.

Include a one-, two-, and three-name sample in component tests. A one-name roster needs one link. A two-name roster should keep the separator between the links. With three names, test that the last conjunction is still outside the final link. These assertions target node boundaries instead of freezing punctuation across locales.

If the roster is also copied as plain text, the output of format on the same input and locale is a useful expected string. Treat that as a separate feature. A clipboard test checks the text, while the component test can also check which spans are interactive.

Record the effective locale in production tests, rather than assuming the requested one was selected. The positional association relies on preserving input order in the locale data you support. The specification recommends putting the first placeholder before the second; check element order with distinct names when adding a locale.

What if two people have the same display name?

Don't look up the destination by name. Suppose two records are both called Lin but their IDs are L7 and L9. The two element values can be identical. Using their text as a dictionary key can link both to one record. Consuming the parts in input order can assign L7 to the first and L9 to the second.

Test the two destinations, not only the number of links or the equality of their labels. The names can remain identical in copied text. Deciding whether the UI needs additional identification is an application decision outside list formatting.
