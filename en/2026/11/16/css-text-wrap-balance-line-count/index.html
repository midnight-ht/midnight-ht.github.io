Can text-wrap: balance add a line to a short heading?

Compare ordinary and balanced wrapping on headings with identical text and width. Test the short-heading line-count rule in the CSS Text 4 draft.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-16 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Measure ordinary wrapping on the same input
  • At five baseline lines or fewer, balance preserves the count
  • Exact soft breaks depend on the browser algorithm

A card title gets text-wrap: balance so the final line is less likely to contain just one word. A regression test can ask whether the same title in the same width uses more lines, and whether it breaks at different words. The short-title line count has a specification constraint. The choice of particular breaks is still up to the wrapping algorithm.

Short headings can preserve line count without preserving every break

The CSS Text Level 4 Editor’s Draft says that balance chooses soft breaks to distribute remaining space more evenly when it can improve on auto. If ordinary wrapping produces five or fewer lines, balancing must not change the number of line boxes. Check that the baseline meets this condition before asserting equal counts.

Balance considers the space left in each line box. Width and font affect that space. The engine may move a word to another line to make the lines more even. An already well-balanced title can keep its original breaks. The feature doesn't require a visible change in every heading.

The exact algorithm is user-agent-defined. Even with the same text and font, different implementations can choose different breaks. An assertion about the last word on one line describes one rendering. Compare each engine's balanced output with its own auto baseline for the short-heading invariant.

The five-line condition does not establish the same invariant for long paragraphs. The product can set its own layout and overflow requirements. Using balance alone does not establish that all cards will stay the same height across different copy.

Change only the wrapping style

The two headings below use the same text, width, font, and explicit line height. Dividing each box height by the line height gives its line count in this controlled layout. The headings have no padding, border, clamp, or fixed height that would alter the measurement.

<!doctype html>
<meta charset="utf-8">
<title>Heading wrap comparison</title>
<style>
  h2 { width: 20ch; font: 20px/24px monospace; margin: 0 0 1rem; }
  #ordinary { text-wrap: auto; }
  #balanced { text-wrap: balance; }
</style>
<h2 id="ordinary">Small teams set a steady pace for shared work</h2>
<h2 id="balanced">Small teams set a steady pace for shared work</h2>
<output id="result"></output>
<script>
const byId = document.getElementById.bind(document);
const height = element => element.getBoundingClientRect().height;
const lineCount = id => height(byId(id)) / 24;
const support = CSS.supports('text-wrap', 'balance');
const values = [support, lineCount('ordinary'), lineCount('balanced')];
const result = byId('result');
result.textContent = ['supported, auto, balance:', ...values].join(' ');
</script>

First read supported. If it is false, equal counts may simply mean the browser ignored the balanced declaration. Next read auto and balance. If ordinary wrapping produces one to five lines here, the draft predicts equal counts. You can also observe the breaks, but the example doesn't prescribe exactly where they fall.

These are predictions from the draft and the fixture. The article does not report a browser run, screenshots, or a support matrix. If the quotient doesn't look like a line count, check whether the intended line height and other styles actually apply. Box height divided by line height is a shortcut for this layout.

In a product regression, keep both headings in layout when measuring. A hidden copy with no box cannot provide a useful baseline. If the font loads later, compare both variants after they use the same font. A baseline from before the font load is a different test.

Test at the component's actual widths

At a narrow card width, choose an input where ordinary wrapping produces three lines. Change the wrapping style and read the count again. Also check that the title remains readable in full. When the width changes, remeasure the baseline before assuming the old count still applies.

Repeat with localized headings if the component supports them. Each language gets its own ordinary baseline. Comparing balanced text in one language with ordinary text in another doesn't isolate a CSS effect. Store the language, font, width, and two counts in the report.

A card design may also require common bottom alignment even when the titles span different numbers of lines. Test the heading's internal wrapping separately from the overall card layout. The height of a fixed-size card doesn't show whether the heading took an extra line.

If the component also clamps lines, turn clamping and balancing on separately when diagnosing an unexpected height. This fixture has no clamp and each actual line contributes to its measured height. In the real card, make a separate check that the visible text is enough to identify what the card is about. Equal counts do not establish that.

What if the title contains a br?

The draft processes groups separated by a forced line break independently. The browser can still balance soft breaks within each group, but it doesn't move text across the forced break to improve the whole heading.

This can express a real structure, such as a project code that needs its own line. If a forced break exists only to reproduce one screenshot, it may divide a narrower or translated title poorly. Check the intended boundary first, then examine the soft breaks inside each group.

For a separate layout concern, see how offscreen sections behave in search and keyboard navigation.
