Why does a mock assertion see a dictionary after it was cleared?

Compare an actual mock call reference with a separate snapshot taken before mutation.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-16 · Estimated read 7 min
Translations
zh-CN en

Article

Key takeaways

  • Call history can preserve the argument reference.
  • Capture values at the handoff when timing matters.
  • Verify identity and contents separately.

unittest.mock keeps references to arguments in its call history. If the caller clears an argument afterward, the recorded call can show the cleared object. Capture a separate value at the moment the substitute receives it when that is what the test needs.

Imagine an export function that passes its batch downstream and then clears its staging list. The mock was called once, but its argument now has no IDs. Check who owns the original object after the call. The history identifies that object, while a later read of it does not establish what it contained earlier.

Decide what the record should establish

The mock examples document that call_args and call_args_list keep references. The records do not make deep copies. An application can intentionally pass one object and later modify it. An identity assertion can still use the original record. A value assertion needs an observer at the handoff. Python mock mutable-argument examples.

Use independent expected data. If the expected value shares the application’s list, a later clear can also erase the answer the test compares against.

Observe the call and the later mutation

This complete program ran on Python 3.11.15. The mock copies the argument as it arrives. The function then clears the nested list. No real export or external delivery takes place.

from copy import deepcopy
from unittest.mock import Mock

def publish(send, payload):
    send(payload)
    payload["ids"].clear()

seen = []
sink = Mock(side_effect=lambda payload: seen.append(deepcopy(payload)))
data = {"ids": [17, 23]}
publish(sink, data)

recorded = sink.call_args.args[0]
assert recorded is data
assert recorded == {"ids": []}
assert seen == [{"ids": [17, 23]}]
print("after", recorded, "during", seen[0])

The archived result keeps the original object in the call history with an empty list, while the capture contains 17 and 23. Identity and both values have separate assertions. A shallow copy of the outer dictionary would keep the inner list shared. Change only the copying strategy to test that error independently. That shallow-copy probe was not run.

Capture the smallest useful value

A dictionary can be deep copied in this fixture. Real calls might carry handles or objects with custom copy behavior. When the contract only cares about a batch ID and selected IDs, capture those values directly. Preserve order or multiplicity where the consumer needs it. A related pytest input article covers shared values across cases rather than observing one call at two different times.

For a retrying caller, keep one snapshot per call. The first attempt may send two IDs and the next only one. A final empty list cannot describe either attempt. These consumer and retry probes are unexecuted.

How can side_effect preserve a configured return value?

After recording the argument, return unittest.mock.DEFAULT so the mock continues with its configured return behavior. Verify the capture and returned status independently using a new mock. That variant was not run. The main program only records the snapshot and the function ignores the mock’s return value.
