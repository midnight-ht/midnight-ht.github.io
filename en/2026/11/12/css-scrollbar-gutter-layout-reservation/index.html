Why did text wrap when the panel kept its width?

Keep a 320px border box fixed and compare usable width with auto and stable under classic and overlay scrollbars.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-12 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Classic scrollbars can consume room inside the fixed border box.
  • Stable reserves the classic scrollbar gutter ahead of overflow.
  • Overlay scrollbars do not get a gutter from this rule.

The sidebar grows from four search results to twenty. Its border box is still 320 pixels wide, yet text can wrap because less room remains inside. A classic scrollbar can consume that room when the panel overflows. A stable scrollbar gutter reserves the space in advance. Overlay scrollbars do not behave the same way.

Find which width changed

CSS Overflow Level 3 defines scrollbar-gutter and distinguishes classic scrollbars from overlay scrollbars. A classic scrollbar occupies space in a gutter. An overlay scrollbar is drawn over content without creating one. The browser determines the width and placement, which may depend on user preferences and direction. A component cannot use a fixed 17-pixel width as a universal measurement.

With overflow set to auto, a classic scrollbar gets a gutter when the box overflows. The stable value reserves that space even with short content. It controls whether there is a gutter, so a visible scrollbar is a separate observation. On a system using overlay scrollbars, neither value makes this space reservation.

Consider a search panel with two columns whose labels sit near a wrapping threshold. The outside of the panel and its borders can remain unchanged even as the scrollbar consumes the remaining room. The component width contract separates the content area from the border edge. Here both borders and padding stay fixed while the gutter changes.

Measure both panels before and after overflow

This complete HTML fixture has not been run in a browser. Both panels use the same dimensions and border. One uses the initial gutter strategy and one uses stable. Four 20-pixel rows fit in a 96-pixel opening; twenty do not. Short labels avoid deliberately introducing horizontal overflow. Switch the row count and record outer width, clientWidth, and vertical overflow for each panel.

<!doctype html>
<meta charset="utf-8">
<title>Measure scrollbar gutters</title>
<style>
.panel {
  width: 320px; height: 100px; box-sizing: border-box;
  border: 2px solid; overflow: auto; padding: 0; margin: 0 0 8px;
}
#stable { scrollbar-gutter: stable; }
.row { height: 20px; line-height: 20px; white-space: nowrap; }
</style>
<button id="short" type="button">Four rows</button>
<button id="long" type="button">Twenty rows</button>
<h2>Auto</h2><div class="panel" id="auto"></div>
<h2>Stable</h2><div class="panel" id="stable"></div>
<pre id="out"></pre>
<script>
const get = id => document.getElementById(id);
const [auto, stable, short, long, out] =
  ['auto', 'stable', 'short', 'long', 'out'].map(get);

function setRows(box, count) {
  const rows = Array.from({ length: count }, (_, i) => {
    const row = document.createElement('div');
    row.className = 'row';
    row.textContent = 'Result ' + (i + 1);
    return row;
  });
  box.replaceChildren(...rows);
}
function report(box) {
  const { clientWidth, clientHeight, scrollHeight } = box;
  const { width } = box.getBoundingClientRect();
  return { width, clientWidth, overflow: scrollHeight > clientHeight };
}
function show(count) {
  for (const box of [auto, stable]) setRows(box, count);
  out.textContent = JSON.stringify({
    count,
    supported: CSS.supports('scrollbar-gutter', 'stable'),
    auto: report(auto), stable: report(stable)
  }, null, 2);
}
short.onclick = () => show(4);
long.onclick = () => show(20);
show(4);
</script>

With a classic scrollbar of width g greater than zero, the auto panel starts at 316 pixels of clientWidth. Its long version loses g pixels. The stable panel already reserves g pixels with four rows, so its two measurements should match each other. The outer boxes remain 320 pixels wide. With overlay scrollbars, the four client widths are expected to match and the long lists should still overflow.

First confirm that long content actually exceeds the available height. Then compare each panel with its own baseline. Matching widths can reflect an overlay mode, an unsupported property, or a test that never overflowed. CSS.supports checks the declaration. The measured width difference in the auto panel tells you whether the particular fixture actually lost usable width.

The example uses short labels to isolate the geometry. Restore realistic labels and counts when checking the real component. A stable width can keep a long list from shifting while making the short version wrap sooner. If that narrow width does not work for the panel’s minimum content, revise the column layout or the content rather than treating a steady width as sufficient.

Place the rule on the box that scrolls

An application can have a scrolling page and a separately scrolling result pane. Apply the rule where the width needs to remain stable. A declaration on the parent does not reserve the space for the child’s scrollbar, and can narrow unrelated content. If a state transition transfers scrolling from the pane to the page, identify which box controls the task before measuring again.

Stable space is useful where a change in usable width can move labels or controls out of alignment during a task. A small read-only panel that rarely overflows may have a stronger need for the extra space in its short state. Check the shortest and longest cases with representative text. The decision depends on which width the design must preserve.

What if a one-sided gutter shifts centered content?

Try stable both-edges when the content has to center within the full border box. If a gutter exists on one inline edge, the rule adds one on the opposite edge. Two equal gutters can preserve the center, at the cost of another gutter width inside. Overlay scrollbars still receive no gutter here. Compare both the center and the remaining space for the content so a symmetric result cannot hide a width regression.
