Why does or vector(0) still leave a missing PromQL instance absent?

Trace PromQL left-preferred union, unlabeled vector(0), and the on() control through a complete unexecuted fixture for labeled display defaults.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-10 · Estimated read 16 min
Translations
zh-CN en

Article

Key takeaways

  • vector(0) supplies one unlabeled zero rather than enumerating missing instances.
  • A separate label inventory and complete scope key can supply known-member defaults.
  • A display default is not measured zero; inventory completeness needs independent evidence.

If instance a returns two and b is absent, or vector(0) does not invent b’s labels. It supplies one unlabeled zero, which an ordinary union can retain alongside a. Inspect the result identities before choosing a default-value source. Adding a number does not necessarily add the required member.

a plus an unlabeled zero is still not a and b

The official set-operator rules say that or keeps all left elements and adds right elements without a left match. It does not discover which instances a dashboard expects. The vector function converts a scalar into one instant-vector element without labels. For zero, that is {} with value zero.

Assume the left side contains only {job="api",instance="a"} with value two. The unlabeled right element does not match that label set, so both appear. Neither input supplied b’s identity. This is different from assigning a default to an empty field in an existing SQL row: the missing object here is a vector member.

One zero can be appropriate for an intentionally dimensionless total. It does not supply per-instance identities. A dashboard displaying an unlabeled zero line therefore has not established that b exists. Inspect labels and element counts, not merely whether a curve touches zero.

on() changes matching rather than enumerating instances

With or on() vector(0), the matching key becomes empty. In this nonempty-left example, the right zero can match an existing left element and is not added. Only a’s two remains. If the whole left side is empty, the fallback is still just an unlabeled zero, not a labeled b. Work through both inputs instead of calling the modifier a broadcast.

The matching reference also restricts group_left and group_right to comparison, arithmetic, and trigonometric operators. They cannot be attached to or to copy a default across missing groups. The group_left article concerns many-to-one division and uniqueness. This problem needs a source of right-side members, not another division modifier.

Give the default labels a source

Now supply an independent current inventory, demo_inventory, containing a and b under job api, each with a finite float value of one. This fixture uses no histograms and does not infer the complete inventory from the already incomplete demo_errors. On the left, sum by(job,instance) fixes the label shape. On the right, multiplying the inventory by zero produces labeled defaults for a and b.

Scalar multiplication applies to each float element and drops the metric name, while job and instance remain available. A by aggregation drops unlisted labels too. The expected output can consequently specify the complete labels without quietly ignoring metric-name or dimension differences. If the inventory carries extra labels, decide explicitly whether to aggregate them; that input is not automatically equivalent to the two-label fixture.

For a, the existing two wins and the right-side zero is not added. For b, no left match exists and its labeled default enters. That preference comes from union direction, not numerical size. Swapping operands can let a template zero hide an actual observation, so it is not an equivalent rearrangement.

One complete file with three different results

The following promtool teaching file is unexecuted. Save it as union_test.yml. Samples begin at time zero, arrive every minute, and are evaluated at one minute. Demo_errors is a prepared display reading; this article did not calculate a counter rate. All numbers are hypothetical inputs, not site traffic. No Prometheus server or promtool command was run.

rule_files: []
evaluation_interval: 1m
tests:
  - interval: 1m
    input_series:
      - series: 'demo_errors{job="api",instance="a"}'
        values: '2 2'
      - series: 'demo_inventory{job="api",instance="a"}'
        values: '1 1'
      - series: 'demo_inventory{job="api",instance="b"}'
        values: '1 1'
    promql_expr_test:
      - expr: 'sum by(job,instance)(demo_errors{job="api"}) or vector(0)'
        eval_time: 1m
        exp_samples:
          - labels: '{job="api",instance="a"}'
            value: 2
          - labels: '{}'
            value: 0
      - expr: 'sum by(job,instance)(demo_errors{job="api"}) or on() vector(0)'
        eval_time: 1m
        exp_samples:
          - labels: '{job="api",instance="a"}'
            value: 2
      - expr: 'sum by(job,instance)(demo_errors{job="api"}) or on(job,instance) (0 * demo_inventory{job="api"})'
        eval_time: 1m
        exp_samples:
          - labels: '{job="api",instance="a"}'
            value: 2
          - labels: '{job="api",instance="b"}'
            value: 0

The official rule-test format defines input series, evaluation time, and expected sample fields. The proposed command is promtool test rules union_test.yml. Record the tool version, exact file hash, stdout, stderr, and immediate exit status if it is executed. Successful YAML parsing cannot certify evaluated PromQL results. Every exp_samples entry above is an independent expectation written before observation.

The first test should return a’s two and an unlabeled zero, exposing the missing b. The second should return only a’s two, showing that empty-key matching also fails to create b. Only the third meets the stated display contract: a two and b zero. Passing the first two tests would validate the semantic controls, not product acceptance that b was filled. A green status must be interpreted through the assertion’s actual contract.

For another negative input, remove b from an independent copy of the inventory while keeping the error reading and query unchanged. The third expression then loses its source of b. An expectation still requiring b should fail. Do not rewrite that expectation to conceal incomplete coverage. Inventory completeness needs evidence outside the fallback expression.

Preserve scope and the meaning of a default

Job and instance may be insufficient where environment, cluster, or tenant also defines identity. If two jobs have instance a and matching uses only instance, one job’s observed member can suppress another job’s default. Preserve the scope labels needed by the question and use a consistent identity on both sides. A result without a query error can still fill the wrong population.

The missing-telemetry article already distinguishes absence from measured zero. An inventory-derived display default does not change that distinction. Use it only under an explicit display contract, retaining collection-health and missing-data investigation states separately. An inventory on the same failed collection path can disappear too. A numeric output does not establish complete monitoring or measured inactivity.

Will a matching left-side NaN be replaced by the right zero?

Not merely because of its value. This adds a condition beyond missing identity: the element exists but contains NaN. Set operators do not interact with sample values, so or keeps a matching left element instead of treating it as an empty field. The dimensionless example vector(NaN) or vector(0) illustrates an existing value state; it does not create missing instance labels. The official float-literal definition includes NaN. This is a documented-behavior prediction, not captured output.

A requirement to identify or handle abnormal numeric values needs its own predicate and display policy. Or is not a numeric-cleaning function, and a failure value should not quietly become a success-looking zero. Decide whether the task concerns a missing member or an existing sample state before selecting the expression. The fixture addresses the former through explicit label sources and union direction.
