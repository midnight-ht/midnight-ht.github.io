Why does /~01 not select the slash-named member?

Resolve JSON Pointer tokens once in the required order, then test root, empty-name members, arrays, and fragment representations by target identity.

Updated 2026-11-10 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Decode each token once in the specified order.
  • The empty pointer selects the root; slash selects an empty-name member.
  • Test object names, array indices, and URI fragment encoding separately.

The JSON Pointer /~01 selects an object member named ~1, not a member named slash. RFC 6901 requires decoding ~1 to slash before decoding ~0 to tilde. The token ~01 contains no ~1 in the first pass; the second pass produces ~1, which must not be decoded again. Repeating replacements until nothing changes can select the wrong member.

Ordinary names such as name and age hide this bug. Give confusing members different values so a test can establish which target was selected. Filling every target with true and checking only that lookup succeeded would miss the error. This is illustrative input; no parser or service was executed.

Split tokens before decoding their names

RFC 6901 §§3–4 defines a pointer as zero or more slash-prefixed reference tokens. A tilde within a member name is encoded as ~0, and a slash as ~1. Use the pointer’s separators to split tokens, then decode each token. Decoding the whole string before splitting can invent extra levels.

/a~1b contains one token selecting a member named a/b. /a/b contains two tokens: select a, then b inside it. Both can resolve successfully to different values. A generic path splitter applied after unescaping can silently turn the first operation into the second.

Section 4 explicitly uses ~01 to explain the decoding order. A controlled single scan or two ordered replacements can implement the rule; newly produced characters must not become input to another unescaping round.

Give each possible target its own value

This complete document has not been passed to a parser:

{
  "": "EMPTY",
  "~1": "TILDE_ONE",
  "/": "SLASH",
  "a/b": "JOINED",
  "a": {"b": "NESTED"},
  "arr": ["ZERO", "ONE"],
  "01": "OBJECT_ZERO_ONE"
}

Specify the independent oracle first: the empty pointer returns the whole object; / returns EMPTY; /01 returns TILDE_ONE; /1 returns SLASH; /a~1b returns JOINED; /a/b returns NESTED; /arr/0 returns ZERO; and /01 returns OBJECT_ZERO_ONE. Do not obtain expected targets from the implementation being checked.

An incorrect 0-then-1 replacement sequence redirects /~01 to SLASH. It still resolves, so a success-only assertion is inadequate. Dropping empty path segments creates another error: / may be interpreted as the root pointer. Both require target-identity assertions.

No tokens differs from an empty token

The RFC’s string examples distinguish the empty string, which selects the document, from /, which selects an empty-name member. The former has no token; the latter has one empty token. Trimming, merging separators, or removing empty segments can change meaning.

The function interface matters too. An empty string can deliberately request the root rather than represent an omitted argument. A successfully resolved JSON null is also different from a missing member. Keep lookup success separate from the value, or provide distinguishable errors, so a caller does not fill both states with the same fallback unknowingly.

Pointer resolution does not authorize modification or access. The site’s JSON Patch coordinate article covers operation order after a target is identified. Correct token decoding does not preserve the resource version against which a patch was prepared.

Object names are not array indices

/01 is valid for the example object because that exact member exists. /arr/01 is not an alternative spelling for the second array element. Section 4 disallows leading zeros in array indices: zero itself is allowed, while positive indices begin with a nonzero digit. Converting every token to an integer too early can accept forbidden input.

A hyphen denotes the nonexistent position after an array’s last element. Plain pointer lookup cannot read the last element with it. JSON Patch add gives that position an application-specific use for appending, but other operations do not inherit that rule. Include /~2 as a syntax rejection case because only ~0 and ~1 are valid escapes.

Retain the raw pointer, document, expected identity, and error category. Distinguish valid array indices, leading-zero indices, and nonexistent positions; for objects, include slash names, empty names, and nested objects. This is an unexecuted acceptance matrix, not a claim of exhaustive standards compliance.

Add an intermediate-type failure probe: /arr/0/x first reaches the array and then the string ZERO, but still asks to resolve member x inside that string. The independent expectation is failure, not successful return of the partial value ZERO. /a/b/x likewise continues beyond the string NESTED. Both detect adapters that silently stop at the closest value when traversal cannot continue.

A “nearest existing ancestor” feature would be a separately named application operation, not ordinary pointer evaluation. Record the failed token and current value kind without dumping an entire sensitive document. This specifies expected behavior for the teaching input; it supplies no executed service error record. Verify the complete path, final identity, and failure category together.

Which layer handles percent escapes after a hash?

URI fragment representation adds an outer encoding layer. Section 6 describes that representation. A space-containing member can use /a b as a plain pointer and #/a%20b in the corresponding fragment form. Identify the representation before handling fragment encoding and token escaping. Do not URL-decode every plain pointer merely because it contains a percent sign.

The RFC also requires a media type to specify JSON Pointer fragment syntax explicitly; being JSON does not automatically confer that syntax. Define which representation the interface accepts, then test space-containing names and literal percent names. Handling the outer percent layer does not permit another pass over ~01. Each layer has its own rule rather than a shared “keep decoding” policy.
