Read composedPath with matching open and closed examples

Use matched open and closed examples to separate retargeting, visible paths and boundary crossing, then account for dispatch cleanup.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-10 · Estimated read 14 min
Translations
zh-CN en

Article

Key takeaways

  • An outside target can differ from the dispatch node.
  • composedPath filters closed-tree paths for the current listener.
  • Capture paths synchronously and define a public action contract.

An event dispatched by an internal button can expose the shadow host as its target outside the component. composedPath also reports only the path visible from the current listener’s position. Fix that position before identifying the action’s origin. Treating the first path entry as an invariably visible private button makes delegation depend on details the component has not promised.

Suppose a custom element contains a Save button while the page listens on document. A target.closest approach that works in a shallow DOM can stop finding the internal button at the shadow boundary. More selectors do not turn a retargeted host back into that button. Separate retargeting, boundary crossing and path filtering before changing the handler.

The observer’s position is an input

The DOM retargeting algorithm uses the relationship between two objects and can move outward through a shadow root’s host. For an outside listener, the internal button may therefore be replaced by the host as the event target. That is part of the native event model, not proof that the button was removed.

The composedPath algorithm uses currentTarget and closed-tree levels to determine the exposed path. It is not a debugging escape hatch that always reveals the deepest internal node. An internal listener and an external listener can see different portions of a closed tree’s path.

The following comparison deliberately dispatches a custom probe event from the button itself. That avoids guessing whether a physical click hit button text, an icon or a nested span. It neither produces genuine user input nor saves anything.

A complete example varying only the root mode

This HTML has not been run in a browser. It creates two hosts with matching buttons, changing the intended encapsulation condition through mode. Both the internal listener and document record the target and path synchronously. Every dispatch uses a new Event.

<!doctype html>
<meta charset="utf-8"><title>Shadow event visibility — unexecuted teaching sample</title>
<div id="open-host"></div><div id="closed-host"></div><pre id="log"></pre>
<script>
const out = document.getElementById('log');
const rows = [];
const describe = node => node instanceof ShadowRoot ? '#shadow-root' :
  node === window ? 'window' : node === document ? 'document' : node.id || node.nodeName;
const observe = location => event => {
  rows.push({location, composed: event.composed, target: describe(event.target),
    path: event.composedPath().map(describe)});
  out.textContent = JSON.stringify(rows, null, 2);
};
document.addEventListener('probe', observe('document'));
for (const mode of ['open', 'closed']) {
  const host = document.getElementById(mode + '-host');
  const root = host.attachShadow({mode});
  const button = document.createElement('button');
  button.id = mode + '-button'; button.type = 'button'; button.textContent = mode;
  root.append(button);
  root.addEventListener('probe', observe(mode + ' internal'));
  button.dispatchEvent(new Event('probe', {bubbles: true, composed: true}));
  button.dispatchEvent(new Event('probe', {bubbles: true, composed: false}));
}
// Expected externally: target host for both modes; open path includes its button/root,
// closed path excludes its internal button/root. Non-composed probes stay internal.
// These are synthetic events, not physical input or browser test receipts.
</script>

Write the expected identities before running it. For both composed probes, the outside target is the corresponding host. The open-root outside path includes open-button and its ShadowRoot. The closed-root outside path excludes closed-button and its ShadowRoot. A listener inside the closed tree still sees its internal portion. “Hidden from this outside observer” does not mean the event never passed through the button.

The non-composed probe stays within each shadow tree rather than reaching document. composed and bubbles answer different questions: crossing the shadow boundary versus bubbling propagation. Setting only bubbles:true does not establish the intended public event contract.

These are expectations derived from the algorithm and the explicitly chosen dispatch node, not captured console results. Compare node identities, rather than path length alone. If a later sample dispatches from a nested span, the leading-node expectation must change accordingly.

Does the page need a node or an action?

An open-root path may make a private button discoverable without making it a good long-term integration point. A later component version could replace one button with two controls while retaining the same public Save request. If the page needs to know which record should be saved, consider a semantic event carrying only agreed stable fields.

This is a design option, not a requirement that every component invent the same event. The component can handle raw interaction internally, then dispatch a save-request at its host with appropriate propagation flags. Its payload need not contain private DOM or arbitrary unvalidated input. Reaching document also proves neither authorization nor persistence.

The negative case is an outside handler asserting that composedPath()[0] must be an HTMLButtonElement for a closed component. It may receive the host instead. Relaxing a type assertion does not reveal an object that the public path excludes. Decide the component contract before routing actions through its internals.

Same-target listeners and propagation stops explains whether later handlers run. No stop method is called here. Even with uninterrupted propagation, target can be retargeted and a closed path filtered. Those mechanisms should not be diagnosed as interchangeable failures.

Can a saved Event produce the same path in a later task?

Do not depend on it. The cleanup in the dispatch algorithm empties the event path. A later task reads that cleaned state. Capture the needed identities or a suitable diagnostic description during the synchronous listener invocation.

A saved array of node references does not freeze those nodes’ text, attributes or business bindings. For diagnostics, recording IDs and the listener location can suffice. Updating a node later requires separate connection and ownership checks. The lifetime of currentTarget covers that asynchronous ownership question; retaining an Event does not preserve all its transient dispatch state.

The browser check remains pending. Keep separate records for open outside, closed outside, closed inside and non-composed dispatch, then compare synchronous reads with an explicitly later task. State the dispatch node, listener position, mode and flags in the report. Without those inputs, a screenshot showing a host as target does not explain the complete event contract.
