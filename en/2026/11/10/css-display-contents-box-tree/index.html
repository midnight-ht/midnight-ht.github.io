Inspect display:contents through layout, selectors and events

Inspect grid layout, DOM child selectors and bubbling separately, then add generated content and accessibility limits as distinct conditions.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-10 · Estimated read 17 min
Translations
zh-CN en

Article

Key takeaways

  • Contents suppresses an ordinary wrapper’s box without deleting its node.
  • Grid participation does not redefine DOM child relationships.
  • Generated content can add layout items; accessibility needs target checks.

For an ordinary wrapper, display:contents suppresses its own box without deleting its DOM node. Child boxes can participate in the parent grid while direct-child selectors and bubbling listeners continue to follow the original document relationships. A flatter layout and an unchanged DOM are compatible observations.

Imagine two buttons inside a div within a two-column grid. Applying contents removes the wrapper’s border and lets the buttons occupy parent-grid positions, yet its click listener still runs. That is not evidence of an incomplete element removal: the declaration never promised to remove an element.

The missing object is a box

The CSS Display Level 3 definition suppresses the element’s own boxes while its children and pseudo-elements continue generating boxes and text sequences. For box generation and layout, the wrapper behaves as if replaced by its contents. Document-tree behavior such as selector matching, event handling and inheritance is not changed by that rule.

The retrieved source is the Editor’s Draft dated 5 June 2026, not a target-browser test report. Its model explains the distinction without proving that every accessibility implementation preserves semantics correctly. The draft itself notes implementation concerns. Required roles, names and reading relationships need checks in the supported browser and assistive-technology combination.

The Grid Level 2 grid-item rules describe boxes representing in-flow content. With a wrapper box, that box participates as an item. Without it, the in-flow child button boxes can participate directly in the parent grid. That does not change their parentElement to the grid container.

One page, two layout states

The sample uses a plain div and no pseudo-elements, keeping unusual-element rules out of the main comparison. It has not been run in a browser. The buttons only produce diagnostics; they send no request and persist nothing.

<!doctype html>
<meta charset="utf-8"><meta name="viewport" content="width=device-width, initial-scale=1">
<title>Box tree and DOM — unexecuted teaching sample</title>
<style>
#grid { display: grid; grid-template-columns: repeat(2, 10rem); gap: .5rem; }
#wrapper { border: 2px solid; padding: 1rem; }
#wrapper.flat { display: contents; }
</style>
<button id="toggle" type="button">Toggle wrapper contents</button>
<div id="grid"><div id="wrapper"><button id="a" type="button">A</button><button id="b" type="button">B</button></div><button id="c" type="button">C</button></div>
<pre id="out"></pre>
<script>
const [grid, wrapper, out, toggle] = ['grid', 'wrapper', 'out', 'toggle'].map(
  id => document.getElementById(id));
const ids = selector => Array.from(document.querySelectorAll(selector), node => node.id);
function report(extra = {}) {
  out.textContent = JSON.stringify(Object.assign({contents: wrapper.classList.contains('flat'),
    domDirectGridButtons: ids('#grid > button'), wrapperButtons: ids('#wrapper > button'),
    wrapperBoxCount: wrapper.getClientRects().length}, extra), null, 2);
}
toggle.addEventListener('click', () => {
  wrapper.classList.toggle('flat'); report();
});
wrapper.addEventListener('click', event => report({target: event.target.id,
  currentTarget: event.currentTarget.id}));
report();
// Independent expectations: direct-grid DOM button list remains [c], wrapper list [a,b].
// In contents mode, a/b/c boxes participate in the parent grid; wrapper generates no box.
// Clicking a still invokes wrapper listener with currentTarget wrapper and target a.
// Screen-reader semantics and target-browser compatibility need separate real tests.
</script>

The independent layout expectation is wrapper-plus-C as parent-grid items in block mode, versus the A, B and C boxes in contents mode. In both modes, #grid > button still selects only C, and #wrapper > button still selects A and B. A direct-child combinator uses document relationships rather than visual participation in a grid.

Clicking A should still invoke the wrapper’s bubbling listener, with target A and currentTarget wrapper. A boxless node can remain on the propagation path of an event from its descendant. By contrast, an action depending on clicking the wrapper’s former border or empty space needs its hit area reconsidered: that geometry cannot be assumed to survive.

These are expected results, not captured pixel coordinates or console logs. GetClientRects observes the wrapper’s box generation; it does not enumerate every grid item. Layout positions and actual event identities need their own observations before the interaction is declared verified.

An unchanged DOM does not preserve every requirement

A wrapper supplying background, border and padding loses the box carrying those decorations. More width or border declarations cannot make that same box both absent and present. Retain the box, separate decoration from layout responsibilities, or consider another arrangement according to the requirement.

Subgrid and shared track sizing addresses a different goal: retaining a card while its children participate in selected parent-track sizing. It is not equivalent to suppressing the card’s box. Compare the need for a complete background and semantic grouping before choosing between these mechanisms.

The plain-div expectation also does not transfer indiscriminately to input, img or other unusual elements. The Display specification has special handling for replaced elements and elements whose rendering is not entirely controlled by CSS; contents can compute to none in relevant cases. Making a control boxless while expecting its operable interior to survive is not established by this sample.

Accessibility checks belong to the real task: can a user identify the group’s purpose, reach its actions in a meaningful order and obtain correct names? A node’s presence proves neither the browser’s accessibility-tree mapping nor assistive-technology behavior. Without a target-environment run, that result remains unverified.

Hidden rows and structural counting offers another example of keeping selectors separate from visual layout. Here A, B and C are not hidden. Contents leaves their content participating in layout; it is neither display:none nor transparency applied to an otherwise present wrapper box.

Can adding ::before create another grid item?

Yes, under the relevant in-flow conditions. Children and pseudo-elements still generate content normally. Adding an in-flow ::before box to the contents wrapper can therefore affect parent-grid auto-placement even though the DOM parent-child relationships remain unchanged.

As a separate, unexecuted comparison, add #wrapper.flat::before { content:"Note"; } to the original page. The independent expectation is additional generated content in contents mode and a changed placement relationship. Removing the rule returns to the three-button layout. This is not a recorded row/column measurement; moving the pseudo-element out of flow would change the conditions again.

Nonempty text can also participate through anonymous boxes, whereas whitespace-only text has specific handling. Grid-item count is therefore not interchangeable with the count of queryable elements. QuerySelectorAll does not return a normal element node for ::before. Do not substitute a DOM-query list for a complete layout-item inventory, or infer action identity from visual item order.

First verify the ordinary no-pseudo-element case through its separate layout, selector and event expectations. Then add generated content as a new condition. If the wrapper also owns decoration, semantics or a click region, include those responsibilities in its usage contract before deciding that suppressing its box is appropriate.
