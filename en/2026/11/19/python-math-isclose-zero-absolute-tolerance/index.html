Why does isclose still reject a tiny residual against zero?

Check signed residuals on both sides of an absolute bound, then verify isclose's special-value behavior.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-19 · Estimated read 11 min
Translations

Article

Key takeaways

  • Defaults reject nonzero finite values against zero.
  • Choose an absolute tolerance from units and an error contract.
  • Validate NaN, infinities, and finite inputs under their own conditions.

A residual is only one trillionth, yet math.isclose returns False against zero. The default absolute tolerance is zero. Relative tolerance alone cannot accept a nonzero finite residual against zero. A near-zero acceptance test needs an absolute bound chosen for its units, with examples on both sides.

Small is different from acceptably small

Suppose a local calculation adds quantities that should cancel and leaves a tiny nonzero result. Replacing equality with isclose will not tell the function what error the application accepts. That choice comes from resolution, algorithm requirements, or an interface contract. A short-looking display cannot supply it.

isclose tests whether the absolute difference is at most the larger of the relative tolerance times the larger input magnitude and the absolute tolerance. Defaults are a relative tolerance of one billionth and an absolute tolerance of zero. Against zero, the relative allowance shrinks with the other value and remains a fraction of it. A nonzero number cannot be smaller than its own billionth.

Shrinking a residual from a billionth to a trillionth therefore does not fix this comparison. Both the difference and relative allowance shrink proportionally. To express a fixed distance from zero, supply a meaningful positive abs_tol. Keeping proportional and fixed allowances distinct makes the acceptance rule explicit.

Choose a hypothetical bound and test both sides

For teaching, the fixture accepts a residual up to one tenth of a billionth in a hypothetical unit. It is no universal measurement threshold. The second group sets relative tolerance to zero so it isolates the fixed bound. Sign and argument order are checked independently.

from math import inf, isclose, nan

assert not isclose(1e-12, 0.0)
assert not isclose(-1e-12, 0.0)
checks = [
    (1e-12, True),
    (-1e-12, True),
    (2e-10, False),
    (-2e-10, False),
]
for residual, expected in checks:
    assert isclose(residual, 0.0, rel_tol=0.0, abs_tol=1e-10) is expected
    assert isclose(0.0, residual, rel_tol=0.0, abs_tol=1e-10) is expected
assert isclose(inf, inf)
assert not isclose(nan, nan)
assert not isclose(inf, -inf)
print("zero needs an absolute bound; sign and argument order verified")

Defaults reject both signs of one trillionth against zero. The explicit absolute bound accepts those values and rejects residuals twice the bound. Swapping arguments preserves the results. A clear outside value protects against an excessive tolerance that makes every expected case pass.

The fixture constructs residuals directly and simulates no device or business algorithm. It verifies acceptance for those finite values. Later special-value assertions support the follow-up separately. Runtime evidence does not establish a production error budget. Algorithm acceptance first needs a justified residual calculation, rather than a tolerance enlarged until a failing test turns green.

Preserve the units and the reason for the threshold

Absolute tolerance uses the input's units. Converting metres to millimetres requires the absolute bound to scale as well. Relative tolerance is a ratio. Store units and error policy together so a report can explain acceptance. An unexplained constant can become an unintended physical error allowance after a field changes units.

When both tolerances are present, the wider allowance wins. A tiny absolute bound does not stop a large-magnitude comparison from passing on its relative term. If a test requires a fixed difference bound, explicitly disable the relative term as the fixture does. A mixed policy needs independent expectations near zero and at a larger scale.

Review the chosen threshold separately from the calculation. Specify units and allowable error at this stage, then compare the algorithm's output. A known outside sample should fail and report the bound and units used. A later tolerance increase then changes that expected rejection visibly. This article implements no service logging.

Approximate equality also needs care as a grouping identity. With relative tolerance zero and absolute bound one, zero is close to 0.75 and 0.75 is close to 1.5, while zero is not close to 1.5. This is a separate deduction from the formula, outside the executed fixture. Grouping and deduplication need their own stable rule so comparison order cannot silently choose group membership.

Display formatting is another operation. Rendering a nonzero residual to three decimal places may show zero while leaving the compared value unchanged. Formatting to text and parsing it again discards information. The site's precision and rounding article explains that kind of lost input detail. Here the finite values stay intact while the acceptance rule changes. Retain enough precision in diagnostic values alongside the tolerance.

What about NaN compared with itself and infinity with itself?

NaN is close to no value, including itself. Positive infinity is close only to positive infinity, and negative infinity only to negative infinity. The fixture checks infinity against itself, NaN against itself, and opposite infinities. A finite-value tolerance derivation cannot be applied to those special cases. If an interface accepts finite measurements only, check finiteness separately before comparing tolerance and report that rejection explicitly. Closeness alone supplies no input-domain validation or industry-specific error budget.
