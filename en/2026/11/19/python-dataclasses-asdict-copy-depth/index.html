Why did dataclasses.asdict replace the field object too?

Use list mutations and a nested owner to compare recursive dataclass conversion with a shallow fields/getattr projection.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-19 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • asdict recursively converts containers and dataclasses and deep-copies other objects.
  • A shallow field projection retains the original field references.
  • Dictionary conversion still needs a separate encoding check at a transfer boundary.

After asdict converts a dataclass, changing the items list in the resulting dictionary leaves the source unchanged. dataclasses.asdict recursively converts dataclasses and containers and deep-copies other objects. A caller that needs field names with the original field references should construct a shallow projection.

Where the values inside the new dictionary come from

Suppose a background task stores an item list and an owner in Packet. The list is mutable, and the owner is another dataclass. A logging system may need independent data. An editor in the same process may need to operate on the existing list. Both interfaces can use a dictionary on the outside, while internal identity determines where edits go.

asdict traverses dataclasses, dictionaries, lists, and tuples. It converts nested dataclasses into dictionaries and uses deepcopy for other objects. The result is more than a renamed reference table. The list in this example becomes a different list, and Owner becomes a dictionary with a name field. Identical displayed values establish neither matching types nor shared identity.

The documentation offers a shallow alternative: enumerate fields, get each value from the source, and build a dictionary. Its outer dictionary is new and its field values retain their references. Adding an outer key does not add a field to the dataclass, but appending to the referenced items list changes the source. Describe the outer structure and ownership of internal values separately at an interface boundary.

Follow two edits back to the source

The fixture starts with one item and one owner. It checks the converted shape, verifies important identities, and changes each exported list separately. No database, file object, or network resource participates.

from dataclasses import asdict, dataclass, fields

@dataclass
class Owner:
    name: str

@dataclass
class Packet:
    items: list[str]
    owner: Owner

source = Packet(["A"], Owner("Lin"))
deep = asdict(source)
shallow = {f.name: getattr(source, f.name) for f in fields(source)}
assert deep == {"items": ["A"], "owner": {"name": "Lin"}}
assert deep["items"] is not source.items
assert shallow["items"] is source.items
assert shallow["owner"] is source.owner
deep["items"].append("B")
assert source.items == ["A"]
shallow["items"].append("C")
assert source.items == ["A", "C"]
assert deep["items"] == ["A", "B"]
print("asdict detached list; field projection retained references")

The deep result initially contains A and an owner dictionary. The shallow projection retains the original list and Owner. Appending B to the deep result leaves the source at A. Appending C through the shallow result changes the source to A, C, while the deep result stays at A, B. The last check establishes that edits traveled to different places despite equal initial values.

Equality alone cannot establish independence. Two distinct lists can start equal, and a shallow projection can print much like a recursive result. Identity checks locate shared objects. Mutations show the practical consequence. A test that compares only newly created dictionaries could allow the implementations to be exchanged and miss the bug until an editor modifies the wrong list.

The owner is a separate control. A consumer that expects Owner methods or attributes faces a changed contract after recursive conversion. A shallow projection retains the instance. If a consumer needs only the name, the application can export that string explicitly and reduce its dependence on internal shape. The consumer's needs should determine the representation.

Choose a snapshot or shared mutable state

Independent data for logging or transfer can reduce the effect of later edits. Recursive copying does not itself establish a consistent cross-field snapshot, though. If another thread changes items and owner concurrently, the application still needs to define when reading occurs and what version it records. This sequential fixture measures neither concurrent updates nor copy costs.

An editor can retain references using the shallow projection, but its consumer needs to know who else will observe mutations. A cache or another caller may hold the same list. Read-only consumers can receive necessary immutable values or an explicit snapshot. A shallow outer dictionary does not make all its contents read-only.

Another failure is editing the deep result while expecting a task update. The function can return normally and an editor can display its changed data while the source remains untouched. Test updates by reading the actual source again for the expected identifier. Test isolated snapshots in the opposite direction: mutate the exported result and require the source to stay unchanged. The two interfaces need different directional assertions.

The site's resource ownership after transfer article addresses a related handoff. This Python fixture leaves the source usable, and a shallow projection can share references within the same process. Its runtime evidence covers the shown types and list contents alone.

Does the dictionary returned by asdict guarantee JSON encoding?

A custom field object can be copied into another instance of its own type without becoming a JSON primitive. A direct json.dumps call may raise TypeError. If the wire format permits strings or numbers, explicitly export the allowed representation and verify encoding and business meaning separately. This custom-field variation is unexecuted. The executed fixture contains strings, lists, and dataclasses. Add an encoding test when the consumer requires JSON instead of treating dictionary conversion as the whole transfer contract.
