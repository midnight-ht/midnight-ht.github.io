Why does at(-0.5) read the first item instead of the last?

Compare negative integers, fractions, and out-of-range positions on one three-item array. Check conversion before inspecting the returned row.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-19 · Estimated read 10 min
Translations
zh-CN en

Article

Key takeaways

  • at converts the position before indexing
  • A small negative fraction can select the first item
  • Test input policy separately from language conversion

A list preview receives a position of minus one half. The developer expects negative positions to read from the end, but the page shows A, the first row. The array was not reversed. The at method converts the position to an integer before applying its relative-index rule. Minus one half becomes negative zero.

Convert before choosing an end of the array

Take the fixed list A, B, C. Position zero reads A and minus one reads C. The parameter goes through ToIntegerOrInfinity before the algorithm tests whether it is below zero.

A finite fraction loses its fractional part. Minus one and a half becomes minus one and reads C. Minus one half becomes negative zero, which satisfies the nonnegative comparison used by the index algorithm. It selects position zero. The method does not add the original fraction to the array length or round it toward negative infinity.

A test using only minus one misses this branch. If a field permits fractions, define whether that is intentional before passing the value to the array. Language conversion does not establish a product rule allowing a fraction of a row.

A converted position outside the array returns undefined. With three items, minus four is out of range. The method does not choose what a preview should show then. Decide whether to clear it, retain it with an explanation, or report an invalid position.

Use five positions on one list

The script checks zero, a small negative fraction, a negative integer, a larger negative fraction, and an out-of-range value on the same dense array. It does not read a form or call a service.

import {deepEqual} from 'node:assert/strict';

const rows = ['A', 'B', 'C'];
const cases = [[0, 'A'], [-0.5, 'A'], [-1, 'C'],
               [-1.5, 'C'], [-4, undefined]];
for (const [position, expected] of cases) {
  deepEqual(rows.at(position), expected);
}
console.log('Integer, fractional, negative, and out-of-range cases passed.');

All five assertions passed in local Node. Zero and minus one half read A. Minus one and minus one and a half read C. Minus four returned undefined. The outputs verify these calls, without establishing that an application should accept those positions.

Follow the actual field entry point in a component test. An integer-only contract should reject the fraction before reading the array. A product that deliberately truncates can explain the effective position. Those are different expected behaviors.

An input path may also call parseInt on text first. That preprocessing can discard part of the original entry before at sees it. Keep parsing and array access distinct in diagnostics so a correct array result doesn't conceal invalid text.

Keep array positions distinct from record identity

A negative index depends on the list at read time. Saving minus one and reading it after another item arrives selects the new final item. If the user intended the record that was last when they chose it, retain that record's stable ID.

For a regression, keep the member IDs or list version. Minus one reads C in A, B, C and D after D is appended. The language operation is behaving consistently. The component must decide whether to follow the changing position or preserve the selected record.

Also check whether upstream rows include group headings or loading placeholders. Array position zero need not represent the first business record. Test the actual collection passed to the method and compare the returned identity with what the UI displays.

An empty list needs its own visible state. This three-row fixture explains fractional indexing without proving that an application clears a stale preview when there are no rows.

For diagnosis, keep the raw position, current array length, and returned member ID in one observation. Take another observation after the list changes. Mixing the first input with the second output can create a false explanation for the selection.

Does undefined prove there is no entry?

No. Add a different input condition: an array can explicitly contain undefined at a valid position. A missing own property at a position can also produce that result. The returned value alone doesn't distinguish them.

If that distinction belongs in the contract, check length and property presence separately. For an ordinary array without inherited indexed values, Object.hasOwn can identify whether the valid index is an own property. Allowing inherited numeric properties adds another condition.

For a separate collection validation issue, see every on empty and sparse arrays.
