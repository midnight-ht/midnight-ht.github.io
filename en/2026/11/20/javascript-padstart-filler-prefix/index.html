Why does padStart use aba when three padding units are needed?

Explain aba7 through the repeated filler prefix, compare short and overlong inputs, and define the role of a display identifier.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-20 · Estimated read 13 min
Translations
zh-CN en

Article

Key takeaways

  • Padding takes only the prefix needed for the remaining length
  • An overlong original is preserved
  • Define the roles of display and formal identifiers

Padding the string 7 to a total length of four with ab produces aba7. The final repetition is incomplete because only three padding units are needed. padStart prepares enough filler, takes the required prefix, and places it before the original string. It also preserves an original string that already exceeds the target length.

Three remaining units take a filler prefix

ECMAScript delegates padStart to a shared padding algorithm with placement at the start. It converts the target length and compares it with the original length. If the target is no larger, it returns the original string before padding. The four-unit target therefore places no upper bound on a five-unit input.

For a larger target, the required padding is the difference between target and original lengths. The string 7 uses one code unit, leaving three. Repeating ab produces enough material; taking its first three units gives aba. Prefixing that to 7 yields aba7. Requiring every repetition to remain complete would produce a different length contract.

The fixture uses ordinary ASCII strings, where a character occupies one code unit. That keeps the arithmetic transparent. It measures no font widths and promises no equal visual columns. Display alignment still requires suitable typography and layout.

Also distinguish filler from a business prefix. If ab is a category marker that must remain intact, do not use it as repeatable, truncatable material. Construct the marker and identifier under their own rules before deciding which part may be padded. Producing aba does not establish a valid category.

Four inputs establish the behavior

This complete script retains identifiers as strings. It covers repeated filler, zero padding, equal-length input, and overlong input. It also checks that the inputs remain unchanged. Expected results are literal values determined in advance, rather than another copy of the same algorithm.

import { deepEqual } from 'node:assert/strict';
const inputs = ['7', '42', '1234', '12345'];
const fillers = ['ab', '0', '0', '0'];
const actual = inputs.map((value, index) => value.padStart(4, fillers[index]));
const expected = ['aba7', '0042', '1234', '12345'];
deepEqual(actual, expected);
deepEqual(inputs, ['7', '42', '1234', '12345']);
console.log(JSON.stringify({ inputs, actual }));

The script ran locally in Node and matched all four expected results. The short value 42 became 0042, 1234 stayed unchanged, and 12345 remained five units long. The input array also retained its values. This establishes behavior for these fixed parameters in the recorded environment. No form, identifier service, or storage operation was exercised.

The overlong input is a deliberate negative control. An interface requiring at most four units must handle 12345 in its validation. A successful formatting call does not establish validity. Truncating the final unit to make a check pass could collapse different identifiers into the same string and needs an actual identity policy.

The argument four can also be misread as “add four units.” For 42 it adds only two zeroes. Always prefixing four zeroes is a different operation. Acceptance criteria should give the complete expected string, avoiding an ambiguous instruction such as “pad four digits.”

Keep the original value's role explicit

Establish whether an external identifier is text or a number. Converting 007 to the number seven loses its original representation. Later padding cannot recover its provenance. A display formatter can retain both the original identifier and its display string with names that explain their roles.

Decide which value is used for saving and lookup. A page may show 0042 while its API expects the original 42. Another system may treat the four-unit text as the formal identifier. The component boundary should identify which contract applies so clicking, copying, lookup, and submission retain the intended object.

For a composite identifier, define which part carries a length requirement. A category prefix and a numeric sequence may have separate rules. Padding the combined string and then guessing which zero belongs to which part obscures those rules. Specify the fields and their expected results first.

A configurable target also needs an input policy. The language converts its argument, while the product may reject fractional, negative, or excessively large targets. This fixture fixes the target at four and does not exercise those conditions. Validate a limited set of supported configurations before formatting when that is the product contract.

Code units also differ from user-perceived characters. Changing the filler to special symbols or combining sequences requires another length decision. See textarea length and UTF-16 for the input-limit context. The padding fixture stays with ASCII so that character perception, input limits, and filler prefixes do not become one ambiguous test.

A product acceptance record can retain the original value, display string, and submitted value for the same record. Repeat with equal-length and overlong identifiers. This helps locate a failure in formatting, validation, or submission mapping. A visually aligned list alone cannot establish correct identity through those steps.

Does an empty filler still reach the target length?

No. This adds an empty filler, whereas all four main cases use nonempty material. StringPad returns the original string for empty material. A target of four can therefore produce a result of length one. This separate complete script checks the new condition.

import { strictEqual } from 'node:assert/strict';
const actual = '7'.padStart(4, '');
strictEqual(actual, '7');
console.log(JSON.stringify({ actual, length: actual.length }));

Local execution returned 7 with length one and passed its assertion. A larger target alone does not guarantee that padding reaches it. If the product requires a full result, validate the filler configuration or choose a meaningful default under that contract. Preserve an explicitly chosen empty input as a distinct case.
