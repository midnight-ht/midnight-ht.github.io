Why must motion actuation be disableable even when an Undo button exists?

Use four undo-state cases to check an alternative control and disableable motion response, then scope the essential-motion condition.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-20 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Check the alternative control and motion disabling separately
  • Keep the button route usable with motion disabled
  • Use fresh initial content to expose unintended commands

An editor has added an Undo button alongside shake-to-undo, yet movement on a bus can still trigger it accidentally. The button provides a route for someone unable to shake the device. Disabling motion response addresses movement that should not invoke undo. Both conditions need acceptance evidence.

Two conditions protect the same action

WCAG 2.2 SC 2.5.4 concerns functionality operated through device or user motion. For ordinary shake-to-undo, it requires operation through user interface components and the ability to disable the response to motion to prevent accidental actuation. This article fixes its scope to a nonessential shortcut for undo.

The Understanding document describes devices held on fixed mounts and users unable to perform particular movements accurately. It also describes accidental actuation associated with tremors. An alternative route and a way to stop motion invoking commands address different failures. The presence of a button alone leaves one of them untested.

The component must offer the same function. A shake that undoes the latest edit and a button that clears the whole document do not provide equivalent operations. Fix the starting document, the edit being undone, and the expected content before comparing the routes.

A disabling choice must reach actual input handling. A settings screen can display disabled while an old listener still invokes undo. Inspect whether the command entry point uses the current choice. Preference persistence and synchronization remain product decisions.

Four local branches establish the content contract

This teaching state model reads no sensors and renders no button. Each case starts from document v2, and an allowed undo restores v1. The local input strings motion and button identify routes; they are not evidence that browser events or device gestures were received.

import { deepEqual } from 'node:assert/strict';
function createEditor(motionEnabled) {
  let documentVersion = 'v2';
  return {
    requestUndo(source) {
      if (source === 'motion' && !motionEnabled) return documentVersion;
      documentVersion = 'v1';
      return documentVersion;
    }
  };
}
const cases = [
  { motionEnabled: true, source: 'motion' },
  { motionEnabled: false, source: 'motion' },
  { motionEnabled: false, source: 'button' },
  { motionEnabled: true, source: 'button' }
];
const actual = cases.map(({ motionEnabled, source }) => {
  const editor = createEditor(motionEnabled);
  return editor.requestUndo(source);
});
deepEqual(actual, ['v1', 'v2', 'v1', 'v1']);
console.log(JSON.stringify({ cases, actual }));

The complete script ran locally in Node and returned v1, v2, v1, v1 as specified in advance. The disabled-motion case retained v2, while the disabled-motion button case still restored v1. This verifies the local branch model, with actual sensor behavior still requiring device evidence.

Fresh instances matter. If an earlier case already restored v1, another unchanged v1 can hide an incorrectly invoked motion path. Independent initial content makes an unwanted mutation observable. A real editor should also record command counts or document versions so an exhausted undo history cannot produce a false pass.

Keep the enabled routes in the test as well. A repair that disables all undo would preserve content but lose the user's function. Specific allowed and blocked content outcomes provide a stronger criterion than an absence of errors.

Reconnect the model to the product

Prepare a recoverable test document and make a defined edit. With motion enabled, use the supported gesture once. Rebuild the same starting state and use the button. Compare content, document identity, and undo depth. Then disable motion while keeping the application open and repeat the gesture. The document should remain unchanged under this contract.

Use the button again with motion disabled. Confirm that the supported input methods can reach and operate it. A decorative icon without a clear name or usable focus path does not establish the complete user route. No keyboard, assistive technology, or physical motion input was exercised here.

If the application relies on an operating-system setting, verify that it changes the application's response. The Understanding guidance permits supporting such a setting. Record the system version, setting, and content outcomes before and after disabling it.

Also change the preference while an editor remains open. An existing instance may retain an earlier Boolean while newly opened pages behave correctly. Cross-tab or account synchronization needs its own evidence if promised. Saving a setting alone cannot establish that every current route uses it.

For a related input problem, see protection for character-only shortcuts. That criterion offers its own alternatives. This motion example requires both the component route and disableable motion response under the stated scope.

Must a pedometer replace every step with a button?

This adds a condition in which motion itself is what the function measures. The Understanding document gives a motion-based pedometer as an essential-motion example. Where removing motion would invalidate the activity, the criterion's essential exception may apply.

Record why motion is essential to that particular function. Merely using a sensor does not settle it. Counting steps and shaking to issue an undo command serve different purposes. If the page also uses shaking to switch tabs, assess that command separately. An exception for one function does not automatically cover every motion command on the page. No actual pedometer product was assessed here.
