Why does a thicker outline leave the neighboring button in place?

Separate outline ink from layout space and compare target geometry, neighbor position, and the rendered indicator.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-20 · Estimated read 13 min
Translations
zh-CN en

Article

Key takeaways

  • An outline takes no layout space
  • Stable geometry does not establish a visible outline
  • Inspect both layout readings and actual rendering

Increasing a button's outline from two pixels to eight leaves its neighbor in place. That can agree with the outline rules. An outline takes no layout space. A thicker painted indicator and a resized box are different observations, so inspect both geometry and the actual rendering.

Painted outlines and layout space

CSS Basic UI Level 4 states that outlines take no space, contribute to ink overflow, and may be nonrectangular. This article uses the 13 November 2026 Working Draft and ordinary buttons without transforms or special painting conditions.

A wider outline does not request another ring of layout space. Button dimensions and the neighbor's position can remain stable. This can help a requirement to avoid movement when an indicator appears. Its visibility under every ancestor, background, and overlap condition still needs inspection.

The element's bounding rectangle also cannot serve as the complete bounds of its outline ink. Geometry readings can check whether layout moved. Rendering evidence needs to show whether the indicator appeared and whether surrounding content interfered with it.

A geometry-only test has a specific false pass: removing the outline entirely can leave every rectangle unchanged. Layout stability and an identifiable current control each need an observable result.

A complete page changing only outline width

The target and neighbor have the same border and padding. A separate control toggles only the target's outline width. It changes no text, borders, gaps, or container dimensions. Readings include target width and height, the neighbor position, and computed outline width.

<!doctype html>
<meta charset="utf-8">
<title>Outline and layout measurements</title>
<style>
.row { display: flex; gap: 12px; padding: 12px; }
button { border: 1px solid; padding: 8px; }
#target { outline: 2px solid #17486b; outline-offset: 2px; }
#target.wide { outline-width: 8px; }
</style>
<button id="change" type="button">Toggle outline width</button>
<div class="row">
  <button id="target" type="button">Target</button>
  <button id="neighbor" type="button">Neighbor</button>
</div>
<pre id="result"></pre>
<script>
const byId = document.getElementById.bind(document);
const target = byId('target');
const neighbor = byId('neighbor');
function read() {
  const box = target.getBoundingClientRect();
  const next = neighbor.getBoundingClientRect();
  return {
    targetWidth: box.width,
    targetHeight: box.height,
    neighborLeft: next.left,
    outline: getComputedStyle(target).outlineWidth
  };
}
byId('change').onclick = () => {
  const before = read();
  target.classList.toggle('wide');
  const after = read();
  byId('result').textContent = JSON.stringify({ before, after }, null, 2);
};
</script>

The standards-based prediction is unchanged layout dimensions and neighbor position when the outline widens, together with a changed computed outline width. No universal button dimensions are specified. Fonts, zoom, and native button presentation can change the baseline.

No browser was run and no screenshot was collected. The full page and readings are a prospective comparison. A real record should retain the environment, before-and-after geometry, the computed value, and the corresponding rendering. Investigate other state or style changes if a geometry value moves.

A negative control can remove just the outline declaration. If every test still passes, it has checked geometry without checking the required indicator. Restore the declaration and repeat the full observation. A developer-tools edit is not evidence that the published code contains the repair.

Preserve the trigger when applying this to focus

The teaching page toggles a style directly. It does not simulate focus input modes. A product using focus-visible must first establish whether the target matches it. See focus and the visible-indicator selector for that decision. Selector matching and layout-space behavior require their own diagnosis.

A thicker border also depends on the box's sizing contract. A fixed outer size and an automatic size can react differently. See content boxes and border edges and retain width, height, padding, and box-sizing conditions when comparing approaches.

Inspect visibility in the actual layout. This isolated fixture leaves room around its buttons; a crowded toolbar may bring wider ink near neighboring text. The gap can remain unchanged while the result becomes harder to distinguish. No reflow alone is an incomplete acceptance condition.

Bind theme checks to the same task. An outline visible against one background needs inspection under other supported themes or system colors. The specification cautions against making the relevant keyboard-focus outline invisible without an alternative highlighting mechanism. No universal color or assistive-technology acceptance is claimed here.

A component contract can retain indicator styling and layout dimensions separately. Changing an outline into a thicker border while also changing padding makes the final geometry harder to explain. Start with a controlled comparison, then verify the combined production design.

Use the same coordinate conditions and observation timing. Scrolling between readings can mix a viewport change into the comparison. Preserve the conditions or record the scroll and size change explicitly. This script does not scroll the page; product events still require attention.

Must a link wrapping across two lines have one rectangular outline?

No such universal shape follows. This adds multiline inline content to the ordinary button fixture. The specification permits nonrectangular outlines. An element's overall bounding rectangle does not determine the outline that must be painted.

Let the link actually wrap in the target browser, inspect whether its content fragments remain identifiable, and save the rendering. Do not require every implementation to paint the same enclosing rectangle or infer complete fragment coverage from one geometry reading. This variant was not run here.
