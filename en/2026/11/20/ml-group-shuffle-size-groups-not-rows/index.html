Why can GroupShuffleSplit with test_size=0.5 test more or fewer than half the rows?

Distinguish group proportions from row proportions with four groups and twelve rows, and inspect split intersections and counts.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-20 · Estimated read 13 min
Translations
zh-CN en

Article

Key takeaways

  • The test_size proportion uses group counts
  • Unequal group sizes change the test row proportion
  • Inspect group intersections and sample quantities separately

GroupShuffleSplit with test_size set to one half can put three quarters of the rows in the test set. The half refers to groups. Four groups with sizes eight, one, one, and two contain twelve rows. Choosing two groups can select nine rows or only three. Establish the parameter's denominator before judging the split.

Keep an entity's records together

Scikit-learn's GroupShuffleSplit generates indices using group information supplied by the caller. A group can represent a person, device, or another domain entity. Grouping can express a requirement that an entity's related records belong on one side within a split.

The artificial groups A, B, C, D have sizes eight, one, one, and two. They describe no observed population. A test_size of 0.5 selects half of four groups: two. The documented floating proportion uses group counts and rounds up. It does not first calculate six rows from twelve.

Selecting A and B gives nine test rows and three training rows. Selecting C and D reverses those counts. Both allocations select two groups. Different row proportions follow from unequal group sizes. A requirement for enough test rows needs its own check.

The group identifier also needs a suitable domain meaning. Labeling each visit by one person as a separate group fails to encode person-level isolation. Combining many independent entities into one group reduces the number available for splitting. Define which unseen entities the evaluation should address before choosing the boundary.

Two valid allocations and a row-split counterexample

This complete script processes fixed rows and groups. It selects A/B or C/D explicitly to check counts and intersections. It calls no scikit-learn code, runs no random splitter, and trains no model. The selections are not presented as output from a particular random_state.

import { deepEqual } from 'node:assert/strict';
const groups = ['A', 'A', 'A', 'A', 'A', 'A', 'A', 'A', 'B', 'C', 'D', 'D'];
const rows = groups.map((group, index) => ({ id: index + 1, group }));
function describe(train, test) {
  const trainGroups = Array.from(new Set(train.map(row => row.group)));
  const testGroups = Array.from(new Set(test.map(row => row.group)));
  return {
    trainRows: train.length,
    testRows: test.length,
    trainGroups,
    testGroups,
    shared: trainGroups.filter(group => testGroups.includes(group))
  };
}
const actual = [['A', 'B'], ['C', 'D']].map(selected => {
  const selectedGroups = new Set(selected);
  const test = rows.filter(row => selectedGroups.has(row.group));
  const train = rows.filter(row => !selectedGroups.has(row.group));
  return describe(train, test);
});
deepEqual(actual, [
  { trainRows: 3, testRows: 9, trainGroups: ['C', 'D'], testGroups: ['A', 'B'], shared: [] },
  { trainRows: 9, testRows: 3, trainGroups: ['A', 'B'], testGroups: ['C', 'D'], shared: [] }
]);
const rowSplit = describe(rows.slice(0, 6), rows.slice(6));
deepEqual(rowSplit.shared, ['A']);
console.log(JSON.stringify({ actual, rowSplit }));

The exact script passed locally in Node. Test counts were nine and three, with no shared groups within either split. Literal expectations include group identities and both counts. The final negative control splits the first six rows from the last six. Its row counts are equal, but A occurs on both sides.

Disjoint row indices do not establish disjoint entities. Every row has a distinct identifier, yet separate records from A can cross the boundary. Retain both checks. “No duplicate samples” cannot silently stand for every isolation requirement.

The receipt establishes this deterministic allocation's arithmetic and set relationships. Actual library output requires the package version, parameters, and returned indices. A later package-based implementation should retain selected groups as well as its seed. No Python package or classifier was executed here.

Report groups and rows together

Retain training and test groups, row identifiers, group counts, and row counts. First check the group intersection within a split. Then inspect whether the sample quantity meets the task's needs. Correct isolation does not settle whether the test set is large enough.

Check for omitted rows too. An empty group intersection establishes no shared groups, but does not prove every input row was allocated. Compare the combined training and test row identifiers with the original input list to expose records lost during filtering or joining.

Unequal groups can affect class coverage. A large group may concentrate particular labels. The group-size parameter supplies no class-stratification promise. Inspect actual label coverage before deciding whether the domain needs another split design.

Feature preparation is another boundary. Correct allocation alone cannot establish that a fitted preprocessing step never saw the test data. Record the sample scope used by preparation and fitting. This article executes neither stage and makes no claim to rule out every form of leakage.

For version comparisons, retain the split's identity. A proportion alone can produce different test objects after the input or grouping changes. The mapping between rows and groups helps attribute a difference to a model, data membership, or the group boundary. A seed assists reproduction but cannot replace the input version.

Data allocation and metric averaging also answer different questions. See micro and macro precision for aggregating already supplied predictions. This article addresses which entities are tested. Changing the average cannot repair an unsuitable allocation.

Must test groups from different rounds be disjoint too?

The splitter does not guarantee mutually exclusive test sets across rounds. This adds a comparison between rounds, whereas the main checks concern training and test groups within one split. A first test set A/B and a second A/C can each exclude their own training groups while sharing A with each other.

That is an additional paper example, not an observed random output from the script. Adding the test row counts across those rounds counts A's eight records twice. State whether a report measures per-round evaluation work or distinct test-object coverage, and calculate the corresponding quantity.
