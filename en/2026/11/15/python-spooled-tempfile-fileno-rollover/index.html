Why does a tiny Python spool roll over when you ask for fileno?

Trace descriptor-triggered and explicit rollover with two executed Python fixtures.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-15 · Estimated read 8 min
Translations

Article

Key takeaways

  • Descriptor access can trigger rollover.
  • Check the descriptor, position, and bytes separately.
  • A reopenable path needs a separate contract.

A tiny Python SpooledTemporaryFile can move to a real temporary file when code calls fileno. The size threshold and descriptor access are two separate triggers. If a consumer needs a descriptor, include that conversion in the resource plan.

Suppose an exporter writes three bytes and hands a file object to an upload adapter. Its threshold is eight bytes. The adapter calls fileno and the spool moves to disk. Find who requested the descriptor before looking for a large write. The adapter might only need a readable object, or it might actually need a descriptor for a system call.

Identify the operation that changes storage

The standard library describes buffering in memory until the content exceeds max_size or code calls fileno. After that it behaves like TemporaryFile. The public rollover method can also trigger the transition. Calling fileno to find out whether a descriptor is available changes the state being inspected. Python tempfile reference.

An eight-byte threshold leaves the descriptor path open. If the deployment can fail to create a temporary file, check where the adapter reports that failure and which side owns cleanup. The local example does not inject such an error.

Check the bytes, position, and descriptor independently

The complete program ran on Python 3.11.15. Each branch writes abc under an eight-byte threshold. One requests a descriptor immediately. The other rolls over before requesting it. It flushes and checks file size, position, and the bytes read back.

import os
from tempfile import SpooledTemporaryFile

def observe(explicit):
    with SpooledTemporaryFile(max_size=8, mode="w+b") as spool:
        spool.write(b"abc")
        if explicit:
            spool.rollover()
        handle = spool.fileno()
        spool.flush()
        assert os.fstat(handle).st_size == 3
        assert spool.tell() == 3
        spool.seek(0)
        assert spool.read() == b"abc"
    return "explicit" if explicit else "descriptor"

print(observe(False), observe(True))

Both branches check size three, position three, and the original bytes. The archive records that both passed. The first shows that a small input can obtain a real file through the descriptor path. The second checks that explicitly converting preserves the same data. The check does not show where the object stored its data before descriptor access or whether anything was persisted to physical media.

To test the size rule separately, prepare inputs equal to and greater than the threshold. Choose an observation that does not call fileno. The documented trigger is exceeding the threshold. A consumer that only needs the bytes can test them directly. Observing the internal transition requires a version-scoped test. The threshold extension was not run.

Choose a resource the consumer can actually use

A read-and-seek consumer can use the file-like interface. A consumer that needs a descriptor should acquire it at a deliberate handoff point and give its error path a clear owner. Test two stand-ins with the same three bytes: one reads the object, while the other asks for a descriptor first. Check their positions separately. Closing the object is an independent part of the ownership contract. These application checks were not run.

An additional unit test can provide a readable object with no usable descriptor. The byte-only consumer should still succeed, while the descriptor consumer should fail during preparation. This check was not run.

Can another program reopen the rolled file by name?

TemporaryFile does not promise a visible name that can be reopened. The directory entry may never exist or may be removed after creation, depending on the platform. If the consumer requires a path, use an interface that guarantees a visible name and test its reopening and cleanup contract. The related NamedTemporaryFile article covers that contract. The descriptor experiment did not start another process or verify reopening by name.
