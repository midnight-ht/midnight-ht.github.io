Why did pytest --deselect remove a second test?

Compare prefix exclusion, a longer node-ID exclusion and the full pytest result.

Updated 2026-11-15 · Estimated read 8 min

Article

Key takeaways

  • The pinned implementation checks a node-ID prefix.
  • Inspect executed items as well as the exit status.
  • Handle module import problems at the collection boundary.

The pinned pytest implementation matches a node-ID prefix, so a longer name can match it too. After passing an apparently complete --deselect argument, check which tests actually ran.

A maintainer wants to exclude one known test and keep observing the others in the module. The command goes green, but a new edge case disappears too. The requested text identifies the shorter test exactly. The selector also matches any item whose node ID starts with that text.

A node’s full name can also be another node’s prefix

The pytest collection guide documents item deselection during collection and allows multiple exclusions. The pytest 9.0.2 implementation uses startswith to decide which collected node IDs to remove. The path, separator and remaining name all participate. Check the version in use before relying on that detail.

This fixture deliberately makes one omitted test fail. The assertion and file stay unchanged across runs. The green result comes from selecting different tests.

Find the missing test across three runs

Save this complete file as test_calculation.py in a disposable directory, alongside a pytest.ini containing only [pytest]. Disable external plugin autoload and extra options from the environment. The fixture ran with Python 3.11.15 and pytest 9.0.2.

def test_total():
    assert 1 + 1 == 2


def test_total_edge():
    assert 0 + 0 == 1


def test_other():
    assert 3 * 3 == 9

Run python -m pytest -v, then add --deselect=test_calculation.py::test_total. On the third run use --deselect=test_calculation.py::test_total_edge instead. Keep the file and working directory the same.

Invocation Executed outcome Exit
No exclusion Short name and other pass, edge fails 1
Exclude the short name Only other passes, two items deselected 0
Exclude the long name Short name and other pass, one item deselected 0

The shorter ID is the start of the longer one, so the second run excludes both. The third run still uses a prefix match. In this set, nothing else starts with the longer ID. Adding another test name that extends it can change that result. The two green runs do not establish the same coverage.

Record the scope of a temporary exclusion

Write down which nodes must execute. A short name that is also a prefix may not be usable for excluding just itself. Use the project’s marker conventions or explicitly select the items that must remain, then inspect the actual node IDs. With parametrized tests, decide whether the intended scope is a function or one case, and check the IDs pytest generated.

Keep the command, working directory, candidate nodes and executed nodes. Collection output can expose a broad exclusion before an expensive run, while the execution report records outcomes. If the exclusion remains in a release job, give it a reason and a condition for removal. A green run supplies no new outcome for an omitted case. The cache selection example covers a separate mechanism based on earlier failures.

When removing the exclusion, check that both the fixed test and the unintentionally omitted neighbor return to the executed set. A stable total count can conceal a renamed or missing node. This is a proposed CI check, separate from the local exercise.

Can deselection hide a module import failure?

The option applies to items obtained during collection. A module can fail before it produces any to remove. To exclude the whole file from collection, use the documented --ignore path option where appropriate and confirm the intended scope. A separate experiment could pair a module with an intentional import failure and a normal one, then compare item exclusion with file exclusion. That variation was not run.
