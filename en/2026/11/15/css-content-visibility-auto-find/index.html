Why can find-in-page still reach offscreen content with content-visibility:auto?

Compare auto and hidden with two offscreen chapters, using separate checks for find-in-page and keyboard navigation.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-15 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Auto retains normal find-in-page behavior
  • Hidden blocks navigation into skipped contents
  • Test search and focus with separate observations

Under the CSS rules, set an offscreen chapter to content-visibility: auto and the browser can still find a reference number inside it. Switch to content-visibility: hidden and the search behaves differently. Being offscreen tells you where the chapter starts. Browser search and keyboard navigation have their own rules for which content remains reachable.

What the two values allow a browser to skip

The specification lets a browser skip rendering work for an auto element's subtree while its contents are not relevant to the user. For find-in-page and sequential focus navigation, the contents must still participate as usual. Being far from the viewport is not enough to remove a paragraph from search.

The hidden value skips contents with different conditions for user interaction. Find-in-page and sequential navigation cannot reach the skipped content. In the example, that means the heading, plain text, and link inside the section. It does not follow that the section's own box takes up no space. The CSS value is also distinct from the HTML hidden attribute.

In a long document, reaching an offscreen chapter may be the behavior the author wants to preserve. A search that jumps to the target doesn't tell you the entire document was rendered at first load. It tells you the browser was able to find the text in response to the search.

If the product requires some contents to be unreachable by keyboard and search for a period, auto won't provide that boundary. Define what a user should still be able to reach before choosing the hiding mechanism. Measure rendering separately if you need to know how much work it saved.

Give the browser two offscreen chapters

Save this standalone HTML file. Each chapter follows a gap taller than the viewport and contains a unique token and an ordinary link. Keep the token out of other visible instructions so a search result has a single source.

<!doctype html>
<meta charset="utf-8">
<title>Offscreen chapters</title>
<style>
  .gap { height: 170vh; }
  section { min-height: 12rem; }
  .auto { content-visibility: auto; }
  .hidden { content-visibility: hidden; }
</style>
<body>
  <a href="#start">Start of test</a>
  <p id="start">Both chapters begin offscreen.</p>
  <div class="gap"></div>
  <section class="auto">
    <h2>Automatic chapter</h2>
    <p>cobalt-nectarine-042</p>
    <a href="#start">Return from automatic chapter</a>
  </section>
  <div class="gap"></div>
  <section class="hidden">
    <h2>Hidden chapter</h2>
    <p>violet-orchard-081</p>
    <a href="#start">Return from hidden chapter</a>
  </section>
</body>

Start at the top and open the browser's find-in-page interface. Search for cobalt-nectarine-042. The specification predicts a match. Reload and return to the top before searching for violet-orchard-081, which is expected to have no match in the hidden chapter. Don't use the previous search's scroll position as the starting point.

Test the keyboard separately. Close the search interface, focus the link at the start, and press Tab to advance within the document. The automatic chapter's return link remains eligible. The hidden chapter's link should not appear in that sequence. Browser chrome and platform navigation preferences can affect where a keypress goes, so record the elements that gain focus inside the document.

Those are expectations from CSS Containment Level 2. No browser was exercised, no timing was measured, and no assistive technology output was observed for this article. In your test log, record the browser, platform, and keyboard settings so another person can repeat the actual procedure.

Use separate checks for the two outcomes. Search means the browser reports a match for the token. Keyboard reachability means the corresponding link receives focus. The gaps keep the chapters offscreen at the beginning. Their height does not establish a portable threshold for when an engine skips rendering a particular subtree.

Avoid navigating to a chapter beforehand. A contents link or a retained search result can move the descendant close to the viewport and change the initial conditions. Start with an isolated file before testing a real page with different scroll containers and additional CSS.

If the result disagrees with the expectation, first inspect the section’s computed style. When both sections resolve to the default, check support and overrides before comparing search results. If both tokens match despite the expected values, see where the browser found them. A diagnostic panel injected into the document might have repeated a token outside the chapter.

For a tighter comparison, duplicate the file and change only one chapter’s class. Keep that chapter at the same position with the same token, then repeat the search and focus checks from the same start. This removes chapter position as a variable. It still checks interaction, so use a separate trace if you need to measure work done by the renderer.

Does focusing an offscreen link change the auto case?

Yes. Introduce a new action: have a script focus the eligible link inside the automatic chapter. Focus on the element or within its content makes it relevant to the user. Once the link receives focus, being offscreen doesn't justify skipping its contents. This example uses a link that can already receive focus.

After the call, inspect document.activeElement to verify which link received focus. Scrolling and an assistive technology announcement are separate observations. Even if you arrange for the focus call to leave the scroll position unchanged, the focused content still meets the relevance condition.

If instead you want content to begin hidden and reveal it when a match is found, see the reveal process for HTML hidden until-found.
