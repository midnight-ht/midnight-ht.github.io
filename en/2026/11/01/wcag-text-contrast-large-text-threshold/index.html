WCAG text contrast: does bold 18px qualify as large text?

Choose the contrast threshold from delivered font and size before reviewing effective colors, rounded results and CJK equivalent-size conditions.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-01 · Estimated read 13 min
Translations
zh-CN en

Article

Key takeaways

  • Eighteen CSS pixels do not mean eighteen points.
  • Large-text qualification depends on size, weight and font conditions.
  • User zoom and numeric rounding do not retroactively satisfy the threshold.

Treating bold 18px as 18pt can select the wrong text-contrast threshold. Establish delivered size, font conditions and background before choosing ordinary text's 4.5:1 or the large-text 3:1 threshold. A heading tag, visual impression or later user zoom does not establish those conditions.

Choose the threshold before comparing colors

The WCAG 2.2 Contrast(Minimum) explanation concerns Level AA SC 1.4.3. Text and images of text generally require at least 4.5:1, with at least 3:1 for large text and specific exceptions such as incidental text and logotypes. Calling faint instructions secondary does not itself establish an exception.

The large-scale definition specifies at least 18 point,14 point bold, or an equivalent size for Chinese, Japanese and Korean fonts. It concerns the delivered size, excluding subsequent user resizing. Stroke and font characteristics still affect readability; a threshold does not make every font equally legible.

CSS absolute lengths relate one inch to 96CSS pixels and one point to one seventy-second of an inch. Thus 14pt is approximately 18.67px and 18pt is 24px. This is a unit calculation, not a measurement of physical screen size or a rule to count screenshot pixels.

For the common Latin-font conditions used here, bold 18px cannot qualify merely because its number matches 18pt. Relative units also need their computed context:1.2em can resolve differently under different inherited sizes. Record font, weight and actual size rather than a design-token label alone.

A complete three-style sample

This unexecuted static file uses Latin sample text so the CJK equivalent-size condition is not silently reduced to a universal pixel number. The colors are teaching choices; their actual ratio was not measured here, and this is not a passed contrast example.

<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>Contrast threshold sample</title>
<style>
  body { color: #6b6b6b; background: #fff; font-family: Arial, sans-serif; }
  .small-bold { font-size: 18px; font-weight: 700; }
  .large-bold { font-size: 14pt; font-weight: 700; }
  .large-regular { font-size: 18pt; font-weight: 400; }
</style>
</head>
<body>
<h1>Compare delivered text styles</h1>
<p class="small-bold">Sample A: bold eighteen CSS pixels.</p>
<p class="large-bold">Sample B: bold fourteen CSS points.</p>
<p class="large-regular">Sample C: regular eighteen CSS points.</p>
</body>
</html>

First classify A, B and C by their size and weight conditions, then obtain foreground and background colors for calculation. A cannot be grouped with C because both declarations contain eighteen; B also depends on its bold condition. Check the actual font when fallback occurs.

This separates misclassification from a correctly classified style whose colors still fail its threshold. Repairing every failure by making text bold hides the distinction and may make prose harder to read. Choose a genuine typography or color change according to the task.

Why can a displayed 4.5 still fail?

Thresholds cannot be met by rounding upward. An illustrative internal result of 4.499 might be displayed as 4.5 at one decimal place, but it remains below 4.5. These are hypothetical values, not measurements of the sample. Preserve sufficient precision or an explicit tool pass/fail basis.

Use the effective color relationship. A translucent foreground is not necessarily the raw RGB token, while a gradient or image can place different backgrounds behind different parts of the text. Choosing the most favorable patch cannot represent the whole passage.

Sampling an antialiased edge pixel in a magnified screenshot does not automatically identify the author's foreground color. Pixel inspection can help investigate rendering, but retain separate evidence for color conditions, font properties and practical legibility.

Does user zoom turn small text into qualifying large text?

User resizing does not retroactively change the delivered-size condition. If the design intends large text, establish that typography and verify its resulting layout. Asking a tester to zoom in is not a substitute.

A larger heading may wrap and displace actions or explanations. For body copy, improving contrast may suit the task better than enlarging everything to retain one palette color. No user study or completion-rate result is supplied here to justify a universal choice.

Can the same 18px rule be applied to every CJK font?

The definition explicitly includes equivalent CJK sizes. Explain the font, delivered size and basis for qualification rather than presenting one Latin conversion as certification for all CJK text. Where the exception is unclear, designing to the ordinary-text threshold is a proposed engineering choice, not a newly invented CJK standard.

Evaluate disabled components separately from useful instructions nearby. A gray module label does not establish that all its text is exempt. Necessary non-text contrast information addresses a different 3:1 requirement; it is not the universal threshold for text.

For example, a genuinely inactive Book button may sit beside “This week is full; check again next week.” Assess the button’s applicable exception from its actual state. The adjacent explanation still communicates a useful next step; proximity to a gray button does not exempt it. Ordinary small explanatory text needs its own text-contrast assessment.

Proposed acceptance records computed size, weight, font and effective colors for the three styles, then examines error, hover and theme changes. Restore the styles to the real page and check that content and actions remain usable. No browser, measurement-tool or assistive-technology check was executed. State why a threshold applies before comparing the color result against it.
