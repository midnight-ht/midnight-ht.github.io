Does an IntersectionObserver ratio of one prove a person saw the content?

Use a complete scrolling-root and opacity sample to examine area ratios, zero-area cases and asynchronous thresholds without claiming a read receipt.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-01 · Estimated read 14 min
Translations
zh-CN en

Article

Key takeaways

  • Ordinary intersection ratios describe geometry rather than reading.
  • Intersection status and area ratio have different edge cases.
  • Preloading and measurement need separate event contracts.

Being geometrically inside an observation root does not prove that a person saw or read a card. In ordinary geometric configuration, IntersectionObserver's intersectionRatio describes an area relationship. Counting a ratio that once reached one as a completed read skips occlusion, duration, background state and attention.

What does the ratio answer?

The Intersection Observer entry definition defines intersectionRatio as intersection area divided by target bounding-box area when the latter is nonzero. Root and clipping relationships matter. It is not simply the percentage of visible screen pixels. This article concerns the geometric mechanism, without certifying optional visibility extensions or browser support.

Identify the root. The viewport and an inner scrolling container are different references; occupying a container's available region still does not establish that someone is looking at the page. Retain root, target and thresholds instead of a lone “exposure succeeded” event.

Geometry can support preloading, deferred loading and position observation without proving comprehension. A proximity signal may be adequate for preparing the next image. Reading measurement needs its own product definition.

A complete transparency comparison sample

This unexecuted file sends no analytics. It provides an inner scrolling root and an opacity toggle. The log is the latest delivered geometric entry, not a live frame-by-frame measurement.

<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<title>Geometric intersection demonstration</title>
<style>
  #root { height: 180px; overflow: auto; border: 2px solid; }
  .space { height: 120px; }
  #target { height: 160px; background: #ddd; }
</style>
</head>
<body>
<h1>Compare geometric entries with transparency</h1>
<button id="toggle" type="button">Toggle target opacity</button>
<div id="root"><div class="space"></div><div id="target">Demonstration card</div><div class="space"></div></div>
<p>The log contains the latest entries, not continuous sampling.</p>
<pre id="log">No entry delivered yet</pre>
<script>
const [root, target, log, toggle] = ['root', 'target', 'log', 'toggle'].map(
  id => document.getElementById(id)
);
const observer = new IntersectionObserver(entries => {
  log.textContent = entries.map(entry => JSON.stringify({
    time: entry.time, ratio: entry.intersectionRatio,
    intersects: entry.isIntersecting
  })).join('\n');
}, { root, threshold: [0, 0.5, 1] });
observer.observe(target);
let transparent = false;
toggle.onclick = () => {
  transparent = !transparent;
  target.style.opacity = transparent ? '0' : '1';
};
window.addEventListener('pagehide', () => observer.disconnect(), { once: true });
</script>
</body>
</html>

The target retains its dimensions when transparent. Opacity zero does not itself shrink its geometric bounds to zero, so ratio and visual appearance can disagree. If opacity changes no intersection condition, it also need not create another threshold notification.

These are mechanism-derived expectations, not captured browser output. Record entry time, scrolling position and transparency when testing; an old log cannot establish current visible state. The default sample also cannot rule out overlay occlusion or certify an optional visibility feature.

How can intersection have zero area?

The specification defines isIntersecting separately from the ratio. Edge adjacency can produce an intersecting state with zero area. A zero-area target also has a special ratio rule based on its intersecting flag. Interpret true, zero and one with the target dimensions and entry conditions.

If work should start when at least half the target enters, isIntersecting alone is insufficient. Express the area condition and any required nonzero-size condition. A preloading task may reasonably choose a different trigger. Do not adopt one merely because a sample uses it.

There is no universal valid-exposure helper here. Image preparation, pagination and reading have different failure costs. Triggering preloading early may consume resources; overcounting reads may distort a product decision. One shared boolean conceals those distinctions.

Does every scroll synchronously invoke the callback?

Entries are delivered asynchronously, with threshold-region and intersection-state changes participating in queueing. This is neither a synchronous event for each scroll pixel nor continuous recording. A callback can include several entries; retain their targets and times rather than assuming one current card.

The sample thresholds of zero, one half and one illustrate intervals, not a recommended measurement policy. Extending rootMargin for advance loading also changes the reference region. Do not describe that trigger as entry into the actual visible viewport without qualification.

Lifecycle handling is another responsibility. Disconnecting does not retract an analytics event already sent. Remounting and receiving another entry do not inherently mean another person's new read. Identity, deduplication and event retries belong to the application contract.

Can reaching one count as an effective read?

Define the unit and evidence first. A product may require sustained duration, pause timing while backgrounded and deduplicate repeated entry for one object. Even then, name the observed exposure or dwell condition accurately instead of claiming comprehension or task completion.

Product-metric denominators addresses units and completion; transparent controls remaining interactive describes another distinction between visual state and behavior. This article adds the geometry signal's boundary rather than combining them into one visibility pass.

Check the whole root’s position as well. An intersection relative to an inner container does not establish that container’s presentation in the enclosing page. A viewport-based requirement needs that relationship examined too. Ratios from different roots cannot simply be multiplied and named a reading percentage without considering their denominators and clipping scopes.

Proposed validation covers full and partial entry, edge adjacency, zero size, opacity changes and remounting. Record roots, bounds, entry times, ratios and business counts separately. No checks or actual reading measurements were performed. Name the observed event accurately before deciding which product conclusion it can support.
