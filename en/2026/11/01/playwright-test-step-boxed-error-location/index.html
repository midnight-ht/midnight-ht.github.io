Playwright test.step: why does box point an error at the call site?

Use a complete deliberately failing comparison to explain test.step box locations while retaining failure status, version conditions and diagnostic ownership.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-01 · Estimated read 12 min
Translations
zh-CN en

Article

Key takeaways

  • Box changes displayed error location without swallowing failure.
  • Shared helpers still need identifiable step context.
  • Box is not timeout, retry or business-repair behavior.

The same failing assertion can point inside a step normally and at its call site when boxed. Playwright test.step's box option changes the diagnostic boundary, not the failed behavior. Decide where report readers should begin their investigation before applying it.

Error location is not execution status

The test.step API lists box as an option, false by default and added in version 1.39. Errors from a boxed step's internals point to its call site. This article checked the current official interface without assuming every old installation supports it. The tests below were not run.

Box is not try/catch. It does not convert an exception into an ordinary result or make later checks treat failure as success. It also does not repeat a click or business command. A clearer report is not evidence that the underlying test has been repaired.

A shared helper makes the choice concrete. Several tests may call the same verification operation. The reader may first need to know which business invocation failed, then investigate its assertion and page state. A useful step name cannot replace those underlying details.

A complete deliberately failing comparison

This sample has no login or API. A local page contains a pending heading while the helper deliberately expects a nonexistent saved heading. Both variants are intended to fail. A failing test command therefore need not indicate broken setup. No command or invented error-line output is presented as executed.

Use a separate directory, install Playwright Test supporting the option and its browser, then save the file as box.spec.mjs. Existing projects should follow their dependency and lockfile policy instead of replacing dependencies with these commands.

npm init -y
npm install --save-dev @playwright/test
npx playwright --version
npx playwright install chromium
npx playwright test box.spec.mjs --workers=1 --reporter=line

import { test, expect } from '@playwright/test';

async function checkDemoRecord(page, boxed) {
  return test.step('check demonstration record', async () => {
    await expect(page.getByRole('heading', { name: 'Saved record' }))
      .toBeVisible({ timeout: 200 });
  }, { box: boxed });
}

for (const boxed of [false, true]) {
  test(`missing result, box=${boxed}`, async ({ page }) => {
    await page.setContent('<h1>Pending record</h1>');
    await checkDemoRecord(page, boxed);
  });
}

The fixture, page content, missing target and test entry point are supplied. No unknown URL or account must be invented. The short assertion budget makes a teaching failure prompt; it is not a service objective or a recommendation for all tests. Record the actual version, both failure states and displayed locations before comparing the result with the API description.

A success variant needs the required page state and a retained result assertion. Turning on box is not that repair. If changing it appears to make a test pass, investigate other changes to code, data or execution rather than assigning success to an error-location option.

Which boundary helps the reader?

A helper representing an understandable business operation can expose a useful call-site context. Name the operation specifically enough to distinguish the task rather than calling every step “Run action.” The caller often owns the object and scenario information.

A low-level generic utility may benefit more from directly exposing its internal failure. Several layers of boxing can make a selector error harder to investigate. Choose by responsibility and diagnostic needs rather than imposing box=true on every step.

Boxing does not make loading faster, targets unique or dependencies reliable. Retain the failing step, the actual reason and useful evidence. A cleaner arrow cannot replace any of those requirements.

What if one helper processes several objects?

A call site inside a loop can still handle many records. Identical step names without identity information may leave the reader unable to locate the failed item. Use appropriate non-sensitive test identities where needed, with sensitive detail limited to controlled evidence.

Do not put full user information into titles simply to improve diagnostics. Reports and attachments may have broader visibility than the business interface. The option itself supplies no privacy policy.

Returned data remains a separate contract. Test.step can return the step body's result. A caller needing object identity should use an explicit return relationship instead of treating log text as its data interface. Returning a value does not replace an assertion of the required outcome.

Does box add timeout or retry budget?

It is not a timer. Other current options have their own version requirements; custom location and step timeout do not automatically belong to a minimum-1.39 example. This sample deliberately excludes them. Check the installed version before combining options from current documentation.

Test, assertion and action budgets retain their existing responsibilities. Timeout budget layers explains why one can expire first. Moving the displayed error to a call site does not change that competition. Whole-test retries also need their own attempt evidence.

Proposed acceptance retains the deliberately failing comparison, then adopts boxing in one shared helper. Check whether readers can identify the object, investigate the internal error and still see the correct failure status. No reports, screenshots or stability improvements were measured here. Describe the changed investigation entry point rather than claiming the error was solved.
