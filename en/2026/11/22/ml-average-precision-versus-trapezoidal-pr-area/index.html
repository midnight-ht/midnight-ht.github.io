Why can AP differ from trapezoidal area on the same PR curve?

Derive AP of 5/6 and trapezoidal area of 19/24 from three ranked examples, then inspect a separate tied-score condition.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-22 · Estimated read 16 min
Translations
zh-CN en

Article

Key takeaways

  • AP weights precision by recall increments
  • Identical points can use different accumulation rules
  • Record version direction and interpolation convention

Average precision and trapezoidal PR area can differ on the same ranked predictions. scikit-learn’s AP weights each precision by the corresponding increase in recall rather than linearly interpolating adjacent points. Calling both numbers PR-AUC without specifying the calculation makes a report difficult to reproduce. Fix the convention before comparing model versions.

The samples stay fixed; the accumulation changes

The official average_precision_score reference defines AP as the sum of recall increments multiplied by the precision at each threshold. The examined page identifies scikit-learn 1.9.1 and notes that the noninterpolated behavior replaced linear interpolation in 0.19. This article describes that implementation, not every historical metric named AP.

A trapezoid averages the precisions at both ends of an interval and multiplies by its recall width. AP uses the current precision across that recall increment. The points can be identical while the accumulation differs. Similar-looking plotted curves do not establish that two numerical reports use the same convention.

The fixture is binary, uses positive label 1, and has no sample weights. Its artificial scores establish an ordering; they are not claimed to be calibrated probabilities. As the threshold falls, samples with score greater than or equal to it enter the predicted-positive set. Retaining true-positive and false-positive counts makes the points independently auditable.

Three ranked examples, two independent expected values

Labels are 1, 0, 1 and scores are nine tenths, eight tenths, and seven tenths. The first threshold includes one positive: precision 1 and recall one half. The second adds a negative: precision one half with recall unchanged. The third adds the remaining positive: precision 2/3 and recall 1. Add the endpoint with recall 0 and precision 1.

AP is one half plus one third, or 5/6. Adding the negative produced no recall increment, so that step has zero AP weight. However, it changes the starting precision of the next trapezoid. Trapezoidal area is one half plus one half times the average of one half and two thirds, or 19/24.

This complete module uses Node’s standard facilities, not scikit-learn or a classifier. Counts and expected fractions are written independently of the tested formulas. It retains the equal-recall vertical change rather than dropping that point to make a smoother picture.

import assert from 'node:assert/strict';
const labels = [1, 0, 1];
const scores = [9 / 10, 8 / 10, 7 / 10];
const thresholds = Array.from(new Set(scores)).sort((a, b) => b - a);
const positives = labels.filter(value => value === 1).length;
const points = [{recall: 0, precision: 1}];
const counts = [];
for (const threshold of thresholds) {
  let tp = 0;
  let fp = 0;
  scores.forEach((score, i) => {
    if (score >= threshold) labels[i] === 1 ? tp += 1 : fp += 1;
  });
  counts.push([tp, fp]);
  points.push({recall: tp / positives, precision: tp / (tp + fp)});
}
let ap = 0;
let trapezoid = 0;
for (const [i, current] of points.entries()) {
  if (i === 0) continue;
  const {recall, precision} = current;
  const {recall: previousRecall, precision: previousPrecision} = points[i - 1];
  const width = recall - previousRecall;
  ap += width * precision;
  trapezoid += width * (previousPrecision + precision) / 2;
}
assert.deepEqual(counts, [[1, 0], [1, 1], [2, 1]]);
for (const [actual, expected] of [[ap, 5 / 6], [trapezoid, 19 / 24]]) {
  assert(Math.abs(actual - expected) < 1e-12);
}
console.log(JSON.stringify({thresholds, counts, points, ap, trapezoid}));

The exact module ran locally in Node. Counts were [1,0], [1,1], and [2,1]; AP was approximately 0.8333 and trapezoidal area 0.7917. These observations describe artificial inputs and a local arithmetic implementation. They are not Python package output, model-quality evidence, or a real business distribution.

AP is larger in this example, but this does not establish a universal ordering. The documentation says linear interpolation can be too optimistic; it does not say it must produce a larger value for every point set. Show the actual points and convention rather than turning a qualified warning into an unsupported universal claim. These fractions expose a definition difference, not a contest to obtain the higher score.

Record direction and integration conventions

The precision_recall_curve reference returns increasing thresholds and decreasing recall, with a final precision-1, recall-0 point that has no threshold. This fixture uses decreasing thresholds to accumulate increasing recall. When consuming library output, account for the actual direction and endpoint instead of blindly copying signs.

Wrong direction can yield negative area; dropping endpoints or vertical changes can produce another number. Record the metric, implementation version, positive label, weights, direction, and interpolation choice. A change against an old report using a different convention cannot be attributed to a model improvement merely because the displayed decimals differ.

The discussion of micro and macro precision concerns aggregation across classes. Here, one binary ranking is evaluated across thresholds and accumulated over recall. Those are different axes. Similar parameter names cannot replace a statement of what is being averaged.

Version comparisons also need stable sample-to-score pairing. Sorting the label and score arrays independently changes which label belongs to which prediction. The formula can still return a number, but it no longer describes the original predictions. Preserve sample identifiers with labels and scores before constructing the threshold table. This fixed fixture pairs arrays by index and does not verify a real evaluation pipeline.

Reproducibility is not representativeness. Three examples are a small teaching oracle, without confidence intervals or deployment coverage. They can detect an implementation-convention change but cannot set a universal product acceptance threshold. Task requirements, error costs, and suitable evaluation data still determine whether a model serves its purpose.

Can equally scored positive and negative examples be ordered arbitrarily for AP?

Not by inventing distinct thresholds. This adds one positive and one negative both scored eight tenths. The curve reference uses unique score values as thresholds and selects scores greater than or equal to each threshold. Both examples therefore enter together: recall 1 and precision one half. Under this noninterpolated definition, AP is one half.

import assert from 'node:assert/strict';
const labels = [1, 0];
const scores = [4 / 5, 4 / 5];
const thresholds = Array.from(new Set(scores));
const selected = scores.map(score => score >= thresholds[0]);
let tp = 0;
let fp = 0;
for (const [i, label] of labels.entries()) {
  if (selected[i]) label === 1 ? tp += 1 : fp += 1;
}
const recall = tp / 1;
const precision = tp / (tp + fp);
const ap = (recall - 0) * precision;
assert.deepEqual([thresholds, selected, tp, fp, recall, precision, ap], [
  [4 / 5], [true, true], 1, 1, 1, 1 / 2, 1 / 2
]);
console.log(JSON.stringify({thresholds, recall, precision, ap}));

This separate script also ran locally. Its sole threshold is eight tenths, both selection flags are true, and AP is one half. Counting the positive alone before admitting the negative invents a score threshold that can separate equal scores. Changing their array order does not create such a decision point.

Keep a tied-score case alongside the distinct-score fixture, preserving the threshold set and membership at each step. The script establishes fixed arithmetic behavior, not Python library output. When checking the real package, retain its version and parameters and compare with the same independent expectation. Do not credit an unexecuted library with a local demonstration’s success.
