Why can a String.raw result still contain an actual newline?

Compare literal segments and evaluated substitutions by exact code units, then inspect an ordinary call with fewer substitutions.

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-11-22 · Estimated read 13 min
Translations
zh-CN en

Article

Key takeaways

  • Raw segments come from the template object
  • Substitutions retain their evaluated contents
  • Code units distinguish values from display escapes

String.raw preserves the backslash spelling in a template’s literal segments. It does not turn an actual newline inside a substitution back into a backslash followed by n. One result can therefore contain both sequences. Separate literal source text from evaluated data, then inspect code units rather than relying on how a console prints the string.

Which input does raw apply to?

A tagged template supplies two kinds of input: the fixed template segments and the evaluated substitution values. String.raw reads fixed segments from the template object’s raw sequence, converts substitution values to strings, and inserts them between those segments. Concatenation does not make their origins equivalent.

The ECMAScript String.raw algorithm describes raw-segment retrieval and substitution processing as separate steps. The source examined here is the current ECMAScript 2027 specification, not a browser release announcement. The name raw does not promise to recover source spelling for every value passed to the function.

Suppose a fixed segment contains backslash-n while a variable already holds a newline. An ordinary template processes the fixed escape into a newline. The raw tag instead retrieves the fixed segment’s original spelling. The variable still supplies the same newline in both cases. Its quotes, escape spelling, or construction history do not reappear merely because the surrounding template uses a raw tag.

Changing the tag cannot repair data that was already transformed elsewhere. If a consumer requires original file text, preserve and pass that text from the reading stage. An evaluated string does not reveal whether its newline originally came from an escape, a literal line break, or concatenated fragments. Several source expressions can produce the same value, so there is no unique reverse transformation.

Verify the complete code-unit sequence

This complete module handles fixed strings only. It reads each UTF-16 code unit by index, and compares the result with independently written numeric arrays. It does not read files or make requests.

import assert from 'node:assert/strict';
const substitution = '\n';
const raw = String.raw`A\n${substitution}B`;
const cooked = `A\n${substitution}B`;
const units = text => Array.from({length: text.length}, (_, i) => text.charCodeAt(i));
assert.deepEqual(units(raw), [65, 92, 110, 10, 66]);
assert.deepEqual(units(cooked), [65, 10, 10, 66]);
assert.equal(substitution.charCodeAt(0), 10);
console.log(JSON.stringify({raw: units(raw), cooked: units(cooked)}));

The exact script ran locally in Node and passed. The raw result contains A, backslash, n, newline, and B: 65, 92, 110, 10, 66. The ordinary template contains A, two newlines, and B. This execution establishes the local runtime’s string behavior, not browser rendering or an external receiver’s interpretation.

Length also differs because the preserved backslash-n spelling occupies two units while the corresponding newline occupies one. Length alone is a weak diagnostic, though: exchanging two characters could preserve it. The complete arrays constrain both the number and position of the units, making the origin of each segment visible.

A console may display an escape to keep a log on one line. A visible backslash can therefore belong to the printer’s representation or to the actual string. A screenshot does not distinguish those cases. Code units, lengths, and construction inputs do: unit 10 is a newline, whereas units 92 and 110 are a backslash and the letter n.

What representation does the receiver require?

If a text protocol requires newlines to be escaped, use its encoder. Preserving literal template spelling does not encode dynamic values for an arbitrary destination. Generated code, log displays, and ordinary page text can have different input contracts; a single tag cannot establish all of them.

A concrete failure is placing a dynamic note in a raw template and expecting every newline in the note to become two visible characters. The main example disproves that expectation. Replacing characters across the entire result afterward can introduce a second mistake by transforming fixed content that was meant to remain unchanged. Identify the layer responsible for converting a value into the receiver’s representation before adding transformations.

The existing article on raw query values and encoded query text concerns a different contract: parameter methods and query parsers accept different input forms. This article instead distinguishes literal template segments from substitution values. In both cases, naming the input form is more reliable than inferring a universal capability from a function name.

During review, mark the boundaries between fixed segments and substitutions and specify the characters expected at each one. When a substitution comes from another function, inspect that function’s return value independently. Even a long final result can then be traced to the step where a newline became an actual character. Fixed teaching data is sufficient for this diagnosis; private business text is unnecessary.

With one substitution and three raw segments, does ordinary function calling still join every segment?

Yes. This introduces a constructed template object and too few substitutions, rather than repeating the tagged-template case. The algorithm appends a substitution only when one exists for the current position, then continues reading raw segments. A missing substitution does not automatically become the text undefined.

import assert from 'node:assert/strict';
const result = String.raw({raw: ['A', 'B', 'C']}, 1);
assert.equal(result, 'A1BC');
assert.notEqual(result, 'A1BundefinedC');
console.log(result);

This separate script also ran locally and printed A1BC. The first gap receives the string conversion of 1. The second has no substitution, but B and C are still joined. The negative assertion excludes A1BundefinedC, distinguishing an absent argument from an explicitly supplied undefined value.

The ordinary call illustrates the argument-count contract; it is not a recommendation to manufacture template objects for routine joining. Use templates when tagging is appropriate, and a receiver-specific encoder when the task is serialization. Retain the actual character sequence as evidence rather than accepting an output merely because it looks like raw text.
