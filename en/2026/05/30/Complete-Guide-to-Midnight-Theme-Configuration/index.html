Complete Guide to Midnight Theme Configuration

A practical guide to hexo-theme-midnight v0.1.16 configuration, covering appearance, navigation, i18n, comments, SEO, analytics, homepage modules

M Midnight Engineering notes on development, quality, security, delivery, and operations. View Author Profile
Updated 2026-05-30 · Estimated read 42 min
Translations
zh-CN en

Article

Midnight configuration is not just about changing a logo or turning comments on.

It behaves more like an editorial control file for a technical publication: homepage channels, navigation states, multilingual article links, comment providers, SEO metadata, sponsorship slots, newsletter pages, privacy copy, and collection pages all have configuration entry points.

This guide is based on the current midnight-ht/hexo-theme-midnight GitHub repository. At the time of writing, the repository page shows v0.1.16 as the latest release, dated May 30, 2026. The main references are the theme _config.yml, README.md, and README.zh-CN.md.

Where the Configuration Lives

Your site-level _config.yml usually keeps the theme selection:

theme: midnight

Then copy the theme _config.yml into a maintainable theme config file, commonly:

_config.midnight.yml

One boundary matters: theme config is read by templates and can become part of frontend output. Do not put model provider API keys, mail service secrets, or private service tokens here. For example, model_session.endpoint should point to your own server-side proxy, while the real provider key stays on the server.

Minimum Useful Configuration

To get the theme running first, start with this:

appearance:
  logo: /img/avatar.png
  logo_text: Midnight
  nick: Midnight
  default_scheme: dark

i18n:
  default_lang: zh-CN
  route_strategy: auto
  languages:
    - zh-CN
    - en

comments:
  enabled: false
  provider: giscus

seo:
  open_graph: true
  robots: index,follow

Navigation, homepage channels, newsletter, advertising pages, and analytics can come later. Midnight has many options, but only a small set blocks the first launch.

Basic Metadata

description Technical theme description Fallback site description.

apple_touch_icon /img/favicon.png iOS home-screen icon.

Put favicon assets under source/img/, then reference them as /img/favicon.ico or /img/favicon.png. Do not use local disk paths.

Appearance: appearance

Option Default Purpose
appearance.logo Empty Logo image path.
appearance.logo_text Midnight Brand text in the header.
appearance.nick Midnight Site or author nickname, used as a fallback in some modules.
appearance.accent #4df2c8 Theme accent color.
appearance.default_scheme dark Default color scheme, usually dark or light.
appearance.background default Background style token read by theme CSS.

For a personal technical blog, change logo, logo_text, nick, and accent first. Use dark mode for a more editorial technical feel, and light mode for a documentation-like reading experience.

Navigation: nav

Midnight uses a fixed navigation skeleton: Home -> custom items -> Archives -> About. You mainly edit nav.items.

nav:
  home:
    name: home
    path: /
  items:
    - name:
        zh-CN: 工程化
        en: Engineering
      path: /tags/Engineering/
      style: underline
      active_match:
        - /tags/Engineering/
  archives:
    name: archives
    path: /archives/
  about:
    name: about
    path: /about/
Option Purpose
nav.home.name / nav.home.path Home link label and path.
nav.items[] Custom navigation items.
nav.items[].name String label or localized object such as { zh-CN, en }.
nav.items[].path Target path. Internal links are processed by the i18n-aware route helper.
nav.items[].style One of underline, text, pill, ghost, outline, or solid.
nav.items[].active_exact Whether active state requires an exact path match.
nav.items[].active_match[] Path fragments that trigger active state.
nav.archives Archive link.
nav.about About link.

Use underline for long-running sections. Reserve stronger styles such as pill or solid for temporary campaigns or commercial links.

Internationalization: i18n

Midnight is built for Chinese and English publishing. The two important pieces are language-aware routes and translation relationships between posts.

Option Default Purpose
i18n.default_lang zh-CN Default language.
i18n.route_strategy auto Language route strategy.
i18n.languages[] zh-CN, en Supported languages.
i18n.article_lang_field lang Front matter field used for article language.
i18n.translation_key_field translation_key Front matter field used to connect translations.

For synchronized bilingual posts:

---
title: "Midnight 主题配置项完整指南"
translation_key: midnight-theme-config-complete-guide
lang: zh-CN
---

---
title: "Complete Guide to Midnight Theme Configuration"
translation_key: midnight-theme-config-complete-guide
lang: en
---

The shared translation_key lets the theme find the matching version during generation. The Chinese and English posts can still use different slugs.

Model Session: model_session

This module provides a browser-side UI. It does not safely store provider secrets for you.

Option Default Purpose
model_session.enabled true Enables the AI session panel.
model_session.endpoint Empty Your server-side proxy endpoint.
model_session.title.zh-CN / .en AI 会话 / AI Session Panel title.
model_session.default_system_prompt English reading-assistant prompt Default system prompt.
model_session.allow_user_system_prompt true Allows users to provide a system prompt.
model_session.max_messages 12 Maximum retained messages.

In production, point endpoint to something like /api/model-session. That backend should call OpenAI, Claude, or another provider. Provider API keys should never appear in the theme config.

A Practical Configuration Order

Do not try to fill every field in one sitting. A better order is:

  1. Configure appearance so the site feels like yours.
  2. Configure i18n and confirm language paths plus front matter rules.
  3. Configure nav.items with only durable sections.
  4. Configure seo with verification tokens and a default share image.
  5. Pick one comment provider and configure comments.
  6. Rewrite inner_pages.about so the about page can handle contact and cooperation.
  7. Configure inner_pages.newsletter.form only when you have a real newsletter endpoint.
  8. Rewrite inner_pages.advertise only when sponsorship is part of the site.
  9. Fine-tune labels and home after the content structure is stable.

Midnight has many options because it is not just a post-page skin. It tries to put the homepage, collections, multilingual publishing, monetization, and reading aids into one static-first Hexo theme. Start with the writing and publishing loop, then let the heavier modules grow as the site needs them.
