Solution: Docker Container Network Connectivity Issue

Problem

When running Docker containers, you encounter issues where:

  • Dependencies fail to download
  • External API calls don’t work
  • Container cannot access the internet

Error Messages

Failed to resolve 'archive.ubuntu.com'
Unable to locate package
Cannot connect to external service
Network unreachable

Root Causes

  1. Docker bridge network not properly configured
  2. DNS resolution issues inside container
  3. Host firewall blocking container traffic
  4. Docker daemon network settings
  5. Host network configuration issues

Solutions

Solution 1: Check Docker Network Status

# List Docker networks
docker network ls

# Inspect bridge network
docker network inspect bridge

# Test DNS resolution in container
docker run --rm busybox nslookup google.com

Solution 2: Use Host Network Mode (Quick Fix)

# Run container with host network
docker run --network host image-name

# Example with Ubuntu
docker run --network host -it ubuntu:20.04 bash
apt update  # Should now work

Solution 3: Specify DNS Servers

# Run with specific DNS
docker run --dns 8.8.8.8 --dns 8.8.4.4 -it ubuntu:20.04 bash

# Or in docker-compose.yml
services:
  app:
    image: ubuntu:20.04
    dns:
      - 8.8.8.8
      - 8.8.4.4

Solution 4: Configure Docker Daemon

Edit /etc/docker/daemon.json:

{
  "dns": ["8.8.8.8", "8.8.4.4"],
  "bridge": "docker0",
  "storage-driver": "overlay2"
}

Restart Docker:

sudo systemctl restart docker

Solution 5: Fix iptables Rules

# Allow forwarding
sudo iptables -P FORWARD ACCEPT

# Or use Docker-recommended rules
sudo sysctl net.ipv4.ip_forward=1

# Make persistent
echo "net.ipv4.ip_forward=1" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p

Solution 6: Check Docker0 Interface

# View docker0 interface
ifconfig docker0
# or
ip addr show docker0

# Bring up docker0 if down
sudo ip link set docker0 up

# Check routes
ip route

Solution 7: Docker Compose Network

version: "3.8"
services:
  app:
    image: ubuntu:20.04
    command: /bin/bash -c "apt update && apt install -y curl"
    networks:
      - mynetwork
    dns:
      - 8.8.8.8
      - 8.8.4.4

networks:
  mynetwork:
    driver: bridge

Testing Solutions

Test Internet Connectivity

# Inside container
docker run --rm ubuntu:20.04 bash -c "apt update && echo 'Success'"

# Test DNS
docker run --rm busybox ping -c 1 8.8.8.8

# Test DNS resolution
docker run --rm busybox nslookup github.com

# Test HTTP
docker run --rm curlimages/curl curl https://example.com

Dockerfile Recommendations

FROM ubuntu:20.04

# Prevent apt from blocking
RUN apt-get update && \
    apt-get install -y curl wget && \
    rm -rf /var/lib/apt/lists/*

# Or with DNS override
RUN echo "nameserver 8.8.8.8" > /etc/resolv.conf && \
    apt-get update && \
    apt-get install -y needed-package

Debugging Steps

# 1. Check container logs
docker logs container-id

# 2. Inspect container network
docker inspect container-id | grep -i ip

# 3. Enter container and test
docker exec -it container-id bash

# 4. Test from host
ping container-ip

# 5. Check host network
ifconfig
netstat -an

# 6. View Docker network info
docker network inspect bridge

Platform-Specific Solutions

Linux

# Check if packet forwarding enabled
cat /proc/sys/net/ipv4/ip_forward  # Should be 1

# Enable if needed
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward

# Check iptables
sudo iptables -L -n

Windows (Docker Desktop)

  1. Open Docker Desktop Settings
  2. Go to Resources → Advanced
  3. Verify memory allocation
  4. Restart Docker Desktop

macOS (Docker Desktop)

  1. Preferences → Resources → Network
  2. Check DNS settings
  3. Restart Docker

Prevention

  1. Always use DNS - Never rely on default
  2. Test containers - Run test commands
  3. Monitor logs - Check container logs regularly
  4. Update regularly - Keep Docker updated
  5. Document configuration - Save working setups

Common Mistakes to Avoid

# ❌ Wrong: No DNS specified
docker run ubuntu:20.04 apt update

# ✅ Correct: With DNS
docker run --dns 8.8.8.8 ubuntu:20.04 apt update

# ❌ Wrong: Depends on iptables rules
docker run --net=host ...

# ✅ Correct: Explicitly configure
docker run --dns 8.8.8.8 --net bridge ...

Quick Reference

Issue Solution
No internet Use --network host or specify DNS
Slow download Use faster DNS (1.1.1.1, 8.8.8.8)
Cannot reach host Check firewall rules
Container IP not stable Use bridge network with fixed IPs

Summary

Most container network issues can be resolved by:

  1. Specifying DNS servers explicitly
  2. Using appropriate network modes
  3. Checking host network configuration
  4. Testing connectivity systematically
